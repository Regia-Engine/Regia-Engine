# Ferrite v0.1.5

Patch release for Direct Order 27's alpha (Saturday 2026-10-17): fixes for DO27's performance and look reports, two
concurrency races found by the merge gates, and new automated checks for the cases that reached the owner's first play.

- **Commit:** v0.1.5 = the tag `v0.1.5` (the gated code commit is named in the tag message).
- **Workspace version:** `0.1.5`.

## Upgrade from v0.1.4 (host source changes)
Six struct literals need one change each. Code that uses the constructors or `..Default::default()` compiles unchanged.
- `MeshRenderer { .. }` gained `gi_proxy: bool`. Set `gi_proxy: true` for the old behavior.
- `ExtractedMesh { .. }` (hosts that build extracted frames directly) gained `gi_proxy: bool`. Set `gi_proxy: true`.
- `GraphTexture { image, srgb }` gained `compressed`, `shared` and `dynamic`. Write `GraphTexture::rgba(image, srgb)`.
- `LabMaterial { .. }` gained `images: MaterialImages`. Add `images: Default::default()` (or `..LabMaterial::default()`).
- `CompressedMaps { .. }` gained `detail`, `detail_normal` and `aux`. Add `..Default::default()`.
- `DdgiSettings { .. }` gained `sdf_pool_bytes` and `sdf_evict_frames`. Use `..DdgiSettings::default()`.

(The first version of these notes listed only three of the six; corrected 2026-10-12 after DO27's pin build.)

Re-capture reflection probes on atmosphere worlds (Mars) after updating: probes captured before v0.1.5 hold Earth's sky.

## Fixed
### Reflection probes on Mars reflected a blue Earth sky
`capture_reflection_probe` rendered the probe faces with the Earth sky, IBL and fog. It now captures the planet's own sky
and atmosphere, does not move a held camera's motion vectors, and a probe far from the camera no longer reflects in
stochastic SSR. Ordinary Mars LDR/MSAA frames are unchanged. The workaround `set_reflection_probes(vec![])` can go.

### Render caches evicted by age, re-uploading units that came back (ADR-183)
Meshes and materials are now kept within a byte budget (texture streaming budget plus a mesh allowance, at most half the
device-local VRAM; 1 GiB cap on Android) and evicted least-recently-drawn first, instead of after 10 s idle. A unit away
for 20 s returns with no uploads. `signal_memory_pressure()`, the OS low-memory event and the VRAM probe trim every
unpinned entry idle 30 frames once. `cache_stats()` reports uploads, evictions, resident and budget bytes.
`set_cache_residency` tunes it.

### One-joint skins (canopies, fans, doors) drew one by one
A skin whose vertices all bind rigidly to joint 0 now folds into the instance transform and draws instanced (16 parts:
per-object draws 16 → 0), pixel-identical. These parts now write motion vectors, so TAA output around them changes;
`set_rigid_skin_fold(false)` restores v0.1.4 behavior.

### DDGI signed-distance brick pool filled up and stopped tracing new meshes (ADR-182)
The pool (default 32 MiB, `DdgiSettings::sdf_pool_bytes`) now frees bricks of meshes not drawn for 300 probe updates
(`sdf_evict_frames`) and reuses them. A full pool retries later instead of marking the mesh failed. `MeshRenderer.gi_proxy
= false` keeps a mesh out of GI tracing (it still casts shadows).

### Material textures: duplicate uploads, uncompressed graph and detail maps (ADR-179)
Graph texture slots and packed detail / detail-normal / aux maps can carry cooked BC7/BC5 chains (`cook_graph_texture`,
`cook_shared_image`, `cook_surface_maps` in `ferrite_asset_pipeline`). A `SharedImage` or shared `CompressedTexture`
uploads once for every material that uses it and is freed with the last one. `DynamicTexture` rewrites one mip in place
with no new bind group (100 updates: 0 allocations). Measured on a sample: 8 private RGBA8 copies 174,752 bytes → one
shared BC7 image 5,488 bytes.

### Effects, decals and glass compiled their pipelines mid-play (ADR-181)
`VfxGpu::warm`, `vfx_warm_job`, `FrameRenderer::prewarm_decals` and `prewarm_glass_instances` build these during the
boot warm (cancellable, using the shipped pipeline caches). The engine's game-frame warm calls them automatically.
Checklist: "Effects, decals and glass (v0.1.5)".

### Scatter rocks popped while shrinking out (ADR-180)
The screen-size fade eases out (quartic) instead of a smoothstep: pops in the test dolly 5 → 0 on an RTX 5090 and
lavapipe. Held frames are unchanged.

### Shutdown could leave a shader-warm thread holding the GPU queue
Three holders were found and removed (queue registry upgrades from other threads, idle workers not joined, test-only
cross-queue compiles). `shutdown()` now joins every worker not inside a driver compile. Under 64 spinning threads:
targeted runs 20/20 failed before, 0/20 after; a panic=abort child exits cleanly 5/5 when quit during the warm.
(ADR-170 addendum.)

### Test reliability
- `light_budget`'s once-only warnings are per renderer (two renderers no longer alternate warnings); its test no longer
  races other tests.
- The three `bcn_fallback` GPU tests run one device at a time (one rerun in three deadlocked the NVIDIA driver; 0/10 now).

## New automated checks
- Smoke rows 19–21 and tests: ultrawide 3840×1600 frame and bench size; black-sky motion (silhouette pixels may not
  brighten past 1.3× under TAAU; fails on v0.1.3, passes with v0.1.4's fix); many moving units (encode budget against a
  baseline; fails with v0.1.3's per-vertex GI prepare).

## Known issues
- The older `ssr.wgsl` pass still blends reflection probes camera-wide; fixing it moves a golden, so it waits for the post-alpha batch.
- Probe faces captured on a planet have no aerial haze (forward fog is off there).
- In a lab scene on Desktop High, held frames can differ by up to 15 grey levels at a paged-shadow edge; not yet
  investigated.
- With texture streaming on, the per-frame resident-byte sum is O(materials) (a few µs at hundreds of materials).
- On DX12 the VRAM size is unknown, so the cache budget has no VRAM cap there (the pressure trim still applies).
- Everything listed under v0.1.4 still applies, except the items fixed above.
