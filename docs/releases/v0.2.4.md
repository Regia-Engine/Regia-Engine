# Regia Engine v0.2.4

Builds on v0.2.2. v0.2.3 was never tagged: its engine work (the Red-Rouge requests RR-1 to RR-6 and the capability
markers, `docs/releases/v0.2.3-red-rouge.md`) is folded into this note, and v0.2.4 is the tag that carries it. This
release adds these feature sets for game teams:

- **Cinematics and render-out**: a sequence player that plays a `.seq.ron` and a `.shots.ron` on one clock, drives
  bound entities, sends markers to gameplay and takes over a camera with blends; render jobs (`.render_job.ron`) that
  render takes, cut lists and movie files from one timeline; render-out on two clocks (slow motion and speed ramps
  through a time map), with a WAV mixdown and per-bus stems, depth/id/motion AOVs and scene-linear EXR frames; shot
  fades drawn by the engine, rotation keys and a Shots panel; replay playback on the simulation clock.
- **Camera shake sensors**: per-camera channels, gain, falloff and travel delay, contact shakes, and shakes that
  show during shots.
- **Water and terrain**: trochoidal swell with exact CPU surface and ray queries, terrain shoreline water drawn in the
  runtime frame, named terrain holes that open and close at runtime, and runtime height patches that reach the draw,
  physics, navigation and caches.
- **Lightmaps**: directional `.flmap` v2 with a v1 migrator, bicubic lookups, adaptive bake sampling with a noise
  report, cooked lightmaps, and static meshes shaded from the lightmap in the forward pass.
- **Rendering**: a per-object shadow LOD hint, opt-in eight skin influences (cooked mesh v3), a frame pass extension
  point with `render.graph`, and the renderer's frame code split into modules (no pixel change).
- **Content pipeline**: FBX and OBJ import, cooked packs that load with no CPU decode (`regia cook --ship`), asset
  validators and a dependency graph, and a pre-fractured destruction tool.
- **Localization and accessibility**: a fixed start-up locale order (flag, environment, saved setting, Steam, OS,
  project) with write-back and font locale; a gather/compile/pseudo-locale pipeline and a subtitle queue;
  screen-reader requests and localizable accessibility labels.
- **Gameplay framework**: AI state trees and abilities, ragdoll get-up, demo recording with a spectator camera, a world
  streaming and HLOD data model, a UI screen stack and breadcrumbs, voice capture on the agent protocol, loudness
  measurement, and an engine-side XR interface (no headset runtime bound yet).
- **Editor**: viewport panes drawn from GPU textures, and out-of-process editor tools with scoped tokens.
- **Windows and macOS**: the DDGI and baked GI shaders compile with FXC on DX12; `windows-pass` uses DXC; the
  pipeline-warm exit hook runs on macOS.

All new features are off, or unchanged for projects that do not use them, except where **Changed** says otherwise
(the camera shake order, terrain water, the start-up locale order, ragdoll recovery, editor GPU panes, bicubic
lightmaps, hidden `collision_*` nodes in the editor, shipping package checks, `.fbx`/`.obj` cooking).

## New

### Render-out: two clocks, time map, replay playback (RR-1, RR-2; ADR-1519, ADR-1524)

- **Two clocks** (`regia_app`). A `SimStep(Duration)` resource sets the simulation clock apart from the presentation
  clock: `Time::sim_delta()` and `Time::sim_elapsed()` follow it, `Time::delta()` keeps the frame step. `FixedUpdate`
  (physics, gameplay) and every sim bridge (`read_snapshot`) run on the simulation clock; `Update` systems (VFX, shot
  players, UI tweens, the material clock) keep the presentation step. Without a `SimStep` both are the same value.
- **Time map** (`render.out_start` `time_map`). `[{frame, scale, ease?}]` keys scale the simulation time each
  delivered frame covers (slow motion, speed ramps, freeze frames) at a fixed output rate. `ease` is `smooth`
  (default), `linear` or `hold`. Frame `j` covers `round(step · scale(j + ½))` ns in exact integer arithmetic. The
  render clock (VFX, shots, HUD, material clock, shutter, TAA) steps as without a map. A fast map raises
  `FixedTime::max_substeps` for the job, or is refused above 64.
- **Manifest `regia.render_out/2`**: `files` is `{ frames, audio, aov }`, `frame_times` is a per-frame table
  (`game_time_*`, `sim_time_*`, `sim_step_ns`, `time_scale`), plus `game_time_s`, `sim_time_s`, `replay_from_tick`
  and the `time_map` echo. `render.out_progress` adds `sim_time_s`, `replay_from_tick`, and for a running job
  `sim_step_ns` and `time_scale`.
- **`replay.play { from_tick, speed, interpolate, max_gap_ticks, start }` and `replay.pause`** play a loaded replay on
  the simulation clock. `start: "render_out"` waits and starts on the next render-out's frame 0.
- **Sub-tick blending** (presentation only): `ReplaySim::set_interpolation(max_gap)` and
  `ReplaySim::presented_snapshot`; `replay.step { presented: true }`. `snapshot`, `seek`, `step`, events and hashes
  stay exact.
- **Version 2 fulls through the writing build's codec**: `FullCodec::v2_full_len` (default `None`),
  `ReplayFile::parse_with` / `load_with`, `ReplaySim::load_bytes` / `load_path`.
- New: `ReplaySim::{hold_clock, held, advance_clock, tick_fraction, speed_permille, interpolation,
  presented_snapshot}`, `ReplayBlend`, `MAX_BLEND_GAP_TICKS`.

### Render-out: audio, AOVs, EXR (RR-3, RR-4; ADR-1520, ADR-1521, ADR-1554, ADR-1572)

- **Audio.** `render.out_start { audio: true }` (or `{ sample_rate, format, stems, timeline }`) writes
  `<name>_audio.wav` (stereo master after the limiter) and `<name>_audio_<bus>.wav` per stem (after the bus fader).
  `pcm16`, `pcm24` (default) or `float32`; 8 to 192 kHz (default 48 kHz). The mixer runs offline, one block per
  delivered frame, so the WAV is exactly as long as the video and two runs give the same bytes. `timeline` is
  `"render"` (default: sounds keep speed and pitch under a time map), `"output"` (varispeed on the simulation clock)
  or `"sim"` (unresampled). The answer, `render.out_progress` and the manifest carry an `audio` block (with `clock`
  and an FNV-1a hash per data chunk); `files.audio` lists the WAVs. Book: `agents/render-out-audio.md`.
- **Mixdown API** (`regia_audio`): `Audio::{begin_mixdown, render_mixdown, end_mixdown, check_mixdown, mixdown,
  mixdown_active}`, `MixdownSettings`, `MixdownBlock`, `MIXDOWN_SAMPLE_RATES`, `MAX_MIXDOWN_STEMS`.
- **AOVs.** `aovs` (any of `"depth"`, `"id"`, `"motion"`) and `aov_format` (`"exr"` default, or `"raw"`) write
  per-frame depth (view depth in meters, `f32`, sky `+inf`), id (`id.instance` per entity, `id.class` per mesh asset,
  0 = sky) and motion (backward, delivered pixels) files from their own unjittered pass. The manifest's `aov` block
  records encodings, id tables, motion resets and per-AOV hashes; `files.aov` lists the files.
- **Scene-linear EXR frames.** `format: "exr"` writes `R`, `G`, `B` in `f32` (cd/m², before exposure, bloom and the
  tonemap); the manifest's `color` block names the space.
- **Fade block.** The manifest's `fade` block lists the frames a shot fade was visible on, for plates that do not
  carry it (EXR and 16-bit frames).
- **Param schemas.** `agent.schema` describes `audio` (stems enum from the default bus layout: `Master`, `Music`,
  `Sfx`, `World`, `Ui`, `Voice`, `Ambience`, `Reverb`), `aovs`, `time_map` and `cuts` with items, enums and limits.
- **Headless showcase audio** (ADR-1561): the headless showcase has a headless mixer, so audio render-out works there.

### Render-out: render jobs driven by a sequence (ADR-1616)

- A **`.render_job.ron` v1** (new frozen format `render-job`, `docs/formats/render-job-ron.md`) names a `.shots.ron`,
  a `.seq.ron` whose markers it may use, takes (`Frames`, `Seconds`, `Markers`, `Shots`, `Whole`), output settings,
  extra cuts and a pre-roll cap. One timeline renders from time 0 and each frame goes into every take that holds it,
  byte-identical to a full render. Paths use `{job}`, `{take}`, `{shot}`, `{frame}`, `{date}`.
- **Automatic cut lists** from shot boundaries plus the job's `cuts`; each take reports its cuts and a `cut_list`.
- The shot list drives the camera on the render clock (shutter subframes follow; a shutter never straddles a cut),
  and render jobs drive `SequencePlayer`s on an external clock.
- **`render.out_job { file | job, date?, dry_run? }`**; `dry_run` answers the resolved plan. Twelve `render_job_*`
  error codes. Book: `agents/render-jobs.md`.
- **`regia render --job FILE [--date] [--dry-run] [--job-timeout-s]`**: runs the job in a running app; exit codes 0
  (done), 1 (no app or failed call), 2 (refused), 3 (failed), 4 (cancelled).
- **Movie takes**: `format` `ffv1`, `prores` or `dnxhr` pipes each take to its own ffmpeg (`.mkv` or `.mov`); without
  ffmpeg on `PATH` the job is refused (`F0019`).

### Cinematics: sequence player, shots (ADR-1614, ADR-1522)

- **`SequencePlayer`** (`regia_framework::sequencer`, `SequencerPlugin`): one entity per sequence, optionally with a
  shot list on the same clock; end policy `hold` (default), `loop` or `once`; optional start delay; gameplay clock or
  an external clock. Whole-nanosecond clock, so 30 Hz and 60 Hz replays apply the same values and markers.
- **Bindings** (`SequenceBindings`, by scene guid or entity id) and **property appliers** (`PropertyAppliers`:
  `transform.position`, `transform.rotation`, `transform.scale`, `visible`, `light.intensity`, `light.color`,
  `camera.fov`; games register more).
- **Messages** `MarkerReached { player, name, time, payload, cycle }` and `SequenceFinished`.
- **`CameraTakeover`**: the most recently started player's shots drive its camera, blending from the live pose over
  `blend_in` and back over `blend_out`; shot changes are renderer camera cuts.
- **`sequence.player`** agent method (load, play, pause, stop, seek, sample, bind, set, clear, query), guide topic
  `sequence_player`, book `agents/sequence-player.md`.
- **Shot fade drawn**: a compositor layer `fade` above the UI (`regia_render::{FADE_LAYER, FADE_ORDER, FadeHandle,
  FadeState, fade_output, install_fade}`, `regia_framework::shots::{ShotFadeLayer, fade_state}`); shows in windows,
  `seeing.screenshot` with `window_layers` and render-out frames. `render.sequence` replies carry `fade_layer`.
- **Rotation keys**: `rotation: [(time, rotation: (x, y, z, w), ease)]` on a shot camera (shortest-arc slerp);
  `camera.set_path` takes `rotation`. `regia_framework::shots::{RotationKey, sample_rotation}`.
- **Shots panel** and `editor.shot_panel_state` / `editor.shot_panel_edit` (fov, roll, focus distance, aperture
  curves). Book `agents/shot-panel.md`.

### Camera shake sensors (ADR-1619)

- `regia_framework::camera::sensor` (installed by `CameraPlugin`): a `ShakeSensor` sets channels (bitmask), gain,
  combine (`Add` or `Max`), world or camera axes and clock (`Gameplay` or `Unscaled`). Cameras without a sensor do not
  shake; rig and shot cameras default to channel 1, so existing projects shake as before.
- `ShakeEmit`: origin, channels, preset (noise `Shake`, blast law, ground shock), falloff radius, optional travel
  speed (delays count fixed steps). `ContactShake`: an opt-in physics body that shakes nearby cameras on impact.
- Agent: `camera.shake`, `camera.shake_sensor`, `camera.set_shake_sensor`; guide topic `camera-shake`; book
  `agents/camera-shake.md`.

### Water: swell and terrain water (ADR-1620)

- **Terrain water planes in the runtime frame**: with `WaterPlugin`, each `Terrain` with a shoreline `WaterPlane`
  gets a plane `WaterBody` tagged `TerrainWater` that follows the plane's edits; `WaterSettings::terrain_planes`
  (agent `water.set { terrain_planes }`) turns them off.
- **Swell**: `swell: Some(Swell { waves, crest_foam, foam_onset })` on a plane body, up to 32 trochoidal waves at
  deep-water speed, a pure function of the water clock's tick on CPU and GPU; `Swell::open_sea` for a deterministic
  spread; crest foam. Low draws 8 waves per body, High 16, Ultra 32.
- **Queries**: `WaterBody::surface(x, z, &clock)` (height, normal, velocity, foam) and `WaterBody::raycast`; agent
  `water.surface { at }` and `water.raycast { origin, direction, max_distance }`.
- **Ring grid**: a camera-centered mesh whose cell follows camera height and field of view. Spec `docs/specs/water.md`.

### Terrain: named holes and runtime height patches (ADR-1595)

- **Named holes**: `HolesMask::set_named`, `set_open`, `remove_named`; `TerrainHoles::edit` changes the mask a linked
  draw cuts on its next frame. A closed hole costs nothing (bit-identical frame) but keeps its slot.
- **Height patches**: `TerrainHeightPatches` queues rectangles of new heights; `TerrainPlugin` writes up to a budget
  (default 65 536 samples per frame) into the `Terrain`, its `TerrainSharedDraw` and a `TerrainHeightsChanged`
  message per band. Heights are quantized to the map's 16-bit grid so draw, CPU map, save and simulation agree.
  `CollisionHeightfield::patch` and `CollisionChunk` (`chunk_grid`, `chunk`, `chunks_touching`) rebuild only touched
  chunk colliders.
- Agent: `terrain.set_hole`, `terrain.patch_heights`, `terrain.get` (book `agents/terrain-runtime.md`; `hole_*` and
  `patch_*` codes).

### Rendering: lightmaps (ADR-1556, ADR-1623)

- **Directional lightmaps** (`.flmap` v2): a dominant light direction per texel lets normal maps bend baked light. On
  by default; `regia bake-lightmaps --no-directional` leaves it out.
- **Bicubic lookup** by default (`LightmapSettings::bicubic`, `render.set_lightmaps { bicubic }`); CPU mirror
  `Lightmap::sample_bicubic`.
- **Bake**: `report.noise` (relative standard error per texel), adaptive sampling (`--noise-target F
  --max-samples N`), bounded `--samples` (1..=65536), `--max-samples` and `--bounces` (at most 64); out of range is
  agent code `lightmap_bake_settings`.
- **Cooked lightmaps**: a `.flmap` under `assets/` cooks into the pak; `render.set_lightmaps { path }` reads the cooked
  copy first (`regia_render::lightmap::read_cooked_lightmap`).
- **Forward-pass receivers**: a static mesh with `regia_render::lightmap::LightmapReceiver { entry }` takes its
  diffuse indirect light from the lightmap (bicubic, directional when present) while `LightmapSettings::enabled` is
  set; direct and specular light are unchanged, other meshes keep probe light. `apply_lightmap_receivers` is added by
  `RenderPlugin`. Hosts that drive `FrameRenderer` use `set_lightmap`, `set_lightmap_receivers`, `lightmap()`,
  `lightmap_forward_stats()`. New `LIGHTMAP` forward variant (UV2 in vertex slot 1, group 3 bindings 12-16).
- Agent: `render.set_lightmaps` takes `bicubic`, `directional`; `render.get_lightmaps` reports `has_directions`,
  `directional`, `bicubic`, `forward { receivers, active, drawn, fallback, unsupported }` and `receivers { ... }`, with
  codes `lightmap_entry`, `lightmap_receiver_lod`, `lightmap_layout`.

### Rendering: shadow LOD hint, eight skin influences, collision nodes (ADR-1622)

- `regia_render::ShadowLodHint { max_lod, min_lod }` (`cap(n)`, `fixed(n)`) bounds a `MeshLodChain`'s shadow LOD.
  Agent: `render.shadow_lod_hints`, `render.set_shadow_lod_hint` (book `agents/shadow-lod-hint.md`).
- A glTF whose `.meta` says `skin_influences: 8` with `JOINTS_1`/`WEIGHTS_1` cooks eight influences (cooked mesh v3);
  `SkinningOptions::for_cooked_skin` builds the compute skinning table. `assets.skin_check` reports
  `stored_influences` and `draw_influences`.
- `regia_asset::is_collision_node_name` and `COLLISION_NODE_PREFIX`.

### Rendering: frame pass extension point (ADR-1552, ADR-1562)

- `FramePass` and `FrameRenderer::register_pass` / `remove_pass` / `registered_passes` / `graph_report`: a pass
  records into the frame's encoder at a slot (`after_opaque`, `after_transparent`, `before_post`, `after_post`,
  `overlay`); a failing pass is skipped and counted. Example: `cargo run -p regia_render --example custom_pass`.
- **`render.graph`**: built-in passes in recording order, slots, registered passes, forward shader permutations. Book
  `agents/render-graph.md`.
- `FORWARD_AXES`, `forward_permutation_report`, `FORWARD_PERMUTATION_BUDGET` (256, provisional, reports only).
- `REGIA_FRAME_HASH_DIR=<dir>` writes the FNV-1a hash of each golden compare
  (`regia_test_utils::golden::{frame_hash, record_frame_hash, FRAME_HASH_DIR_ENV}`).

### Content pipeline (ADR-1602, ADR-1594, ADR-1568, ADR-1567)

- **FBX import** (`regia_asset_pipeline::fbx_import`, `ufbx` C parser, pipeline only): binary and ASCII FBX converted
  to an in-memory glTF and cooked by the glTF importer (meshes, normals, up to eight UV sets with `uv_set` choosing
  UV0, first color set, skins with the eight strongest influences, blend shapes, PBR materials and textures, node
  hierarchy, animation stacks). `.meta` settings `scale`, `import_animation`, `sample_rate`, `uv_set`, `limits`.
  Untrusted-input caps (`FbxLimits`). `regia import <file.fbx> [--out GLB] [--json]`; agent `editor.fbx_inspect`
  (MCP `fbx_inspect`) with `fbx_*` codes. Book `agents/fbx-import.md`.
- **OBJ import** (pure Rust, `regia_asset_pipeline::obj_import`, `ObjLimits`): `.obj` + `.mtl` through the same path;
  `editor.obj_inspect` (MCP `obj_inspect`), `obj_*` codes; `regia import file.obj`.
- **Cooked packs** (DO-3): `regia cook --ship` writes paks that load with no glTF parse, PNG decode or transcode and
  checks every entry (`texture_family_mismatch`, `supercompressed_textures`, `unreadable_textures`,
  `legacy_meshes`), report `build/paks/<platform>/cooked_pack.json`. `--gpu-meshes` (same as
  `REGIA_PAK_GPU_MESHES=1`) and `--pack-report`. `AssetServer::load_forms()`, `LoadForms::cooked_only()`,
  `AssetServer::mounted_pak_summaries`, `AssetServer::platform()`, `regia_asset::cooked_pack`. Agent
  `assets.cooked_pack {inspect?}`, guide topic `cooked-packs`. Bench example `cooked_pack_bench` (the build server, 524,288
  triangles and two 2048² textures: runtime glTF 929 ms, plain pak 906 ms, cooked pack 8.8 ms).
- **Asset validators and dependency graph** (`regia_asset_pipeline::{validators, asset_graph}`): a `Validator` trait,
  `ValidatorRegistry`, six built-ins, `ValidationReport` (`format_version` 1); `AssetSet` and `DependencyGraph` with a
  cooked-size roll-up. Agent `editor.asset_validate`, `editor.asset_graph`.
- **Pre-fractured destruction** (`regia_asset_pipeline::fracture::fracture_mesh`): seeded Voronoi chunks of a closed
  mesh with capped faces and area-scaled breakable joints; `FractureSet` serializes to `.fracture.ron` v1 and converts
  to `regia_physics::ChunkDesc`. Agent `editor.fracture_preview` (editor host).

### Localization and accessibility (ADR-1618, ADR-1570, ADR-1621)

- **Start-up locale order**: `--locale <tag>`, `REGIA_LOCALE`, the saved settings language, the Steam per-game

- **Pipeline** (`regia_ui::loc_manifest`, `loc_compile`, `loc_pseudo`): gather keys and references into a

- **Subtitle queue** (`regia_ui::subtitles::SubtitleQueue`, inserted by `UiPlugin`). Agent `ui.localization`,
  `ui.subtitles`; book `agents/ui-localization.md`.
- **Screen-reader requests** (`regia_ui::a11y::A11yRequest` with `A11yAction`: `press`, `raise`, `lower`, `set_text`,
  `focus`, `close`, `scroll_into_view`, `page_up`/`down`/`left`/`right`), refused with an `A11yReject` for disabled,

### Editor (ADR-1555, ADR-1523, ADR-1582)

- **GPU viewport panes**: each pane's renderer target is an egui native texture (picture byte-identical to the

## Changed

- **Camera system order** (ADR-1614, ADR-1619, ADR-1634): new `CameraSet::Cinematic` between `CameraSet::Update` and

### Changed behavior

- **Camera order**: work ordered `.after(CameraSet::Director)` still sees the final shot pose, now with the shake on
  top. Work between the shot pose and the shake orders `.after(ShotDriveSet).before(CameraSet::Director)`. A camera
  with `CameraPlugin` and a shot sequence now shakes during the shot; give it `ShakeSensor::off()` to keep it steady.
  A camera the shot player or a sequence takeover drives gets `CinematicCamera` and a `ShakeReceiver`, not a
  `CameraRuntime`. A host that sampled `CameraDirector` itself after `ShotDriveSet` to work around the lost shake must
  not also add `CameraPlugin` (the shake would apply twice). While a sequence player's shots hold a camera, other
  writes to its transform and field of view are overridden.
- **Terrain water**: one more `WaterBody` entity per terrain with a `WaterPlane`; set
  `WaterSettings::terrain_planes = false` to keep the old picture.
- **Terrain patches**: `TerrainPlugin` inserts `TerrainHeightPatches`, registers `TerrainHeightsChanged` and adds
  `apply_terrain_height_patches` to `Update`. Hosts that draw a terrain insert `draw.height_patches_handle()` as the
  `TerrainHeightPatches` resource (as with `holes_handle()`).
- **Plugins**: `AiPlugin` runs `tick_abilities` (in `AiStep`, before the behavior-tree tick) and ticks state trees
  after behavior trees, and registers three reflected types; `UiPlugin` inserts `ScreenStack` and `SubtitleQueue`,
  registers `ScreenChanged` and runs `screens::sync_screens` before `layers::sync_layers`; `LocalizationPlugin` and
  the settings plugin register `PlayerSetLocale` and `LocaleWriteBack`; `RenderPlugin` adds
  `apply_lightmap_receivers` before `extract_frame`; `AgentPlugin` installs the sequencer. Each acts only on entities
  or resources that use the new features.
- **Lightmaps**: a shader that includes `lightmap.wgsl` declares `@binding(3) var lightmap_direction:
  texture_2d<f32>` (the bind group layout has a fourth binding). Existing lightmaps sample bicubic unless
  `LightmapSettings::bicubic = false`.
- **Ragdoll**: set `Ragdoll::recover_snap = false` to keep the rig in place on recovery.
- **Editor**: tools that expected `collision_*` meshes in a spawned hierarchy pass `show_collision: true`. A host that
  embeds the editor panel with its own egui renderer inserts `PaneTextures` and calls
  `PaneTextures::apply(&mut EguiNative { renderer, device })` once per present (without it the panel reads back).
- **Shaders**: a dev override of `lab_forward.wgsl` that still defines the moved helpers fails to compose and falls

- **Render-out paths**: a host without an asset server that sets `AgentSettings::project_dir` finds a relative `out`

- **Time map**: gameplay that moves in `Update` with `Time::delta` stays at render speed under a `time_map`; read

- **Cooking**: `.fbx` and `.obj` files under `assets/` now cook (were "unsupported extension" errors); textures beside

  `cargo xtask notices`.

## Known issues

### Render-out and replay

- Gameplay that moves in `Update` on `Time::delta` stays at render speed under a time map, in the picture and AOVs.
  With `audio.timeline` `output` or `sim` under a map, `Audio::tick` (fades, ducking, music clock) runs on the render
  clock. Blending across a gap of more than one tick is a straight line. After a render-out an armed replay keeps
  playing until `replay.pause`. `replay.load` reads a relative `path` against the working directory.
- Audio: a job ends every sound playing at its start and end; events start on their delivered frame, not inside it;
  streamed sounds can outrun their decoder; no dither; stereo only; one WAV per job (takes name sample ranges). The
  `stems` schema enum lists the default bus layout only.
- AOVs: no AOV for translucent materials, particles, water or decals; alpha-masked cards are untested with mipmaps;
  terrain holes and edits during a job are not drawn; large heightfields use a sample stride; morph targets are
  ignored. `format: "exr"` needs a view that runs the post stack. EXR and 16-bit frames never carry the shot fade.
- Render jobs: pre-roll renders every earlier frame at full size; jobs drive existing sequence players but do not
  create or bind them (`sequence_tracks_not_applied`); `regia render --job` does not launch an app.

### Cinematics and camera

- The spec-35 camera runner is not built. The Shots panel has no undo, draws `Smooth` segments as lines and no
  position paths or rotation keys.
- The FOV kick is one value for all cameras; `ContactShake` emits from the body's position; `BlastShock` and
  `camera.schedule_shock_shake` measure to the first rig.

### Water and terrain

- No shoaling or breaking at the shore; the ring grid can shimmer on far rings and is not frustum-culled; water GPU
  time and the Steam Deck swell budget are not measured.
- A physics collider shape swap rebuilds the whole heightfield (use `CollisionChunk`); `regia_nav`'s tile cache cannot
  re-voxelize patched terrain; any height change invalidates every resident virtual-texture page.

### Rendering

- Lightmap receivers: the `LIGHTMAP` variant builds on the first frame that draws a receiver (a warm on a stand-in
  renderer does not); `LightmapReceiver` is not reflect-registered (not saved in `.level.ron`); receivers cannot use
  material graphs, skins, morph targets, LOD chains or cross-fades and draw one CPU draw each; a `--direct-sun` bake
  adds the sun twice when the live sun is on; an atlas over the device's 2D limit is not uploaded; `lightmap.wgsl`
  edits do not hot-reload into the forward variant; one direction per texel; adaptive sampling can stop early (keep
  `--samples` at 16 or more).
- No eight-influence vertex-shader path (devices without compute draw the four strongest). The shadow LOD hint does
  not apply to terrain scatter or cluster-cast shadows.
- The render graph does not yet own recording order, transients or pipelines; part of the frame setup is still in
  `render_into`; the permutation count is not in the cook report or `ship_check`.

### Content pipeline

- FBX: one UV set is cooked; Lambert/Phong shininess maps, cameras, lights, NURBS, constraints and per-instance
  material overrides are not imported; an animation-only FBX fails with `fbx_no_mesh`; the C parser runs in the cook
  process; Windows MSVC / `cargo xwin` and macOS builds of the C file were not run by the lane.
- Cooked packs: skinned, morphed and `COLOR_0` meshes and all Android meshes stay compact; a ship build that misses a
  pak entry can still fall back to the dev cooked cache; package time grows by one read of every texture entry.
- Fracture chunks carry positions only and need a closed 2-manifold mesh; no cook step writes `.fracture.ron`; dropped
  small chunks' volume is not redistributed. No `AssetSet` from the cook cache, `regia validate` command or validator
  panel.

### Localization, accessibility, gameplay

- Not done: Android localized app label, OS-provided native locale names, a bundled Japanese or Traditional Han subset.
  `loc_no_self_name` warns only once a locale defines `locale-name`. Nothing ticks `SubtitleQueue` from game time; no
  CLI command runs the localization pipeline; the `.ftl` gather is a line scanner. Two gather scanners
  (`loc_gather`, `loc_manifest`) and two pseudo-locale implementations exist side by side (ADR-1589).
- The OS accessibility bridge is not built (the AT-SPI stub only records); hint and label keys take no arguments.
- Ragdoll joints stay unlimited ball joints (ADR-1563 j). State-tree tasks take no parameters; no editor panel or hot
  reload. No plugin records an ECS world into a demo; the spectator pose is not written to a render camera. Nothing
  consumes the streaming/HLOD model. XR: no runtime, swapchain or wgpu hand-off; four session states; not run on a
  device.

### Editor

- GPU panes: with grid or outline on, the id buffer and an overlay still go through the CPU; play-in-editor panes read
  back; GPU timings lag one frame; a new pane shows its background for one frame; the 60 fps goal is not measured.
- Editor tools: only the launched program is stopped (no process-group kill); a master-token `editor.tool_call` waits
  for the idle editor's next frame (up to about a second); methods a tool provides are not in `agent.schema`
  (`editor.tool_methods` lists them); not run on Windows or macOS hardware.

### Platforms and tests

- Windows DX12 without DXC crashes creating the forward pipelines (FXC overflows its stack on `lab_forward.wgsl`);
  shipping DXC is an open decision (ADR-1583, ADR-1624). `hwrt_shadow_ray_query.wgsl` needs SM 6.5 and DXC. Start
  `cargo xtask windows-pass` from the console session, not `ssh`.
- macOS (M5, Metal): `ssao_blur_tile`, `bent_normals` (not re-run after ADR-1626), `perf_overlay::
  cost_stays_within_budget` (flaky) and `gpu_matches_cpu` (needs Sponza) fail; `regia doctor` reports Android checks
  as failures on a Mac.
- The `regia_render` lib test binary hits SIGSEGV at exit in the gate's real-GPU pass after all tests pass (counted as
  a pass). `nan_guards` fails 3 of 4 cases on the RTX 5080 under Windows; `atmosphere_golden` sky_noon SSIM 0.978 on
  the 5080 awaits an owner decision; three `regia_render` lib test processes on one GPU can run out of device
  contexts; other two-render compare tests may need a blocking scope.
- The 8192 m showcase scene needs more than 10 GiB of RAM; `ssgi.wgsl` has the same clamped edge test as the old SSAO
  (unchanged); `unit_budget` cannot run from a copied binary; `golden_sponza` and `golden_skinned_fox` skip without
  their models.
- A root `NOTES.txt` (lane scratch from five ext2 lanes) is still in the tree.

## Golden changes

- None blessed. The renderer split and the FXC shader rewrites keep frame hashes identical (lavapipe reference). The
  SSAO far-edge rule is expected to leave frames byte-identical on cards that already rounded the edge difference to
  zero. The new golden `lightmap_forward_quad_box.png` is not blessed and its test stays ignored.
