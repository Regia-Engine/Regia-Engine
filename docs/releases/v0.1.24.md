# Ferrite v0.1.24

Builds on v0.1.23. A stability and audio release: the deliberate-exit change for a lost GPU device, cue filter offset
and per-event seed (`.cue.ron` v2), more test and temp-path audits, hand-run performance microbenchmarks, new manual
pages, and the UI planning docs.

## New

- **Cue filter offset and per-event seed** (ADR-272, `.cue.ron` v2). Optional `filter_cutoff_hz` and
  `filter_offset_octaves` put a low-pass on a cue (cutoff = base * 2^offset, clamped to 20..20000 Hz). Files
  without them are v1 and play unchanged, with no filter track. `Audio::play_cue_seeded`, `play_cue_event` and
  `cue_event_seed(event_id, tick)` take the cue pick and its pitch/volume variation from the event, so the same
  event replays the same variation; `play_cue` is unchanged. Cues have no agent-protocol surface today.
- **Deliberate-exit API** (ADR-276). `ferrite_platform::begin_deliberate_exit`, `finish_deliberate_exit`,
  `deliberate_exit_code` and `DeliberateExit` are new. A host with its own `main` loop (not `ferrite::run_with`)
  should call `finish_deliberate_exit(|| log_guard.flush())` before it returns from `main`.
- **Perf microbenchmarks.** Hand-run timing tests for ReplaySim, camera path sampling and the render-out sink
  (`docs/06-testing-and-ci.md` § 9). They are not part of the gate.
- **Test helper** `ferrite_test_utils::unique_temp_dir`.
- **Manual and book pages** for shot sequences, replay playback, render-out and the macOS bring-up, plus agent page
  fixes.
- **UI planning docs** (docs only, no UI code yet): the UI parity roadmap (ADR-273, proposed) and the default UI
  design with theme tokens, `.theme.ron` and default widget looks (ADR-274, proposed).

## Changed

- **Pipeline warm shutdown wait** (ADR-276, following ADR-269's rule). A warm compile already inside the driver is
  waited for up to 30 s at shutdown (was 2 s; `FERRITE_WARM_SHUTDOWN_WAIT_MS` sets another limit in milliseconds)
  and up to 30 s in all at process exit (was 5 s). Once the device is lost, the warm and material-graph worker waits
  are at most 250 ms.
- **Test audits.** Agent tests use unique never-created paths; the editor glTF and report fixtures use unique
  per-process temp names; golden-failure artifacts are written atomically; the Steam tests no longer mutate the
  environment. Wall-time budget measurements retry so one preempted frame does not fail them. Replay, moments,
  `render.out_*` and camera path coverage is stronger; `camera.set_path` is denied read-only at the dispatcher.
- Docs: macOS references point at ADR-264 (testing-only bring-up); ADR and doc cleanup.

## Fixed

- **Device-lost and deliberate exits no longer run process-exit driver teardown** (ADR-276). A loaded soak of v0.1.23
  saw a SIGSEGV in the NVIDIA driver's process-exit teardown after a device-lost exit, and the native crash handler
  then wrote a second "native crash" bundle. After the device-lost bundle is written, the engine now begins a
  deliberate exit: the native crash handler writes no bundle from then on, and once the app has exited
  `ferrite::run_with` flushes the log and ends the process with code 3 (4 for no window surface) through `_exit` /
  `TerminateProcess`, skipping the process-exit handlers that touched the driver. An exit watchdog (15 s, same
  code) covers a teardown that hangs on the dead device. This is not claimed fixed for all cases until a loaded
  60-run soak is clean (see Known issues).

## Upgrade

- `.cue.ron` is now v2. Older (v1) files load through the migrator; `ferrite upgrade-project --write` rewrites them
  and stamps `version: 2`. The cue format hash in `docs/formats/format-hashes.ron` is re-recorded.
- Hosts with their own `main` loop: see the deliberate-exit API above.
- Hosts that relied on the 2 s / 5 s pipeline-warm waits should allow for the longer ones above.

## Known issues

- A loaded 60-run soak has not yet confirmed the exit fix; treat it as a mitigation until it does.
- `pipeline_warm` leftover workers may still be inside the driver at exit under extreme load; ADR-269 and ADR-276
  do not fully cover them.
- macOS (not gated): 8 tests fail on Apple M5, and the macOS guards are not in this release. The `lane/macos-triage`
  and `triage2` lanes follow in v0.1.25.
- Selector state for cues (shuffle bag, no-repeat window, sequential index) is still per cue, so a seeded play is
  reproducible only given the same cue history.

Not in this release: baked light (reserved for v0.2.0), UI code (ADR-273 and ADR-274 are plans).
