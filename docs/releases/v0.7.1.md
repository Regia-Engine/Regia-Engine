# Regia Engine v0.7.1

> **Never released.** The v0.7.1 gate was stopped and v0.7.1 was not tagged. Everything below ships in
> v0.7.2, together with a patch for the public v0.7.0 tree: see [v0.7.2](v0.7.2.md).

Builds on v0.7.0. v0.7.1 is the multiplayer hosting release asked for in request R23 (spec 89 § 16,
ADR-10375): a player can host a game on a dedicated server they own without anyone seeing their
address, a host can hide its own address behind the relay, and the lobby hub and the relay ship as one
deployable process. It also carries the review fixes of those features, template build-path remaps,
SPDX headers on Regia's own vendored upscaler files, onboarding docs for the `quick` template,
gate tooling fixes, and the user manual (feature catalog, glossary, index, quickstarts, and how-tos).

One content format moved: **`hub.toml` is format 2** (`regia upgrade-project` migrates it, see Upgrade).
The hub wire codec is generation 2, but the handshake protocol stays 1: **v0.7.0 clients keep working
against a v0.7.1 hub, and v0.7.1 clients keep working against a v0.7.0 hub.** No CLI subcommand,
shader program, agent method or fuzz target was added.

Read **Upgrade** first if your code matches on the lobby hub's protocol types: eight of them changed
and are now `#[non_exhaustive]`; the fix is one line per match or pattern.

## New: hosting multiplayer games (R23)

### Host on your own dedicated server without exposing your address (delegated sessions, NL-07)

A player (the owner) binds a dedicated server they run to their player key, then creates a lobby on
it. Members find it through the hub and join the server directly. They never learn the owner's address,
and every member pins the server's `ServerKey` during the sealed handshake.

1. The server proves the binding: the owner signs a binding with Noise pattern `X`
   (`regia_net::crypto::binding`, a fixed 49-byte payload), and the server registers with it
   (`HubLobbyBackend::register_server`, or `HubServer::register_server` in your own hub).
2. The owner creates the lobby on that server (`HubLobbyBackend::create_delegated`).
3. Members ask for reach as they do for any lobby. The hub brokers mapped, punched or relayed paths
   (`SimNat` matrix tested) to the server, not to the owner.
4. If the owner leaves mid-match, the game keeps running for the grace period (`GraceStarted` /
   `GraceEnded`; `grace_ms = 0` keeps the lobby until `CloseLobby` or the server goes offline).
   The same player key reconnects as owner.
5. Revoking a binding (`revoke_binding`) stops that owner's new lobbies on that server at once. The hub
   keeps revocations in `revocations.ron` (temp file plus rename, cap 4,096) and reloads them on restart.

A server that registers with no owner proof may still open a **public dedicated lobby** (an ownerless
server); its directory card says `dedicated` and carries no address. Codes for every refusal are listed
in [Delegated hub sessions (agents)](../../book/agents/net-delegated-sessions.md) (`hub_binding_unbound`,
`hub_binding_expired`, `hub_binding_revoked`, `hub_binding_not_owner`, `hub_binding_invalid`,
`hub_server_offline`, `hub_server_full` and the rest). `lobby.hub_servers` and `lobby.hub_bindings`
report servers and bindings; no new agent method.

### Hide the host's address: relay-only (NL-08)

- A dedicated server started with **`--relay-only`** (with `--relay`) registers its game port with the
  relay and never publishes its address. It skips the router mapping and the host check.
- A lobby owner (listen host, delegated owner or the bound server) can switch a lobby to relay-only
  with `set_reach_mode`. Every member then plans the relay path only; neither side's candidates are
  sent. A single `ReachOffer.relay_only` hides just that pair.
- On the wire: relay-only plans carry no candidate or mapped address, the member's ticket names an
  unspecified address with the same server key, and the relay's `HostInfo`, `Allocate`, `Allocated`
  and `ClientJoined` replies name neither side. `RelayRegistrar::relay_only` and
  `JoinPath::relay_first` are the building blocks for your own host.

### Addresses stay private, asks are limited, bans hold (NL-09)

- No listing, query, presence event or lobby-data read contains an address. Lobby data, member data
  and handles that spell a socket address (including bracketed, zoned, `udp://` and `steam:` forms)
  are refused (`hub_address_in_data`) or replaced by a stand-in handle.
- `AskReach` is rate limited per player key (4 per 10 s) and per source address (16 per 10 s), with
  at most 2 open asks per key and 64 on the hub (`hub_ask_rate_limited`, `hub_ask_inflight`). The
  limits are optional `[limits]` keys in `hub.toml`.
- Ban lists are checked before any candidate is copied, and again at approve: hub-operator bans (a
  player-key file, `[bans] path`), the lobby owner's bans (`set_bans`, cap 64) and the server's
  published list. A banned key gets `hub_banned` and no candidates.

### Join without the ECS (NL-10)

`regia_net` builds with `default-features = false`: the wire, crypto, relay helpers and the hub join
surface link none of `regia_ecs`, `regia_app`, `regia_scene`, `regia_asset` or `regia_platform`.
`JoinPlanDriver` runs a member's `JoinPlan` on a socket your game owns (`push_datagram`, `advance`,
`poll_send`, then `take_endpoint` for the connected socket and the `ServerKey` to pin).

### One deployable hub and relay process (NL-11)

`regia package --server` stages `regia-lobby-hub` with `hub.toml` and systemd units. With
`[relay] enabled = true` (the default in a fresh `hub.toml`, UDP port 7812, 256 allocation sockets)
the same process runs the relay. To deploy:

1. Copy the packaged directory to the host and install `deploy/regia-hub.service`.
2. Open UDP 7810 (hub) and, if the relay is on, UDP 7812 plus the allocation sockets.
3. Ship the hub's hex public key in your game's config (the private key stays in `key_path`, outside
   any project). A client that pins a different key ends during the handshake (`hub_key_mismatch`).
4. Watch `GET /health` (loopback 7811) or `lobby.hub_status`: `relay_allocations`,
   `servers_online` and `draining`, numbers only.

SIGTERM drains: new sessions and new relay allocations stop, issued allocations keep refreshing, and
the process exits 0 when they are gone or after 30 s of the process clock, whichever is first. The hub
unit's `TimeoutStopSec` is 45 s so systemd does not kill it inside that window. Key rotation is two
processes: bring the new key up on a new port, ship a pin list with the new key first, then stop the
old one.

## Changed

- `HubLobbyBackend::note_hub_game_version`: a hub that announces game version `"2"` is a v0.7.1 hub;
  anything else stays on wire 1, and version-2-only calls are refused locally (`hub_needs_wire_v2`)
  before a byte is sent.
- A delegated server session that is not a lobby member and calls an owner-only method gets
  `not_owner` (was `not_in_lobby`).
- Shipping builds remap the home directory to `/builder` (was `/home`), so a `/home/...` prefix no
  longer trips the packaging host-string gate. Panic locations read `/builder/...`; in a debugger use
  `set substitute-path /builder <real root>` (ADR-10354, ADR-10370).

## Fixed

### Networking

- **Delegated lobbies** (review of NL-07, ADR-10395): a resumed owning player no longer receives a
  member's `ReachAsk` (with its candidates) on resync; the server session does. A second link that
  takes a server key no longer becomes the delegated lobby's owner, and the old link's disconnect
  starts grace. Replacing a server link no longer leaves a listen lobby listed under a dead member.
- **Relay-only** (review of NL-08, ADR-10399): a stored server or lobby flag now hides both plan
  directions (approve passed `false`), `ReachAsk` no longer carries the member's address when either
  offer is relay-only, and the relay's replies no longer name the host or the member.
- **Address exposure and late bans** (review of NL-09): the address spellings above are refused, and a
  ban that lands between `AskReach` and `Approve` ends the ask with `ReachDenied` instead of copying
  the owner's candidates into a plan.
- **Hub process** (review of NL-11): the hub's systemd unit stopped it after 10 s, inside the 30 s
  relay drain (now 45 s); `relay.per_address_per_sec = 0` (documented as "no limit") was rejected;
  migrating a version-1 `hub.toml` whose `[relay]` table had no `enabled` key turned the relay on
  (it now writes `enabled = false` into that table, and refuses an inline relay table it cannot edit);
  `format_version = +1` or `0x1` (valid TOML for 1) did not migrate; and a link that connected during
  the drain and was refused could hold the drain open for the idle timeout (the 30 s window is now the
  upper bound once sessions are gone).

### Packaging and privacy

- **Template build paths** (ADR-10370): new projects from the templates ship directory-root remaps and
  append the home-directory remap last, so a release build does not embed the build machine's paths.
  Samples resolve project paths at runtime instead of `env!("CARGO_MANIFEST_DIR")`.
- `regia package` refuses a release binary that contains private build-machine strings (ADR-10354,
  `cargo xtask host-strings`).

### Licensing

- **SPDX headers on Regia's own upscaler vendor files** (`crates/regia_render/src/upscaler/vendor/`,
  ADR-10377). `cargo xtask spdx` now skips only the root `vendor/` tree (third-party code), so these
  Regia-authored files are checked.

  ones second (it read only the old names while its comment named the new ones). The engine's

## Upgrade

### Lobby hub protocol types (one-line fixes)

These hub protocol types gained variants or fields and are now `#[non_exhaustive]`, so later additions
do not break you again. `HubLobbyBackend` itself did not change shape.

| Type | What changed | Fix in your crate |
|---|---|---|
| `HubRequest` (enum) | `AnnounceWire`, `RegisterServer`, `RevokeBinding`, `CreateDelegated`, `SetReachMode`, `SetBans`, `CloseLobby` | add a `_ =>` arm to the match |
| `HubEvent` (enum) | `ServerOnline`, `ServerOffline`, `LobbyAssigned`, `GraceStarted`, `GraceEnded`, `BindingChanged`, `SessionConfirmed` | add a `_ =>` arm |
| `HubError` (enum) | `NeedsWireV2`, `NotReady`, the binding and server codes (`BindingUnbound` ... `RevokeFull`) | add a `_ =>` arm |
| `ReachOffer` (struct) | `relay_only` | `..` in patterns; build with `ReachOffer::default()` then assign fields (no struct literal) |
| `HubLobbyCard`, `RoomState` (structs) | `kind`, `relay_only`, `capacity`, `load` | `..` in patterns |
| `DirectoryPage` (struct) | `servers` | `..` in patterns; build with `default()` then assign |
| `HubReport` (struct) | `servers`, `servers_online`, `relay_allocations`, `draining` (all `#[serde(default)]`) | `..` in patterns; build with `default()` then assign |

Other host-visible changes:

- `HubSettings` and `HubLimits` gain `ask_per_identity_per_10s`, `ask_per_address_per_10s`,
  `ask_inflight_per_identity`, `ask_inflight_hub`: a struct literal adds `..HubSettings::default()` /
  `..HubLimits::default()`.
- `CliOverrides` (dedicated server) gains `relay_only`: a literal that names every field adds it or
  `..CliOverrides::default()`.
- `lobby.hub_status` results include `relay_allocations`, `servers_online`, and `draining` on each
  hub (the `HubReport` fields above). A reader of the old result adds those fields. They are
  `#[serde(default)]`.
- `HUB_WIRE_VERSION` is 2; the handshake still uses `HUB_WIRE_VERSION_V1` (`HubWire::PROTOCOL_VERSION`
  stays 1, `HubWire::GAME_VERSION` is `"2"`).
- `verify_binding` takes `now_ms`.
- Setting `ReachOffer.relay_only` now changes what `broker_reach` and `plans_for` return (`Relay`, or
  `NoReach` without a relay and join code): a match that named only `Mapped` and `Punch` needs a
  `Relay` arm. `JoinPath::relay_first` no longer gathers or sends candidates.
- A host that stored a socket address in lobby or member data now gets `hub_address_in_data`.
- New public items (additions): `HubServerCard`, `ServerRegister`, `LocalBinding`, `HubNotice`,
  `LobbyKind`, `ServerCard`, `ServerNotice`, `BindingState`, `ServerPresence`, `BindingClaims`,
  `JoinPlanDriver`, `PlanEndpoint`, `PlanSocket`, `PLAN_QUEUE`, `HubDocument`, `HubRelayFile`,
  `HubBansFile`, `HubLogFile`, `HubServer::set_reach_mode`, `encode_register_hidden`,
  `RELAY_HIDE_ADDR_EXT`, and the `HubServer` / `HubLobbyBackend` delegated-session methods.

### `hub.toml` format 2

Version 1 still loads, with the relay off. Run **`regia upgrade-project`** to stamp version 2: the
migrator keeps your bytes, rewrites the version line, and adds `[relay] enabled = false`, `[bans]` and
`[log]` where they are missing, so an existing hub does not open port 7812 until you turn the relay on.
A fresh package writes `enabled = true`.

### Compatibility with v0.7.0

The handshake protocol is unchanged. A v0.7.0 client connected to a v0.7.1 hub keeps its session; the
hub hides dedicated lobbies from its directory and rewrites events it cannot read. A v0.7.1 client
connected to a v0.7.0 hub stays on wire 1 and refuses version-2-only calls locally
(`hub_needs_wire_v2`) without sending them.

## Known issues

- Both compatibility directions are tested against a simulated wire-1 peer (one that never announces
  wire 2), not against a v0.7.0 build.
- Spec 89 § 16.10 row 10 asked that a version-1 client and a version-2 hub refuse each other with
  `protocol_mismatch`; ADR-10378 kept the handshake at protocol 1 so they interoperate instead.
- A banned key, or a stranger asking an invisible dedicated server that is full, can tell the lobby
  exists (`hub_banned` / `hub_server_full` rather than `lobby_not_found`, ADR-10392). A keyless session
  matches none of the ban lists (bans are player-key sets).
- A revoke of an unknown serial is stored; a failed `revocations.ron` write is logged while the
  in-memory revoke still succeeds; a transfer to an offline live owner does not start grace.
- The hub reads the whole ban file before applying its 4,096-key cap; `hub.toml` and the ban file are
  not reloaded on SIGHUP (restart to change them). Several rate settings have no upper bound.
- The client-side `join::set_bans` helper still returns `hub_not_ready` (use `HubServer::set_bans` or
  the host's `SetBans`).
- Copying a template tree by hand, without `regia new` or the editor, does not append the home-directory
  remap; add it, last, before a release build on an account whose name is private.
- Thirty-seven specification rows are in the feature catalog with an em dash. Their inventory
  `documented` cell is still `NONE`, so the generator does not link a guide. Chapters exist for many
  of them; the cell was not mass-edited.
- The generated heading index copies older page headings, including "grey", "behaviour", and
  "licence". New how-to and start pages are US English. The older book was not respelled in this
  release.
- `cargo xtask perf-budgets --counts-only --enforce` still fails the two `net_relevance_n214` rows,
  the same v0.6.0 known issue as in v0.6.1. On this line the counts are about 38,691 allocations
  against a budget of 37,000, and p99 46,387 against 38,000. The budgets were not changed.
