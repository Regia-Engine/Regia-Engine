# Ferrite v0.1.29

Builds on v0.1.28. This is the sprint-2026-10-21 line: baked light grows from groundwork into a usable path, the
renderer gains new post-effect, exposure, upscaler, cloud and bindless work, the runtime UI gets text editing, menus,
themes, drag and drop, accessibility and a focus graph, and every crate went through audit rounds. The v0.1.29 gate
(run v0129-g3) was green; five rounds of gate fixes and the owner-approved golden updates are listed below.

The text below consolidates 278 release fragments (`v0.1.27-ui-l6-textinput`, every `v0.1.28-*` lane
fragment written after the v0.1.28 tag, and the `v0.1.29-*` fragments). The two `v0.2.0-*` fragments
(`v0.2.0-bake-from-scene.md`, `v0.2.0-gi-compare.md`) belong to the v0.2.0 line and are left in place.

Highlights:

- **Baked light** (probe volumes): incremental and tiled bakes, HDRI and emissive light inputs, bake quality controls,
  wall and interior leak control, probe-relative SSAO, per-tap visibility, de-ringing, leak guard and sun relight,
  multi-volume blending across streamed seams, GPU/CPU bake paths, debug views (`render.get_gi_probes`,
  `render.explain_gi`), validation against the path tracer, an editor Bake panel, and a lightmap pipeline (groundwork
  for v0.3.0).
- **Renderer**: bloom/depth-of-field/motion-blur bounds, exposure zones, probe specular at every roughness, TAAU
  quality work (including the half-float clip-floor fix), stable sun cascades, cloud weather, shadow map and god rays,
  the upscaler boundary and vendor seam (no vendor SDK bundled), frame-generation preparation, ray-traced shadow
  groundwork, bindless level 3 (opt-in), visibility-buffer LOD hand-off, water shading and refraction in the terrain
  renderer, DX12/Windows swapchain readiness.
- **Runtime UI**: text input editing, default widgets, scroll containers with inertia and scrollbar styles, tooltips
  and gamepad hints, motion presets, theme swap transitions and agent surface, focus ring v2, drag and drop, popup
  menus and menu bars (`.ui.ron` v2), shortcut registry, focus graph, text shaping report and accessibility tree.
- **Editor**: undo/redo audit, Content Browser index, thumbnails and search, Outliner hierarchy edits, budget meters,
  Bake and Bake runner panels, Theme panel.
- **Agent protocol**: 91 new methods (212 to 303), none removed; every method now publishes a contract (`example`,
  `errors`, `limits`, `cost`).
- **Platforms and hosts**: Android native crash records, suspend/resume drills and touch controls, Steam Deck prep,
  Windows bundles and HLSL checks, Deck prompts and power policy.
- **Audit rounds** over every crate (hostile input, overflow, NaN, concurrency, determinism) and the gate fixes.

Read **Upgrade: host changes since v0.1.28** first if you build a game or shell against the engine crates.

## New

### Agent contracts, Android, audio, bake tooling and bindless

- **Agent method contracts** (ADR-1034). Every protocol method publishes `example`, `errors`, `limits` and `cost`; `agent.schema` carries them per entry, takes an optional `method`, and adds top-level `limits`. `heavy_rate_limit_per_second` in `.ferrite/agent.toml` (default 60) budgets heavy calls (screenshots/captures, image compare, `scene.serialize`, replay loads/steps). Unknown method names answer `F0008` with `data.suggestion`. `errors.explain` knows the UI methods' lowercase codes and `too_many_pending`. `cargo xtask agent-coverage` also checks contracts and documented error codes.
- **Native crash records on Android** (ADR-328, ADR-329). `crash-handler` installs signal handlers on Android; a `write(2)`-only record goes to `files/crash/pending.bin` (signal, `si_code`, fault address, thread, PC/LR/SP/FP, 32-frame frame-pointer walk, build identity, executable `/proc/self/maps` lines). Next launch logs `native crash record from the last run: ...`, writes `logs://crash-<time>-native.txt` (listed by `diagnostics.crash_reports`), keeps `files/crash/<time>.crash.bin` (newest 5) and, with `FeedbackPlugin`, writes a crash bundle with `"minidump": null`, `"platform": "android"`. `ferrite_platform::native_crash::record` (`encode`, `decode`, `decode_file`, `RecordError`, `walk_frame_pointers`, `MapsFilter`, `collect_pending`, `write_report`, `stack_lines`); Android-only `attach`, `is_attached`, `set_recording`, `take_collected`, `CrashContext`, `RECORD_DIR`, `CRASH_TEST_PROPERTY`; `ferrite_framework::feedback::native::{record_bundle_input, previous_log_tail, write_record_bundle}`. `cargo xtask android-pass --crash-test [--crash-delay-secs 8]` (property `debug.ferrite.crash_test`).
- **Android suspend/resume drills and surface audit** (ADR-527). `ferrite_platform::LifecycleDrill` queues synthetic suspend/resume cycles (one per frame in the windowed runner); `SurfaceAudit` checks no surface alive while suspended, one per window after resume, created - dropped = alive, and logs `ferrite surface audit:` per resume; `run_queued_drill` is the headless harness. ### Post effects, exposure, GI quality, upscalers, DX12, Deck, editor and CI

- **Post-effect constants** (ADR-1152): `MotionBlur::MAX_BLUR_FRACTION` (1/8 of frame height), `MotionBlur::SAMPLE_SPACING_PX` (4), `DepthOfField::MAX_CIRCLE_OF_CONFUSION_DIAMETER` (128 px, the cap on `DepthOfField::max_circle_of_confusion_diameter`).
- **Exposure zones drive auto exposure** (ADR-322). `FrameRenderer::set_exposure_target(Option<EvTarget>)`, `set_exposure_dt(Option<f32>)`, `exposure_zones` / `exposure_zones_mut`, `RuntimeRenderer::set_exposure_target`. With a target, the newest histogram EV is clamped into the range (shifted by exposure compensation) and the eye takes one `adapt_ev` step per frame; when the target clears, the eye walks back to the meter and hands over within 0.05 EV. Manual exposure ignores zones; texture views are not zoned; a camera cut starts the next zone frame on its goal. `ferrite_framework::exposure_zones::ExposureZonesPlugin` (in `DefaultPlugins`) combines the `ExposureZone`s at the window camera with the lowest `order`; `ExposureZoneState` reports zone count, target and camera. `ferrite_render::exposure_zones` adds `ZoneExposure`, `ExposureReport`, `ZoneExposureMode`, `MeterReading`, `zone_goal_ev`, `adapt_settle_steps`, `combine_weighted_zones`, `ZONE_OPEN_RANGE`, `ZONE_RELEASE_TOLERANCE_EV`, `EXPOSURE_SETTLED_TOLERANCE_EV`.
- **Exposure agent methods** (ADR-323, ADR-513). `render.get_exposure` (EV, goal, mode, adapting, settled, zone target, zone count); `render.exposure_log {action: start|stop|get, cap?}` (the `(time, ev, target)` curve); wait atom `{predicate: "exposure_settled", tolerance?}`; error reasons `renderer_missing`, `invalid_action`, `invalid_cap`, `invalid_tolerance`; guide topic `exposure-zones`. `render.get_exposure_settings` / `render.set_exposure_settings` read and set tonemap operator (`agx`, `aces_fitted`, `neutral`), auto exposure, fixed EV, compensation, EV100 clamp, physical camera, contrast, saturation, bloom, bloom intensity, vignette, film grain and the meter; values are validated before any is applied (`book/agents/exposure.md`).
- **Material clock** (ADR-1238). `ferrite_render::material_clock(elapsed, delta) -> (now, prev)` and `MATERIAL_CLOCK_PERIOD_SECS` (3600): gameplay time wrapped hourly in integer nanoseconds with the previous frame's value on the same lap. `FrameRenderer::set_material_clock(now, prev)` and `material_clock()`. Agent (read-only) `render.material_clock` returns `{ set, now, prev, delta, period_secs, gameplay_secs }` (`book/agents/material-clock.md`).
- **Probe specular at every roughness** (ADR-1103).   `planet_mars_sunset`, then `planet_mars_noon` and `planet_airless_noon` (the `planet_presets` test stops at the first
