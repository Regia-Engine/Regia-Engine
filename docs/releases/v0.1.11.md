# Ferrite v0.1.11

Patch release for Direct Order 27's alpha build (code freeze Friday 10-16), made on `release/0.1` from v0.1.10. It
closes the warm-coverage gaps the v0.1.10 integration smoke found: about 14 pipelines per map still compiled "outside
the warm queue" at the start of play.

- **Commit:** v0.1.11 = the tag `v0.1.11` (the gated code commit is named in the tag message).
- **Workspace version:** `0.1.11`.
- **Branch:** `release/0.1` (alpha hotfixes). `main` is the post-alpha development line (batch v020); this release is merged forward into it.

## Upgrade from v0.1.10
No host source change. New: `FrameRenderer::set_warm_probe_capture` / `RuntimeRenderer::set_warm_probe_capture`
(additive). Host checklist: "Warm coverage (v0.1.11)".

## Warm coverage: probe captures and glass instances (ADR-210)
The v0.1.10 engine logs of both smoke maps place every remaining "outside" pipeline:
- **Reflection-probe capture (14 per map):** `do27.apply_lighting` → `capture_reflection_probe` on the main thread,
  before the game-frame warm. The capture draws its six faces without the post stack into the `Rgba8Unorm`
  readback target, a target no game frame or warm used. It compiled the terrain's plain and hole-cut sets for that
  target (`ferrite_terrain` gpu/mod.rs 4501–4637, two sets, so each site appears twice) and the lab forward set
  (`frame.rs` 12929/12750/12781/12813).
- **Glass (1 site, frame thread, at or just after the first game frame):** the `lab glass` sets. Frame warms built
  them only for a transmissive material or a glass instance in the warm frame. DO27's first canopy was not in that
  frame: its vehicle most likely spawned after the warm started.

Now:
- Game-frame warms always build the glass-instance sets.
- Frame warms render one probe face (the capture's exact configuration) when the renderer captures probes:
  reflection probes installed, a capture already made, or `set_warm_probe_capture(true)`. A capture after the warm
  compiles nothing.
- The terrain's frame-warm hook builds the plain and hole-cut sets for every format the terrain was drawn into, so
  a hole cut between two captures is covered.
- `samples/lookdev/tests/warm_coverage.rs` now plays DO27's order: a probe captured at level load before the warm, a
  canopy mid-play, and a recapture after the hole cut. It measures from the first game frame on, including that
  frame, and asserts **0** outside the warm queue and 0 on the frame thread. On v0.1.10 the same session created 13:
  the 8 glass pipelines and the 5 of the hole-cut terrain set in the capture's format, the same sites as DO27's log.
  A second test asserts that a capture after the warm, on a holed terrain, compiles nothing.
- Cost: that session's game-frame warm now builds 79 pipelines instead of 58 (13.7 s instead of 6.8 s on lavapipe,
  on a worker behind the loading screen). On a GPU with a warm pipeline cache, most of these are cache hits.

Still compiled where the host calls it: a capture made **before** the game-frame warm (DO27's current order: about
14 pipelines on the main thread, behind the loading screen, before `first_game_frame`). To move them onto the warm
worker, call `set_warm_probe_capture(true)` at level load and capture once `GameFrameWarm` is done. Either way,
nothing compiles after `first_game_frame`.
