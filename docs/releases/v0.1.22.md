# Ferrite v0.1.22

Builds on v0.1.21. One release for the camera-path, kit-subpath, review-follow-up, macOS bring-up, ReplaySim and
render-out work.

## New

- **Camera paths and shot sequences** (ADR-268, Red-Rouge RR-F3). `ferrite_framework::shots`: keyed camera paths
  (linear, step or centripetal Catmull-Rom through the keys; look at the heading, a point or a moving target),
  field-of-view and roll tracks, depth-of-field tracks (focus distance, aperture, focus on target, bokeh), cuts
  between shots and fades at their edges. `ShotSequence::sample(time)` is a pure function of the time, so a seek is
  frame-exact and a fixed-step run is reproducible bit for bit.
  - `.shots.ron` v1 asset format (`docs/formats/shots-ron.md`, example `shots.example.ron`): versioned, validated,
    canonical on re-save, registered with `check-formats` and `ferrite upgrade-project`.
  - `ShotPlayer` and `ShotPlugin` drive a camera entity (pose, `fov_y`, depth of field) from gameplay time; a shot
    change, a seek into another shot and a loop wrap are camera cuts and clear the renderer's temporal history.
    `AgentPlugin` installs the player. Do not put a `CameraRig` on the camera a sequence drives.
  - Agent: `render.sequence` (load, play, pause, stop, seek by time or frame, sample, export, query, clear),
    `camera.set_path` (with `preview` and `dry_run`), `camera.raycast` (a screen point to a ray, cast over terrain
    and meshes like `world.pick`). All work headless. Guide: `book/agents/camera-paths.md`, topic `camera_paths`.
- **ReplaySim** (ADR-266). `ferrite_framework::replay_sim::ReplaySim`, an `ExternalSim` that plays a Direct Order 27
  `.do27replay` (version 2 or 3) deterministically for rendering and camera work. Use it as
  `SimBridgePlugin::<ReplaySim>`; nav beacons become `"beacon"` entities and Moments, peer commands and the abort
  flag arrive as `ReplayEvent` bridge events (`moment.hit`, `moment.down`, `moment.kill`, `command`, `abort`).
  - `ReplayFile::parse` / `load` read the header, player and peer tables and every record from their lengths.
    Malformed input is a `ReplayError`, never a panic.
  - Fulls are opaque: the snapshot and state hash inside a full belong to the writing sim build. Install a
    `FullCodec` (`ReplaySim::with_codec`) to get its entities and recompute state hashes; `ReplayFile::verify` then
    compares them bit for bit. Without a hashing codec the audit reports `hash_unchecked`, which is skipped, not
    passed.
  - Tick-exact `seek` (fires nothing) and `step` (each event once), plus an integer frame clock that lands on the
    same ticks at any frame rate. `MomentQuery` filters by kind, tick window, entity, attacker, victim, fight,
    round, weapon and importance.
  - Agent: `replay.load`, `replay.seek`, `replay.step`, `moments.list`, `moments.get` (headless-capable); guide
    topic `replay`, page `book/agents/replay.md`. Test helper `replay_sim::SyntheticReplay`; no DO27 data is in the
    repo.
- **Offline fixed-dt render-out** (ADR-267, RR-F4). `render.out_start` / `render.out_progress` / `render.out_cancel`
  render the running scene to a PNG sequence, or through an `ffmpeg` pipe to FFV1, ProRes 4444 or DNxHR 444 movies,
  at any size and frame rate, with 1..4x supersampling (linear-light resolve) and the game HUD laid out for the
  output (16:9 or native 9:16).
  - The job drives the game clock by exactly 1/fps per frame and reads no wall clock. The same project and request
    give the same frame hashes; each job writes `<name>_render_out.json` with them.
  - Camera cuts (`cuts`, and frame 0) restart TAA/TSR, fog, shadow (terrain included), probe and exposure history;
    `warmup_frames` lets effects settle.
  - New error codes F0018 and F0019; guide topic `render_out`; book page `agents/render-out.md`.
- **macOS bring-up on Metal** (ADR-264, amends ADR-009). Testing only: the whole workspace builds on macOS and the
  test suite runs on a real Metal GPU (Apple M5, 32 GB, macOS 26.6, Metal 4, Homebrew rustc 1.99.1). A new
  `ferrite_platform::platform::macos` module (open URL, locale, OS info, `_exit`) replaces the Linux module, which
  used Wayland and X11 window attributes. macOS tests stay non-blocking in CI; there is no macOS release build,
  signing or notarization.
- **SpaceMouse Step mode direction** (ADR-265). New: `NavContext::list_dir(step_held, step_dir)`,
  `NavContext::step_dir`, `NavDelta::step_dir`.

## Changed

- **Kit subpaths** (ADR-263 addendum). `SHA256SUMS` in a Tincal kit may list in-folder subpaths such as
  `textures/x.png` (forward slashes). Every listed file is checksummed; a mismatch or a missing file reports as
  before. Still refused: `..`, `.`, absolute or leading-`/` paths, backslashes, drive letters and colons, NUL, empty
  components, and symlinks (or linked folders) that leave the kit folder. `kit.json` `faction` accepts `generic`
  (shared assets such as weapons and props) without a warning; the field is still required. With a cockpit glb at
  `socket_cockpit`, the hull glb must not also contain the static cockpit geometry (the editor draws both and does
  not hide nodes). API: `ferrite_editor::kit::KitFolder::resolve_listed` (new); `FACTIONS` is now 5 entries.
- **Render-out API.** Build `RenderOutSpec` with `RenderOutSpec::new(w, h, layout)` (new `supersample` field; a
  struct literal no longer compiles outside the repo). `RenderOutSpec::supersample` and `ForcedOutput::pixel_scale`
  give a supersampled HUD scale; default calibration and a 4096 size cap apply. Still open from the ADR-202 audit:
  pointer hover reaching the HUD, windowed TAA history sharing, EXR/HDR output.
- **Metal backend.** `instance_backends()` is Metal on macOS. The exposure histogram uses one workgroup array on
  Metal (64 scalar workgroup variables exceed Metal's 31 threadgroup arguments); the frame GPU timer is off where
  `TIMESTAMP_QUERY_INSIDE_ENCODERS` is missing; the terrain impostor shader no longer needs
  `SHADER_EARLY_DEPTH_TEST`. `host_platform()` is `macos` on macOS, so dev cooks land in `.ferrite/cooked/macos`
  (they went to `cooked/linux`).
- **Forward shader discard order** (ADR-265). `shade_forward` (all materials, exterior glass included) now decides
  the alpha test early and takes the `discard` after the derivative work, as `shade_canopy` has since v0.1.21.
  Output is unchanged where the derivatives were defined; alpha-test edges can differ on real GPUs. Alpha-rejected
  fragments pay a few more samples. Guarded by the static check `shade_forward_discards_after_its_derivatives`.
- `world.pick`'s cast is a shared helper (`pick::cast`); behavior unchanged.
- Docs: a duplicate provenance row for the own-canopy shader was removed.

## Fixed

- Forward-shader normal-map, ORM and emissive samples, specular-AA `dpdx`, shadow normal and skin curvature no
  longer run with undefined derivatives in quads where a neighbor was discarded (see Changed).
- SpaceMouse Step mode: a tilt that flips from one side to the other between two frames is a new crossing; it steps
  at once and restarts the repeat clock. `NavContext::list(held)` keeps the old behavior.
- A windowed host no longer steps particles twice during render-out.
- The source watcher reports changed paths under the root it was given (FSEvents reports real paths; `/var` is
  `/private/var`), and the soak RSS probe works on macOS.

## Upgrade

Additive except where noted.

- A host that wants camera sequences without the agent adds `ShotPlugin`.
- Apps using Step mode should switch to `list_dir` and pass `NavDelta::step_dir` back. Struct literals of
  `NavContext` / `NavDelta` without `..` need the new field.
- Build `RenderOutSpec` with `RenderOutSpec::new`.
- `book/reference/agent-methods.md` and the manual need `cargo xtask manual` for the new methods.

## Known issues

- `lookdev warm_coverage` can crash at process exit with a SIGSEGV in the NVIDIA 615.71.09 shader compiler when a
  material-graph worker is still compiling under heavy load. All tests pass first. There is no investigation in the
  ADR notes yet; a fix is planned.
- The macOS port passes 4979 of 5006 tests on an M5 (472 test binaries, 38 ignored). The 27 failures are listed in
  the lane reports and are not gated: goldens that differ on Metal (not re-blessed), tests that encode a Vulkan
  capability set, and tests that need `spirv-val`, which is not installed on the Mac.
- The editor hot-reload fixture test (`hot_fixture_edits_keep_reflected_state`) fails on macOS: the baseline load is
  refused with "engine changed". Hot reload is not verified on macOS.
- Not verified on macOS: frame-rate budgets, Vulkan SPIR-V validation, native crash capture, SpaceMouse (`hid` has
  no macOS backend), Steam and audio devices. Metal has no pipeline cache in wgpu 30, so every launch compiles its
  pipelines.
- Not in this release: an editor panel or curve UI for shots, cooking `.shots.ron` into paks, a rendered fade
  overlay, rotation keys; decoding a replay full without the writing sim's codec, version 2 files that contain
  fulls, interpolation between fulls; a `ferrite render --sequence` CLI wrapper, per-cut exposure choice, HDR/EXR
  output and audio in render-out.

Not in this release: baked light (reserved for v0.2.0).
