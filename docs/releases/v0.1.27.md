# Ferrite v0.1.27

Builds on v0.1.26. A sprint release: zero-copy pak loads, a clean end of the process, the UI theme resolver, agent
surface and input layers, morph weights per node, procedural loops, Windows preparation, agent protocol hardening, and
the first groundwork for baked light.

**Baked light is groundwork, not yet a feature.** The v0.2.0 baked-light work is incomplete: the pieces below build and
have tests, but baked light is not usable end to end yet. Do not plan a map around it.

## New

- **Baked-light groundwork (v0.2.0 work in progress).**
  - *Bake from the real meshes* (ADR-279, ADR-280). `.bake.ron` v1 (`docs/formats/bake-ron.md`) is a versioned format
    with static meshes as occluders and bounce surfaces (emissive parts are lights), automatic detail bricks
    (`layout.auto_bricks`), DO27 bake bundles (`static_meshes.json`, `interiors.json`, `MANIFEST.sha256`, every file
    checked against the manifest), `terrain_mesh` for mesh-only maps, and interior tags in the bake plan.
    `ferrite bake-gi --dry-run` validates and prints the layout without tracing (no GPU); the summary lists probes and
    validity per layer and brick. Agent page: `book/agents/baked-gi-bake.md`. New API in `ferrite_pt`: `bake_meshes`,
    `auto_bricks`, and in `bake_desc` `BAKE_DESC_FORMAT_VERSION`, `BakeDescError`, `BakePlan`, `BrickPlan`,
    `migrate_bake_ron` and related items; `ferrite_cli::commands::bake_gi` gains `GltfBakeLoader` and helpers.
  - *Near-field GI* (ADR-281, ADR-282). `.fgiv` v2 adds interior bricks (`BrickFlags::INTERIOR`) so outdoor light does
    not leak into an enclosed room, and capsule occluders for dynamic units:
    `FrameRenderer::set_gi_occluders` / `RuntimeRenderer::set_gi_occluders` (up to `MAX_GI_OCCLUDERS` = 64 a frame),
    `ferrite_render::baked_gi::{GiCapsule, MAX_GI_OCCLUDERS, capsule_visibility}`. Agent: `render.set_gi_occluders`;
    `render.get_gi_mode` `baked` adds `occluders`, `occluder_cap`, `occluders_dropped`, `interior_bricks`. Guide:
    `book/agents/baked-gi.md`. Frames without an installed volume are unchanged.
  - *Scene install* (ADR-283). `LevelLook::baked_gi` names a `.fgiv` and optional per-map overrides
    (`LevelBakedGiSettings`). `BakedGiLevelPlugin` (in `DefaultPlugins`) installs the volume on level load, reinstalls
    it on hot reload and removes it on unload. `GiMobility { Static, Dynamic }` component (data only for now).
    `ferrite cook` takes `.fgiv` as an asset. Agent: `level.get_baked_gi`; page `book/agents/baked-gi-maps.md`.
- **Zero-copy pak loads** (ADR-177, ADR-285). Pak entries are served as `PakPayload` views of the mapped pak; lz4
  entries decompress once, and in parallel on the compute pool for 8 or more 256 KiB blocks. A hashed pak this build has
  not verified yet mounts with its zero-copy gate closed until the background `pak_verify` check passes; a pak that
  changed on disk is read through the file from then on (`PakError::Corrupt`, not `SIGBUS`). Opt-in GPU-ready desktop
  mesh entries (`FERRITE_PAK_GPU_MESHES=1`, layout `FGPM` v1, never on Android) and the `pak_migrate` binary
  (`pak_migrate <old.fpak> <new.fpak> [--raw]`). Meshes decode on the compute pool. The staging belt writes into
  persistently mapped buffers (`FERRITE_UPLOAD_RING=0` restores the old belt). Agent: `assets.status` returns
  `paks: { mounted, zero_copy }`; guide `book/agents/assets.md` § Faster loads. Bench: `lookdev` `pak_load_bench`.
- **Exit workers** (ADR-287). `ferrite_platform::{GpuWorkerBuilder, GpuWorker, DriverCall, GpuWorkers, LeftWorker,
  gpu_workers}` register engine threads that may call the GPU driver. `ferrite_platform::finish_exit(code, flush)` waits
  for them within one budget (`EXIT_WORKER_WAIT`, 30 s; `FERRITE_EXIT_WORKER_WAIT_MS` overrides) and, if one is still
  running, ends the process with `code` without exit handlers (ADR-276). Also `DeliberateExit::finish_after_workers`,
  `note_exit_started`, `parse_exit_worker_wait`, `Telemetry::signal_probe_stop`.
- **UI theme resolver, D6** (ADR-289, ADR-290). `apply_themes` resolves every classed node from the active `.theme.ron`
  theme: `ThemeOverride`, then the variation chain (`Button.danger` -> `Button.primary`), then the widget type, then
  the theme defaults, with states composed in the design order; disabled applies last. New: `ActiveTheme` resource
  (theme name, density, high contrast, reduced motion; writing it swaps the theme at runtime with a cross-fade over
  `motion.base`), `ThemeScope`, `ThemeOverride`, `ThemeResolver` (`stats()`, `active()`, `error()`,
  `resolved_theme()`), `theme_resolve::builtin_theme_set()`. `ferrite-dark` ships `Button`, `Panel`, `List.row`,
  `Toggle`, `Slider.track` and the variations `Button.primary|danger|ghost|secondary|nav`,
  `Panel.surface|overlay|list-item|dropdown-item`.
- **UI agent surface, L1** (ADR-273 lane 1, ADR-291). `ui.query`, `ui.state`, and with `edit_scene` `ui.click`,
  `ui.focus`, `ui.type`, `ui.set_value`; `play.wait_until` / `play.expect` gain `ui.node_exists` and `ui.node_state`.
  A click is a real pointer move, press and release through the input path. Page `book/agents/ui.md`. New:
  `ferrite_ui::agent_bridge`, `ferrite_agent::{UiAgentHost, UiHostCall, UiHostError}`.
- **UI input layers, L4** (ADR-273 lane 4, ADR-293). `UiEvent` carries `button`, `modifiers` and `click_count`; new
  event kinds `DoubleClick`, `ContextClick`, `MiddleClick`, `Scroll`, `LongPress`, `Repeat` (opt-in `LongPressable`,
  `RepeatOnHold`; `UiInputConfig`). `ferrite_ui::layers`: `InputLayer`, `InputLayers`, `LayerInputMode`, `push_layer`,
  `pop_layer`; an open `Modal` is a layer. Agent: `ui.layers`; page `book/agents/ui-input.md`.
- **Per-node morph weight channels** (ADR-297). A glTF `weights` channel keeps its node (`MorphTrack::node`,
  `MorphNode`), so two morphing meshes in one clip get their own weights; files with no skin import their `weights`
  clips (`GltfAnimationImport::node_clips`, cooked as `<file>#nodeclip/<animation>`). Runtime: `SourceNode`,
  `NodeMorphPlayer`. Agent: `anim.morph_weights` reports `source_node` and `node_driver`; `anim.get_state` reports
  `morph_tracks`. Book: `book/agents/morph-weights.md`.
- **Procedural loop generator** (ADR-299, ADR-300). `.loopgen.ron` v1 describes a seamless loop as a graph of noise,
  oscillators, filters, modulation, gain and mix; rendering is a pure function of the file, identical on every
  platform. `ferrite_audio`: `LoopGenDef`, `RenderedLoop`, `LoopGenCache`, `LoopGenError`,
  `AudioPatch::from_def_with_loopgen`, `SoundAssets::add_loopgen` and related. Agent: `audio.loopgen_render` and a
  `loopgens` object in `audio.list_emitters`. Format doc `docs/formats/loopgen-ron.md`.
- **Windows preparation** (ADR-295, ADR-296). `cargo xtask windows-pass` (toolchain check, Windows test subset, pipeline
  compile times, measured `vfx_lab` runs, start-and-quit runs; `--read <summary.json>` prints the verdict); CI job
  `windows-cross` (`cargo xwin clippy`, allowed to fail until seen green); an HLSL gate that writes every shader as
  Shader Model 6.0 with naga's `hlsl-out`. Guide `book/user-guide/windows.md`.
- **Agent protocol hardening** (ADR-340). See Changed and Fixed. Page `book/agents/render-out.md`, `safety.md`,
  `protocol.md`.
- **Docs.** `book/user-guide/do27-interface-contract.md` and spec 25 § 7 re-checked against main (ADR-301);
  `docs/evidence/baseline-triage-1020.md`, `docs/notes/heap-trace.md`; contract example tests in
  `crates/ferrite_terrain/tests/do27_contract_examples.rs`.

## Changed

- **`render.out_start` output roots** (ADR-340). `out` is confined to the project root (the default for relative paths),
  the system temp dir, the working dir, and any `output_roots` entry in `.ferrite/agent.toml`. `..`, absolute paths
  under no root and symlinks leaving every root are `invalid_params`. Answers show `out`, `files` and `manifest`
  relative to the root, and the `ffmpeg` field is the name, not the path.
- **Agent errors no longer carry absolute host paths** (`assets.*`, `terrain.load_holes`, `render.out_*`;
  `assets.watch_status` roots are project-relative). The full text is logged server-side.
- **Agent limits** (ADR-340): 256 shots per sequence, 4096 keys per path/track, 4096 `cuts`; at most 16 concurrent
  connections, a 1024-entry bounded inbox, WebSocket message 32 MiB and frame 16 MiB; the mutating rate limit is a
  sliding one-second window; `ChangeLog` keeps at most 10,000 records (`seq` still increases).
- `GiBakeDescription::build` places cooked meshes only; use `build_with` with a loader for glTF (the CLI does).
  `GiBakeDescription::from_ron` accepts v0 and v1 and refuses newer versions.
- `.fgiv` writes version 2 (`BakedGiVolume::to_bytes_v1` writes version 1). `.fgiv` files under `assets/` are cooked and
  no longer copied raw by `ferrite package`.
- `ferrite::run_with` calls `finish_exit` with the app's exit code; `finish_deliberate_exit(flush)` is now
  `finish_exit(0, flush)`. The telemetry probe is told to stop at the clean exit's first step.
- `load_cooked_model` no longer keeps a `CpuMesh` copy in `AssetServer::meshes()`. `StagingBelt::has_room` counts only
  ring chunks free to write.
- **Default UI look** follows the theme files: the design palette replaces the v0.1.22 palette; disabled widgets draw
  at 0.45 opacity (`UiThemes::disabled_opacity` defaults to `DISABLED_OPACITY`). While an input layer is active, nodes
  outside the top layer are not hit-testable or focusable, and an open `Modal` now blocks pointer input behind it.
  `.theme.ron` v1 is frozen. UI goldens that show classed widgets change (intended).
- `ferrite_ui` depends on `serde_json`; `ferrite_agent` depends on `ferrite_ui`; `xtask` depends on `ferrite_pt`.
  `ferrite::DefaultPlugins` inserts `UiAgentHost` when the `agent` and `ui` features are on.
- Cooked clip payload is v2 (`CLIP_FORMAT_VERSION`, magic `FCLP`); v1 clips load with every track unbound.
  `AnimationClip::sample_morphs` returns only unbound tracks; bound tracks come from `sample_node_morphs`.
  `ferrite upgrade-project` lets formats share a file suffix (`.fckd`): the first probe that recognizes a file owns it.
- `cargo xtask check-formats` and the manual's format table know the `loopgen`, `bake` and `cooked-clip` formats.

## Fixed

- **Exit SIGSEGV after a normal quit under load** (Known issue of v0.1.23 to v0.1.26): the process now waits for the
  registered GPU workers or ends without exit handlers. Not claimed fixed until the loaded 60-run soak
  (normal-quit variant) is clean. `lookdev` `warm_coverage` joins leftover warm workers before each device drop.
- A pak truncated in place during a load no longer raises `SIGBUS`; the load fails with `PakError::Corrupt`.
- **`replay.load`** opens one descriptor, requires a regular file and reads through a bounded `take`, so its 512 MiB cap
  now bounds the read.
- **A `.ferrite/agent.toml` that exists but cannot be read or parsed now fails closed**: `read_only` with `read` only,
  logged at error level. A missing file still gets the default profile.
- **`seeing.compare_images`** refuses a PNG side outside `1..=4096` from the header, before allocating.
- Outdoor light no longer leaks into an interior covered by an interior brick.
- Color transitions in the UI interpolate from the color shown when they start.
- Two morphing meshes in one file no longer mix their weights, and a `weights` channel on a non-skin node is no longer
  dropped.
- The DO27 contract example test parses the holes example with `HolesMask::from_holes_ron`.

## Upgrade

Host-visible API changes (build `shell-ferrite` against this release before taking it):

- **Zero-copy loads:** `CookedTexture.ktx2` is `PakPayload` (was `Vec<u8>`; build with `bytes.into()`).
  `CompressedTexture.levels` is `Vec<PakPayload>`. `ferrite_terrain::TileSource::load` returns
  `Result<PakPayload, StreamError>`; `TileCache::residency` returns `Option<PakPayload>`. `UploadBytes::slice` is
  generic over `T: AsRef<[u8]> + Send + Sync + 'static`. `AssetLoadError` has a new variant `GpuMesh`. Code that decodes
  pak mesh entries with `CookedMesh::from_postcard` fails on GPU-ready entries (only in paks built with
  `FERRITE_PAK_GPU_MESHES=1`): use `ferrite_asset::load_mesh_bytes` / `AssetServer::load_mesh`. Hosts that read meshes
  from `AssetServer::meshes()` after `load_cooked_model` call `load_mesh` themselves. Do not overwrite or truncate a
  mounted pak in place; replace it by rename. No content format version changes.
- **UI events:** `UiEvent` has new public fields `button`, `modifiers`, `click_count`; struct literals
  `UiEvent { target, kind }` become `UiEvent::new(target, kind)`. `UiEventKind` has new variants (`DoubleClick`,
  `ContextClick`, `MiddleClick`, `Scroll`, `LongPress`, `Repeat`): exhaustive matches need a wildcard arm. `UiPointer`
  and `UiInputState` have new public fields; construct them with `Default`.
- **UI theme:** `UiThemes` has a new field `set: ThemeSet`; `Themed` has new fields `generation`, `anim_from`,
  `anim_to`. Use `..Default::default()`. `UiThemes::disabled_opacity` defaults to 0.45 (was 1.0); set `1.0` for the old
  look. Games that need the old palette set their own theme (`extends: Some("ferrite-dark")`) or select a legacy palette
  with `UiThemes::select`. A host with its own app (not `DefaultPlugins`) that wants `ui.*` inserts
  `UiAgentHost::new(ferrite_ui::agent_bridge::host_call)`; without it the methods answer `ui_not_installed`.
- **Morph channels:** new fields `MorphTrack::node`, `CompressedMorphTrack::node`, `GltfAnimationImport::node_clips` and
  `warnings`, `FinishedEval::node_morphs` break struct literals; build tracks with `MorphTrack::new` or
  `MorphTrack::for_node`. Cooked clips are format v2: run `ferrite upgrade-project --write` to rewrite cooked clips in
  the dev cache (paks load v1 clips in place).
- **Baked light:** `.bake.ron` is v1; v0 files load unchanged and `ferrite upgrade-project --write` stamps
  `format_version: 1` and keeps a `.bak`. Struct literals break for `GiBakeDescription` (new `format_version`, `root`,
  `terrain_mesh`, `meshes`, `static_meshes`, `interiors`, `interiors_file`, `manifest`, `default_albedo`), `LayoutDesc`
  (`auto_bricks`), `GiBakeJob` (`plan`), `ferrite_cli::commands::bake_gi::BakeGiArgs` (`dry_run`), `DetailBrick`
  (`flags`: add `flags: 0`), `BakedGiStatus` (`occluders`, `occluders_dropped`, `interior_bricks`), and `LevelLook`
  (`baked_gi`: add `baked_gi: None`). `.fgiv` v2 files are refused by older builds (`UnsupportedVersion { found: 2 }`);
  v1 files load as before; rebake to get interior bricks. `SCENE_FORMAT_VERSION` is 10: run `ferrite upgrade-project`
  to rewrite v9 levels. `CookError` has a new variant `BakedGi(String)`.
- **Exit:** hosts with their own `main` loop keep calling `finish_deliberate_exit` last, and should prefer
  `finish_exit(code, flush)`. Hosts that start their own GPU threads use `GpuWorkerBuilder`. A quit can take up to 30 s
  longer only when a driver call hangs.
- **Agent:** `render.out_start` callers writing outside the project root, temp dir or working dir add the directory to
  `output_roots` in `.ferrite/agent.toml`. A broken `agent.toml` now grants `read` only. `ReplayFile::load` and
  `seeing.compare_images` refuse oversize input. No wire-schema change.
- **Audio:** `.audiopatch.ron` is still v1; a patch may name a `*.loopgen.ron` as its `sound` when built with
  `AudioPatch::from_def_with_loopgen`.
- Run `cargo xtask check-formats --update` and `cargo xtask manual` after taking this release (new formats and methods).

## Known issues

- **Baked light is not usable end to end yet.** There is no scene -> `.bake.ron` exporter (`GiMobility` is data only);
  the bake samples no textures (`default_albedo`); an interior with an opening is flagged as a whole, so no light
  enters through the opening; a long capsule under-counts toward its ends; the capsule term attenuates baked light
  only; the bake has not run on the Bore Twelve bundle end to end; the GPU interior and occluder paths were not run on
  a device in their lanes. Planned for v0.2.0.
- macOS (not gated), on Apple M5: the `ferrite_editor hot_reload` fixture test and the Sponza-dependent
  `ferrite_test_utils gpu_matches_cpu` fail; the rest pass.
- **Windows is not verified on hardware since 2026-10-14**; DX12 cannot be forced on a machine with a Vulkan GPU
  (ADR-296). Run `cargo xtask windows-pass`.
- Exit: threads not started through `GpuWorkerBuilder` are not covered; a renderer kept alive past `finish_exit` makes
  the end of the process wait the full budget.
- Zero-copy: views served before a pak changed on disk can still fault; the first launch after an update copies raw
  entries until the background check passes; the upload ring keeps 2 chunks (set `FERRITE_UPLOAD_RING=0` if a bench
  shows upload spikes).
- UI: the focus ring is still the accent color; `translate`, `scale`, ring width, parts, elevation and easing curves
  resolve but are not drawn yet; `ui.click` options (button, count, modifiers) are not yet exposed; clicking does not
  move focus (use `ui.focus`).
- Morph: a skinned rig's clip keeps the skin mesh node's weights unbound; the hierarchy spawn does not add a
  `NodeMorphPlayer` itself.
- Loop generators are not hot-reloaded in v1; saw and square oscillators are not band-limited.
- Agent: `reference_trace`/compare file I/O permissions, `replay` step/moments paging and `endpoint.json` `token_file`
  remain open; `replay.load` is not confined to the project root.
- Several lanes were written without a build; the merge gate was their first compile.
