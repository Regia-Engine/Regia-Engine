# Ferrite v0.1.28

Builds on v0.1.27. Runtime UI grows accessibility settings, tweens, virtual lists and scrollbars. The
visibility buffer takes cooked meshlets from the ECS and recycles its cluster memory. Steam Input glue, the
bindless texture-set census, graph-glass tint, baked-light guard rails, a second agent-hardening round, and the fixes
from the audits and gate g1 and g2.

Baked light is still groundwork, not yet a feature: the guard rails below make a bake safer and checkable, but a baked
volume is not usable end to end yet.

## New

- **UI accessibility settings and right-to-left layout** (ADR-341). The `UiAccessibility` resource (`ferrite_ui`) carries
  `text_scale`, `reduced_motion` and `high_contrast`; the framework copies `GameSettings.accessibility` into it on
  every settings change. `accessibility.text_scale` (0.5 through 3.0) multiplies all UI text sizes and re-shapes text
  on the next frame; the device text floor still applies. `Style.text_dir` now works: `rtl` mirrors a node's row
  direction and its left/right margin, padding, border and inset, `auto` follows the locale, `ltr` never mirrors.
  Agent: `ui.accessibility` (report and set), page `book/agents/ui-accessibility.md`.
- **UI tweens and the visual transform** (ADR-343). `ferrite_ui::tween`: `UiTween` animates `Opacity`, background,
  border and text colour, `Style` inset, width and height, and the new `UiTransform`. `Tween`, `TweenPlan` (single,
  sequence, parallel), `Ease` (linear, quad, cubic, expo, back, bounce, elastic, each in / out / in-out, and cubic
  bezier). `TweenPlan::sample` is a pure function of time. `UiTween::show` / `hide` fade or slide a node in or out
  (`Reveal`); a finished tween sends `UiTweenFinished` and removes itself. Reduced motion jumps to the end.
  `UiTransform { translate, scale, pivot_ratio, hit_test }` moves and scales a node and its subtree after layout
  without changing layout (`UiLayoutBox` keeps the layout rect, `HitTestSpace` picks the rect hit testing uses).
  Agent: `ui.tween` (start, show, hide, stop, query, set_transform) and the `ui.tweening` atom for `play.wait_until` /
  `play.expect`; page `book/agents/ui-animation.md`.
- **Virtualized lists, selection and scrollbars** (ADR-344). `ferrite_ui::list`: variable row heights (`ListHeights`),
  tile mode (`ListTiles`), selection (`ListSelection`: none, single, multi; click, Ctrl, Shift, Home/End/PageUp/PageDown,
  Ctrl+A), type-ahead, sticky section headers (`ListHeaders`), `ScrollToItem`, and slot-stable row recycling with
  `ListEntryBind` (`CustomEntries` turns the default label writer off). Messages `ListSelectionChanged` and
  `ListActivated`. `ferrite_ui::scrollbar`: opt-in `Scrollbars` component with vertical and horizontal bars, thumb drag,
  click-on-track, auto-hide, and theme classes `scrollbar-track` / `scrollbar-thumb`. Agent: `ui.list` (info, items,
  select, scroll_to) and `ui.scroll_to`; page `book/agents/ui-list.md`.
- **Cooked meshlets from the ECS** (ADR-354). `ferrite_framework::meshlet_bridge`: the `MeshletSource` component names an
  entity's `.fmlt` meshlet sub-asset (`MeshletSource::for_mesh` / `for_mesh_path`). While the render profile has
  `visibility_buffer` on, `MeshletBridgePlugin` (now in `DefaultPlugins`) loads the payload and inserts it under the
  entity's mesh key, and replaces or removes it on a mesh change, despawn, hot reload of the `.fmlt`, or a profile
  switch. Skinned, morphing, translucent and material-graph meshes stay on the forward path. A bad or old payload logs
  one warning and the mesh draws forward. `ferrite_render::MeshletMesh::load`, `visbuffer::MeshletLoadError` (stable
  codes `meshlets_not_cooked`, `meshlets_unreadable`, `meshlets_old_version`, `meshlets_invalid`),
  `FrameRenderer::remove_meshlets`, `has_meshlets` and `visbuffer_arena_stats` (`visbuffer::VisBufferArenaStats`).
- **Visibility-buffer create counters** (ADR-355). `FrameRenderer::visbuffer_create_stats()` returns
  `visbuffer::VisBufferCreateStats { total, last_frame, frames, quiet_frames }`, counting the pipelines, bind groups,
  buffers and textures of the whole path (cluster arena, instance and cull lists, parameter blocks, shadow cull,
  targets), with their bytes and upload bytes. A GPU test holds the count at zero per frame once warm.
- **Agent method `render.get_visbuffer`**: whether the path is on, meshes and entities on it versus forward (with the
  reason), resident clusters, cluster-arena used / free / capacity bytes, buffer creates since start (`creates`), and
  failing payloads. Page `book/agents/visbuffer.md`.
- **Texture-set census** (bindless step 2a, ADR-356). Every standard material entry records the key of the seven
  texture views its material group binds. `FrameRenderer::texture_set_stats` returns a `TextureSetStats` (resident
  materials, distinct texture sets, materials that share a set, largest set); `set_texture_set_census(true)` (off by
  default) also counts each main-view frame's opaque list: material-group changes today against the changes with
  groups shared by texture set. Agent methods `render.texture_sets` and `render.set_texture_set_census { enabled }`;
  page `book/agents/texture-sets.md`. Rendering does not change. ADR-356 also records the design for the rest of the
  bindless work (steps 2b to 5), which is not built.
- **Steam Input glue** (ADR-350, `ferrite_steam::input`, opt-in). Input contexts become Steam Input action sets,
  gamepad-bound actions become Steam actions named `<context>_<action>`, and a `PreUpdate` bridge holds their values on
  `InputInjection`. Eight fixed UI actions per set are reported as `GamepadButtonChanged` messages so
  `ui_gamepad_navigation` keeps working when Steam delivers actions instead of a virtual gamepad. Enable it with
  `SteamInputSettings { enabled: true, player: 0 }`. `ferrite_steam::action_manifest(&InputConfig)` generates Steam's
  in-game actions file. Agent methods `steam.input` and `steam.input_manifest` (page `book/agents/steam.md`).
  `MockSteam` gains Steam Input helpers.
- **Baked-light guard rails** (ADR-357; groundwork). `ferrite bake-gi <desc> --check-volume <volume.fgiv>` compares a baked
  volume with its description (scene hash, probe layout including brick flags, bake light levels and settings), needs
  no GPU, prints `{"ok", "stale", "reasons", "code", "volume", "description"}` and fails with `bake_volume_stale` (or
  `bake_volume_unreadable`). `BakePlan::volume_bytes` (in `--dry-run` and the bake summary) is the renderer's one
  storage binding size; a layout above 128 MiB (`ferrite_asset::baked_gi::PORTABLE_VOLUME_BYTES`) fails with
  `bake_volume_too_large`. `GiBakeReport` gains `dead_interior_cells` and `borderline_back_face`.
  `probe::filter_probes_with` takes a per-neighbor visibility factor for the 3 x 3 x 3 filter (`filter_probes` is
  unchanged). API: `GiBakeJob::stale_reasons`, `probe::bake_info`, `ferrite_asset::baked_gi::RUNTIME_BRICK_BYTES`.
- **`cargo xtask nightly-sweep`** (ADR-352). Runs the cold, replay and quit scenes at the `high`, `mid` and `low`
  profiles and writes `sweep.csv` and `sweep.json` with frame percentiles, hitch count and pipeline-cache state per
  row. Page `book/user-guide/nightly-sweep.md`.
- **`do27_chase`** accepts `--content <dir>` (the DO27 content bundle; a read-only layout check before any GPU device is
  opened), `--hitch-csv <path>` (per-frame hitch table) and `--camera-path orbit|line|figure8` (deterministic soak
  cameras) (ADR-351).
- **Zero object keys warn under temporal AA** (re-cut of `lane/v0115-zero-key-warning`, ADR-349). A TAA/TSR frame
  with at least `ZERO_KEY_WARN_MIN` (4) moving meshes submitted with `object_key 0` logs one `ferrite_render` warning per
  run. `DrawStats::zero_key_moving_meshes` and the telemetry `draws.zero_key_moving_meshes` (window maximum) count them.
- **Replay step results** carry `clamped`, `events_total` and `events_truncated`.
- **Pak and animation API:** `ferrite_asset::pak_verify::gate_until_verified`, `ferrite_terrain::PakTileSource::with_verify`,
  `ferrite_platform::GpuWorker::try_driver_call`, `ferrite_animation::AnimationClip::decode_cooked_payload` and
  `CompressedClip::sample_node_morphs`.
- **Docs:** `docs/open-questions.md` (open owner and DO27 questions with the default written in each ADR);
  `book/user-guide/host-changes-since-v0122.md` (what a host edits, what changes silently, v0.1.22 to v0.1.27);
  host checklist sections and `book/COVERAGE.md` rows for the v0.1.27 features.
- Regression tests for gaps found by audits (behavior trees, audio, assets, `upgrade-project --write`, animation,
  terrain, render, agent fuzz over every schema method).

## Changed

- **Staging belt spill chunk** (ADR-358). When every chunk of the mapped upload ring is still in flight, the frame's
  belt writes go into one kept 1 MiB CPU chunk (uploaded with `write_buffer`, the `FERRITE_UPLOAD_RING=0` path) instead
  of a new transient mapped buffer, so a GPU a frame or two behind creates no buffer per frame. Each renderer whose ring
  filled keeps 1 MiB more device memory.
- **Recycled cluster memory** (ADR-353). The visibility buffer's cluster records and geometry words are suballocated from
  a best-fit coalescing free list with generation keys. Removed, released and changed meshes return their ranges, so a
  streaming map creates no buffer once warm. A stream doubles when full, up to a cap (logged once; meshes past it draw
  forward). `VisBufferStats::geometry_bytes` counts bytes allocated to resident meshes, so it can go down. Its list and
  parameter buffers are now created through the renderer's tracked device, so the frame-path counters
  (`FramePathCounters`, `play.hitch_report`, hitch traces) see them; the first visibility frame's buffer totals rise by
  about twelve buffers. The shadow cull reuses its job-parameter bytes.
- **Transmissive material-graph glass tints what is behind it** (ADR-347). A graph material with
  `LabMaterial::transmission > 0` is now two blends like standard glass: the view behind it times the graph's base color
  (clamped to 0..1), then the pane's own light added. It was one premultiplied blend that dimmed the view by the base
  color's luminance. Graph pipeline sets build one more small pipeline per graph and target.
- **Frames without IBL bind the BRDF's DFG table** (ADR-359). A `FrameRenderer` builds the 32x32 split-sum table once and
  binds it as `brdf_lut` when `ibl` is off (it was a 1x1 white texture). Frames with IBL are unchanged.
- **UI layout:** right-to-left rows also swap `JustifyContent::Start` and `End` (columns and centered / spaced values are
  unchanged). Text that fits its box within one pixel of rounding stays on one line (ADR-359). Nodes with
  `text_dir: Auto` lay out mirrored while an RTL locale is selected; LTR locales are unchanged.
- **UI lists and scrolling:** a list's scroll extent is the full list (a one-pixel spacer node sits at the content bottom),
  rows out of view are hidden (`Display::None`) instead of despawned, and row styles are rewritten only when they change.
  `ui_scroll` scrolls a newly focused node into view only when focus moves, only for views that contain it, on both
  axes; before, a focused node pinned every scroll view to it on every frame. A drag that starts on a list row scrolls
  the list (touch). Nodes under a `UiTransform` report the transformed rect in `ComputedNode`, so hit testing, focus
  navigation, `ui.query` bounds and `ui.click` follow what is drawn.
- **Automatic bricks: clusters coarsen before interiors.** Over `max_probes`, only the cluster bricks coarsen while they
  can fit in what the interiors leave; interiors keep their spacing. The old common factor applies only when the
  interiors alone leave fewer than 8 probes per cluster. `plan.auto_bricks.interior_scale` is new;
  `plan.auto_bricks.scale` is the clusters' factor. Layouts that fit `max_probes` are unchanged. With a manifest, a mesh
  `source` outside the bundle root is refused (`bake_manifest_missing_entry`) instead of being traced unhashed.
- **Agent hardening, round 2** (ADR-345). `seeing.reference_trace` and `seeing.compare` need `edit_scene`, count against
  the mutating-call rate limit, and confine `out_dir`, `a`, `b` and `map_png` to the `render.out_start` output roots.
  `replay.step` advances at most 36 000 ticks and returns at most 1000 events per call; `moments.list` no longer
  allocates every match. `endpoint.json` is written with mode 0600 on Unix. `play.step` rejects `frames` outside
  `1..=10000`, `seeing.capture_sequence` rejects `every_n` outside `1..=3600`, and `audio.loopgen_render` confines
  `out_dir` to the project or the system temp directory (no `..`); all with `invalid_params`.
- **Exit and the encode workers** (ADR-287 refinement). After the exit's `signal_stop`, a marked worker can no longer
  open a driver call through `try_driver_call`, and a worker registered after the stop starts with its stop already
  requested. The command-buffer encode workers open their driver call before they take a segment, take no segment after
  the stop, and are woken by the stop.
- `LoadSets::on_progress` callbacks run after the registry lock is released (the snapshot-then-call rule of ADR-303); a
  callback may now call back into the same `LoadSets`.
- **Terrain tile source follows the zero-copy gate.** `PakTileSource::new` reads a pak this build has not verified as
  copies for the life of the source; the next launch maps it again.
- **Windows: a mounted pak denies other writers.** `PakReader::open` opens without write sharing; reading, renaming and
  deleting stay allowed.
- `Audio::apply_user_settings` logs a warning for a bus name the layout does not define (it was skipped silently).
  `AnimationClip::cooked_payload_version` reports the version the payload decodes as.
- Material graph shutdown no longer waits up to 5 s for the GPU to go idle after the device is lost; the wait is capped
  at 250 ms (ADR-342).
- Documentation: 160 implemented ADRs moved from proposed to accepted and 16 partly implemented ADRs carry a `Status
  note` (ADR-346). `book/agents/safety.md`, `ui-input.md` and `book/user-guide/ui.md` are corrected.

## Fixed

- **Interior bricks reach the baked volume.** The bake plan's `interior_flag` was never written into the bricks, so a bake
  from a description with interiors shipped every brick with flags 0 and the interior lookup never ran. Bricks whose whole
  box lies in a non-`sky_open` interior now carry `BrickFlags::INTERIOR`, so a sealed room no longer blends with the
  outdoor terrain cascade. The bake loader reverses the winding of a mesh part whose triangles face against its vertex
  normals (a negative-determinant glTF node). `DetailBrick::probe_count` and `VolumeLayout::probe_count` saturate instead
  of wrapping. A failed same-path baked-GI reload keeps the old volume but still applies changed level overrides.
- **Material graphs lost their diffuse light in frames without IBL.** The multi-scatter compensation read the white
  stand-in table and removed the whole diffuse lobe: an opaque graph material under the sun alone rendered black. Fitted
  area lights, interior probe specular and the stochastic-SSR packing in such frames also read the real table now.
- **Graph glass lost its hue** (see Changed): a red pane showed the backdrop gray.
- **A label sized to its text could wrap its last glyph** when layout rounded the node a fraction of a pixel narrower than
  its text ("Tiny" at 8 px became "Tin" over "y"). RTL row layout packed children to the left edge.
- **Gate g1:** `ferrite_terrain` `texture_views` and `arena` `spawn_hitch` no longer see staging-belt buffers
  created after warm-up when the GPU is shared or behind (gate g1). The visibility buffer no longer leaks cluster memory
  when meshes are released, changed or re-inserted, and hitch reports no longer miss a visibility-buffer list growth.
- **A load-set progress callback that called back into `LoadSets` hung its thread** (`set_state` held the registry's
  `RwLock` read guard while it called the callbacks).
- **A version 1 cooked clip whose name begins with `CLP` and is 70 bytes long** loads and migrates again (its postcard
  bytes start with the version 2 magic). `CompressedClip::sample_morphs` returned node-bound morph tracks as weights for
  every morph mesh; it returns only unbound tracks now.
- **`PakReader::read_raw` could crash on a truncated pak** (`SIGBUS`); it now goes through the zero-copy gate and returns
  `PakError::Corrupt`. **Editor exit used a destroyed window handle**: the surface is dropped first. **Hot reload export
  table:** read with `read_unaligned`; a null function pointer returns `GameLibraryError::NullEntry`.
- **Agent:** `seeing.compare_images` no longer aborts on grayscale, RGB or 16-bit PNGs (and checks the buffer size);
  `seeing.screenshot` range-checks `width` / `height` before narrowing; `scene.apply_edits` no longer despawns during
  validation (a rejected or `dry_run` transaction leaves the entities in place); `endpoint::read` ignores the
  `token_file` field and refuses a `url` that is not `ws://127.0.0.1…`.
- **UI agent and input:** `play.expect` / `play.wait_until` accept only `ui.node_exists` and `ui.node_state` as `ui.`
  predicates (they could run mutating `ui.*` methods). Input layers keep the page's saved focus when one modal closes and
  another opens in the same frame, and cancel a drag that began outside a new top layer. Pointer buttons arm on the
  press, not on entering a node. `ui.click` / `ui.focus` / `ui.type` reject a node outside the top input layer (or under
  a `game_only` layer) with `ui_node_blocked_by_layer`; `ui.set_value` rejects a disabled node (`ui_node_disabled`);
  `ui.click` rejects a non-string `button` (`ui_bad_param`). Gamepad input under a `game_only` layer no longer switches
  the UI to navigation mode. Removing a node's classes during a colour cross-fade no longer hides an explicit
  `Background`. `ui.layers` list results are marked `applied: false`.
- `Skeleton::from_local_bind` and `Skeleton::globals` no longer abort on malformed input (`SkeletonError::MismatchedLengths`,
  `SkeletonError::ParentNotEarlier`).
- macOS: `hot_fixture_edits_keep_reflected_state`'s warm-up game build now sets the same `FERRITE_ABI_HASH` pin as the
  host (ADR-348). Unverified until run on the Mac.
- Windows pak and editor fixes above are not yet run on Windows.

## Upgrade

- **Struct literals break** for these public types; add `..Default::default()` (or the named field) where the type has
  one:
  - `AccessibilitySettings` (`reduced_motion`, `high_contrast`; missing in older settings files, read as off);
  - `ferrite_ui::TextSystem` (`text_scale`, default 1.0);
  - `ferrite_render::DrawStats` (`zero_key_moving_meshes: usize`);
  - `BakePlan` (`volume_bytes`), `AutoBrickReport` and `ferrite_pt::auto_bricks::AutoBricks` (`interior_scale`),
    `GiBakeReport` (`borderline_back_face`, `dead_interior_cells`), `ferrite_cli::commands::bake_gi::BakeGiArgs`
    (`check`);
  - `lookdev::chase::ChaseOptions` (`camera_path: Option<CameraPath>`; set it or use `..ChaseOptions::default()`).
- **Changed signatures:** `PakReader::read_raw` returns `Result<Cow<'_, [u8]>, PakError>` (was `Result<&[u8], PakError>`);
  code that names the type `&[u8]` needs `&*raw`. `CompressedClip::sample_morphs` no longer returns node-bound tracks;
  call `sample_node_morphs` for them. `GameLibraryError::NullEntry` also covers a null function pointer in the export
  table (no new variant).
- **New public API (additive):** `ferrite_ui::{UiAccessibility, Ease, HitTestSpace, Reveal, Tween, TweenPlan,
  TweenProperty, TweenValue, UiLayoutBox, UiTransform, UiTween, UiTweenFinished}` and the `list` / `scrollbar` modules
  (a glob import of `ferrite_ui::*` next to another crate's `Tween` or `Ease` may become ambiguous);
  `style::locale_is_rtl`, `Style::mirrored`, `Style::to_taffy_dir`, `TextDir::is_rtl`, `Edges::mirrored`;
  `ferrite_render::{TextureSetStats, ZERO_KEY_WARN_MIN}`, `visbuffer::{VisBufferArenaStats, VisBufferCreateStats,
  VisBufferCreates, MeshletLoadError}` (match enums with a wildcard arm), the `FrameRenderer` methods listed under New;
  `ferrite_framework::meshlet_bridge`; `ferrite_steam::{action_manifest, ManifestError, SteamInputSettings,
  SteamInputStatus, UI_ACTIONS, STEAM_INPUT_PAD_DEVICE}` and `ferrite_steam::input::{action_name, active_context}`.
  `TextureSetStats` is `#[non_exhaustive]`: read its fields.
- `SteamBackend` has five new methods with defaults (`input_init`, `input_connected`, `input_activate_action_set`,
  `input_digital`, `input_analog`); existing implementors compile unchanged. `SteamPlugin` registers the
  `GamepadButtonChanged` message and the resources `SteamInputSettings` and `SteamInputStatus`; with default settings
  nothing changes at runtime. `ferrite_steam` now depends on `ferrite_core`.
- `DefaultPlugins` adds `MeshletBridgePlugin`. A host that builds its own plugin set and wants cooked meshlets adds it; a
  host using `DefaultPlugins` must not add it a second time. `UiPlugin` registers the new list messages.
  `ferrite_ui::scroll::virtualise_lists` is now a re-export of `ferrite_ui::list::virtualise_lists`. `ui_scroll` gained
  system parameters; a host that calls it directly must provide `ChildOf` and `ListRow` queries.
- **Agent protocol:** new methods `ui.accessibility`, `ui.tween`, `ui.list`, `ui.scroll_to`, `render.get_visbuffer`
  (with `creates`), `render.texture_sets`, `render.set_texture_set_census`, `steam.input`, `steam.input_manifest`; the
  `ui.tweening` wait atom; new error reasons `ui_node_blocked_by_layer`, `ui_node_disabled` (and `ui_bad_param` for `ui.click`);
  `replay.step` result fields `clamped`, `events_total`, `events_truncated`; the `draws` telemetry object has a new key
  `zero_key_moving_meshes`. `seeing.reference_trace` and `seeing.compare` are now mutating and need `edit_scene`:
  read-only agent profiles lose them. `play.step`, `seeing.capture_sequence`, `seeing.screenshot` and
  `audio.loopgen_render` return `invalid_params` for out-of-range or out-of-root values. `Endpoint.token_file` is no longer
  followed by `endpoint::read`. Regenerate the reference pages with `cargo xtask manual`, and run
  `cargo xtask check-formats --update`.
- **Formats:** no content-format change. `.bake.ron` stays v1, `.fgiv` stays v2, `.fmlt` stays meshlet v1. Rebake volumes
  from descriptions with interiors to get interior bricks; older volumes still load and look as before, and `--check-volume`
  reports them stale (`layout`). A description whose layout needs more than 128 MiB fails with `bake_volume_too_large`:
  coarsen `terrain_spacing` or `auto_bricks.spacing`, or lower `max_probes` or `moment_resolution`. No `ferrite
  upgrade-project` step is needed.
- **Rendering:** transmissive graph glass is tinted where it was gray (check content tuned around the gray result).
  Frames rendered with `ibl: false` that contain multi-scatter materials (material graphs, hard-surface profiles),
  fitted area lights, interior probes or stochastic SSR can look different (brighter diffuse); re-bless such goldens
  (reason: ADR-359).
- **UI:** text in a box up to a pixel narrower than the text now stays on one line. RTL rows with the default
  `JustifyContent::Start` pack to the right edge. `Style` with `text_dir: Auto` mirrors under RTL locales.
- **Windows:** tools that open a mounted `.fpak` for writing while a game or editor has it open get a sharing error; write
  a new file and rename it instead.
- A host-owned marked GPU worker (`driver_calls_marked()`) that takes jobs from a queue should open its section with
  `try_driver_call` before it takes a job and stop taking jobs when it returns `None`.
- Hosts that compare absolute `FramePathCounters::buffers` totals across a visibility frame see about twelve extra
  buffers on the first frame; differences across warm frames are unchanged.
- Game code that relied on `play.step` above 10000 frames, `every_n` above 3600, or an `audio.loopgen_render` `out_dir`
  outside the project and temp directory now gets `invalid_params`.

## Known issues

- Baked light is not usable end to end yet. Every half-resolution texel still scans every brick (no lookup grid), openings
  have no portals, door frames can leak through 4 x 4 moments, textured parts bake with `default_albedo`, and the bake
  does not read the level's sun and sky. Ranked plan in ADR-357.
- macOS (not gated), on Apple M5: the `ferrite_editor hot_reload` fixture test (fix above unverified) and `ferrite_test_utils
  gpu_matches_cpu` (needs Sponza) fail; the rest pass.
- The Windows pak share-mode test (`a_mapped_pak_refuses_other_writers`) has not run on Windows. Steam Input is not
  verified on a Steam Deck (manifest keys against Steam's parser, action set activation); it has no action set layers,
  one controller (player 0), no glyphs, and a Steam template that also emulates a gamepad makes menus receive presses
  twice. `cargo xtask nightly-sweep` and `do27_chase --content` have not run end to end on a GPU.
- `arena` `spawn_hitch` failed once in 86 loaded runs on the rig's RTX 5080 after the staging fix (2 buffers, 2 MiB, after
  warm-up), not reproduced in 48 labelled runs since; the gate's rerun-alone rule still applies. A legitimate growth after
  warm-up is one visibility-buffer create, and then the count stays flat.
- UI: `reduced_motion` and `high_contrast` are stored and reported, but no theme code reads them yet. The `.ui.ron` `List`
  widget builds a plain list (selection, tiles, headers and scrollbars are code-only); sticky headers are not available in
  tile mode; scrollbar bars are siblings of the scroll view, so it needs a non-scrolling parent; theme entries for
  `scrollbar-track`, `scrollbar-thumb`, `list-header` and `list-sticky` are not in the default theme. No rotation in
  `UiTransform`; scale does not scale border width, corner radius, shadow blur or glyph size. A tween on a color the theme
  also writes fights with the theme. No gallery RTL page or golden; grid placement is not mirrored. `ui.layers` needs
  the EditScene permission and counts against the mutate rate limit even for `list`.
- Visibility buffer: a mesh drawn through a mesh LOD chain draws its LOD 1+ frames forward; the editor's mesh resolver and
  `ferrite_render::cooked_model` do not attach `MeshletSource` yet; no agent method switches `visibility_buffer`; the
  velocity draw (TAAU) is covered by code reading only.
- Transmissive graph glass has no refraction pass, is not part of the glass front layer, and its translucent shadow uses
  the material's standard block; the `.matgraph.ron` format cannot author transmission.
- Texture-set census counts are an estimate (collection order, not the GPU-driven batches); two uploads of the same image
  are two sets. Bindless steps 2b to 5 are designs only.
- `upgrade-project` registers `.vfx.ron` as current v1 while `VFX_FORMAT_VERSION` is 4, so a current file is reported as
  newer than the engine (`#[ignore]` test `a_current_vfx_file_plans_as_up_to_date`).
- `replay.load` is still not confined to the project root. `docs/open-questions.md` status notes come from a read-only
  audit made without a build. `docs/releases/v0.1.27.md` says `ui.click` options are not exposed; the code accepts
  `button` and `count` (no modifiers).
