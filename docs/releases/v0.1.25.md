# Ferrite v0.1.25

Builds on v0.1.24. A foundations release: the UI theme and widget style groundwork (nothing looks different yet),
review fixes for the cue and deliberate-exit work of v0.1.24, and macOS test guards.

## New

- **UI theme tokens and `.theme.ron` v1** (ADR-274, ADR-277). A theme is a file of design tokens (colors, spacing,
  radius, type scale, sizes, elevation, motion) that can extend another theme. Derived colors are expressions
  (`lighten(@color.accent, 0.06)`, `alpha`, `mix`, in OKLab), so changing the accent restyles hover, pressed and
  selection. Errors name the key path and a rejected reload keeps the previous theme. Three built-in themes ship as
  files: `ferrite-dark` (the default), `ferrite-light` and `ferrite-high-contrast`, each with `comfortable` and
  `compact` densities; the default palettes meet the WCAG contrast targets in the spec, asserted in tests. Docs:
  `docs/formats/theme-ron.md`, `book/agents/ui-theme.md`.
- **UI widget style surface** (lane D2). `VisualOverrides` is widened to the spec property set (padding, height, gap,
  opacity, translate, scale, focus ring width and offset, icon color, elevation, text size). `StyleClass` gains
  `selected`, `error`, `sm`, `lg` and named `parts`; `resolve_state` composes `normal, size, selected, hover,
  pressed, error, focused, disabled`, with disabled winning and suppressing hover, pressed and focus (`resolve`
  keeps its signature). New `Selected` and `Invalid` markers, a `WidgetSize` component and a `UiDensity` resource.
  `Themed` carries the resolved opacity, height, padding, translate, scale and ring values. Agent guide:
  `book/agents/ui-widget-style.md`.
- **Editor role bridge** (lane D5, ADR-274 § 7). `ThemeTokens::from_ui_roles(&UiRoles)` maps UI color roles onto the
  editor tokens; `editor.*` roles can override overlay, widget and accent colors. New `theme_source` preference
  (`default` or `ui:<name>`) and `editor.set_theme { ui_theme }` (a name or a role object; `"default"` goes back),
  with `theme_source` in the `editor.get_theme` / `editor.set_theme` replies. Agent page: `book/agents/theme.md`.
  Built-in role tables for `ferrite-dark` and `ferrite-light` are used until the loader is wired in.

## Changed

- Default look unchanged. `UiThemes` and `apply_themes` are not wired to the new themes (lane D6), `UiThemes::
  disabled_opacity` stays 1.0, and the default editor theme is the ADR-229 look; the bridge is opt-in. The
  `ui.theme_*` agent methods arrive with lane D7. Extract now honors `Themed::opacity`.
- Old `UiTheme` / `ThemeClasses` data migrates to v1.
- **macOS test guards** (ADR-275, ADR-278; tests only, no engine, format or API change). The relaxations apply on
  Metal only: GPU-timer tests skip where the adapter has no in-encoder timestamps (the non-timing assertions run
  everywhere); capability-fallback assertions follow the device's own `fallback_notes()`; the terrain virtual-texture
  minspec check skips without `SHADER_EARLY_DEPTH_TEST`, and the early-depth assertion is real where the device has
  it; the allocator-report atlas check skips where wgpu has no report; visibility-buffer and uncut-apron comparisons
  keep their strict bounds on software rasterizers and use a hardware floor (97 % close, 20 %). `arena agent_expect`
  no longer races the bots' first kills. `ferrite_editor hot_reload` runs a warm-up game build on macOS before the
  script (Linux unchanged).

## Fixed

- **Cue review fixes** (ADR-272). The cue low-pass filter track no longer outlives its voice; a cue file's version is
  read first, so a newer file reports "upgrade the engine" instead of a RON field error; `ferrite upgrade-project`
  cue migration finds the root struct past `//` and nested `/* */` comments and parentheses inside strings or
  comments; more tests for the seeded cue API.
- **Deliberate-exit review fixes** (ADR-276). The native crash handler re-checks the exit flag before arming and
  before the dump, so an exit that begins while it is arming starts no bundle; the Windows path ends the process
  without returning into the crash path; the stdio flush at exit is bounded to 2 s on a helper thread; the exit
  watchdog ends the process before its diagnostic is printed, so a blocked stderr cannot hold it.

## Upgrade

- No format version changes. `.theme.ron` v1 is new; older `UiTheme` data loads through the migrator and
  `ferrite upgrade-project --write` rewrites it.
- Hosts with their own `main` loop: nothing new beyond the v0.1.24 deliberate-exit API.

## Known issues

- UI foundations only: no widget changes are visible yet, and `theme_source` is not persisted across editor
  restarts (the editor has no preferences file yet).
- macOS (not gated), on Apple M5: the `ferrite_editor hot_reload` fixture test and `ferrite_test_utils gpu_matches_cpu`
  (needs Sponza) fail; the rest pass. Also needed on a Mac: `brew install spirv-tools` for the `spirv-val` tests and
  `cargo xtask fetch-test-assets`. The guards are Metal-only.
- `pipeline_warm` leftover workers may still be inside the driver at normal quit under extreme load.
- The loaded `device_lost_exit` soak has not been run on this build; it runs after the tag.
- Selector state for cues is still per cue, so a seeded play is reproducible only given the same cue history.

Not in this release: baked light (reserved for v0.2.0), widget-level UI changes.
