# Regia Engine v0.2.5

Builds on v0.2.4. This release adds these feature sets for game teams:

- **Gameplay camera framework**: a data-driven `.camera.ron` asset of camera rigs built from nodes (boom, collision,
  smoothing, lean, shake and more), transitions, directors, overlay and additive layers, with presets that match the
  legacy `CameraRig`.
- **AI**: state trees v2 (enter writes, fallbacks, held transitions, ambient tasks, includes, hot reload, pause) and
  smart objects v2 (claim priorities and handles, filtered search, `.smartobject.ron` definitions, entrances, tags).
- **Networking**: the new `regia_net` crate: a UDP client-server transport (reliable and unreliable channels,
  connect handshake, ticks and input history, a network conditioner, relay and port mapping), plus the net model
  (modes, ownership, roles, net messages) and entity replication on top of it.
- **Animation**: montage format v2 warp windows (modes, rotation, bone anchors), skeleton slot tables, montage
  variants, scripted warps, root-motion routing, montage rate curves, and motion-matching tags, filters and biases.
- **Voice chat**: packet format, codec seam with a PCM codec, jitter buffer, loss simulator, capture conversion,
  channel routing and mute/block/deafen, all testable without a microphone.
- **Destruction level 2**: a `.destructible.ron` chunk asset, a deterministic bond-and-support break model, pooled
  debris bodies, moving structures, a cook step and the `regia fracture` command.
- **Studio environments**: a horizon-to-zenith gradient environment and a caller-supplied HDR equirect image as the
  image-based lighting of a studio scene.

All new features are opt-in, or unchanged for projects that do not use them, except where **Changed** says otherwise.

The text below consolidates the `v0.1.28-*` release fragments of the lanes merged after v0.2.4 and the integration
notes (ADR-1654). The lanes: `destruction-l2`, `regia-net-extract`, `b13-net-a`, `b10-camera-framework`,
`b11-ai-statetree-smartobj`, `b15-voice-chat`, `studio-sky-gradient` and `b14-animation-montage-mm`, merged in
`integ-v026`. The tag's gate ran 5,531 GPU tests with 0 failures.

Read **Upgrade: host changes since v0.2.4** first if you build a game or a shell against the engine crates.

## New

### Rendering: studio environments (ADR-1653)

- **Gradient studio environment.** `StudioGradient { zenith, horizon, ground, falloff }` and
  `FrameRenderer::set_studio_gradient(&device, Some(&gradient)) -> Result<bool, StudioEnvError>`: a horizon-to-zenith
  ramp (`sin(elevation)^falloff`) with a flat ground color and no sun disc. It feeds the diffuse irradiance and the
  specular prefilter, so a metal surface reflects a ramp instead of one flat sky.
- **HDR equirect studio environment.** `StudioEquirect::new(width, height, texels)` and
  `FrameRenderer::set_studio_equirect(&device, Some(&image)) -> bool` use a caller-supplied linear-radiance image as
  the same environment. Values above `SKY_IBL_SCALE` are kept (the new maps are RGBA16F).
- **Rebuild only on change.** Both calls return whether they rebuilt; `StudioGradient::cache_key`,
  `StudioEquirect::cache_key` and `FrameRenderer::studio_environment_key` expose the 64-bit key.
- **Agent method** `render.set_studio_environment` (`kind` gradient, equirect from an OpenEXR file, or none). Page:
  `book/agents/studio-environment.md`.

### Camera framework (spec 35, ADR-1637)

- **`regia_framework::camera::{asset, nodes, director, runtime, driver, presets, debug}`.** A camera entity with a
  `CameraDriver` runs a `.camera.ron` asset (format `camera` v1, `docs/formats/camera-ron.md`):
  - rigs of nodes (`Pivot`, `LookInput`, `Boom`, `Collision`, `Fov`, `Offset`, `SmoothPosition`, `SmoothRotation`,
    `Lean`, `Frame`, `Shake`, `Fly`, `Group`, `When`);
  - shared and per-rig transitions (cut, linear, smooth, ease; start-facing policies; hold-outgoing, share-state,
    interruptible) and directors (`Fixed`, `Rules`, `Ranked`, `Hook`);
  - parameters, runtime variables, input slots, overlay and additive layers with `CameraLayerEvent` messages, and
    `LookAt` actions.
  - Evaluation is deterministic and allocation-free in steady state.
- **Legacy-parity presets** `presets::third_person()`, `overhead()`, `first_person()`, `free()` and `from_legacy`,
  with starter files `assets/camera/presets/*.camera.ron`. Preset poses match the legacy `CameraRig` within 1e-4 on a
  600-frame scripted path.
- **Gizmo group** `camera_rig` (`regia_render::gizmos::CameraRigGizmos`, off by default).
- **Agent methods** (eleven): `camera.assets`, `camera.validate`, `camera.inspect`, `camera.set_var`,
  `camera.set_param`, `camera.set_input`, `camera.push_overlay`, `camera.add_additive`, `camera.release_layer`,
  `camera.hold_overlay`, `camera.set_driver`; nine `camera_*` error codes. Page: `book/agents/camera-framework.md`.

### Animation (specs 34 and 52, ADR-1644, ADR-1645)

- **Montage format v2 warp windows**: `mode` (`Similarity`, `PathScale`), `rotation_kind`, `rotation_fraction` and
  `anchor` (`Root`, `Bone`, `Offset`); a bone anchor lands the bone on the target, not the origin. New types
  `WarpWindow::new`, `WarpMode`, `RotationKind`, `WarpAnchor`, `RateCurve`, `SegmentFollow` in `regia_animation`.
- **Montage rate curves** play: `Montage::rate_curve` (`Step` or `Linear`) changes how fast montage time runs.
  `.montage.ron` also accepts and validates `follow` links; playback ignores them for now.
- **Slot tables** (`.slots.ron` v1, `SkeletonSlots`): a skeleton-owned slot table with groups and joint masks;
  `Montage::validate_against` reports `montage_unknown_slot`; rename and delete follow the montages that name a slot.
- **Montage variants** (`.montagevar.ron` v1, `MontageVariant`, `MontageLibrary`): derived montages that swap clips
  and optionally rescale.
- **Scripted warps** (`ScriptedWarps`, `ScriptedWarp`, `ScriptedWarpEvent`): bend a graph clip's root motion for a
  while.
- `MontagePlayer::try_play` (`PlayError`) and `MontagePlayer::cancel_all`.
- **Root-motion routing** (`RootMotionRoute`, `Animator::root_motion_route`): ignore, report, graph and montages, or
  only montages.
- **Motion-matching tags, spans and filters**: `TagTable`, `Span`, `ClipAnnotation`, `SearchFilter`,
  `MotionDatabase::annotate`, `search_with`, `search_top_k`; `MatcherSettings::{stay_bias, loop_clip_bias,
  lockout_window}`; `MotionMatcher::filter`; `KdTree::nearest_biased`.
- **Agent methods** `anim.warp_state`, `anim.scripted_warp`, `anim.root_motion_route`, `anim.motion_match_set`;
  `anim.motion_match` also reports the new settings and the tag table, and the montage agent module lists the new warp
  fields.

### AI: state trees v2 (spec 38, ADR-1639)

- **`.statetree.ron` format version 2.** New optional fields:
  - `StateDef.enter_set` (literals written to the blackboard when a state becomes active, before its tasks tick);
  - `StateDef.fallback` (`NextEnterable` tries the following siblings when nothing can be entered below the target);
  - `TransitionDef.hold` (seconds, counted in fixed steps; fires on exactly the step its counter is reached);
  - `StateTreeDef.ambient` (tasks ticked first on every tick, so their writes are visible to the first selection);
  - `StateTreeDef.includes` (other trees inlined at compile time with a `prefix/` on every state name, nesting up to
    4, cycles refused).
  - New targets `Parent`, `Stay` and `NextEnterable`. Version 1 files still load unchanged.
- **API.** `StateTree::compile_with` (includes through a loader closure), `StateTree::reload` (hot reload: keeps the
  active path, tick count and event queue when every active state survives, otherwise restarts; returns
  `ReloadOutcome`), `pause` / `resume` / `is_paused`, `held`, `has_state`, `set_debug` / `debug_lists`,
  `StateTreeDef::expand_includes`, `migrate_ron_v1_to_v2`, `StateTreeError::reason` / `state`, and the dev-build
  component `StateTreeDebug` (`disabled`, `pause_on_enter`; compiled out of shipping builds).
- **Agent methods** `statetree.compile` (read), `statetree.control` (`pause`, `resume`, `restart`),
  `statetree.reload`, `statetree.debug` (dev builds). Errors are `F0002` with `data.reason`. Page:
  `book/agents/state-tree.md`; guide topic `state-trees`.

### AI: smart objects v2 (spec 39, ADR-1638)

- **Claim priorities and handles** (`regia_ai::smart_object_v2`): `ClaimPriority` (`Background` .. `Urgent`),
  `claim_with` (a strictly higher priority preempts a holder), `ClaimHandle { slot, generation }` (stale after a
  release or preemption; `to_bits` / `from_bits` pack it for a blackboard `Int`), `begin_use`, `release_handle`,
  `slot_state` (`Free | Claimed | InUse | Disabled`). Automatic release (holder or slot despawned, slot disabled, slot
  removed by a definition reload) writes one `SlotLost` each.
- **Filtered search**: `SmartObjectIndex::search / find_first / availability` with `SlotQuery` (region, activity tag
  query, requester tags, behavior families, priority, preemptable, disabled, conditions, limit) and an optional
  `RejectionLog` naming the first failing stage per candidate. Rules come from `SmartObjectRules`, conditions from
  `SmartObjectConditions` and the `SmartObjectRegistry`, behavior payloads from `SlotBehaviors` (`slot_behavior::<T>`).
- **Definitions**: `.smartobject.ron` v1 (`SmartObjectDef`, `docs/formats/smartobject-ron.md`) and
  `SmartObjectDefinition` on an object; slots are spawned as children and reconciled by definition slot on reload.
- **Entrances** (`SlotEntrance`, `entrance_for`), **runtime tags** (`add_runtime_tag`, `remove_runtime_tag`),
  **off-reasons** (`set_enabled`), **messages** (`SlotChanged`, `SlotLost`, `SmartObjectEvents`), and a uniform grid
  above 256 slots (`SmartObjectIndex::{candidates, has_grid, cell_size}`).
- **Agent methods** `smartobject.search`, `.begin_use`, `.set_enabled`, `.tags`, `.messages`; `smartobject.claim`
  takes `priority` and `use` and returns a `handle`; `smartobject.release` accepts a `handle`. Errors are `F0002` with
  `data.reason`. Page: `book/agents/smart-objects.md`.

### Physics: destruction level 2 (ADR-1597)

- **`.destructible.ron` v1** (`regia_physics::destruction::asset`, `docs/formats/destructible.md`): `DestructibleAsset`
  (source kit, seed, pattern, stage, outer/inner materials; chunks with name, parent, mass, inertia, 1 to 16 convex
  hulls, bounds, support flag, LODs, fx tag, small, lifetime, edge heat; bonds with area, anchor, normal and break
  impulse; `DestructionMaterial`), `from_ron` / `to_ron` / `validate`, `migrate_destructible`,
  `destructible_schema_fingerprint`, and `DestructibleAsset::box_grid` (walls, decks, piles). Registered as
  `destructible` in `cargo xtask check-formats` and `regia upgrade-project`.
- **Break model** (`destruction::sim`): `DestructionWorld` with `damage` (explosion, projectile, impulse), `step`
  (bond accumulation, per-tick break cap, support-graph collapse), `BreakEvent` with ids, ticks and seeds (serde),
  `Authority::Replica` + `apply_events` for clients, `structure_hash` / `state_hash`, `DestructionBudget`, and
  `DestructionFx` sound/VFX hooks. Bit-identical on every platform (IEEE-exact operations only).
- **Rapier side** (`destruction::bridge`): `DestructionPhysics` with intact hull colliders per chunk, pooled debris
  bodies capped by `max_active_chunks` and `max_spawns_per_tick`, sleep / lifetime / kill-height despawn, collider
  removal and `NavInvalidation` boxes on break, and `chunk_of_collider` for game raycasts.
- **Moving structures**: `DestructionWorld::set_pose`, `DestructionPhysics::follow_pose` (the intact body turns
  kinematic) and the `follow_root_transforms` system (moving a `DestructibleRoot` entity's `Transform` moves it).
- **ECS** (`destruction::plugin`): `DestructionPlugin { authority }`, the `Destruction` resource, messages
  `DestructionBroke`, `DestructionFxMessage`, `NavmeshInvalidated`, components `DestructionChunk` and
  `DestructibleRoot`, systems `step_destruction` (before `PhysicsStep`) and `write_back_destruction`.
- **Samples**: `destruction::sample` (brick wall and plank bridge, hit script, `run_sample_headless`), the headless
  example `cargo run -p regia_physics --example destruction_scene` (`--perf` for timings) and the drawn sample
  `cargo run -p regia --example destruction --features quick` (`REGIA_DESTRUCTION_CAPTURE=out.png` saves a frame,
  prints the hashes and quits). Helpers without the ECS: `destruction::step_standalone`, `destruction::add_fixed_box`;
  `DestructibleAsset::chunk_descs` feeds the level 1 `DebrisSpawner`.
- **Cook**: `regia_asset_pipeline::destructible_cook::cook_destructible` turns a `.fracture.ron` (ADR-1567) into a
  `.destructible.ron` (`CookSettings`: density, bond time, `SupportRule`, material, mesh path).
- **Agent methods** `physics.destruction_define`, `physics.destruction_damage`, `physics.destruction_state`,
  `physics.destruction_budget`; guide topic `destruction`; page `book/agents/destruction.md`; error reasons
  `destruction_*`.

### Networking: `regia_net` transport (phase 1, ADR-1600)

A new layer-2 crate for client-server games over UDP, re-written from the generic core of DO27's `ir-net`:

- `Connection`: a reliable-ordered channel (resend on an RFC 6298 timeout, fragments up to 256 KiB, backpressure) and
  an unreliable channel over one UDP flow, with RTT, jitter, loss and kbps statistics.
- `NetServer` / `NetClient`: padded connect request, stateless cookie challenge, join token (name, player or
  spectator, build id, password proof, game join data), accept with a session token, deny with a reason (`full`,
  `banned`, `bad_password`, `protocol_mismatch`, `build_mismatch`, `invalid_join`, `shutting_down`), disconnect
  reasons, silence timeouts, kicks, IP bans and an optional per-IP peer cap (`ServerConfig::max_peers_per_ip`).
- `NetGame` and `NetCodec`: the game's message set, per-tick input and join data are the game's own types.
- `TickDriver`, `TickClock`, `InputHistory`: the authoritative tick, per-peer input buffers, redundant input bundles
  and missed-input counts per peer.
- `NetConditioner`: seeded loss, duplication, delay, jitter, reorder and loss bursts on every outbound datagram;
  profiles `off`, `lan`, `home`, `wan`, `wan_stress`, `bad`, `burst`.
- `CongestionNotches`, `ReliableRateLimiter`, `send_clock`; `relay` (join codes, punch introduction, opaque
  forwarding, game directory, NAT simulation); `port_map` (PCP, then NAT-PMP, then UPnP IGD through `upnp`; a fake
  router); `discovery` (LAN announcements); `DiagnosticsOverlay`.
- `LoopbackNet` (an in-memory network for deterministic tests) and `UdpTransport` (non-blocking `std` UDP).
- Example `cargo run -p regia_net --example net_duel` (local, `server`, `client` modes).
- **Agent methods** `net.status`, `net.peers`, `net.conditioner_set` (guide topic `net`; codes `net_no_endpoint`,
  `net_unknown_endpoint`, `net_unknown_profile`, `net_bad_conditioner`). Pages `book/user-guide/networking.md` and
  `book/agents/net.md`.

### Networking: net model and entity replication (specs 70 and 71, ADR-1643)

- **Net model**:
  - `NetMode` (`Offline`, `DedicatedServer`, `ListenServer`, `Client`) and the run conditions `on_server()`,
    `on_client()`, `with_local_players()`, `offline()`. Gameplay written for the network runs unchanged offline.
  - `PeerId::SERVER`, `NetPlayerId`, `NetPlayer`, `NetId`, `NetTick`, `NetTickFrac`, `LocalPeer`.
  - Ownership: `NetOwner`, `NetOwnerLink`, the walk through `NetOwner` → `NetOwnerLink` → `ChildOf` (`resolve_owner`,
    `OwnerCache`, `net.owner_chain_broken` once per entity), `set_possession_owner`; clients see `NetOwnedLocally`.
  - Roles: `NetRole` (`Local`, `Authority`, `Predicted`, `Proxy`), `has_authority`, `is_locally_controlled`.
  - Net messages: `NetMessage` (direction, four delivery classes, rate limit, `ALWAYS_ADMIT`, `ALIGN_TO_VIEW`,
    `SKIP_PREDICTING_OWNER`, `validate` with `Accept` / `Reject` / `Kick`), the direction markers, `NetSender`,
    `NetMessages<M>`, per-type counters, queue bounds, and the per-peer flood guard (`Clear` / `Slowed`, stall
    forgiveness).
  - `NetPlugin` and `NetSet` (`Receive`, `Apply`, `Predict`, `Assign`, `Gather`, `LagCompRecord`, `Send`, `Flush`,
    `Interpolate`): net work runs per fixed tick.
  - `config/net.ron` (`NetSettings`, `format_version` 1, sections `messages` and `replication`; unfrozen until
    v0.5.0). Format page `docs/formats/net-ron.md`.
- **Entity replication**:
  - `Replicated { profile, transform, sleep }`, `app.replicate::<C>(ReplicateOptions)`, `#[derive(Replicate)]`
    (`regia_macros`; field attributes `skip`, `quantize`, `angle`, `unit_vec`, `rotation`, `max_len`).
  - Spawn records (bare, prefab through the host's `NetPrefabSpawner`, level-bound by `EntityGuid`), field deltas,
    despawns, hierarchy (parents first), entity references as `NetId`s with pending references, the eight audiences,
    change notices (`NetChangedEvents<C>`, `NotifyWhen`, `keep_previous`, `notify_on_server`), sleep with no lost
    edits (`NetSleep`, `NetAsleep`, `net_wake`, `net_resend`), the transform fast path with `net_teleport`, and
    `NetVec<T>` with element events.
  - `bridge::{ServerBridge, ClientBridge, NetFrame}`: the replication runtime over the UDP `NetServer` / `NetClient`
    (frames cut into 16 KiB parts, backpressure backlog, joins/leaves and kicks mapped).
  - `testing::LoopbackHub`: N processes as N worlds at fixed steps with seeded loss, delay, duplication, reordering
    and a reliable-only delay; `replay_client` for packet-log replays.
- **Agent methods** `net.entity`, `net.messages`, `net.peer_flood`, `net.set_owner`, `net.replicated`,
  `net.entity_state`, `net.wake`, `net.set_asleep`, `net.resend`, `net.pending_refs` (guide topics `net-model` and
  `net-replication`; pages `book/agents/net-model.md`, `book/agents/net-replication.md`). Errors are `F0002` with
  `data.reason`: `net_not_running`, `net_not_server`, `entity_not_replicated`, `entity_not_found`, `peer_unknown`,
  `message_type_unknown`, `component_not_replicated`.

## Changed

- **Camera.** `CameraPlugin` also installs `CameraAssets`, `CameraHooks`, the `CameraLayerEvent` message, the driver
  system and `CameraDebugPlugin`. The legacy `CameraRig` update skips entities that have a `CameraDriver`.
- **State trees.** `STATE_TREE_FORMAT_VERSION` is 2; a file above 2 is refused as
  `UnsupportedVersion { found, supported: 2 }`. `StateTreeStatus` reports `paused` and `held`; a paused tree does not
  count the tick (ADR-1639).
- **Smart objects.** `claim_slot` / `release_slot` delegate to the v2 code at `Normal`; signatures and results are
  unchanged.
- **Montages.** `MontagePlayer::stop` now records one `Ended { interrupted: true }` (and no `Started`) for each queued
  montage it drops. Hosts that count `Ended` events see these extra events.
- **Networking.** `net.status` also answers `mode`, `local_peer`, `tick`, `peers` and `players` when the app has the
  net runtime. The `regia` umbrella has a `net` feature, and `regia_dylib` forwards it.
- **Agent.** `render_out::confine_path` in `regia_agent` is no longer behind the `reference-trace` feature (the studio
  environment method uses it to confine the EXR path); no behavior change.
- **Dependencies and layers.** `regia_ai` depends on `regia_framework` (a new allowed layer edge in
  `xtask/src/layers.rs`). `regia_agent` depends on `regia_net`. `regia_net` depends on `regia_core`, `regia_app`,
  `regia_scene`, `regia_asset`, `regia_macros`, `glam` and `ron` (all already in the workspace; no new external
  dependency) and stays in layer 2; `xtask layers` and `docs/02-architecture.md` list it there. The workspace has 56
  members; no third-party dependency changed.
- **Docs.** `specs/16` § 3b and the `opus` row of `docs/03` describe the voice-chat codec split (ADR-1647).

## Fixed

- **A replaced image-based light reaches the frame** (ADR-1654 (7)). A studio sky, uniform sky, gradient or equirect
  environment set after the first frame kept the old maps, because the cached view bind groups were not dropped when
  the IBL was replaced. They are now dropped on every replacement.
- Merged-tree fixes (ADR-1654 (2), (5)): doubled ADR, provenance, coverage and summary rows from the criss-cross merge
  of the net lanes appear once; `Cargo.lock` gives `regia_net` the workspace version; a state-tree test literal gains
  the v2 `hold` field; three clippy lints in `regia_ai`; the smart-object agent contracts no longer list the
  universal `F0002`; the studio-environment page's host example is `rust,ignore`.

## Upgrade: host changes since v0.2.4

### Struct literals that stop compiling

Add the new fields, or end the literal with `..Default::default()` (or the named constructor):

- `regia_ai`: `TransitionDef` (`hold`), `StateDef` (`enter_set`, `fallback`; or use `StateDef::new`), `StateTreeDef`
  (`ambient`, `includes`), `StateTreeStatus` (`paused`, `held`).
- `regia_ai`: `SmartObject` and `SmartObjectSlot` gain public fields.
- `regia_animation`: `WarpWindow`, `MontageSection`, `MontageNotify`, `Montage` and `WarpInput` gain public fields
  (build windows with `WarpWindow::new(target, start, end)` and `..`); `Animator::root_motion_route` (the default
  keeps today's behavior); `MatcherSettings::{stay_bias, loop_clip_bias, lockout_window}` (use
  `..MatcherSettings::default()`); `MotionMatcher::filter`.

### Enum variants that break exhaustive matches

- `regia_ai` state-tree `Target`: `NextEnterable`, `Parent`, `Stay`.
- `regia_ai` `StateTreeError`: `IncludeMissing`, `IncludeCycle`, `IncludeDepth`, `HoldOnEvent`, `ParentOfRoot`.
- `regia_ai` `SmartObjectError`: `StaleHandle`, `NotHolder`, `SlotInUse`.

### Changed traits, plugins and systems

- `regia_ai`: `SmartObjectIndex` no longer derives `Default` (it implements it by hand). `SmartObjectPlugin` registers
  two messages and three resources.
- `regia_animation`: `evaluate_animators` writes a new message, `ScriptedWarpEvent`, registered by `AnimationPlugin`;
  code that registers the system by hand must register the message too.
- `regia_framework`: `CameraPlugin` adds resources, a message, the driver system and `CameraDebugPlugin` (see
  **Changed**); legacy `CameraRig` entities that also carry a `CameraDriver` are no longer driven by the legacy update.
- `regia_render`: `regia_render::gizmos::GizmoConfigStore` has one more group (`camera_rig`); code that enumerates
  groups sees it.
- `regia_physics`: a project that adds `DestructionPlugin` gets three new message types. No existing item changed.

### New crate: `regia_net`

`regia_net` did not exist in v0.2.4; games opt in by depending on it (or the `regia` umbrella's `net` feature). For
the agent methods, insert `regia_net::NetAgentState` and call `NetServer::publish` / `NetClient::publish` each frame.
Notes for code written against the lane branches:

- `regia_net::PeerId` is `PeerId(pub u32)` (the extraction lane had `u16`) and has `PeerId::SERVER`; build ids from a
  `u16` with `u32::from(x)`. `PeerRow::id` and `NetStatus::peer_id` are `u32` / `Option<u32>`.
- `regia_net::DisconnectReason` has six variants added by the net-model lane (`InvalidMessage`, `MalformedPacket`,
  `ReliableOverflow`, `Flood`, `ServerFull`, `TooManyLocalPlayers`).
- The components `Replicated`, `NetGroups`, `NetAsleep` may appear in `.level.ron` / `.prefab.ron`; files without
  them load unchanged (no format version changed). `config/net.ron` is optional (defaults apply when it is absent).

### Formats

- `.statetree.ron` is v2. v1 files need no edit; `regia_ai::state_tree::migrate_ron_v1_to_v2` rewrites the version
  number.
- `.montage.ron` is v2 (`MONTAGE_FORMAT_VERSION`). v1 files load unchanged and `regia upgrade-project` rewrites them.
- New formats, v1 each: `camera` (`.camera.ron`), `smartobject` (`.smartobject.ron`, no migrator), `slots`
  (`.slots.ron`), `montage-variant` (`.montagevar.ron`), `voice-chat` (`config/voice_chat.ron`), `destructible`

## Known issues

### Rendering

- `regia_render/tests/studio_gradient.rs`: the two look tests (`a_metal_sphere_reflects_the_gradient_...`,
  `the_two_tone_studio_reflects_a_flat_sky_...`) are ignored: their never-measured thresholds do not hold on lavapipe
  (numbers in the ignore reasons and ADR-1654 (7)); a look review decides the expected values.
- **Open defect:** an equirect image of a gradient and the same analytic gradient render 183.5 levels apart on
  lavapipe (`an_equirect_image_of_the_gradient_reflects_like_the_gradient`, ignored); the CPU bakes agree. Switching
  back to an earlier gradient after another one does not restore its frame
  (`restoring_the_first_gradient_brings_its_frame_back`, ignored). Hosts that switch studio environments at run time
  or use `set_studio_equirect` should wait for the sky lane's follow-up.
- The studio-environment agent method reads OpenEXR only (no Radiance `.hdr`), and the image has no rotation
  parameter. The ground is a hard step at the horizon, as in the two-tone call.

### Camera framework

- A driver names its asset in the `CameraAssets` resource; loading `.camera.ron` through the asset server and hot
  reload are not wired yet (`CameraAssets::load_ron` is the entry point).
- Layer markers in the gizmo overlay are cuboids, not text labels.
- A legacy `lag_speed` of 0 (frozen camera) maps to no smoothing in `from_legacy`.

### AI

- State trees: no `cargo fuzz` target (a seeded damage test covers the loader instead). The zero-allocation budget of
  spec 38 § 9 is not asserted; the tick still builds small vectors (events, completions, candidates) as v1 did.
- Smart objects: `SmartObject.definition: Option<AssetRef<..>>` and the asset-server loader are not built; the host
  sets `SmartObjectDefinition(Arc<SmartObjectDef>)`. Gizmo rings by priority, entrance arrows and the timing budgets
  of spec 39 § 12 are not done; a search without a log allocates for the activity set when an activity query is
  present.

### Destruction

- Intact structures are fixed bodies, or kinematic ones that follow a set pose; never free rigid bodies (debris of a
  moving structure does start with its velocity). A collapsing section breaks into its chunks instead of falling as
  one compound body.
- Bonds are loaded by hits only (no gravity or stacked-weight load); debris hitting a structure does no damage unless
  the game feeds contacts in as `Impulse` hits.
- No network code (the events and replica path are the hooks), no navmesh rebuild (`NavmeshInvalidated` reports the
  boxes; `regia_nav` is not called), and no level 3 (runtime fracture, carving).

### Networking

- Payload packets are not encrypted or signed in phase 1 (session tokens only filter stray traffic).
- `default_gateway_v4` works on Linux only; elsewhere pass the gateway to `try_port_mapping`.
- Until spec 72 lands, replication rides a reliable-ordered stream (head-of-line latency under loss) and every entity
  is relevant to every connection unless a game installs `NetRelevance::filter`. No prediction or lag compensation.
- Proxies' physics bodies are not made kinematic yet, `Handle<T>` fields do not travel (use `AssetRef<T>`), and
  despawns of interpolated proxies are immediate (spec 74; ADR-1643 (10)).
- Server gathering is above the spec 71 § 15 desktop budget: about 0.9 ms per tick for 10,000 idle replicated
  entities and about 3 ms with 10 % changing (one connection, release, a shared build machine under load), against
  0.4 ms. Client apply meets its budget (about 0.4 ms for 1,000 deltas).
  `cargo run --release -p regia_net --example net_replication_bench` measures it (ADR-1643 (14)).
- The quantization golden hash was taken on Linux x86_64; Windows and Android runs of
  `cargo test -p regia_net --test replication` confirm the cross-platform bytes.

### Voice chat

- Not built: Opus (`voice-opus`), the spatial chat emitter, echo cancellation, noise suppression, AGC, WSOLA time
  scaling, two-frame packets, the `voice_chat_talk` input-action binding, the editor panel, the Android permission
  prompt, the cpal device opener, `Reflect` derives and the unknown-key round trip of the user settings (ADR-1647).
- Packets longer than 400 bytes parse only for PCM; PCM at the High profile is over the network MTU and is for tests
  and loopback only.

### Verification

- The state-tree, smart-object and studio-gradient lanes were written without a compiler; integ/v026 was their first
  compile and test run. Real-GPU, Windows, macOS and device runs are the lanes' open items; the integration ran on
  lavapipe only.
