# Regia Engine v0.2.0

Builds on v0.1.29. Releases up to v0.1.29 were published as Ferrite; from this release the engine is **Regia Engine**.
Two things define v0.2.0:

- **The rename** (ADR-1388, ADR-1421): crates, CLI, environment variables, project files, the per-user data
  directory and the MCP scheme carry the new name. The old names keep loading for one release, with a warning. File
  formats are byte-identical.
- **Baked light on probe volumes**: baked emitters are no longer counted twice (`.fgiv` v3), the seams along the edges
  of interior bricks are gone, ZH3 is available as an opt-in reconstruction, and bent normals carry the AO's direction
  into the indirect light. Lightmaps stay groundwork in this release; they are the v0.3.0 line (`docs/versions.md`).

Besides that, the showcase work adds water bodies, a grass field, valley mist, cloud genera with a cirrus sheet, a
late-winter ground look, a Cinematic offline profile, motion blur, 16-bit and raw frames in render-out, crash effects
from a vehicle crash up to a 1 kt surface blast, mesh debris and impact sites, an entry streak, and streamed forests
at the scale of a whole map. All of them are off until a host or an agent turns them on.

The text below consolidates the 36 release fragments of the v0.2.0 line: every `v0.1.28-*` fragment written after
the v0.1.29 cut, `v0.1.29-versions-doc`, and the two `v0.2.0-*` fragments that v0.1.29 left in place. The
`v0.1.19-*`, `v0.1.20-*` and `v0.1.21-*` fragments stay: the notes of those versions link them.

Read **Regia Engine: the rename** and **Upgrade: host changes since v0.1.29** first if you build a game or a shell
against the engine crates.

## Regia Engine: the rename

ADR-1388 is the decision and the compatibility policy, ADR-1421 the fallbacks added while applying it. User guide:
`book/user-guide/rename-regia.md`. Runbook (lead and lane branches): `docs/rename-regia.md`. The rename is one commit
made by `cargo xtask rename-brand` plus `cargo fmt` (tool binary sha256 `3e2f9e64c06e...`, 26,962 replacements in
2,378 files, 1,988 paths moved), followed by hand-made fallback commits. The v0.1.x tags keep the old name.

### What changed for hosts

| Before (v0.1.x) | From v0.2.0 |
|---|---|
| crates `ferrite`, `ferrite_*` (33 crates under `crates/ferrite*`) | `regia`, `regia_*` (`crates/regia*`) |
| CLI binary `ferrite` (`cargo run -p ferrite_cli --bin ferrite`) | `regia` (`cargo run -p regia_cli --bin regia`); no `ferrite` alias |
| environment variables `FERRITE_*` | `REGIA_*` |
| project manifest `Ferrite.toml` | `Regia.toml` |
| project state directory `.ferrite/` (cook cache, asset database, agent endpoint, `agent.toml`, autosaves) | `.regia/` |
| per-user data `<data dir>/Ferrite/<game>` | `<data dir>/RegiaEngine/<game>` (Linux `~/.local/share/RegiaEngine/<game>`, Windows `%APPDATA%\RegiaEngine\<game>` and `%LOCALAPPDATA%\RegiaEngine\<game>`) |
| type paths `ferrite_scene::...` in levels, prefabs and cooked scenes | `regia_scene::...` |
| editor script marker `// FERRITE:SCRIPTS` | `// REGIA:SCRIPTS` |
| MCP server `ferrite mcp` (`ferrite-mcp`), resources `ferrite://...` | `regia mcp` (`regia-mcp`), resources `regia://...` |
| Android shim `FerriteActivity`, JNI `com_ferrite_*`, ids `com.ferrite.*` | `RegiaActivity`, `com_regiaengine_*`, `com.regiaengine.*` (a game's own app id is not touched) |
| log targets `ferrite_agent`, `ferrite_render`, ... | `regia_agent`, `regia_render`, ... |

### Old names that still work for one release

Each prints a one-time warning that names the replacement:

- `FERRITE_X` runtime variables (`REGIA_X` is read first; the current name wins when both are set). The CLI's log
  filter reads `REGIA_LOG`, then `FERRITE_LOG` (ADR-1421).
- `Ferrite.toml` when there is no `Regia.toml`; `.ferrite/` is used in place when there is no `.regia/`.
- The per-user directory: `<data dir>/Ferrite/<game>` is moved to `<data dir>/RegiaEngine/<game>` once, on the first
  launch of a renamed build. If the move fails, the old directory is used in place with a warning.
- Type paths `ferrite_*::` in levels, prefabs and cooked scenes are retried with the new crate names; a level's
  `LevelSettings` written under the old path are read before the format migrations run. New saves write the new names;
  `regia upgrade-project` does not rewrite the strings.
- Cooked files and paks written before the rename (`.fckd`, `.fpak`, cook caches): the type tag is computed from the
  old crate names, so the bytes are the same as in v0.1.x and everything loads (see Rename compatibility audit).
- Built-in UI theme names `ferrite-dark`, `ferrite-light`, `ferrite-high-contrast` and `ferrite-light-high-contrast`
  map to the `regia-*` themes (warned once), in `.theme.ron` `extends`, agent calls and editor settings.
- Log filters and `logs.read` targets that name an engine crate by its old name (`ferrite_render=debug`,
  `target: "ferrite_agent"`) keep matching.
- Save files, the editor's recent-projects list and telemetry session summaries and alpha logs written before the
  rename.
- The `// FERRITE:SCRIPTS` marker for the editor's "new script".
- MCP resource URIs `ferrite://...` resolve to the same calls (`resources/list` names only `regia://`, ADR-1421).
- `regia upgrade-project --project <dir> --write` renames `Ferrite.toml` and `.ferrite/` in a project and never
  overwrites (without `--write` it lists the renames).

### No fallback

- **Crate names** are compile-time. The smallest change for a game is
  `ferrite = { package = "regia", path = "<engine>/crates/regia" }`, which keeps `use ferrite::...` compiling. The
  derive macros of `regia_ai` and `regia_framework` expand to `::regia_ai::...` / `::regia_framework::...`, so a game
  that uses them depends on those crates under their new names. Feature names that named crates changed with them
  (`dep:regia_agent`, ...); the umbrella crate's own features (`agent`, `ui`, `quick`, `steam`, `crash`,
  `dev-assets`, `static-dxc`, `frame-gen`) are unchanged.
- **Public identifiers that carried the name**: `regia_telemetry::RegiaInfo` (was `FerriteInfo`) and
  `SessionSummary::regia` (was `ferrite`); `regia_framework::REGIA_ABI_HASH`, `replay_sim::{sim_to_regia,
  nav_cm_to_regia}`, `sim_bridge::to_regia_pose`; `regia_render`: `DepthConvention::REGIA`,
  `MotionVectorConvention::REGIA`, `InputConventions::REGIA` and its `motion_scale_from_regia`, `motion_from_regia`,
  `motion_to_regia`, `jitter_from_regia`, `jitter_to_regia`, the vendor upscaler's `REGIA` convention;
  `regia_editor::theme` `regia_default()`; samples: `lookdev::{cooked_runtime, vis_cooked}::regia_cli`,
  `third_person::character::fox_to_regia_rotation`.
- **Build-time variables** read with `option_env!` when a game is compiled: `REGIA_GIT_HASH`, `REGIA_BUILD_VERSION`,
  `REGIA_BUILD_PROFILE` (crash reports and telemetry say `unknown` otherwise) and `REGIA_ABI_HASH` (hot reload).
  `regia package` and the editor set them; a build script of your own must set the new names.
- **Variables read by the engine's tests, samples and `cargo xtask`**: only the new names (`REGIA_DO27_CONTENT`,
  `REGIA_DO27_TPAK`, `REGIA_GPU_INDEX`, `REGIA_SWEEP_REMOTE_ROOT`, `REGIA_SWEEP_REMOTE_CONTENT`, `REGIA_WRITE_EVIDENCE`,
  `REGIA_BLESS`, `REGIA_KEEP_RESIDENT`, `REGIA_TELEMETRY` in the lookdev benches, ...). Gate, farm and sweep scripts
  export the `REGIA_` names.
- **Log text**: log lines that named the engine say `regia` (for example `regia lifecycle: Resumed`), so scripts that
  grep log text need the new text. Filters and targets are not affected (they fall back, above).
- **Telemetry session summaries in new logs**: the engine-build section of `summary.json` is the key `regia` (was
  `ferrite`) and `SessionSummary::regia` is the field name. Summaries written before the rename still read (serde
  alias); external dashboards that read the file directly must look up both keys. New log lines carry the target
  `regia::*`.
- **Built-in UI theme names** are `regia-dark`, `regia-light`, `regia-high-contrast`, `regia-light-high-contrast`
  (theme ids `ui:regia-*`). The old `ferrite-*` names are still accepted and map to the new ones; new files should use
  the new names.
- **Window app ids** are `regia.<exe>` (Wayland `app_id`, X11 `WM_CLASS`; were `ferrite.<exe>`): window-manager rules
  that match `ferrite.` need `^((ferrite|regia)\..*)$`.
- **Agent scratch folders**: default output folders of a few agent methods moved with the name (`<tmp>/regia_loopgen`,
  `<tmp>/regia_audio_mix`, `<tmp>/regia_pt`).

Kept on purpose: the crash upload header `X-Ferrite-Report-Name` (the crash server needs no change), the OpenEXR
header attributes `ferrite.*` that the path tracer and the resource inspector write and read back, host paths
(`<build-dir>`, `<scratch>`, ...), self-hosted runner labels and GitHub repository variables
(`vars.FERRITE_*`), and DO27's own names (`shell-ferrite/`, `assets_ferrite/`, `ferrite_bake/`,
`FERRITE_BAKE_BUNDLE`, `FERRITE_BAKE_HASH`). Agent protocol method names and error codes never carried the name and
did not change. ADR texts, `docs/provenance.md`, `docs/progress.md` and past release notes keep the old name as
history.

### Rename compatibility audit

After the rename was applied, an audit loaded old-named input (files written by the v0.1.29 release itself, and
DO27's content drop, read only) through the converted engine and fixed everything that broke (ADR-1429). Fixed:

- **Cooked files and paks.** Every `.fckd` and pak entry cooked before the rename failed with "type tag mismatch"
  (old cook caches stay current, so they were never re-cooked). `TypePathHash::of` now hashes engine crate names in
  their old spelling, so the tags are the v0.1.x bytes and nothing on disk changes. Old cook-cache and pak manifests
  with `ferrite_asset::...` strings also match again.
- **Level settings.** Levels written before the rename (DO27's maps included) loaded with default level settings:
  atmosphere, look (exposure, LUT, local exposure, baked GI volume) and gravity were ignored, and old-format files
  skipped their migrations. The scene loader reads the settings under their old type path before the migrations run.
  Only that key is renamed; other type paths keep their spelling and resolve written-path-first, so a game crate that
  is itself named `ferrite_*` is never renamed.
- **UI themes.** A `.theme.ron` that `extends` a built-in by its old name, and agent or editor calls naming the old
  built-ins, failed with "unknown theme". They map to the `regia-*` themes.
- **Saves.** A save with a resource whose type path names an engine crate dropped that resource on load.
- **Material graphs** cooked before the rename did not compose (their WGSL imports the old shader module names).
- **Old type paths in tools.** Full paths with the old crate names were rejected by agent scene and state calls, the
  editor's commands, undo and inspector, tween targets and `types.describe`.
- **Log filters and targets.** `ferrite_render=debug` and `logs.read target:"ferrite_agent"` matched nothing; the
  directive is now followed by the same directive for the new name.
- **Projects.** A fresh clone with only `Ferrite.toml` got a new `.regia/` (cook cache, asset database, the agent's
  bearer token) that its `.gitignore` does not cover: it uses `.ferrite/` until `regia upgrade-project --write`, which
  now also adds the new directory to `.gitignore`. A dev run of such a project found no project root unless started
  from its directory. The editor's recent-projects list (`<config>/ferrite/`) was empty after the update.
- **`regia run`**: a `FERRITE_START_LEVEL` left in the shell still applied; `--dev` failed for a launcher that kept its
  dependency name (`ferrite = { package = "regia", ... }`). The shipping feature check missed a renamed engine
  dependency enabling `dev-assets`, `editor` or `agent`.
- **Telemetry and alpha logs.** `cargo xtask alpha-triage` on v0.1.x alpha logs found no telemetry events and no
  engine version, and counted no engine crash frames; session summaries written before the rename lost their engine
  section.
- **DO27 lookdev loader**: `visual/heightfield.json` with the engine section under `"ferrite"` failed.
- **Asset watcher**: `.ferrite-tmp*` atomic-write scratch files were treated as sources (spurious cook errors).

Public API: `regia_core::brand` gains `THEME_PREFIX`, `LEGACY_THEME_PREFIX`, `current_theme_name`,
`current_log_target` and `current_log_filter`; no struct or enum changed shape. No file format changed. Host actions:
export `REGIA_*` for test, sample and xtask variables in gate, farm and sweep scripts (no `FERRITE_` fallback);
Steam Auto-Cloud needs the `RegiaEngine/<exe>/` roots (keep `Ferrite/<exe>/` for one release).

### Formats

No file format, extension, magic or version changed because of the rename: `cargo xtask check-formats` reports no
change on the converted tree, and frozen content (`.fgiv`, `.fpak`, `.tpak`, `.gltc`, `.level.ron`, `.do27replay`,
...) needs no migrator. The `primitive` format fingerprint spells its field types with the old crate names, so its
frozen hash is unchanged. (`.fgiv` v3, `.vfx.ron` v5 and the new `.grass.ron` v1 come from features in this release,
not from the rename; see below.)

### Sweep of the renamed build

The player sweep (2560x1440 headless, profiles high/mid/low x cold/replay/quit, a crash row and three plates per
card) ran on the renamed candidate and failed every row at first: the rename tool had changed two key names that
belong to frozen DO27 content, the `ferrite` block of `visual/heightfield.json` and the
`ferrite_scene::level::LevelSettings` resource key of `level.ron` (ADR-1431). Both spellings load now. After the fix
the RTX 5090, the Intel Arc Pro B65 and the GTX 1080 passed all 27 rows (9 per card) and all plates. The RTX 3080 Ti
was not swept: its host was unreachable for the whole session. New: `scripts/regia-sweep-lane.sh` (the player sweep
with `REGIA_*` names) and `scripts/plate-psnr.py` (plate diffs). No public API changed.

### For DO27

Only when DO27 moves its engine pin to v0.2.0; builds pinned to v0.1.x tags are not affected. In `shell-ferrite/`, on
a branch:

1. Pin the engine to the v0.2.0 commit. Cargo: rename the dependency (the `package = "regia"` line above) or the
   whole shell to `regia` / `regia_*`; fix derive-macro crate names if the build asks for them. Custom Java/Kotlin or
   manifest lines that name the engine's shim classes change to `RegiaActivity` / `com.regiaengine.*`; DO27's app id
   `com.do27.shell` stays.
2. `regia upgrade-project --project <shell project> --write`; commit the renames, add `.regia/` to `.gitignore` and
   keep `.ferrite/` ignored for this release.
3. Scripts: `ferrite` CLI calls become `regia`; build scripts set the `REGIA_` build-time variables; harnesses that
   drive engine tests set `REGIA_DO27_CONTENT`; log filters and log greps use the new names; MCP client configs launch
   `regia mcp`; `.theme.ron` files and agent scripts that name a built-in theme may keep `ferrite-dark` for this
   release (it maps to `regia-dark`) but should move to `regia-dark` / `regia-light`; tools that read telemetry
   `summary.json` look up `regia` (and `ferrite` for older logs).
4. Steamworks: add the `RegiaEngine/` Auto-Cloud root path next to the old `Ferrite/` one while players can still run
   a build from before the rename.
5. Levels and prefabs load unchanged (old type paths are retried; the maps' `LevelSettings` are kept). Cooked files
   and paks written before the rename load too. Rewrite the type-path keys (`ferrite_` → `regia_`, `ferrite::` →
   `regia::`) before the fallback is removed, or re-save from the editor. DO27's `visual/heightfield.json` files with
   the engine section under `"ferrite"` still read in the engine's lookdev loader.
6. Smoke run: the log shows one warning per old name still in use. Clear them during v0.2.x.

### The rename tool

- `cargo xtask rename-brand [--dry-run] [--report] [--root <tree>]` converts a tree (crate directories and package
  names, dependency keys, `use` paths, identifiers, environment variable names, strings, docs, the book, shaders,
  scripts, CI YAML, `Cargo.lock`, the Android shim and ids, generated files). Deterministic and idempotent; binary
  files are moved, never rewritten. `xtask/rename-keep.txt` (compiled in) and `rename-keep` markers list what must not
  change. A branch cut before the rename converts with the same binary (`docs/rename-regia.md` § 4).
- `scripts/rename-regia-verify.sh <src> <scratch>` runs the tool on a scratch copy and then the formatter, format
  hashes, manual, book check, clippy and the core, asset, scene, agent, CLI and framework tests, and lists every
  old-name hit left.
- `regia_core::brand`: every brand name in its current and legacy spelling and the helpers the loaders use
  (`env_var`, `env_var_os`, `project_manifest`, `is_project_root`, `project_state_dir`, `user_app_dir`,
  `current_type_path`, `lookup_type_path`, `fingerprint_type_path`, `warn_legacy_once`, ...). One release later the
  legacy constants and fallbacks are deleted (a new ADR).

## New

### Baked light

- **Baked emitters counted once: `.fgiv` v3** (ADR-1386). The bake names its emitters: the header lists the world
  bounds of every placed emissive mesh the bake traced into the emissive component (`BakedGiVolume::emitters`,
  `regia_asset::baked_gi::BakedEmitter` with `from_points`, `from_object_bounds`, `slack`, `matches`,
  `EMITTER_MATCH_SLACK_M`, `EMITTER_MATCH_SLACK_SHARE`; `regia_pt::probe::baked_emitters`;
  `regia_render::baked_gi::BakedEmitterSet`; `emissive_lights::BAKED_EMITTER_TAG`). `regia bake-gi` writes v3; v1
  and v2 files still load. On Desktop High and Ultra the area lights of baked emitters give way to the bake where it
  covers (their diffuse, and their specular as far as the probes stand in for the rough lobe); emitters the bake did
  not trace keep their area lights everywhere, and over the emissive light budget the tagged lights go last. Agent:
  `render.get_gi_mode` returns `baked.emitters` (`null` for a v1/v2 volume), `render.emissive_lights` returns
  `baked`. `regia bake-gi --check-volume` and `--from-scene --check` report the stale reason `emitters`.
  `cargo xtask gi-compare` records `gi.emitters` and `gi.emissive_lights`.
- **Interior bricks hold surfaces on their faces** (ADR-1364). A point up to an eighth of a cell outside an interior
  brick's probe box reads the interior (`BGI_INTERIOR_EDGE_SLACK`, CPU mirror `sample_static_gi`); the receiver push
  (half a cell along the normal) is unchanged, so outer walls still read the outdoor light. The look-review fixtures
  put each interior brick's lattice on its interior box, the layout `regia bake-gi --from-scene` builds.
- **ZH3 from L1, opt-in** (ADR-1377). The baked volume's L1 SH can be evaluated with a quadratic zonal harmonic along
  the light's luminance direction (after the hallucinated ZH3 of Roughton et al., I3D 2024, with a closed-form curve).
  Directional light through a doorway, from a lit wall or from a sky body keeps its contrast: on a near-point source
  the error against the exact convolution falls from 0.128 (L1) and 0.067 (de-ringed L1) to 0.033. Uniform light is
  unchanged bit for bit. Off by default (`BakedGiSettings::zh3`): against the path tracer on the gi-compare fixtures
  it moved FLIP by −0.0002 to +0.0009, so it waits for a by-eye review. Agent: `render.set_gi_sampling {zh3}`,
  `render.get_gi_mode` reports `baked.lookup.zh3`, `render.sample_baked_gi` takes `zh3` per call. CPU evaluation:
  `regia_render::baked_gi::zh3_irradiance_over_pi`. `cargo xtask gi-compare --reconstruction zh3|l1`. Book:
  `agents/gi-sampling.md`.
- **Bent normals** (ADR-1375, `RenderProfile::bent_normals` / `FrameQuality::bent_normals`). On Desktop High and
  Ultra the SSAO pass (its GTAO rows) also writes each pixel's bent normal (the normal leaned away from the occluders
  its samples saw, at most 60°). The forward pass reads the sky irradiance, the irradiance probes and the baked
  volume along it, so creases and wall bases take less of the light from the occluder's side. Where the baked probes
  already hold an occluder (the probe-relative AO split, ADR-1104) it does not lean the normal. With it, the SSAO's
  share of the specular occlusion is the share of the lobe's cone inside the visibility cone (Jimenez et al. 2016);
  a material's occlusion texture keeps its AO form. Agent: `render.set_bent_normals {enabled}`; guide topic and page
  `bent-normals`; lookdev `LOOK_R2_PROFILE=bent=0`, the chase's `--off bent`.
- **Bake input from the scene** (ADR-310, ADR-311; in the code since v0.1.29, described here). `regia bake-gi
  --from-scene <level>` spawns the level headless and writes `<project>/bake/<stem>.bake.ron`: each
  `GiMobility::Static` entity with a `MeshSource` becomes a mesh entry, the static mesh tagged `terrain` becomes
  `terrain_mesh`, and the sun, sky and sky bodies come from the level's atmosphere. It prints one JSON line
  (`statics`, `skipped`, `triangles`, `bounds`, `hash`, `stale`); a re-export of an unchanged level is byte-identical.
  `--check` exits 0 when the description is current and 2 when it is stale (input hash in
  `<name>.bake.stamp.json`); `--bake`, `--write-level`, `--dry-run`, `--bounds`, `--terrain-spacing`. DO27 bundles:
  `--from-static-meshes <bundle>/static_meshes.json` (with `interiors.json` and `MANIFEST.sha256` when present; the
  manifest hash is verified). Agent: `level.export_bake { path? }` (permission `assets`); `level.get_baked_gi` gains
  `bake_input_stale`, `bake_input_hash`, `bake_input`; error reasons `export_no_level`, `export_path_invalid`,
  `export_mesh_missing`, `export_terrain_ambiguous`, `export_no_input`, `export_read_failed`, `export_write_failed`.
  `regia_scene::bake_query` (`spawn_headless`, `gi_entities`), `regia_agent::bake_export`. Book:
  `agents/baked-gi-export.md`.
- **Baked-light look review kit: `cargo xtask gi-compare`** (ADR-314, ADR-315, ADR-1326, ADR-1364; in the code
  since v0.1.29, extended in v0.2.0). For each view of a views file it renders the baked frame, the same frame with
  DDGI and the `regia_pt` reference at `--spp` (full and indirect only), and writes a contact sheet per view (baked,
  DDGI, reference, FLIP error; a third row with the direct-only frame and `|baked − reference| × 4`), the tiles as PNG,
  linear EXRs, the baked volume and `summary.json` (FLIP, SSIM, relative RMSE, a leak metric, the volume status,
  timings). `--read`, `--baseline`, `--volume`, `--gpu-lock`, `--size WxH`, fly-through strips (`flythrough` keys in
  the views file, `--flythrough-frames n`, error `views_flythrough`) and `--emissive-lights <n>` (a diagnostic override
  of Desktop High's emissive area light budget). Fixtures in `assets/fixtures/gi_compare/`: `cornell`, `leak_room`,
  `rocks_capsule`, `corridor`, `window_room`, `courtyard`, `outpost_standin`. Its last line always says that the plates
  decide. Book: `agents/gi-compare.md`; `docs/06-testing-and-ci.md` § 10.

### Lights, fog and atmosphere

- **Light source size** (ADR-1367). `LightSourceSize { radius_m }`, an optional component next to a `PointLight` or
  `SpotLight`: the PCSS penumbra of its local shadow scales with the radius, and the forward specular is lit from a
  representative point of the sphere with an energy term (Lagarde & de Rousiers 2014 § 4.7.5 with Karis 2013), so
  glossy highlights take the light's size; the diffuse is unchanged. Against the path tracer's sphere light on the
  material grid the forward direct term is within 0.24 %. The default is 0.45 m (the old engine-wide shadow source);
  0 is a true point. Reflect-registered (levels, prefabs, inspector, `scene.add_component`, `editor.set_property`).
  `regia_render::light_source` holds the CPU mirrors; `regia_pt::extract::push_local_lights` turns a frame's local
  lights into path-tracer lights (a sized point light becomes a `PtLight::Sphere`). Book: `agents/light-source-size.md`.
- **Local lights in the froxel fog** (ADR-1365, ADR-1383). A spot light lights only the haze inside its cone, with the
  forward pass's ramp between the half-angles. The fog's four light slots take the four best-scored lights from the
  primary camera (`candela × max(color) × window / max(d², r²)`, a light picked the frame before ranks 1.25× higher so
  the set does not flicker): `regia_render::fog_lights` (`FogLightPick`, `FogLightChoice`, `FogLightCandidate`,
  `pick_fog_lights`, `fog_light_score`, `FOG_LIGHT_SLOTS`, `FOG_PICK_HYSTERESIS`). On Desktop High and Ultra a picked
  spot that casts shadows and has a local shadow tile is shadowed in the haze (one atlas tap per froxel sample), so a
  floodlight through a doorway throws a shaft; four shadowed spots add about 0.005 ms to the fog pass on an RTX 5090
  at 1440p. `FogLight::{point, spot, from_local, cone_factor, gpu_cone}`, `FogCone`, `fog_light_falloff`,
  `FrameRenderer::fog_light_shadowed`. Agent: `render.fog_lights` (slots, scores, `held`, kind, candela, cone,
  `shadowed`). Book: `agents/volumetric-fog.md`.
- **Valley mist** (ADR-1394). `regia_render::ValleyMist` adds a local fog whose density is relative to the terrain:
  it lies on slopes, pools in hollows, thins on open ground and ridges, drifts with a noise field and is lit by the sun
  through the froxel fog (the cascade shadow carves the shafts; a short march toward the sun dims the light a bank
  receives). It is a function of the terrain grid, the position and `time_s` (`ValleyMist::time_for_frame(frame, fps)`),
  so a frame number gives the same mist; the fog draws without history while it is on. `MistHeightGrid`,
  `regia_terrain::mist_grid_from_map`, `MistQuality`, `mist_quality`, `MIST_GRID_MAX_SIDE`, `MIST_MAX_SUN_STEPS`,
  `FrameRenderer::set_valley_mist`, `OutdoorState::set_valley_mist`. Profiles with volumetric fog draw the full mist;
  Low, Deck and Mobile a reduced one unless `reduced_on_low_tiers` is false. Agent: `render.get_valley_mist`,
  `render.set_valley_mist` (guide topic `valley_mist`, book `agents/valley-mist.md`).
- **Cloud genera and the cloud look** (ADR-1408). `regia_render::cloud_types`: `CloudGenus::{FairCumulus, Cumulus,
  Stratocumulus, Cirrus}`, each a full layer (`CloudSettings::with_genus`, `WeatherState::of_genus`, weather presets
  `fair_cumulus`, `cumulus`, `stratocumulus`, `cirrus`; transitions blend two genera). `CloudLook`
  (`CloudSettings::look`): two-stream diffusion inside clouds, erosion, edge breakup and a cirrus sheet (`CirrusSheet`:
  ice streaks along the wind at 9 km with a forward ice phase). Agent: `render.set_clouds` takes `genus`, `diffusion`,
  `erosion`, `breakup`, `breakup_scale_m`, `cirrus_coverage`, `cirrus_altitude_m`, `cirrus_optical_depth`,
  `cirrus_scale_m`, `cirrus_stretch`; `render.get_clouds` reports `look`, `genus`, `genera`; `render.set_weather`
  accepts the genus presets. Book: cloud types, low sun.
- **Haze color** (ADR-1408). `regia_render::AerosolSpectrum { angstrom }`: an Ångström exponent for the Earth Mie haze,
  so a low sun no longer turns the distance sepia (`AEROSOL_WAVELENGTHS_NM`, `CONTINENTAL_ANGSTROM`,
  `angstrom_factors`). Agent: `render.get_aerosol`, `render.set_aerosol` (guide topic `aerosol`).

### Terrain, water and vegetation

- **Water bodies in the runtime frame** (ADR-1399). `regia_terrain::WaterBody` is a level plane (lake, pond, sea) or a
  sloped ribbon along a centerline (stream, river). Add `WaterPlugin`; every body draws through the frame renderer's
  translucent layer, so it shows in the window, `seeing.screenshot` and `render.out`, with or without a `Terrain`.
  Ripples are advected by the flow (two flow-map layers), stretched along fast water and choppier where it is faster
  (a ribbon's speed from Manning's equation when not authored); the bed shows through (absorption along the refracted
  path, in-scatter, screen-space refraction, caustics); the surface reflects what is on screen, then the frame's sky,
  then a fallback sky; the sun glints without aliasing at distance. Wet banks, standing waves and whitewater around
  `WaterObstacle`s, an optional `IceShelf`. Deterministic: animation is a pure function of `WaterClock::tick`. Tiers:
  `low` (Deck, mobile, Desktop Low: blended, no scene copy, no rays), `high`, `ultra`. Agent: `water.state`,
  `water.probe`, `water.set` (book `agents/water.md`, guide topic `water`). `FrameRenderer::{translucent_layers,
  insert_translucent_layer}` let several crates share the translucent seam. Example
  `regia_terrain/examples/water_shots`.
- **Grass field** (ADR-1400, `book/agents/terrain-grass.md`). GPU-generated clumps of tapered blades (no alpha-tested
  cards) over the terrain: dead winter grass with green shoots (`GrassClass::winter_dead`) and summer grass
  (`GrassClass::summer`). Density, greenness, height and tint come from a per-class `GrassMask` baked from the
  terrain's layer weights (painted splat weights included), slope and altitude bands, a density map, noise, holes and
  exclusion paths. Clumps thin with distance at constant clumps per screen area out to 300 m (600 m on Ultra) without
  patch seams or pops, cast sun shadows near the camera and sway with a host-driven deterministic clock.
  `GrassQuality` (Off, Minimal, Low, Medium, High, Ultra) follows the render profile unless the host chooses (mobile
  Minimal, Deck and Desktop Low Low, Cinematic Ultra). New format `.grass.ron` v1 (`docs/formats/grass-ron.md`). Agent:
  `terrain.grass`, `terrain.set_grass`. Bench: `cargo run --release -p regia_terrain --example grass_cost`.
- **Terrain ground look** (ADR-1408). `regia_terrain::TerrainGroundLook` (presets `OFF`, `VARIED`, `LATE_WINTER`):
  world-position variation and a second-scale remix tap against foreground tiling, thin patchy snow on shaded slopes
  and high ground with a wet melting fringe, wet mud, hoarfrost in the shade. `TerrainGpu::set_ground_look`,
  `TerrainSharedDraw::{set_ground_look, ground_look_handle}`, `GroundLookHandle`, `TerrainGroundLookControl`. Agent:
  `terrain.get_ground_look`, `terrain.set_ground_look` (guide topic `ground_look`, book terrain late-winter look).
  Contact darkening for host-placed scatter: `ContactRaster::from_footprints`, `ContactMap::update_footprints`.
- **Terrain splat weight packs** (ADR-1402). `TerrainSharedDraw::set_splat_weights` / `TerrainGpu::set_splat_weights`
  take the cook convention's `macro/pack0.png` and `macro/pack1.png` (`docs/formats/terrain.md` § 9) and paint the
  layers on the photoreal material path: a layer's weight is its pack weight times its slope and altitude band. Before
  this the packs were cooked but never sampled.
- **Forests at scale: streamed scatter on the ECS frame** (ADR-1415). `regia_terrain::RuntimeScatter` holds a
  `ScatterField`; `ScatterRuntimePlugin` streams it around the primary view each frame and appends its draws to
  `ExtractedFrame::meshes` (`extract_runtime_scatter`, `ScatterField::extract_meshes`, `scatter_view_of`), so an ECS
  app draws a whole map's scatter, hundreds of thousands of instances, with no entity per instance; `terrain.scatter`
  reports it. Multi-material scatter meshes (`ScatterMeshAsset::parts`, `ScatterMeshPart`: bark, twig cards and a
  billboard part at the last LOD, cross-faded like any LOD switch) and a shadow LOD (`ScatterMeshAsset::shadow_lod`).
  Book: `agents/scatter-forest.md`.

### Effects

- **Crash effects** (ADR-1398, ADR-1414, `regia_vfx::crash`, book `agents/crash-fx.md`). A crash that scales from a
  vehicle crash to a 1 kt surface blast: `CrashScale` (TNT-equivalent tonnes, 0.05 to 1000) sizes every layer with
  cube-root scaling for lengths, buoyancy scaling for the fireball's timing and the speed of sound for the blast. Each
  layer is generated for a scale and named with it (`crash_fireball@250t`), so crashes of different sizes share a
  scene. Layers: fireball (flash, fire body, soot, heat haze), condensation shell (optional), blast front and lifted
  cover (`crash_dust_<ground>`), base surge, ejecta fountain, mushroom column, first-contact puff
  (`crash_contact_<ground>`), and ground fires (`crash_ground_fire_<small|medium|large>`, sites from
  `crash_fire_sites`). At 250 t, measured with the CPU probe: a fire body about 180 m across at 1.25–1.3 s, the blast
  front at 343 m/s (leading edge within 1.8 %), a base surge about 560 m out at 15 s, a cap at about 1.2 km at 60 s.
  `CrashScale::crater()` and `ejecta_launch()` give a crater and clod arcs for decal, terrain or debris systems.
  `CrashSequence` (driven by `VfxPlugin`; `advance_crash_sequence` without ECS) fires the contact puff before the
  detonation and sends `CrashEvent` messages (`Contact`, `Detonation`, `Crater`, `BlastArrived { distance }` with a
  camera shake that falls with distance). Tiers `CrashTier::Full` and `CrashTier::Lite` (Low, Deck, mobile).
  `crash_ring_slots` gives the particle-pool slots a crash occupies. Agent: `vfx.crash` (`yield_t`, `impact_in`,
  `contact_lead`, layer switches), `vfx.crashes`, `vfx.crash_profile`. `vfx_lab --crash-bench [file] [quick]` and
  `--crash-sheets <dir> [w h]`.
- **CPU kinematic probe** (`regia_vfx::probe`): `probe_effect` and `probe_effect_moving` play an effect's real spawn
  jobs with the GPU kernel's gravity and drag and report each emitter's envelope, front, top, speeds, alpha and luma at
  chosen times, so effects can be measured in meters and seconds without a GPU.
- **`.vfx.ron` v5** (ADR-1398): velocity mode `Planar { speed, lift }` (outward in the instance's plane). v1–v4 files
  load unchanged; `regia upgrade-project --write` re-saves them as v5.
- **Mesh debris** (ADR-1405, `regia_vfx::debris_mesh`, `DebrisPlugin`). A `DebrisSpec` throws earth, stone, turf and
  hardware fragments from a point; launch, landing and rest pose are fixed from the seed and the pose at any time is a
  closed-form function of the frame on `DebrisClock` (parabola with optional drag, friction-limited slide, settle,
  partial burial), so two runs agree and a seek in either direction matches playing through. Per-tier budgets
  (`fragment_budget`, 48 on MobileLow to 4096 on Ultra; hardware kept first). Only molten-flagged fragments glow.
- **Impact sites** (ADR-1405, `regia_vfx::impact_site`, `ImpactSitePlugin`). `ImpactSiteSpec` gives a crater height
  profile, five decals (soot, burn, blanket, floor, a core with a cooling ember) and the buried-hull rest pose;
  `ImpactSites` schedules them with a first-contact dust puff; `DamageSwap` swaps an entity to its battered variant at
  the impact frame and back on a seek. Agent: `vfx.debris_burst`, `vfx.debris_state`, `vfx.debris_clock`,
  `vfx.impact_site` (book `agents/debris-impact.md`).
- **Entry streak** (ADR-1406, `regia_vfx::entry`, `EntryStreak`, `EntryStreakPlugin`). A deterministic
  atmospheric-entry effect along a timed track: a bright head whose glow follows air density times speed cubed, an
  ionized trail, a dust and smoke train that drifts with the wind, shed pieces and a dark body; nothing glows at or
  below 20 km. A `Cheap` tier (Low, Deck, Mobile) drops the pieces and thins the trail. Agent: `vfx.entry_state`
  (read-only; book `agents/entry-streak.md`).

### Offline output

- **Cinematic render profile** (ADR-1403, `RenderProfilePreset::Cinematic`). An offline profile above Desktop Ultra
  for `render.out` stills and sequences: every cloud texel marched every frame at full resolution (no reprojection),
  192 view-march steps and 4 stratified marches per texel averaged in linear light, so cloud edges carry no
  start-jitter dither without a temporal resolve and two runs give identical frames; 8192² sun cascades, 512 lights,
  mesh LOD held toward LOD0, terrain anisotropy 16. Not in `RenderProfilePreset::ALL` (menus and the quality detector
  never pick it); `RenderProfilePreset::WITH_OFFLINE` lists all seven. Tier gate (`cinematic::gate_preset`): Android
  runs Mobile High, a GPU tier below High runs its own preset, unless forced. `CloudMarch` (marches per texel, step
  ceiling up to 256, largest divisor) on `RenderProfile` and `FrameQuality` gives any preset the clean march. Host
  preset choice: `cinematic::take_preset_arg` (`--render-profile NAME`) and `choose_preset` (command line, then
  `REGIA_RENDER_PROFILE`, then the scene directory's `render_profile.txt`, then the host default; errors
  `render_profile_missing_value`, `render_profile_unknown`, `render_profile_unreadable`). Agent: `render.set_profile`
  takes `preset: "Cinematic"`, `cloud_samples`, `cloud_step_percent`, `cloud_reprojection`, `cloud_max_divisor`,
  `force` and returns a `gate` record; `render.get_profile` reports `cloud_march`, `csm_resolution`, `near_sun_tile`,
  `max_visible_lights`, `offline_presets`. Book: `agents/cinematic.md`.
- **Motion blur in render-out** (ADR-1404). `render.out_start` takes `subframes` (1..=64) and `shutter_angle` (more
  than 0 and at most 360 degrees, default 180): each delivered frame is the linear-light average of that many renders
  taken while a virtual shutter is open. The clock steps between subframes, every frame still advances one step, and
  subframe times are whole nanoseconds from the frame number, so a request gives the same hashes. Cost: one render per
  subframe.
- **16-bit frames** (ADR-1404). `bit_depth: 16` renders into a half-float target and writes 16-bit RGBA PNGs (or raw),
  so skies and mist do not band. `regia_render::deep_readout` (`DeepTarget`, `DeepFrame`, `read_deep`,
  `display_image_format`, half-float helpers) and `FrameRenderer::render_offscreen_deep` give any host a 16-bit
  offscreen capture.
- **Raw frames and a writer pool** (ADR-1412). Frame files are encoded and written by a bounded pool of writer threads
  (`writers`, default half the cores up to 8), so the render loop is not held up by deflate. `png_compression`
  `"fast"` (the new default), `"balanced"` or `"best"` changes size and time, never pixels or hashes. `format: "raw"`
  writes uncompressed RGBA8 or little-endian RGBA16 with the layout in the manifest's `raw` block, for an external
  encoder. `render.out_progress` reports `written` and `subframe`. Cancel keeps frames 0 up to the last delivered one;
  a failed write keeps the unbroken run from frame 0. Book: `agents/render-out.md`.

## Changed

- **Baked emitters** (ADR-1386): on Desktop High and Ultra under a baked volume, emitter-lit rooms are darker than in
  v0.1.29 (the double count is gone). Desktop Low, Deck and Mobile are unchanged (no area lights).
- **Bent normals** are on for Desktop High and Ultra (active with their GTAO rows): the indirect light follows the open
  side in creases and contact, and glossy surfaces at a wall's foot lose the sky reflection. Cost on an RTX 5090 at
  2560×1440: Desktop High +0.033 to +0.037 ms, Ultra +0.047 to +0.059 ms. Desktop Low, Medium, Deck, mobile and the
  LAB/EDITOR baselines are unchanged. The SSAO target is a 2-layer rgba8unorm array (+7.4 MB at 1440p half
  resolution); the forward pass's binding 17 is a 2D array, so forward pipeline caches built by an earlier version miss
  once.
- **Terrain probe reflection** (ADR-1377): under the probes with probe specular on (the default), the terrain's sky
  reflection takes the probe light in the GGX lobe's dominant direction instead of the irradiance toward the normal,
  as meshes do since ADR-1103: wet or glossy ground facing a lit wall reflects the wall. `BakedGiSettings::deringing`
  applies only with `zh3` off.
- **Fog local lights**: the fog's local lights are the strongest at the camera, not the first four in extraction
  order. Their falloff matches the forward pass (`saturate(1 − (d / r)⁴)² / (d² + 1)`): a lamp at the eye no longer
  floods the nearest slices; beyond about 3 m haze is within 10 % of before.
- **Reference traces from the scene export** include the frame's point and spot lights (`FrameExport::local_lights`,
  `regia_pt::extract::from_export`), as the extracted-frame path already did. Export-based traces of scenes with local
  lights change.
- **Default PNG frames in render-out use fast deflate**: larger files, written several times faster; pixels and hashes
  are identical.
- **Skinned draws** that join the batches no longer get a per-object uniform buffer.
- **GPU resource labels**: bloom targets are `bloom down N` / `bloom up N`, terrain VT atlas pages
  `terrain vt atlas N`. With the agent plugin, targets that lacked `COPY_SRC` (SSAO, the outdoor passes) have it.
- **Cloud pass**: the view-march loop bound is 256 (was 96; real-time presets still stop at 96). The pass also runs for a
  cirrus sheet with no volumetric coverage. `CloudGpu` is 576 bytes (per-texel staleness, look, cirrus rows) and
  `FogGpu` 1264 bytes; the fog bind group has binding 7 (local shadow atlas) and binding 8 (mist grid). The terrain
  material uniform is 224 bytes; the terrain data bind group has entry 23 (splat packs). Zero rows mean the old
  behavior. Shader forks: `volumetric_fog.wgsl`'s `local_shadow_map` is `@binding(7)`; the terrain `engine_gi` stub
  takes a perceptual roughness and returns `EngineGi` (`diffuse`, `spec`, `has_spec`); `lab_shadow.wgsl` has an
  `ALPHA_TEST` variant and starts with `enable wgpu_binding_array`.
- **Interior-brick fixtures**: the look-review fixtures' interior lattices sit on their rooms' air boxes, so their
  gi-compare numbers change. The contact sheet has a third row; tools that cropped tiles by position should read the
  tile PNGs.
- **`regia doctor --platform all`** runs every section; the text report groups checks by section with the fix under
  each problem. **`regia package`** ships the engine's `THIRD_PARTY_NOTICES.md` even when the game's workspace has
  none, and warns that the game's own dependencies must be added.
- **`cargo xtask preflight --changed`** also selects a crate when a file it includes from outside its directory
  changes. `ci.yml` no longer skips `docs/**` (only evidence, releases, progress and the READMEs) and runs the gate's
  conflict-marker refusal, `book-check --fences`, `book-check` and `check-shaders`.
- **`deny.toml` checks every feature** (`[graph] all-features = true`), so `regia_crash/tls`, `regia_steam/steamworks`
  and `regia_pt/denoise` get the advisory, licence, ban and source checks; `webpki-roots` may be CDLA-Permissive-2.0
  (crate-scoped exception, waiting for the owner). `regia upgrade-project` reads every format's version from its crate.
- **Showcase sample**: the GPU-driven path is the default (the ordered cull keeps it repeatable; `--cpu-draw` selects
  the CPU path); the photo-texture relief preset is the sample's default; density maps are looked up beside the
  `.scatter.ron` first.

## Upgrade: host changes since v0.1.29

This section was derived from the code, not from the lane notes: v0.1.29 was converted with the same rename-tool
binary (plus `cargo fmt`) and compared with this release, so the rename does not hide or inflate anything. Every
`pub` struct and enum reachable by hosts (public module path or crate-root re-export) was compared field by field and
variant by variant, every `pub fn` signature, the agent method table and error codes, the Cargo manifests and the
format registry. Crate-internal types are not listed. The rename itself is in **Regia Engine: the rename** above.

### Struct literals that stop compiling

A literal needs the new field, or `..Default::default()` where the type has `Default` (marked **D**). Types with
private fields are not listed.

### Baked light

- A baked emitter moved after the bake by more than the match slack (2 cm + 2 % of its size) is counted at both places
  until the map is rebaked (`--check` reports `scene`). Changing a baked emitter's color or intensity at runtime does
  not change the bake (`emissive_scale` rescales all baked emitters together): rebake after emitter changes.
- A bright sun patch on a floor darkens the baked indirect light on the floor around it (window room, corridor), and
  leak_room `inside_back` has bright blobs at the wall foot. Not on the emitter path; the L1 lookup is the suspect and
  ZH3 (off by default) is the test.
- ZH3 still dips about 4 % of the peak below zero before the clamp on a single point source.
- Bent normals have the AO's resolution (half resolution on Desktop High and under a baked volume); the terrain keeps
  its own sky and probe lookups. Cost not measured on AMD, Intel, the Deck or Android (off on the last two).
- Bake from the scene: the terrain is a static mesh tagged `terrain` (scene v10 has no terrain link); a
  `MeshSource.material` file is hashed but not baked; unloaded prefab templates are not expanded; the sky is one
  uniform radiance; `--write-level` rewrites the level in canonical form (comments lost, saved at the current version);
  the agent's export loads no meshes (`triangles` and `bounds` are `null`).
- gi-compare: `--scene` refuses a level (`scene_level_unsupported`); the leak threshold (0.25) and the FLIP tolerance
  (0.01) are first guesses.

### Lights, fog and atmosphere

- Spot lights with a source size are traced as delta spots by `regia_pt`; the terrain's shared local-light pass keeps
  punctual specular. On a resolvable highlight the forward specular is still about 22 % from the traced sphere (41 %
  for a point light). A local shadow's penumbra stops growing at the 10-texel filter cap.
- Point lights stay unshadowed in the fog, as does a spot without a shadow tile. The fog's spot shadow is one
  unfiltered tap per sample (a shadow edge across a froxel shows the grid). Only four local lights reach the fog.
- Mist banks are as smooth as the 40×24×16 froxel grid; the path tracer does not trace the mist.
- The CPU cloud-shadow column does not model the breakup noise. Without a temporal resolve the march's start jitter is
  visible on cloud edges except under Cinematic or a multi-sample `CloudMarch`.

### Terrain, water and vegetation

- Water is not drawn when the camera is below its surface; height fog and aerial perspective do not apply to the
  water's own reflection and glint; effects particles draw over water also where they are below it; screen-space
  reflections fall back to the sky off screen; no FFT ocean and no shoreline foam on planes. A host that calls
  `FrameRenderer::set_translucent_layers` after `WaterPlugin` installed its layer drops it for one frame.
- Grass sway is not cast into the sun cascades (the rest pose is); grass is not drawn into the decal receiver and does
  not bend under characters or vehicles; the grass tier is inferred from the terrain anisotropy level until
  `FrameQuality` carries a grass lever.
- Alpha-tested shadows cover the GPU-driven instanced shadow path only (the CPU draw path, visibility-buffer shadows
  and the warm worker's frames still cast card outlines). Trees do not sway: Tincal's `tincal.wind/1` attributes are
  not read. In ordered-cull mode a batch's indirect count is its highest visible slot plus one.
- Without the ordered cull, the GPU-driven path is not bit-repeatable with temporal AA.
- Cook layout: `macro_albedo.png` and `macro/{normal,ao}.png` are not used yet; `heightfield.json` `origin` is not read.

### Effects and output

- Heat-haze cards draw from the unsorted additive list, so many overlapping haze cards are not byte-stable between runs;
  the crash keeps 3 haze cards. The mobile profile draws alpha unsorted (frames not byte-identical between runs).
- Fire lights do not flicker; the condensation shell spawns on a full sphere; the offscreen harness ground is a 240 m
  patch, so evidence frames draw the large layers over the sky beyond it. `Radial` velocity mirrors one axis of the spawn
  offset (kept for the v4 looks).
- Debris has no fragment-fragment or fragment-terrain collision (fragments land on a height function); crater volume
  is not conserved; a seek back retires decals but does not undo a host's terrain edit.
- The entry streak's head brightness (`peak_radiance`) is a host knob with no calibration against the sun's disc; its
  cost at 1440p and 4K is not measured.
- Cinematic is for offline output: on an RTX 5090 a 4K Cinematic frame of the lab bench scene takes 51.8 ms of GPU
  time (Ultra 1.98 ms), almost all in the cloud pass; the near sun tile stays at 4096; Cinematic is not in the editor
  viewport menu or the generated render-profile reference table.
- 16-bit frames: no HUD, PNG or raw only, neutral calibration only; on SMAA tiers the frame has 8-bit precision. With
  subframes, systems that move things only in `FixedUpdate` without interpolation blur only when the fixed rate is
  above the frame rate. The `ffmpeg` pipe formats still run on the render thread.

### Renderer controls and platforms

- Skinned instancing's CPU saving was measured only on the `do27_chase` A/B; DO27's real crowds are not measured. On an
  RTX 5090 a test binary that runs a compute-skinning test in parallel with others can end in a SIGSEGV (pre-existing;
  serial runs pass).
- The resource inspector lists textures only (no buffers); a released target stays listed until its label is created
  again.
- Nothing selects ETC2 for a whole project cook yet. The ETC2 encoder searches the individual and differential modes
  only. Its output was checked against an independent CPU decoder, not yet on a phone GPU (`tests/etc2_gpu_decode.rs`
  skips on lavapipe and desktop NVIDIA).
- The `player-sweep` CI job needs a registered self-hosted GPU runner.
