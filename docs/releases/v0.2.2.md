# Regia Engine v0.2.2

Builds on v0.2.1. This release adds these feature sets for game teams:

- **Post volumes and the physical camera**: boxes, spheres or unbound regions that change the look (exposure,
  tonemap, color grading, vignette, grain, ambient occlusion, fog tint, eye adaptation) for every camera inside
  them, with priorities and soft edges; and a camera that can expose from ISO, shutter time and aperture.
- **Montages, sync groups and motion warping**: one-shot action timelines with sections, events and branching
  points played over the animation graph; walk and run cycles that stay in step across graph nodes; and root motion
  bent so an attack or a vault lands on its target.
- **Motion matching**: a feature database built from animation clips, an exact k-d tree search and a runtime matcher
  that picks the frame that best continues the pose along a desired path.
- **IK retargeting**: the joint names an animation graph and its editor sidecar refer to (IK chains, look-at joints,
  layer masks, sockets) move between skeletons through the retargeter's role map.
- **Smart objects**: interaction slots on world entities (stand, sit, operate, take cover) that AI agents can
  discover, claim and release.
- **Sequencer data model**: a `.seq.ron` timeline of named tracks and markers on one master clock, sampled
  deterministically (data only; no player yet).
- **Per-vertex ambient occlusion**: an opt-in material flag that turns the vertex color alpha of an opaque material
  into a smooth factor on its indirect light.
- **Content data**: a localization workflow (gather, validate, pseudo locale, fallback chains, a CLDR plural
  table), asset registry queries that find assets by tag, type, path or dependency without loading them, and typed
  data tables in RON or CSV.
- **Physics**: an XPBD cloth and rope solver, approximate convex decomposition of triangle meshes into compound
  colliders, and ray-cast vehicles. NaN and infinite inputs no longer reach the rigid-body simulation.
- **Navigation**: a navmesh tile cache with runtime obstacles, and crowd steering with avoidance.
- **Tools**: a lightmap UV atlas generator (`regia atlas`, `editor.atlas_generate`), CPU reference implementations
  for LUTs and three post effects, and a crate packaging check.
- **Windows**: the workspace builds and passes its lint and test pass on Windows 11 (MSVC) again.

All new features are off, or unchanged for projects that do not use them, except where **Changed** says otherwise
(Arabic plural text, the locale fallback chain, `/`-separated editor paths on Windows, the moved project templates).

The text below consolidates the `v0.1.28-*` release fragments of the lanes merged after v0.2.1 and the integration
notes (ADR-1469, ADR-1496, ADR-1515). The lanes: `post-volumes-camera`, `montages-warping`, `localization-registry`,
`windows-build-fix`, `crate-self-contained`, `perf-remaining`, `zai-fixup`, `detour-tile-cache`, `gpu-supervisor`,
`cloth`, `convex-decomp`, `motion-matching`, `vehicle-wrap`, `xatlas-port`, `c-task-verify`, `windows-loop`,
`windows-rerun` and `lab-vertex-ao`.

Read **Upgrade: host changes since v0.2.1** first if you build a game or a shell against the engine crates.

## New

### Rendering: post volumes and the physical camera (ADR-1464)

Spec: `docs/specs/30-post-volumes-and-physical-camera.md`.

- **Post volumes** (`regia_render::post_volumes`). A `PostVolume` component (box, sphere or unbound; priority, blend
  distance, weight, enabled) overrides any of 21 optional post settings for every camera whose eye it reaches:
  exposure compensation, the auto-exposure band and meter center weight, tonemap, contrast, saturation, bloom
  intensity, white balance, tint, lift/gamma/gain, vignette, film grain, local exposure, ambient-occlusion strength,
  a fog tint, and an eye-adaptation range.
  - Volumes blend in priority tiers. Equal priorities are weight-averaged, so the result does not depend on spawn
    order. White balance blends in mired, and the tonemap switches at half weight.
  - Each camera (split-screen and render-to-texture too) blends at its own position.
  - Saved in level and prefab files (`post-volume` format v1, `docs/formats/post-volume-v1.md`) and editable in the
    inspector.
- **Volumes drive the exposure-zone eye.** A volume's `eye` range joins the exposure zones (ADR-322) with the
  volume's weight and priority; `ExposureZoneState::volume_count` reports how many did.
- **Physical camera exposure.** `PhysicalCamera::exposure` selects `Inherit` (unchanged behavior),
  `Manual { ev100 }` or `Physical`: EV100 from the lens's ISO, shutter time and aperture
  (`log2(N²/t) − log2(ISO/100)`).
  - In physical mode the shutter time also sets the motion blur (`shutter_seconds × shutter_reference_fps`), and the
    aperture is shared with the depth of field.
  - An optional `focal_length` sets the view's field of view from the sensor height
    (`vertical_fov_from_focal_length`).
- **Agent methods:** `render.post_volumes`, `render.set_post_volume`, `render.get_physical_camera`,
  `render.set_physical_camera` (guide topic `post-volumes`), with the error reasons listed in
  `book/agents/post-volumes.md`.
- Book: `book/agents/post-volumes.md`, `book/user-guide/post-volumes.md`.

### Animation: montages, sync groups, motion warping (ADR-1465)

Spec: `docs/specs/17-animation.md` § 4b.

- **Montages** (`regia_animation::montage`, `.montage.ron` v1). One-shot action timelines:
  - clip segments per slot track (start, end, rate, loops);
  - named sections linked with `Continue`, `Stop` or `Jump` (a self-jump loops);
  - timeline notifies (instant), windows (begin/end) and branching points;
  - blend in/out with an optional lead, automatic or held ends;
  - a root-motion switch, root-motion-off windows and motion-warping windows;
  - an optional `sync_group` the montage leads while it blends out.
- **Montage player** (`MontagePlayer` component on the rig). Plays montages over the animation graph through
  rig-side slots (`SlotDef { name, group, mask }`).
  - Calls: `play`, `play_named`, `queue`, `stop`, `jump_to_section`, `set_next_section`, `on_branch` (an action
    applied at a branching point's exact time), `set_rate`, `set_warp_target`, `instances`, `history`.
  - A montage in the same slot group interrupts the playing one.
  - `MontageEvent` messages report `Started`, `Section`, `Notify`, `WindowBegin`, `WindowEnd`, `BranchPoint`,
    `BlendingOut { interrupted }` and `Ended { interrupted }`. Segment clip notifies still arrive as `AnimNotify`.
- **Sync groups across graph nodes** (`regia_animation::sync`, `.sync.ron` v1). `Animator::set_sync_setup` declares
  groups (roles `MayLead`, `AlwaysLead`, `NeverLead`) and sync markers per clip.
  - `Clip` nodes naming a declared group follow the leader's clock by shared markers or normalized phase, and
    followers fire no notifies.
  - A synced blend space in a declared group joins it as one member (normalized phase).
  - `EvalContext::with_sync` / `take_sync_state` serve code that evaluates graphs itself.
- **Motion warping** (`regia_animation::warp`). Inside a warp window the frame's root motion is turned and scaled so
  the rig lands on a `WarpTarget` (optionally turning to its facing); a moving target is tracked.
- **Agent methods:** `anim.montage_state`, `anim.montage_play`, `anim.montage_stop`, `anim.montage_jump`,
  `anim.montage_set_warp_target`, `anim.sync_state` (guide topic `montages`, `book/agents/montages.md`; stable
  `data.error_code` values).
- **Sample:** `samples/anim_lab` has a Fox "pounce" case: a full-body montage with a branching point, a claw window,
  two sections and a warp window to a target 2.5 m off-axis. It prints `pounce_miss=` and fails above 5 cm.
- Book: `book/user-guide/montages.md`, `book/agents/montages.md`; formats `docs/formats/montage-ron.md`,
  `docs/formats/sync-ron.md`.

### Content data: localization, asset registry, data tables (ADR-1466)

Spec: `docs/specs/content-data.md`.

- **Localization workflow.**
  - Keys in content (`Loc("key")` in `.ui.ron`, `"loc:key"` in any `.ron`) and in code
    (`regia_ui::loc!("key", name = value)`, a `LocText`).
  - `regia loc gather` appends the keys a locale lacks to its `gathered.ftl`, never rewriting existing messages.
  - `regia loc validate [--strict]` reports `loc_*` findings with file and line: missing along the fallback chain,
    untranslated, unused, extra, variable mismatch, missing or unreachable plural categories, duplicates, parse
    errors.
  - `regia loc pseudo` writes an `en-XA` pseudo locale; `regia loc plural <locale> <n>...` prints CLDR categories.
  - Optional `assets/localization/localization.ron` (v1: `source`, `locales`, `fallbacks`, `gather`).
- **Fallback chain** `fr-CA` → `fr` → source, with extra edges from `localization.ron` (`Localization::chain`,
  `fallback_chain`, `set_fallbacks`, `provider_of`, `nearest_loaded`).
- **`LocaleChanged { from, to, generation }`** message the frame after a locale switch (`LocalizationPlugin`, added
  by `UiPlugin`).
- **Pseudo mode at runtime:** `Localization::set_pseudo(true)` (accents, about 40 % padding, brackets; placeables
  keep their values).
- **CLDR plural table** `regia_ui::plural` (en, fr, de, es, it, pt, nl, sv, ru, uk, pl, cs, ar, he, ja, zh, ko, tr
  and languages sharing their rules), used by the runtime, the validator and agents.
- **Localization agent methods:** `localization.status`, `localization.set_locale`, `localization.resolve`,
  `localization.set_pseudo`, `localization.validate`, `localization.plural` (guide topic `localization`, book
  `agents/localization.md`); error codes `loc_not_loaded`, `bad_locale`, `loc_unknown_locale`, `bad_args`,
  `bad_flag`, `loc_unknown_plural_locale`, `bad_number`.
- **Data tables** (`regia_asset::data_table`): typed rows by key from any
  `#[derive(Reflect, Serialize, Deserialize)]` struct, in `.table.ron` (v1; a v0 bare list migrates on load) or
  RFC 4180 `.table.csv`.
  - `DataTable<R>::get`, validation (`table_*` issue codes, game row rules), RON/CSV import and export.
  - `DataTables` resource and `DataTableAppExt::register_data_table::<R>(path)`, with hot reload in dev builds (a bad
    file keeps the old rows). Untyped `RawTable` for tools.
  - Agent methods `tables.list`, `tables.describe`, `tables.get`, `tables.set`, `tables.validate`, `tables.export`
    (guide topic `data_tables`, book `agents/data-tables.md`); CLI `regia table validate|to-csv|to-ron`. Format page
    `docs/formats/data-table-ron.md`.
- **Asset registry** (`regia_asset::registry`, `regia_asset_pipeline::registry_build`).
  - Every cook writes `asset_registry.bin` (magic `RGASREG\0`, v1) with each cooked asset's id, path, type, tags,
    cooked size and dependencies (read from the cooked headers only).
  - Packing writes `<pak stem>.registry.bin` beside each pak, and packaging ships it.
  - Tags: automatic `ext` and `folder`, plus glob rules in `config/asset_tags.ron` (v1).
  - Queries by path glob, substring, type, tags, dependencies and referencers (transitive, cycle-safe), without
    loading any asset. The live cook updates the registry per source.
  - `LoadedAssetRegistry` resource; agent methods `registry.query`, `registry.describe`, `registry.dependencies`,
    `registry.referencers`, `registry.tags` (guide topic `asset_registry`, book `agents/asset-registry.md`; codes
    `registry_not_loaded`, `registry_unreadable`, `registry_bad_query`, `registry_bad_tag`,
    `registry_unknown_asset`); CLI `regia assets query|tags`.
- **CSV** (`regia_asset::csv`): an RFC 4180 reader and writer (also LF / lone CR line ends, BOM, missing final line
  break), with line numbers in errors.

### Animation: motion matching (ADR-1478)

- **Motion matching** (`regia_animation::motion_matching`, `book/user-guide/motion-matching.md`).
  - `MotionDatabase::build(skeleton, clips, FeatureSchema)` cuts every clip frame into a feature vector: root
    velocity, future trajectory positions and facings, foot positions and velocities, all in the character frame.
  - Features are normalized per group with user weights (`FeatureWeights`).
  - `MotionDatabase::search` uses a linear scan (`SearchMethod::BruteForce`) or an exact k-d tree
    (`SearchMethod::KdTree`, also public as `KdTree`). Both always return the same frame.
  - `MotionMatcher` advances the playing clip. It searches every `search_interval`, and its `transition_cost`,
    `exclude_window` and `min_jump_interval` keep playback from flickering between similar frames.
  - The `MotionMatching` component and the `step_motion_matching` system run it on an entity. The host adds the
    system and plays the matched clip; `AnimationPlugin` does not register it.
- **Agent method `anim.motion_match`** (read-only, guide topic `motion_matching`, `book/agents/motion-matching.md`).
  It returns one entity's database, settings, playback, search and jump counts and latest search. With `speed` or
  `trajectory` it also runs a probe search that changes nothing. Errors: `F0003`, and `F0002` with `[bad_probe]`,
  `[bad_speed]` or `[bad_trajectory]`.
- **Hand-run timing** `perf_micro_motion_matching_search` (`regia_animation`, `#[ignore]`): database build time and
  the per-query search cost of both methods on 12,000 frames (the build server, release: k-d tree p50 24.5 µs, linear scan
  p50 169 µs).

### Animation: IK retargeting (ADR-1507)

- **IK retargeting** (`regia_animation::ik_retarget`). Moves the joint-name references of an animation graph and its
  `.animedit.ron` sidecar (IK chains, look-at joints, layer masks, sockets) between skeletons through the retargeter's
  role map. Unmapped chains and sockets are dropped.
- `Retargeter` gains `target_of`, `retarget_joint_name`, `retarget_joint`, `retarget_chain`, `retarget_mask`,
  `source` and `target`.
- CPU functions over existing data with no runtime path of their own, so there is no agent method.

### AI: smart objects (ADR-1507)

Spec: `docs/specs/31-smart-objects.md`.

- **Smart objects** (`regia_ai::smart_object`). A `SmartObject` component (tags, enabled) on a world entity, and
  `SmartObjectSlot { role, enabled }` on its child entities, placed and rotated in the editor (a slot faces its local
  -Z axis).
  - `SmartObjectIndex` (rebuilt per frame by `SmartObjectPlugin`), `claim_slot` and `release_slot`. A slot is available
    when it and its object are enabled and nobody holds it.
  - A `SmartObjectGizmos` debug group in `regia_render` draws objects and slots.
- **Agent methods** `smartobject.list`, `smartobject.claim` and `smartobject.release` (guide topic `smart-objects`,
  `book/agents/smart-objects.md`). A slot held by another agent, or a disabled one, answers `claimed: false` with the
  holder and a reason; a missing slot answers `F0003`.

### Framework: sequencer data model (ADR-1507)

- **Sequencer data model** (`regia_framework::sequencer`, `.seq.ron` v1, format `sequence`,
  `docs/formats/seq-ron.md`). One master clock of named tracks (float, vec3 or bool channels) and markers, sampled
  deterministically. Data and sampling only: no player and no agent surface yet.

### Rendering: per-vertex ambient occlusion (ADR-1512)

- **`LabMaterial::vertex_ao`** (default off). On an opaque, lit, non-hair, non-transmissive material (graph
  materials included), `LabVertex::color[3]` becomes a 0..1 linear occlusion factor (clamped; a non-finite value
  counts as 1) instead of an opacity. It scales only the indirect light: sky, irradiance probes, baked GI and the reflections that read them. The
  sun, local lights, emissive light, the material occlusion texture and SSAO are untouched. With the flag off the
  frame is bit-identical to before.
  - Content can bake a continuous sky-visibility falloff into the vertices (for example a tunnel portal) instead of
    splitting a mesh into stepped occlusion variants.
- `regia_render::vertex_ao`: the CPU reference (`factor`, `scale_indirect`, `is_active`, `write_vertex_ao`,
  `alpha_range`).
- glTF importer setting `vertex_ao` in the `.meta` (clamps `COLOR_0` alpha to 0..1).
- **Agent methods** `material.vertex_ao` (read) and `material.set_vertex_ao` (`EditScene`), guide topic and page
  `vertex-ao` (`book/agents/vertex-ao.md`). The entity gets its own copy of the material.

### Physics: cloth, convex decomposition, vehicles (ADR-1476, ADR-1477, ADR-1479)

- **Cloth and ropes** (`regia_physics::cloth`, ADR-1476). A deterministic CPU solver using extended position-based
  dynamics: particles with inverse mass (0 pins), distance and dihedral bending constraints with compliance, a fixed
  step split into substeps, and collision with spheres, capsules and infinite planes with Coulomb friction. No
  self-collision.
  - `ClothSolver::new(config)`, `add_particle`, `add_distance`, `add_bend`, `pin`, `set_position`, `set_velocity`,
    `add_collider` / `set_collider`, `step(dt)`, `particles()`, `stats()`, `state_digest()`, and the builders
    `add_grid(&ClothGrid)` and `add_rope(&ClothRope)`.
  - Invalid input (NaN, infinity, negative values, bad indices, degenerate shapes) is a typed `ClothError` and
    changes nothing.
  - `ClothPlugin` and `ClothSet`: named solvers in a resource, stepped once per `FixedUpdate` after the rigid-body
    step.
  - Agent method `physics.cloth_stats` (read-only extension method): counts, steps, dropped steps, contacts, max
    stretch, bounds and a digest per solver. A host registers it with
    `regia_agent::cloth::install_cloth_methods(world)`. Book: `user-guide/cloth.md`, `agents/cloth.md`.
- **Approximate convex decomposition** (`regia_physics::convex_decomposition`, ADR-1477).
  `decompose(&TriMesh, &DecompositionParams)` splits a triangle mesh into at most `max_hulls` convex hulls
  (voxelize, cut by the axis-aligned plane that minimizes concavity, hull each part from the clipped mesh, merge to
  the limit), for dynamic bodies that need a concave collider. `compound_shape` turns the hulls into a
  `ColliderShape::Compound`. Deterministic; hulls are capped at `max_hull_vertices` (default 64).
  - Agent method `physics.convex_decompose` (read-only, heavy): the hulls of an entity's `TriMesh` collider with
    counts, volumes and centroids (and points on request). Guide topic `convex-decomposition`, page
    `book/agents/convex-decomposition.md`.
- **Ray-cast vehicles** (`regia_physics::vehicle`, ADR-1479). A safe wrapper over rapier's ray-cast vehicle
  controller.
  - `VehicleConfig` and `WheelConfig`: position, radius, suspension rest length, travel, stiffness and damping,
    friction slip, steer/drive/brake flags. `VehicleConfig::default()` is a 1,200 kg four-wheel car.
  - `Vehicle::spawn` / `Vehicle::attach`, `Vehicle::update` with `VehicleInput` (throttle, brake, steer; +1 steers
    right), `wheel_states` and `state` for rendering and gameplay (chassis-space and world-space wheel poses, steer
    and spin angles, grounded, compression, contact, ground entity), `reset` / `reset_to_spawn`.
  - `VehicleError` with stable codes. Nothing panics on a removed chassis or a bad time step.
  - ECS: `VehiclePlugin`, `VehicleController`, `VehicleInput` (reflected component) and `spawn_vehicle`. The plugin
    updates vehicles in the fixed-step physics chain, after the velocity sync and before the step.
  - Agent methods `physics.vehicles` (read), `physics.vehicle_input` and `physics.vehicle_reset` (`play`
    permission), guide topic `vehicles`. Book: `user-guide/vehicles.md`, `agents/vehicles.md`; spec
    `docs/specs/15-physics.md` § 7.

### Navigation: tile cache and crowds (ADR-1484)

- **Navmesh tile cache** (`regia_nav::NavTileCache`). Builds the navmesh in square tiles of a configurable size
  (`NavTileCacheParams::tile_size`, in cells).
  - Cylinder and box obstacles (`NavObstacleShape`) are added and removed at runtime. `update()` rebuilds only the
    tiles an obstacle touches (`update_limited(n)` spreads the rebuilds over calls), and `NavTileUpdate::rebuilt`
    lists them.
  - `query()` plans on the current mesh; `revision()` increments when polygon indices change. Errors are typed
    (`NavTileCacheError`, with `code()`).
- **Crowd steering** (`regia_nav::NavCrowd`, `NavCrowdPlugin`). Agents with radius, height, max speed and max
  acceleration follow navmesh corridors (visibility shortcuts, turn anticipation, slow-down at the goal), keep apart
  (separation, velocity-sampling avoidance of neighbors and walls, collision resolution) and stay on the mesh.
  - The update is a deterministic fixed step: two identical runs are bit-identical (`digest()`).
  - `NavCrowdPlugin` steps the crowd in `FixedUpdate` (set `NavCrowdStep`) and rebuilds queued tiles first. Errors
    are typed (`NavCrowdError`).
- **Agent methods** `nav.tile_cache_status`, `nav.tile_cache_add_obstacle`, `nav.tile_cache_remove_obstacle`,
  `nav.crowd_status`, `nav.crowd_add_agent`, `nav.crowd_set_target`, `nav.crowd_step`, with lowercase `data.reason`
  codes; guide topic `navigation-crowds`, page `book/agents/navigation-crowds.md`.
- Ported from Recast & Detour (zlib, Copyright (c) 2009-2010 Mikko Mononen); the notice is in
  `THIRD_PARTY_NOTICES.md`.

### Tools and pipeline (ADR-1482, ADR-1483, ADR-1485)

- **Lightmap UV atlas generator** (`regia_asset_pipeline::atlas`, ADR-1483, `book/agents/atlas.md`). A Rust port of
  the MIT-licensed xatlas generator:
  - chart segmentation (normal deviation, roundness, straightness, normal and texture seam costs);
  - orthogonal or least squares conformal flattening, with a piecewise fallback;
  - bitmap packing with padding, a bilinear footprint, optional 90° turns and an automatic density search.

  The output is UV2 in `[0, 1]` per output vertex with `xref` to the source vertex, one output triangle per source
  face, and the charts. The result is the same for any thread count. Pipeline and editor side only.
  - `editor.atlas_generate` agent method (editor extension): unwraps a built-in shape or an inline mesh and reports
    charts, density, utilization and typed warnings; `include_uvs` returns the buffers. Codes are listed on the
    book page.
  - `regia atlas <mesh.obj>`: the same generator from the command line. It prints the report (`--json` for tools),
    and `--out` writes the unwrapped mesh as `.obj` with the atlas coordinates as `vt`, for inspection in any 3D
    tool.
  - Measured on the build server (release build): a 100k-triangle mesh unwraps and packs at 2048 in 0.85 s; a 48×24 sphere
    packs at 64 % utilization at 1024.
- **CPU references for post effects** (ADR-1482). `regia_asset::lut_cube`: a `.cube` LUT parser (`parse`,
  `CubeLut`, `CubeLutError`) and CPU sampler (trilinear, tetrahedral, 1D).
  `regia_render::post_ref::{radial_blur, glow_longtail, lens_flare}`: deterministic CPU reference implementations
  that later GPU passes are checked against. Book page `agents/post-reference.md`; no agent-protocol surface until a
  GPU pass uses them.
- **`cargo xtask check-packaging`** (ADR-1485): fails when a crate's compiled code reads a file outside its own
  folder (`include_str!`, `include_bytes!`, `include!`, `#[path]`, or `CARGO_MANIFEST_DIR` joined with `..`). It is
  a `cargo xtask preflight` step and runs in CI. Test code is exempt.
- **`regia_templates` crate**: the `regia new` / editor project templates live in
  `crates/regia_templates/templates/` and are compiled in from there.
- **Benchmark scripts** `scripts/bench/perf-remaining/` (ADR-1491): `sweep.sh` (census per variant on one card,
  rounds interleaved and rotated, optional chase `--off` toggles), `summarize.py` (per-pass medians with min-max) and
  `bstep.sh` (incremental release build of one commit into a bin directory).
- **GPU job supervisor** `tools/gpusup/` (ADR-1481, `docs/06-testing-and-ci.md` § 12): tooling for the test farm. It
  builds the newest candidate head and keeps up to three GPU jobs running (the real-GPU test pass, the player sweep,
  look-round renders, a per-pass perf A/B and hitch soaks, plus queued one-off jobs).

## Changed

- **Post settings.** `PostSettings` has `ao_intensity` (scales the SSAO strength) and `fog_tint` (multiplies the
  view's fog color). Their defaults (1 and `[1, 1, 1]`) leave every frame byte-identical. The SSAO pass multiplies its
  strength by the view's `ao_intensity` (`SsaoPass::set_intensity_scale`).
- `TonemapOperator` derives `Reflect` (pinned type path `regia_render::post::TonemapOperator`).
- **Animation.** `evaluate_animators` also runs the rig's `MontagePlayer` after the graph and writes `MontageEvent`;
  rigs without a player are unchanged. `ClipNode.sync_group` and a synced blend space's `sync_group` now sync across
  nodes when, and only when, the animator has a `SyncSetup` that declares the group. Without one, graphs play exactly
  as before.
- **Localization.** `Localization::set_locale` selects the nearest loaded parent when the exact locale is not loaded
  (`fr-CA` → `fr`); before, it returned `false`. `resolve` and `has` walk the whole fallback chain instead of
  selected + fallback. `load_localization` reads `assets://localization/localization.ron` for the source locale and
  fallback edges.
- `regia_ui` depends on `fluent-syntax` 0.12 directly (the parser `fluent-bundle` already builds; no new crate in the
  build).
- `regia_physics` depends on `glam` directly (already a workspace dependency, re-exported by `regia_core`), for the
  f64 geometry in convex decomposition.
- **SSAO pipelines by bent normals** (ADR-1491). `ssao.wgsl` has a pipeline constant `BENT_NORMALS`; `SsaoPass`
  builds the kernel and the blur with it off and on (four compute pipelines, all at the first dispatch) and runs the
  pair that matches the frame's bent-normal switch. With bent normals off there are no bent-normal sums and no
  layer-1 writes. With them on, the blur loads each workgroup's 11×11 texels into workgroup memory once instead of
  once per tap. Every pipeline writes the same bytes as before (`tests/ssao_blur_tile.rs`). RTX 5090, DO27
  switchbacks census: SSAO 0.129 → 0.125 ms with bent normals on, 0.125 → 0.121 ms with them off.
- **Terrain cost debug views compile out** (ADR-1491). The shared color pass compiles `terrain.wgsl` without the
  cost views' tests (views 78-92) unless one of them is on; switching to one builds the full color pipelines on that
  frame. Same pixels for every other view. RTX 5090, DO27 switchbacks census: terrain_forward 2.047 → 2.021 ms.

## Fixed

- **Arabic plurals.** The rule data bundled with `fluent-bundle` 0.16 (`intl_pluralrules` 7.0.2) reads Arabic
  `few`/`many` from the integer digits instead of `n % 100`, so 103 showed the `other` form and 3.5 the `few` form.

  103..=110, 203.. and so on, and for decimals, now follows CLDR.

- **Windows build** (ADR-1480): `regia_framework` no longer fails to compile on Windows (`unsafe_code` was denied in
  the native crash path).
- **Paks on Windows:** a pak that was just rewritten could not be opened ("being used by another process", os error
  32) because the writer renamed it into place with its handle still open.
- **CRLF content on Windows:** the showcase example generator and the terrain RON writers (layers, water, grass,
  scatter, scatter sets) wrote `\r\n` line ends on Windows; they write `\n` everywhere now.
- **Forward pipeline on Direct3D 12 with FXC:** `lab_forward.wgsl` did not compile (X3507 in `probe_depth_row`).
- **Soak RSS on Windows:** `tasklist` memory values with a `,` thousands separator were read as the last group
  (`1,234,567 K` read as 567).
- **Rename tool cleanroom check on Windows:** drive-letter deny paths (`C:\...`) were ignored.
- **Packaged crates** (ADR-1485): `regia_vfx` and `regia_cli` (and so `regia_editor`) no longer fail to compile from
  a vendored or packaged copy.
- **Non-finite physics inputs** (ADR-1507, the open half of ADR-383). A NaN or infinite `Transform`, `Velocity`,
  force, impulse, damping, gravity scale or explicit `Mass` no longer reaches rapier, where one such value used to
  spread through contacts into every touching body and come back to the scene on write-back. A new body with a
  non-finite spawn pose is created parked at the origin; other non-finite edits are not pushed and the body keeps its
  last valid state; non-finite `Teleport` and `ExternalImpulse` markers are consumed. The 2D chain has the same guards.
  Each dropped value is counted in `PhysicsStats::non_finite_inputs`.
- **Tests on Windows** (test-only). Two `regia_editor` content-browser tests built folder names with the platform
  separator (`assets\tex`); they now use the `/` form the content index stores. The `regia_agent` vehicles test
  compared a JSON position holding an f32 widened to f64 (`0.8999999761581421`) with the literal `0.9`; it now compares
  the vector with an f32 tolerance, so it no longer depends on how `serde_json` renders an f32.

## Known issues

### Post volumes and the camera

- Volumes do not override lens effects (depth of field, motion blur) or the level LUT. Other shapes and per-volume
  LUT blending are not built.
- `regia upgrade-project` does not rewrite `PostVolume` components inside scene files; a future v2 would migrate at
  load (as the primitive component does) and must add an upgrade-project pass if fields are renamed.
- `shutter_reference_fps` is fixed per camera (default 30), not the measured frame rate.
- `PhysicalCamera` has no reflection, so it is not saved in scene files; code and the agent methods set it.

### Animation

- Slots apply after the whole graph, so IK nodes inside the graph do not see montage poses (a graph `Slot` node
  needs animgraph v3).
- Blend spaces join named sync groups by normalized phase only (no marker sync for spaces).
- Montages play forward only; a section jump inside a warp window skips the warp for that frame.
- No editor panel; montages are authored as RON or through the agent protocol.

### Content data

- `.table.ron`, `localization.ron`, `asset_tags.ron` and the registry file are proposed formats: not yet in
  `cargo xtask check-formats` and without `regia upgrade-project` steps (`.table.ron` migrates on load and
  `regia table to-ron` rewrites old files).
- Profile paks written by `write_profile_pak` get no registry file. Registry change detection uses size and mtime;
  `refresh: true` re-reads it on demand.
- Fluent attributes (`key.attr`) and terms are validated but not gathered; computed keys (`loc!` with a non-literal)
  are invisible to the gather tool by design.
- The plural table follows the CLDR release the runtime data comes from; later CLDR `many` for exact millions in
  French, Spanish, Italian and Portuguese is not in it (the cross-check test fails when the upstream data moves).

### Motion matching

- No tags or per-query clip filters, no cooked database file, no automatic inertialized switch: the host switches
  clips on `MatchStep::jumped` and inertializes. No sample drives the matcher yet.

### Physics

- Cloth colliders are static within a step and friction ignores their velocity; moving one teleports it.
- Cloth bending uses the unsigned dihedral angle: a hinge with a non-flat rest angle also restores toward the
  mirrored angle when folded through flat.
- Cloth has no renderer integration yet: games build their own dynamic mesh from `ClothSolver::particles()`.
- The importer's convex-decomposition collision option (specs/12) is not wired to `convex_decomposition` yet. Cuts
  are axis-aligned only: a narrow diagonal notch needs a higher `resolution`.
- A car resting on its springs reports a small downward `linear_velocity` (about −0.06 m/s at 60 Hz) while its
  position holds still: rapier applies the suspension impulse once per step and gravity across its substeps.
  `forward_speed` is not affected.
- Wheel rays ignore sensors and the chassis but not collision layers. Vehicle configuration is code-only (no asset
  format).

### Navigation

- Crowd agent overlap is soft: a dense crossing may leave up to about 2 cm of overlap for a step (bounded by the
  50-agent test). Off-mesh links are crossed instantly, without a traversal animation. Path planning in the crowd
  is synchronous (no per-frame budget). Tiles keep one walkable surface per column (no stacked floors).
- A tile-cache update re-stitches the whole mesh (linear in the walkable grid): about 7 ms for an add + remove pair
  on a 128 m map with 0.25 m cells on the build server reference machine. Tile rebuilds themselves are local.

### Tools and pipeline

- The atlas generator is not wired into `regia bake-lightmaps` yet; that command still unwraps with `lightmap_uv`
  (ADR-860).
- Atlas utilization depends on the chart shapes: about 60 to 65 % for a sphere at 1024 with the default padding of
  2. Many tiny charts are dominated by padding (10,000 small quads reach 33 % at 1024 and 78 % at 4096). The xatlas
  chart-merge pass and its multi-page atlases are not ported; a density that does not fit one atlas is lowered
  instead.
- `lut_cube` and `post_ref` are CPU references only; no GPU path uses them yet.
- Tests under `tests/` and `#[cfg(test)]` modules still read `docs/`, goldens and sibling crates' fixtures, so
  `cargo test` does not work from a packaged copy; only the library, binaries and build script are the package
  contract. `regia_render/build.rs` hashes sibling crates' shader sources; from a copy it warns and hashes fewer
  files.
- The GPU job supervisor does not restart after a host reboot (`bash tools/gpusup/deploy.sh --start`).

### Windows and performance

- **`regia_dylib` does not link on Windows in the dev profile** (152,539 exports; the PE limit is 65,535). Release
  links (38,505). Windows hot reload needs a release editor until the dev-profile change proposed in ADR-1480 is
  decided; run Windows tests with `cargo test --workspace --exclude regia_dylib`. The Linux dev dylib has 157,297
  dynamic symbols, so `cargo xtask check-exports` fails on every OS.
- **Direct3D 12 without `static-dxc` (FXC):** the DDGI blend and screen-lookup kernels and the baked-GI screen
  lookup do not compile (FXC X4026 and X3511), so DDGI and baked-GI scenes fail on DX12 builds without DXC.
- On the NVIDIA 610.88 Windows Vulkan driver the NaN-input cases of three `nan_guards` tests return NaN (DX12
  passes); on the RTX 5080 (Vulkan and DX12) `bindless` storage and uniform paths differ in 190 bytes of the first
  frame.
- Same card and session, v0.1.29 vs v0.2.2 is about +0.10 ms gpu_frame (+2 %) on the RTX 5090. About 0.03 ms of
  that is taken back by the SSAO and terrain changes; the rest is feature cost left for the owner (ADR-1491): the
  terrain's probe-specular lobe (0.027 ms), its probe plumbing (about 0.025 ms), bent normals (about 0.02 ms forward
  + 0.004 ms SSAO), fog local lights and mist (0.003 ms).
- A first switch to a terrain cost view (78-92) compiles color pipelines on that frame (debug use only).

### Tests

- `regia_render`'s `texture_table::frame_tests::table_and_per_material_paths_draw_identical_pixels` failed once on
  lavapipe while the build host was under heavy load (189 bytes differed in the first frame), then passed alone and in
  two further full runs of the library tests. It is not caused by the changes in this release; if it fails again it
  should be registered as flaky.

### Smart objects, sequencer, IK retargeting, vertex AO

- Smart-object queries are linear scans (fine for about a thousand slots). `SmartObjectGizmos` has had no visual
  check.
- The sequencer has no player, no editor panel and no agent surface; IK retargeting has no agent surface.
- `PhysicsSettings::gravity` and `LevelSettings::gravity` are not guarded against non-finite values.
- No authored or cooked material field carries the vertex-AO flag yet (it would need a cooked-material version bump
  and a migrator); the game sets it when it builds the `LabMaterial`, or through the agent method. The path tracer
  (`regia_pt`) reference ignores the factor. The factor also dims indirect specular.

### Windows

- **`regia_matgraph` `all_nodes` and the shader-check tests need `spirv-val`.** A host without SPIRV-Tools (the
  Windows rig today, a fresh Mac) sets `REGIA_SPIRV_VAL_FALLBACK=1` or installs SPIRV-Tools; without either, a missing
  `spirv-val` is an error by design (`book/user-guide/merge-gate.md`).
- The rest of the Windows workspace test pass (the crates after `regia_matgraph`'s `parity`, and the doctests), the
  GPU benchmarks and the showcase render have not run on Windows for this release. The rig had 4.4 GB free on `C:`.

### Carried over from v0.2.1

- Every known issue in `docs/releases/v0.2.1.md` still applies, with one update: `resize_memory`, which failed 3 of 3
  runs on an RTX 5080 under Linux (driver 615.71.09) at the v0.2.1 head (ADR-1467), passes on the same card under
  Windows (driver 610.88) on the v0.2.2 (b) candidate. It has not been rerun on Linux with that card, so the v0.2.1
  entry stays open for Linux.
