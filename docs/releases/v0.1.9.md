# Ferrite v0.1.9

Patch release for Direct Order 27's alpha build (Thursday 10-15): the agreed log contract (spec 28) and a host LOD
cross-fade.

- **Commit:** v0.1.9 = the tag `v0.1.9` (the gated code commit is named in the tag message).
- **Workspace version:** `0.1.9`.

## Upgrade from v0.1.8
One host source change (checked from the code diff): **`ExtractedMesh { .. }` gained `lod_dither: f32`**; a host that
builds extracted meshes literally adds `lod_dither: 0.0` (DO27: `window_play.rs` ~3777). `OsInfo` gained `cpu_model` (an
engine-filled resource; hosts read it). Everything else is additive (`ferrite_telemetry::phase`, `MeshLodFade`,
`TelemetryOptions` fields with defaults, `TelemetryHost` fields).
**Log format change (spec 28 § 2):** `fields.data` is now a nested JSON object on every engine event. The old string form
is also written as `fields.data_json` on every event **except `ferrite::frame_summary` and `ferrite::hitch`** (the two large
periodic events; review decision to avoid doubling log size). Parsers must read the nested `data` for those two.

## Log contract (spec 28, ADR-194)
- `ferrite::phase` markers: engine `boot_done`, `shaders_ready`, `scene_load_start`/`scene_load_end`, `quit_start`/`quit_done`;
  hosts emit `menu_ready`, `match_start`/`match_end` and map names through `ferrite_telemetry::phase(name, data)`.
- `summary.json` per session (next to the JSONL sink): system, display (all monitors), settings, frames and
  `frames_by_map`, hitches, stalls, memory, shaders, audio, errors, exit; `host` filled through `TelemetryHost`.
  `summary.partial.json` every 60 s (atomic rename); the final is written as `clean: false` when the exit starts and
  rewritten `clean: true` only when the clean exit finishes, so a hang or crash in teardown stays unclean. The next start
  records `previous_exit` and emits a WARN `previous_session_unclean` phase.
- Session header: `cpu`, `ram_gb`, `vram_gb`, `os_version`. Frame profiler on by default (a missing layer warns once after
  600 frames). Default host-span prefix: the executable's name (never a dependency crate's).
- Home paths in engine messages are written as `~`. A caught worker panic is counted but does not mark the session crashed.
- `xtask alpha-triage` reads `summary.json` first, nested `data`, `ferrite::phase`, per-map frames and `previous_exit`.


## LOD cross-fade (v0.1.9)
A host that picks its own LODs can fade between two levels instead of popping: add `ferrite_render::MeshLodFade(c)` to the
two entities of a switch. It is optional and additive (`MeshRenderer` is unchanged; an entity without it, or with
`MeshLodFade(0.0)`, draws exactly as before).

- The **incoming** LOD gets `MeshLodFade(c)` and keeps the share `c` of the screen pixels; the **outgoing** LOD gets
  `MeshLodFade(-c)` and keeps the other `1 - c`. Together they cover every pixel exactly once. Ramp `c` from 0 to 1, then
  remove the component and despawn (or hide) the outgoing entity. TAA averages the dither into a blend.
- A dithered mesh draws through the alpha-test pipeline in its own batch (it is not eligible for the visibility-buffer path).
- **Shadows:** the incoming LOD (`c > 0`) casts the shadow for the whole fade, the outgoing LOD (`c < 0`) casts none, so the
  shadow neither doubles nor pops (the shadow pass does not dither). `NotShadowCaster` still removes both.
- The component is `Reflect`, so the scene inspector and agent protocol list it.

```rust
use ferrite_render::MeshLodFade;
// Host switch LOD0 -> LOD1 over `t` in 0..1 (entities `old` and `new` carry the two meshes).
let c = t.clamp(0.001, 0.999);
world.entity_mut(new).insert(MeshLodFade(c));
world.entity_mut(old).insert(MeshLodFade(-c));
// When t reaches 1: world.entity_mut(new).remove::<MeshLodFade>(); world.despawn(old);
```
