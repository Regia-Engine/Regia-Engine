# Regia Engine v0.2.11

Builds on v0.2.10. This release adds these feature sets for game teams:

- **World streaming runtime** (spec 78): a new `regia_world` crate that cooks levels into cells and a world index,
  streams them around cameras, players and scripted sources under budgets, draws flat-colored HLOD proxies for far
  cells, keeps physics safe at cell borders, and moves the floating origin through physics, rendering, terrain, water,
  baked GI, effects, nav, audio and the network.
- **Weather** (spec 99): rain and snow, a precipitation occlusion view, surface wetness, puddles and snow on lab
  materials and terrain, a weather-driven scene wind, `config/weather.ron`, and per-material and per-terrain-layer
  weather responses. Off unless a project turns it on.
- **Foliage wind** (spec 88): one scene wind for every swaying plant, a ready-made sway vertex stage, and a
  dynamic-caster shadow class so swaying plants cast shadows that sway with them on the paged tiers.
- **Cloth and soft-body assets** (spec 55): `.cloth.ron` and `.soft.ron` sources, cooked payloads, a cooker and tet
  generator, vertex-map edits, and framework glue that puts cloth and soft bodies in the game world and draws them.
- **Lightmap tools**: `regia bake-lightmaps --scene`, the UV atlas generator as the default unwrap, seam measurement
  with a shipping budget, `.flmap` v3, an editor Lightmaps panel and an optional GPU baker.
- **Ray-traced sun shadows, step 2**: a trace pass in the frame (hardware ray queries, a compute reference or a
  screen-space trace), selected by `RenderProfile::sun_shadow_trace`, off in every preset.
- **Renderer-owned render graph**: a versioned graph with a transient texture pool, and a new pass record signature.
- **Shader-permutation policy**: per-profile pipeline budgets at cook and package time, and a runtime guard that
  refuses uncooked material graphs in shipping builds.
- **Networked project template**: `regia new --template net-game`, the `samples/net_game` sample and `regia_net::link`.
- **Editor gameplay panels**: State Trees, Smart Objects, Cameras (with `.camera.ron` loading and hot reload), Tables,
  Abilities, Montage timeline and Ragdoll.
- **Hardening**: a fifth outside-audit wave (screen readers, network handshakes and bans, server content hashes, Lua,
  cooked meshes), an Adreno shader fix, and a lock that closes a Vulkan loader race behind many "SIGSEGV under load"
  test failures.

All new features are off, or unchanged for projects that do not use them, except where **Changed** says otherwise
(the shipping permutation guard, the lightmap seam budget, the default lightmap unwrap, swaying shadows on paged
tiers, server content hashes).

The text below consolidates the `v0.1.28-*` release fragments of the lanes merged after v0.2.10 and the integration
notes (ADR-2043, ADR-2113). The fragments: `android-pass-v0210`, `cloth-assets-glue`, `docs-truth-pass`,
`fix-audit-wave5`, `hwrt-step2`, `integ-fix032`, `integ-fix032b`, `integ-fix032c`, `integ-v032`, `lightmaps-tools`,
`net-template-game`, `permutation-policy`, `render-graph-own`, `streaming-runtime-2`, `streaming-runtime`,

## New

### World streaming: runtime and cook (spec 78, ADR-1804, ADR-1888, ADR-2022)

Spec: `docs/specs/78-world-streaming.md`; lane split in `docs/notes/world-streaming-lanes.md`.

- **`regia_world`**, a new workspace crate. Cooked streamed levels load around streaming sources (`StreamingSource`,
  the implicit camera, scripted pins) with priorities, per-frame budgets (loads per plan, reads in flight, decoded
  bytes, apply time, entities) and a hard memory bound. Reads run on the IO pool and decode on the async pool; a cell
  cancelled while queued, loading or applying leaves no entity; failed cells retry without stopping the others.
  `Lockstep` timing applies a load a fixed number of steps after issue, so a run repeats exactly, and `Replay`
  repeats an async run from its trace. `WorldStreamingPlugin` is part of `DefaultPlugins` and idle without a streamed
  level; the dedicated server has it too.
- **Streamed-level cook.** `regia cook` partitions levels with an enabled `LevelStreaming` resource into cell blobs
  (`.wcell`), the always-loaded set and a world index (`.wstream`), both `format_version` 1
  (`docs/formats/world-stream.md`). Output is byte-identical for the same sources and unchanged blobs are not
  rewritten. `regia assets stream-report <level>` shows the partition.
- **Opening streamed levels.** `regia run --level` and the dedicated server open a level cooked for streaming
  through the runtime (`StreamedLevelOpener`, `regia_world::open_if_cooked`): the index and the always-loaded set are
  read and cells stream; the source file is not parsed. A level with no cooked index opens as before.
- **Readiness gates** (`regia_scene::streaming::StreamGates`): `physics`, `render` and `nav`. A cell moves
  `spawned`, `sim_ready`, `visible`; a stuck cell names its missing gate in `stream.cells`.
- **Physics guard.** Dynamic bodies and characters near a cell that is not `sim_ready` freeze and keep their
  velocity; moving members change cells; `StreamAutoMember` adopts a runtime entity.
- **HLOD proxies.** The cook merges each cell's static meshes and simplifies them with meshoptimizer; parents merge
  their children. Every leaf is covered once by something ready (`holes` counted, `CellRenderHidden` on members behind
  a proxy). Each proxy draws with one flat linear color, the area-weighted average of the `Primitive` colors it merges
  (`HlodIndex::node_colors`; `stream.hlod` names each entry's `color`). With `tuning.hlod_fade_frames` set, a switch
  dissolves over that many frames with complementary dithers (`stream.hlod` reports `fade`).
- **Floating origin.** `WorldOrigin`, whole-cell rebases at step boundaries, shifting root, global and previous
  transforms, rapier bodies, colliders, poses and cloth, the camera and draw history, audio motion, decals and montage
  warp targets. The rebase also reaches nav (`NavOriginPlugin`, added by every nav plugin, moves `NavMesh`,
  `NavTileCache`, `NavObstacles`, `NavCrowd`, `NavLaneGraph`, `NavRegionQueue` and each `NavAgentState`), effects
  (instances, pending spawns, the GPU particle pool through a `shift_pool` kernel, debris, fire lights, impact sites and
  decals), the installed irradiance field and reflection probes, and the fog, cloud and camera-cut histories.
- **Terrain, water bodies and baked GI across a rebase.** They keep their own world-anchored space and the frame
  converts at the boundary (`SharedFrameInfo::origin_offset`, `SharedFrameInfo::in_world_space`). The picture on
  either side of a rebase agrees to under 0.03 of an 8-bit level on the reference device. `WaterQuery` and
  `regia_pick` keep speaking local coordinates.
- **The origin goes home.** A level file opened with the origin moved lands where it was authored; the origin returns
  to cell zero through a normal rebase once no streamed level is open. A streamed level with another origin cell size
  opens on the same offset when the offset falls on its grid, and is refused otherwise.
- **Rebase blockers.** `RebaseBlockers` names host stores that cannot follow a rebase (nothing in the engine
  registers); `StreamStats::rebases_blocked`, `stream.origin`'s `blocked_by` and the error code
  `stream_rebase_blocked` report it.
- **Terrain tiles follow the streaming views**: insert `regia_terrain::TerrainTileStream` over a `TileCache`.
- **Nav tiles stream with their cells** (spec 78 § 13.2): with `LevelStreaming::nav` set the cook writes each nav tile
  of the level's static colliders into its cell; `regia_nav::NavStreamPlugin` builds the streamed `NavTileCache` and
  holds a cell at `spawned` until its tiles are built.
- **Cutscenes prefetch cells** (§ 7.2): a playing sequence's camera three seconds ahead is a look-ahead source
  (`StreamPrefetch`, `StreamingSource::look_ahead`). Procgen anchors include the streaming sources (§ 7.4).
- **Cell VRAM is reported** (§ 8.4): `StreamStats::resident_vram_estimate`, `vram_over_budget`, and a
  `stream_cells:<level>` load set in `render.memory_budget`.
- **Positions cross the wire in the shared world frame** (§ 14): each peer keeps its own floating origin
  (`OriginOffset`); interpolation buffers, prediction history and lag compensation history follow a local rebase.
  Without a streamed level the wire bytes are unchanged.
- **`samples/stream_world`**: a generated 8 km² world of 512 cells and its scripted flight; `cargo xtask stream-bench`
  is the teleport bench.
- **Agent:** sixteen `stream.*` methods; guide page `book/agents/streaming-runtime.md`.

### Weather and precipitation (spec 99, ADR-1847, ADR-1920, ADR-2032)

Spec: `docs/specs/99-weather-precipitation.md`; builder phases in `docs/notes/weather-precipitation-lanes.md`.

- **Rain and snow** (`regia_vfx::precip`): stateless instanced streaks, flakes and splashes in a wrapped box around the
  camera, through the VFX translucent layer. No CPU work per drop, no compute, a full field on the first frame after a
  cut, tier budgets in `PrecipBudget`.
- **Precipitation occlusion view** (`regia_render`): a depth tile of the shadow atlas seen from the sky hides drops
  under cover, places splashes and keeps covered surfaces dry.
- **Surface weather.** `regia_scene::weather::SurfaceWeather` integrates wetness, puddles and settled snow over game
  time. Lab materials and terrain respond with porous darkening, a water film, puddles with ripples and snow on what
  faces up. `LabMaterial::weather` (`WeatherResponse`) tunes or refuses it. The Mobile lite forward path shades the
  same rule in a variant (`LITE_SURFACE_WEATHER`) composed only on a wet, snowy or extinguishing frame;
  `FrameRenderer::set_warm_surface_weather(true)` (set by the weather runtime when weather is configured) warms it so
  the first wet frame on a phone compiles nothing.
- **Scene wind.** `regia_scene::weather::SceneWind` is the wind near the ground: a height profile from the cloud wind
  plus deterministic gusts. `regia_terrain::couple_scene_wind` lets it steer the shared `TerrainWind` by its gust-free
  mean (heading in whole degrees, strength = speed / 5 m/s in 1/32 steps, at most 4), writing only when the result
  changes, so gusts never redraw the grass's cached shadows. `terrain.wind` answers `weather_steered`.
- **Weather model.** `WeatherState` gains `temperature_c`, `precipitation_kind` and `gustiness`; new presets `rain`,
  `snow`, `blizzard`; `Weather::rates` gives rates in mm/h.
- **`config/weather.ron`** (new format, v1; JSON Schema in `docs/formats/weather.ron.schema.json`): which effects run,
  named presets, the start preset and the model's numbers. `regia new` writes it with all three effects on.
- **Per-material weather**: `.material.ron` v5 has an optional `weather` block (`porosity`, `wet`, `snow`, `puddles`;
  `MaterialWeatherParams`) carried into `LabMaterial::weather` (`docs/formats/material-v5.example.ron`).
- **Per-terrain-layer weather**: `.terrain.layers.ron` v4 has an optional `weather` block per layer (`porosity`,
  `snow`; `LayerWeather`) and the stack's `puddles` (default true). On a wet or snowy frame the terrain blends the
  layers' blocks by their weights; a dry frame and a stack without overrides shade as before.
  `render.surface_weather` answers `terrain_layers`.
- **Agent:** `render.scene_wind`, `render.set_scene_wind`, `render.precipitation`, `render.set_precipitation`,
  `render.surface_weather`, `render.set_surface_weather`, `render.surface_exposure`; guide topic and book page
  `weather-precipitation`.

### Rendering: foliage wind and dynamic-caster shadows (spec 88, ADR-2028)

- **Scene wind for materials.** `FrameRenderer::set_foliage_wind(Option<[f32; 2]>)` and `foliage_wind()`: meters per
  second on world X and Z, written into slot 0 `zw` of every time-reading material graph. Longer than
  `FOLIAGE_WIND_MAX_M_PER_S` (40 m/s) is shortened; `None` (the default) leaves the slot as the material carries it.
  `set_outdoor` passes a `SceneWind` to it, so `FoliageSway` materials follow the weather (ADR-2043 (1)).
- **`FoliageSway`**, a ready-made vertex stage for surface graphs (`FOLIAGE_SWAY_VERTEX`; parameters in slots
  `FOLIAGE_SWAY_SLOT` = 15 and `FOLIAGE_SWAY_LIMIT_SLOT` = 14): a height-squared bend downwind with a per-instance gust
  and a leaf flutter weighted by vertex color red. `graph`, `graph_code`, `apply`, `max_offset`, the CPU mirror
  `offset`, and `sanitize_wind`.
- **Dynamic-caster shadow class.** Casters whose material has a time-reading vertex stage have their cached sun pages
  (and, on Desktop High and above, their local-light atlas tiles) redrawn every frame in the nearest cascades.
  `FrameRenderer::set_dynamic_caster_shadows(DynamicCasterShadows)`, `dynamic_caster_shadows()`,
  `dynamic_caster_report()`; `DynamicCasterShadows { Tier, Off, On { cascades, local_lights } }`,
  `DynamicCasterPolicy`, `DynamicCasterReport`.
- **Shared draws on the class**: `SharedPassDraw::dynamic_shadow_boxes` and `dynamic_shadow_box_cascades` (provided).
  The terrain grass's shadow sways with the blades in the refreshed cascades once the grass clock runs, and its patches
  join the class (`GrassReport::shadow_sway_cascades`, `dynamic_boxes`; `GrassLayer::dynamic_shadow_boxes`,
  `dynamic_shadow_cascades`).
- **Agent:** `render.foliage_wind`, `render.set_foliage_wind`, `render.set_dynamic_caster_shadows`
  (`book/agents/foliage-wind.md`).

### Rendering: ray-traced sun shadows, step 2 (renderer chain A5, ADR-2035)

- **`RenderProfile::sun_shadow_trace` and `FrameQuality::sun_shadow_trace`** (`hwrt::RtShadowRequest`): `Off` (every
  preset), `On` (hardware ray queries, or the screen-space trace without them), `Compute` (the reference BVH on any
  adapter, not for play), `Screen` (the screen-space trace on the shadow map).
- **Screen-space trace** (`SunShadowVariant::ScreenTrace`) where ray queries are unavailable; it multiplies the shadow
  map, so nothing goes missing off screen.
- **A trace pass in the frame**: the frame graph gains the `sun_shadow_trace` node (its pooled target takes the place
  of contact shadows) and the warm keys `sun_shadow_trace` and `forward_sun_rt`. Acceleration structures build from
  the mesh arena, which carries `BLAS_INPUT` on a device with ray queries.
- **Agent:** `render.set_sun_shadow_trace { mode }`; `render.hwrt`'s `sun_shadows` gains `frame`, and `applied` is
  real. Guide: `book/agents/hwrt.md`.
- New: `FrameRenderer::sun_trace_report`, `FrameRenderer::sun_trace_applied`, `SunTraceReport`,
  `RenderDevice::headless_with_ray_queries`, `hwrt::set_device_request`, `hwrt::device_request`,
  `hwrt::frame_sun_shadow_selection`, `hwrt::FrameTraceSupport`, `hwrt::sun_trace`.

### Rendering: render graph ownership (renderer chain A2, ADR-2018)

- **Versioned render graph.** `RenderGraph::versioned()` gives every write a new version of its resource; a read
  binds to the latest version registered before the reader. `RenderGraph::resolve` returns the order, the culled nodes
  and each node's versions (`CompiledGraph`, `ResourceVersion`); `RenderGraph::pipeline_keys` lists the live nodes'
  pipeline keys.
- **Transient texture pool.** `TransientPool` hands out textures keyed by `TextureDesc`, so a steady frame creates and
  allocates nothing; `TransientPool::stats` reports textures, bytes, creates, reuses and evictions. The frame's linear
  HDR target, the glass refraction copy and front layer, and the SSAO targets come from the view's pool (frames
  unchanged).
- **The frame's graph**: one versioned graph of built-in and registered passes; the game-frame warm builds the
  pipeline keys its live passes declare. `render.graph` gains a `graph` block and a `pipelines` list per pass row
  (`book/agents/render-graph.md`). Compile errors have agent codes `graph_duplicate_output`, `graph_cycle`,
  `graph_desc_mismatch`.

### Rendering: shader-permutation policy (master plan § 5.5a, ADR-2026)

- **Cook-time counts and budgets.** Every cook counts the material-graph pipeline sets of each render profile the
  platform runs and writes them to `permutations.json` in the cooked cache (`docs/formats/permutations.md`). The cook
  report has one line per profile (sets, pipelines, shader modules, code bytes, estimated cold compile time). Defaults:
  Desktop and Deck 4096 pipelines and 120 s, Mobile 1024 pipelines and 90 s; override with
  `[cook.permutation_budget.<Profile>] max_pipelines / max_compile_ms` in `Regia.toml`. `regia package` fails a
  shipping package over budget and warns on a dev one.
- **Runtime guard.** `regia package` ships the list as `content/permutations.json`; the render plugin installs it at
  startup. An unlisted graph is built with a warning (`PermutationEnforcement::Warn`, dev) or never built and drawn
  with the standard surface of the same pass (`Fallback`, shipping). `REGIA_PERMUTATION_POLICY=off|warn|fallback`
  overrides at launch; `FrameRenderer::set_permutation_guard` and `permutation_stats()` are the host API.
- **Agent:** `render.permutations`, `render.set_permutation_policy`; error codes `permutation_bad_enforcement`,
  `permutation_manifest_unreadable`, `permutation_unknown_profile` (`book/agents/permutation-policy.md`).
- Modules `regia_render::permutation_policy` and `regia_asset_pipeline::permutation_cook`.

### Lightmaps: tools (ADR-2024)

- **`regia bake-lightmaps --scene <level>`** bakes a level directly, with no `.bake.ron`: its `GiMobility::Static`
  meshes, sun and sky. Entries are keyed by entity; the default output is `assets/maps/<level>.flmap`; the bytes do not
  depend on entity order or `--threads`.
- **`LightmapSurface { density_scale, receive }`** on a mesh entity sets its texel density, or leaves it to the probes.
- **The UV atlas generator lays out the second UV set** by default; `--unwrap charts` keeps the planar charts.
- **Seams are measured**: every bake reports the luminance step across chart seams per entry and chart. A shipping
  `regia package` fails with `lightmap_seam_budget` when an entry's `p95` passes `[lightmaps] seam_budget` in
  `Regia.toml` (default 0.25); `--seam-budget F` checks one bake.
- **`.flmap` version 3**: entries carry their entity and seam figures. `render.set_lightmaps { auto_receivers: true }`
  and `regia_render::lightmap::receivers_by_key` attach a level's receivers from the file.
- **Editor Lightmaps panel**: source, settings, Lay out, Bake, Cancel, progress, an atlas preview by density or seams,
  and the worst seams in the viewport. Agent: `editor.lightmap_bake`, `editor.lightmap_status`,
  `editor.lightmap_cancel`, `editor.lightmap_preview`.
- **GPU lightmap baker** behind the `lightmap-gpu` feature (`regia bake-lightmaps --gpu`), checked against the CPU
  baker within a tolerance.

- **Vertex-map edits** (`regia_physics::cloth::maps`): `MapEdit::{Set, Sphere, Relax, Ramp, Flood, FromVertexColor}`,
  `apply_map_edit`, `transfer_maps`, `store_maps`.

- **Messages** `ClothStateChanged`, `ClothTeleported`, `ClothTear`; **sim-mesh LODs at runtime**

- **Android substeps**: `ClothParams::for_platform`, `SoftParamsSource::for_platform`, `ANDROID_SUBSTEPS` (4);

- **Agent:** `physics.cloth_edit_map`; every `physics.cloth_*` method takes `{ entity }` of a `ClothSim` / `SoftSim`.

### Networking: the net-game template (ADR-2039)

- **`regia new <name> --template net-game`**: a project with a shared `game` crate, a headless `server` (no renderer or
  audio) and a windowed `client`. Encrypted UDP with the server key pinned, client-side prediction, interpolated
  proxies, lag-compensated shots, lobby following, and an end-to-end test in the generated project.
- **`samples/net_game`** with `net_game_server` and `net_game_client`; its tests play over real encrypted UDP with a
  lossy conditioner, replay a match twice, walk a lobby launch, render a client headless and run the two binaries as
  processes. The server's `--until-stdin-eof` lets a supervisor stop it.
- **`regia_net::link`**: `NetLink` and `NetLinkPlugin` run replication over any `DatagramSocket` (raw UDP, the
  in-memory network, Steam sockets through `regia_steam::SteamSocket`); the endpoint report reaches `net.status`,
  `net.peers`, `net.crypto` and `net.conditioner_set`. `LinkClock::Manual`, `LinkInterpolationPlugin`.
- Book: `book/tutorials/networked-game.md`, `book/agents/net-link.md`. The nightly templates job compiles the
  `net-game` template, its server crate by itself.

## Changed

- **Shipping packages refuse uncooked material graphs** once a project cooks at least one graph (permutation policy,
  above). `regia cook` prints the permutation lines and any over-budget profile.
- **`regia bake-lightmaps` lays out with the UV atlas generator by default**, so a new bake from the same scene has
  other rectangles, charts and noise. Installed files keep working; `--unwrap charts` keeps the old layout.
- **Swaying plants' shadows redraw every frame on paged tiers** (Desktop Low, High, Ultra, Cinematic, the Deck): cascades
  0 and 1 and the atlas on Desktop High and up, cascade 0 on Desktop Low and the Deck; reported as `dynamic_pages`.
  `DynamicCasterShadows::Off` keeps the old caching. `SurfaceGraph::uses_time` graphs receive the scene wind in
  `params[0].zw` when one is set.
- **Grass and the scene wind** (ADR-2043 (1)): while a `SceneWind` sets the foliage wind, `SharedFrameInfo::foliage_wind`
  is `None`, so grass takes the wind once (through `TerrainWind`) and gusts stay out of its shadow key.
  `render.set_foliage_wind` writes the `SceneWind` when one exists; `render.scene_wind`'s `renderer_foliage_wind` reads
  the renderer. `TerrainPlugin` runs `couple_scene_wind` before `sync_terrain_wind`.
- **Weather**: `render.get_weather` answers `rates`, `config`, the new state fields and the longer preset list;

## Known issues

### Streaming

- Every budget marked ★ in spec 78 § 20 is a target until measured in `docs/perf-log.md`.
- Spec 71 § 4.5 buffered binds are not built: a replicated level entity that arrives before its cell spawns a bare copy
  and logs `net.level_entity_missing`.
- DDGI settles again after a rebase. A map wider than about 16 km keeps more than 1 mm of `f32` spacing at its rim.
- A material graph that reads the world position sees local space, so its pattern jumps across a rebase. Terrain edit
  APIs (height patches, craters, holes) take world meters; a game calling them from a local position adds `OriginOffset`.
- Proxies have one flat color, not a texture atlas; the cross-fade is off unless authored. Distant proxies of many small
  props look spiky (the sloppy simplifier merges across gaps).
- The `render` gate does not check base texture mips, and a host that leaves `MeshSource` unresolved keeps its cells
  `sim_ready`.
- The nav cook takes colliders with a static body on the same entity, not `Terrain` heightfields (per-tile terrain
  collision is absent, spec 78 § 13.1); a static body under a moved group is cooked at its world pose while the run-time
  region rebuild places it by its local `Transform`.
- Spec 78 is not listed in `docs/specs/README.md`.

### Weather and foliage wind

- The look defaults (wet darkening, puddles, snow) await the owner's look review; GPU budgets await a real-card run.
- Rain and snow draw at full resolution on Mobile tiers; the half-resolution pass waits for a Pixel 6 measurement.
- The procedural-atmosphere sky takes no precipitation extinction; in heavy rain it stays clearer than the ground.
- The interior rule reads only the interior volume that holds the camera, beyond the occlusion map.
- The terrain's per-layer weather blend uses band and splat weights, not the height blend or the legacy mottle.
- A `terrain.set_wind` holds only until the weather's mean wind changes a step; to pin the wind, set the scene wind
  (`render.set_scene_wind`) or turn it off.
- Grass boxes reach the renderer one frame late. The dynamic-caster frame cost is measured on lavapipe only.

### Ray-traced sun shadows

- Under `ray_query` and `compute_fallback`, opaque surfaces get no shadow from skinned, morphed, vertex-animated or
  alpha-masked meshes (`render.hwrt` counts them). A frame with a shared draw (terrain) or persistent visibility-buffer
  sets under `on` keeps the shadow map under the screen trace, so a terrain scene gets no hardware-traced sun yet.
- A mesh submitted with key 0 rebuilds its acceleration structure every frame: give casters stable keys.
- The traced shadow is hard-edged and the shadow maps are still drawn, so the traced variants cost more. Only the main
  view traces.

### Render graph and permutations

- Built-in passes still record in the frame's fixed order inside `render_into`, and transients are not aliased yet.
- The compile-time estimate's constants and default budgets are provisional until calibrated on reference devices.
- A mod's graphs are not on the game's list, so a shipping build draws them with the standard surface.
- The Android extraction of the permutation list has compiled but not run on a device.

### Lightmaps

- Receivers draw through the CPU color loop only; every-tier and Mobile-Low static paths, GPU-driven and
  visibility-buffer receivers and `LIGHTMAP` prewarm are the renderer's next step.
- `auto_receivers` attaches part 0 of a multi-part mesh; other parts are listed in `unmatched_keys`.
- The panel's budget is a preview value; the package reads `Regia.toml`.
- Cancelling a bake in the instant of its final write can leave a `<out>.tmp<pid>` beside the output.
- `--gpu` has run on lavapipe only; its dispatch size is reasoned, not measured on a real card.

### Cloth

- `WorldQueries::overlap` still reports nothing for heightfields; cloth uses `overlap_aabb`.
- A sim-mesh LOD switch keeps motion but not tears; agent `physics.cloth_set_params` changes stay on the old solver.
- The `layer` map is stored, not simulated. Reaction is a linear impulse (no torque).
- Cloth pauses on `InheritedVisibility`, not `ViewVisibility`.
- The editor's cloth inspector and paint mode (spec 55 § 6) are not built; `physics.cloth_edit_map` and `apply_map_edit`
  are the headless equivalents. The spec 55 test 19 golden images and the Android 600-step run are pending.

### Networking and template

- The template's server is a paced loop, not the spec 76 host; joining the two is future work (ADR-2039 (8)).
- A lobby launched to a Steam id server is not followed by the template (`TODO(template)`).
- `NetLink::stop` sends no goodbye; peers time out.
- Direct `NetClient`/`NetServer` use with `CryptoMode::Off` still sends a password proof on a plain non-loopback link
  (ADR-1901); `NetLink` and `NetSession` refuse it.
- The nightly templates job does not compile the `top_down` template (not new).

### Editor

- The rig graph shows and switches; camera asset structure is still edited as text. **Save** writes canonical RON, so
  comments do not survive. A `.camera.ron` that changes on disk replaces the Cameras panel's unsaved working copy.
- A play session with no game has no state trees, slots or drivers to show. A hot-reloaded driver's rigs restart.
- `statetree.*`, `smartobject.*` and `camera.*` reach the world that serves the agent (the edit world in the editor); use
  `editor.*_panel_*` for the play world.
- The montage pose preview samples the main track only. Curve colors follow the curve index. No golden images of the
  panels yet.

### Platforms, GPU and tests

- Image-light ground plane and local captures do not draw on Adreno GPUs (opt-in studio features).
- Until the distro Vulkan loader carries the upstream fix (Vulkan-Loader 6b45d762), a **debug** build that creates a
  second Vulkan instance (adapter listing or ray-tracing probe) while its renderer creates objects can still crash in the
  loader. Other multi-test GPU binaries that open a device per test on parallel threads can hit the same race.
- `clean_exit_renderer_drop`'s rare SIGSEGV under gate load is a different fault; its cause is open.
- A steady frame sometimes does extra work for one frame (48 allocations, once 189) about once in a few hundred frames, on
  lavapipe and an RTX 5090; the cause is not known. `hwrt_frame_alloc` tolerates one such batch.
- Deferred findings of audit wave 5 (painted splat upload in the editor, split-screen hit claims and local-player checks,
  streaming host design items, NGX evaluate lifetimes) are in the lane report.
- The three `regia_xr` formats are not yet in the `check-formats` fingerprint table.

## Golden changes

- None. The default frames of the look presets and all goldens are unchanged (only a receiver of a `sun_direct`
  lightmap moves). `samples/showcase/example_scene` is regenerated for terrain layers v4.
