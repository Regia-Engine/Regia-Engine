# Regia Engine v0.2.9

Builds on v0.2.8. This release adds these feature sets for game teams:

- **Networking**: encrypted transport (Noise, server keys, sealed remote admin), an acknowledged unreliable state
  channel with a negotiated fallback and a parallel server send loop, lobbies and matchmaking with a Steam sockets
  transport, networked characters (moving bases, replicated montage root motion), voice chat with Opus coding over
  `regia_net`, multi-client play-in-editor with a stats overlay and a bandwidth view, and hardening from four net
  audits (relay, flood bounds, stream limits).
- **Dedicated servers**: a `server` build of `regia` with no renderer, audio or UI in its graph, `regia package
  --server`, `regia server`, and a `net-manifest.ron` in every package.
- **Rendering**: two-phase occlusion of the depth prepass (on in Desktop High and Ultra), an opt-in compute software
  rasterizer for small visibility-buffer clusters, a fix for dynamic-GI light leaking into closed rooms, a staging
  flush that bounds peak memory during level load, frosted-glass UI backdrops, and a path-traced cloud layer
  reference.
- **Cinematics and replays**: the full sequencer (`.seq.ron` v2 with Bezier keys, clip, audio and sub-sequence tracks,
  a curve editor, render jobs with a binding table), and ECS-wide demo recording with a scrub bar, a spectator camera
  binding and the `.frec` match record.
- **Content and localization**: shipping localization bundles, dialogue lines with voices and subtitles, localized
  asset variants, loudness measurement at import with an optional normalization switch, and DDS, TGA and BMP
  importers.
- **UI and input**: a UI designer with view-model binding (`.ui.ron` v3), a rebinding panel for chords and key groups,
  anchor presets, fuzzy matching and a gesture recognizer.
- **Navigation**: region rebuilds, tile streaming hooks, polygon area costs, dormant crowd agents and crowd lane
  graphs.
- **Extensions and tools**: the extension host of spec 57 (registry, content mounts, render passes, packaged games,
  `regia plugin`), the finished DCC scene feed, a fuzz-target registry for every frozen format, and a determinism
  matrix across thread counts and builds.
- **Hardening**: two outside-audit waves (paths confined to the project, a bounded Lua pattern matcher, crash-log
  redaction) and test-quality passes over `regia_core`, `regia_animation`, `regia_audio`, `regia_terrain`, `regia_ui`
  and the asset pipeline.

Several defaults change (see **Changed** and the upgrade section): encryption is required for non-loopback peers, the
state channel is the default wire, `send_every_ticks` takes effect, `max_peers_per_ip` is 8, and Desktop High and
Ultra cull the depth prepass in two phases. Old builds cannot join new servers.

## New

### Rendering: two-phase occlusion and the software rasterizer (ADR-1887, spec 98)

- **Two-phase occlusion of the forward depth prepass.** The GPU-driven prepass draws the instances last frame's depth
  pyramid does not hide, rebuilds the pyramid from that depth, and draws the instances the new pyramid does not hide
  in a second depth pass. The depth and the frame are the same as the unculled prepass; only the prepass's work drops.
  It runs on the main view of single-sample frames with at least 2048 GPU-driven depth instances and Hi-Z occlusion
  on.
  - `RenderProfile::two_phase_occlusion` (on in Desktop High and Ultra), the override
    `RenderSettings::two_phase_occlusion`, and `RenderSettings::effective_two_phase_occlusion()`.
  - `FrameRenderer::{set_two_phase_occlusion, two_phase_occlusion, prepass_occlusion_stats,
    prepass_occlusion_counters}` (the last is a blocking per-phase readback for tests and benches), with the types
    `PrepassOcclusionStats`, `PrepassOcclusionSkip` and `PrepassOcclusionCounters`.
  - Agent methods `render.get_occlusion` and `render.set_occlusion { two_phase }`, guide topic `occlusion`, page
    `book/agents/occlusion.md`.
- **Compute software rasterizer for small clusters** (spec 98 § 8a). With `VisBufferSettings::software_raster` on (off
  by default), clusters that span at most `software_raster_max_px` pixels (default 16, at most 64) rasterize in
  compute on the visibility-buffer path and merge into its ID target and depth. The image matches the hardware raster
  to within edge pixels. Agent: `render.set_visbuffer { software_raster, software_raster_max_px }`, reported by
  `render.get_visbuffer`; `VisBufferCounters::software_clusters` counts them.

### Rendering: other

- **Dynamic GI** (ADR-1949): `DynamicGiBudget::{finest_above_m, finest_below_m}` (how far around the eye the finest
  probes hold at full weight: 2 m above on every tier; 3 m below on Low and Medium, 7 m on High and Ultra) and
  `DynamicGiBudget::room_rule` (whether the layout runs the closed-room rule). Both appear in `render.get_dynamic_gi`
  under `tiers[]` and `renderer.budget`.
- **Staging flush during level load** (ADR-1346). Once the bytes written through the renderer's queue since the last
  submit reach a cap (128 MiB), the pending writes are submitted on their own, and the frame path waits for its
  previous flush before it writes more, so a load holds about two caps of staging instead of the level's texture
  bytes. Pixels are unchanged (a first frame flushed after every write is byte-identical).
  - `REGIA_STAGING_FLUSH_MIB` (MiB; `0` or `off` turns it off), `regia_render::set_staging_flush_cap`,
    `regia_render::staging_flush_stats()` / `StagingFlushStats` and the `regia_render::staging_flush` module.
  - `seeing.memory_report` returns `peak_rss_bytes` (`VmHWM`) and `staging` (`cap_bytes`, `flushes`, `flushed_bytes`,
    `waits`, `peak_pending_bytes`). Page `book/agents/load-memory.md`.
  - `load_rss_bench` (lookdev sample) measures the peak RSS of a synthetic large scene's first frame.
- **Path-traced cloud layer** (`regia_pt::cloud`, ADR-1834): `PtCloudLayer` (a scattering slab as a path-tracer medium
  layer), a validation scene (`validation_scene`, `measure_ground_ratio`), an independent transport reference
  (`slab_transport_reference`, `reference_ground_ratio`), the renderer's cloud model as functions
  (`renderer_sun_ratio`, `renderer_sky_ratio`, `renderer_ground_ratio`, `renderer_log2_gap`) and
  `two_stream_diffuse_transmittance`. Example `cloud_validation`, page `agents/pt-cloud-layer.md`.
  `regia_pt::MAX_PATH_VERTICES`; `regia_render` re-exports `COLUMN_FILL` and `type_gradient`.

### Audio and importers (ADR-1855, spec 95)

- **Loudness at import.** The cook decodes every `.wav`, `.ogg`, `.flac` and `.mp3`, measures integrated loudness,
  loudness range and true peak (EBU R128), and writes `<cooked cache>/loudness.ron` (v1) with one record and gain per

- Agent methods `audio.loudness` and `audio.set_loudness_normalization`, error codes `loudness_decode_failed`,

### Networking: encrypted transport (ADR-1901)

- `regia_net` protects connected traffic with `Noise_NX_25519_ChaChaPoly_BLAKE2s` through the `snow` crate
  (confidentiality, authentication, forward secrecy, replay window). `CryptoMode::Auto`, the default, requires it for
  every non-loopback peer and leaves loopback plain; `Required` and `Off` are the others. Set it in
  `ServerConfig::crypto`, `ClientConfig::crypto`, `session.encryption` in `config/net.ron`, `[net] encryption` in
  `server.toml`, or `encryption` on `session.host` and `session.connect`.
- **Server keys**: `ServerIdentity` and `ServerKey`. A client pins with `ClientConfig::server_key`,
  `ConnectOptions::server_key` or `server_key` on `session.connect`; a mismatch ends the attempt with
  `server_key_mismatch` before any secret is sent. A dedicated server keeps its key in `[net] identity_file` (default
  `server.key`, mode 0600); the console command `serverkey` prints it.
- **Remote admin** is on for a UDP dedicated server without the dev override, over sealed links only.
- Agent: `net.crypto`; `net.status` gains `crypto` and six `totals` counters; `net.peers` rows gain `sealed`;
  `session.state` gains `encryption`, `sealed` and `server_key`. Guide topic `net-crypto`.

### Networking: state channel and server scale (ADR-1950, spec 72)

- **Acknowledged state channel** (protocol 2). Spawns and deltas travel in unreliable `STATE` frames, each delta
  against the baseline the client acknowledged; a lost frame needs no resend. Ownership bits, despawns and reliable
  messages stay on reliable tick frames. Clients keep the last 64 versions per entity, and a delta they cannot apply
  asks for a resync of that entity alone.
- **Negotiated fallback.** A connection's first `ACK` decides its wire: `acked_deltas` for protocol 2 clients,
  `reliable_stream` for protocol 1. `replication.state_channel: Reliable` keeps every connection on the tick stream.
- **`send_every_ticks` and `mtu_bytes` take effect**: frames go on multiples of `send_every_ticks` (default 2); state
  frames stay within `mtu_bytes`, and a record larger than a packet goes reliably.
- Agent method `net.state_channel`, guide topic `net-state-channel`, `book/agents/net-state-channel.md`.
- `testing::LoopbackHub`: `down_filter`, `up_filter`, `up_rewrite`, `down_rewrite`, `negotiate`, `FrameFate`,
  `set_serial_gather`; `REGIA_NET_TEST_STATE_CHANNEL=unreliable` runs every hub test on the state channel.
- `runtime::MAX_PENDING_STATE_FRAMES` (1024) and `NetNode::pending_state_frames`.

## Changed

### Networking

- **Defaults**: `CryptoMode::Auto` (encrypt every non-loopback peer); `replication.state_channel: Unreliable`;
  `send_every_ticks: 2` now takes effect (state and messages leave every other tick); `max_peers_per_ip` is 8 (was
  unlimited). A sealed link gives up 25 bytes of each packet.
- `REGIA_NET_WIRE_VERSION` is 2 (handshake `KeyInit`, `KeyReply`, sealed records; `ConnectRequest` and `Challenge`
  carry the crypto version). `NET_PROTOCOL_VERSION` is 2 with a new `MIN_NET_PROTOCOL_VERSION`;
  `Hello.protocol_version` names the oldest protocol the sender speaks and the server checks a range.
- On a sealed link the password proof is bound to the Noise session and a wrong password ends the key exchange (one
  exchange, one guess); a lost refusal ends the client with `connect_timeout`. `fresh_secret` draws from the OS random
  source first. A new join does not drop the peer at its address until it passes every join check, and a sealed peer
  only after 2 s of silence (`regia_net::server::SEALED_PEER_QUIET_MS`).
- The server send loop works on dense per-connection arrays and runs per connection on the compute pool: 20,000
  entities, 64 connections, 2,000 relevant, 10 % moving, 8 workers on a shared machine went from 71.6 ms a tick to
  about 5 ms a send tick (2.8 ms in the spans spec 72 § 14 counts when the cores are free); 50,000 entities and 100
  connections take about 5.5 ms in those spans. Per-connection memory gains 8 bytes per replicated entity. Budgets are
  per send tick. `net_relevance_bench` gained workers, wire and `walk` options.
- Relay (ADR-1892): `RelayServer` answers one directory page per `ListGames`; `Register` takes a cookie round trip,
  renewing keeps the join code, and lifetimes are capped at an hour. A client cuts a heavy tick into frames of at most
  512 KiB of payload and sends 64 resync ids per frame. A reconnect token works once (a resume's `Welcome` carries a
  new one). A protocol-mismatch `Deny` no longer names the game.
- `client_session_started` clears the applied tick on connect (`ClientBridge` calls it). A new client session also
  clears the state channel and its pending state frames.
- `server.toml` `tick_hz` and `idle_tick_hz` set the app's `FixedTime`; `admin.token_file` and `logs.dir` must stay
  inside the server directory (exit 2).
- `HitClaim` is rejected until the server holds a `HitClaimPolicy` (ADR-1892 item 11).
- `PredictionStats::resets` (`net.prediction` `resets`) no longer counts the first server state of a predicted entity
  new to the client; it catches up without a reset and logs `net.prediction_adopted` (spec 73 § 6.3, ADR-2011).
- `net.messages` rows gain `bytes_sent` and `bytes_received`. `impl DatagramSocket for Box<T>`. `regia_steam` depends
  on `regia_net`; `regia_editor` depends on `regia_net`; `regia_net` has an optional dependency on `regia_audio`.
- Characters: `movement_step` is a loop around `step_character` (characters written one at a time).
  `RapierCharacterQuery` applies no push impulses while `NetResimulating` is set, and a `NetCharacter` autosteps
  dynamic bodies. With `NetCharacterPlugin`, `NetSet::Apply` runs before `PhysicsStep` and `NetSet::Predict` after it.
  `regia/net` turns on `regia_framework/net`.

### Rendering

- Desktop High and Ultra frames with 2048 or more GPU-driven depth instances cull their depth prepass in two phases.
  The image is unchanged; GPU cost moves (one more pyramid build, two small dispatches, fewer prepass vertices).
  `FrameDrawCounts::depth_prepass` counts one draw per batch and phase.
- Dynamic GI under the Depth option: cascade 0 of every tier (and the coarser cascades at 8 layers, Low and Medium)
  sit differently in height, and a probe ray's hit reads its own cascade or finer, never coarser. A host layout whose
  coarsest cascade is 3 m or finer keeps its old placement. A camera walking 0.25 m a frame holds the light better on
  Low (error 2.312 to 1.679) and about the same on High (1.293 to 1.274).
- A frame that writes more than the staging cap makes one more submit per cap and may wait for the previous one.
  `lookdev::cooked_runtime::render_model_owned` takes meshes by value; `pak_load_bench load --frame` uses it.
- `PtSettings::max_bounces` is clamped to `MAX_PATH_VERTICES` (1024) instead of 64.
- `ui-overlay.wgsl` gains kind 6 and the entry points `vs_blur` / `fs_blur`.
- Entry streak shed pieces (2 to 20 cm) break off one after another, fall back along the flight path by drag, glow
  from their own heating (at most 0.4 of the head), cool from white to orange, and fade at the end of a 2 to 4 s life.
  Each is drawn as a short soft streak along its velocity; the wide halo layer is gone. The head, wake and trains are
  unchanged bit for bit.

### Content, assets and audio

- The cook now cooks `.wav`, `.ogg`, `.flac`, `.mp3`, `.dds`, `.tga` and `.bmp` (before: `unsupported extension`).
  `editor.import` accepts them. `regia package` no longer ships `.dds`, `.tga` and `.bmp` raw beside their cooked
  forms; sounds still ship raw.
- Non-square textures cook a full mip chain down to 1x1 (a 16x4 image has 5 levels, was 3), desktop and Android. The
  KTX2 writer sizes levels the same way.
- Paths are confined to the project (ADR-1897): a glTF URI, a Tiled image, an FBX texture and a glass-crack stamp must
  stay inside the project above the referencing file; a URI with any scheme but `data:` is refused.
  `level.export_bake` answers `export_path_invalid` outside the project. A chunk's `file` must be a unique bare name
  that is not a Windows device name. The tilemap cook keeps tileset images inside the project.
- `https://` content fetches do not follow a redirect to `http://`. An Android store pack already on the device is
  hashed before mounting; one that fails is removed. An Opus or Vorbis header past 8 channels is refused.
- `regia loc pseudo` refuses `--to` equal to `--from`, and an existing locale other than `en-XA` without `--force`.
- `DefaultPlugins` (feature `ui`) adds `DialoguePlugin`. `captions.set_options` `persist` writes the settings. The
  caption clock follows the audio sample clock while output runs. A gap between cues shows nothing. `regia loc
  compile` shares its writer with `regia package` (output unchanged).
- A level holding a `Spline`, `Shape`, `RoadOf`, `ProcGenAnchor`, `PaintedPoints`, `BiomeArea`, `ProcGenerator`,
  `InstancedMeshSet` or `FunctionalTest` with a newer `format_version` leaves that component out with a warning (kept
  for the next save under the editor's `Preserve` policy).
- Saving a level refuses holes or paint unsaved on two terrains.
- Grid samplers treat a rectangle as half-open; `max_points` of `sample.poisson` is a cap per run.
- The cooked sound's loudness record counts as `audio` (presentation) in the server-package manifest, not gameplay
  data, so a sound edit no longer moves the server content hash.
- Voice chat: the live pump follows real time; `AudioCapture` falls back to the device's sample rate and notices a
  fatal stream error; a device removed while self-muted returns to `Muted`; `AudioOcclusion::set_extra_rays`.

## Fixed

### Networking (ADR-1892, ADR-1901, ADR-1957)

- A public relay was a UDP reflector (a 5-byte forged `ListGames` sent about 33 KB to the victim): answers are no
  larger than requests and control traffic is limited per source IP. `Bind` needs the key from `Lookup`, a flow in use
  cannot be displaced, and a host's `Register` and `Publish` always reach the relay. The lobby table is bounded and
  indexed.
- One joined peer could stall the server with tiny messages or records: packets, receives and the inbound queue are
  bounded and excess is dropped before decoding. `ALWAYS_ADMIT` messages stop at the queue bound. The bridge's send
  backlog no longer grows without limit behind a silent peer.
- A forged tick frame could strand a client; far-future tick messages were kept forever; a corrupt frame could spawn
  entities before failing (frames are walked whole first).
- The flood guard, send budget and bandwidth counters assumed 60 Hz. Game messages could evict `PlayerJoined` or
  `PlayerLeft`. A stalled or trickling stream no longer pins its buffer. `client_rate_bytes: 0` no longer paces
  streams at one byte per second. Stale packets no longer apply ack fields; to-server types from a server are
  rejected.
- UPnP takes URLs only from the answering host. The manifest diff, ban list, resync history and `AdminOutput` decoding
  are bounded or indexed.
- An unreliable message could be replayed after 8,192 newer ones; an `Accept` before any `Challenge` was taken (a
  plain client now refuses it); a tick sync of `u64::MAX` froze the estimate; an ack past the server tick put entities
  to sleep. Steam: an oversized `JoinRequested.connect` is dropped.
- `Hello.password`, reconnect, join and admin tokens no longer cross a non-loopback link readable by default, and
  connected datagrams to non-loopback peers can no longer be forged by anyone who saw the session token.
- A predicted character that joined after the prediction clock started counted a reset (ADR-2011).
- `max_error_m` of `net.prediction` reports the error on the base for a rider, not the base's lag.
- Unreliable messages shed by the pending cap still count as received.
- `regia_steam --features steamworks` compiles again against `steamworks` 0.13.1.

### Media

- A hostile timestamp no longer overflows `frame_index`; a laced frame's time cannot wrap negative; a symlink cannot
  leave the media root; a stream with no keyframe left or a seek past the last keyframe fails with `decode_failed`.
  `video.seek { frame: 1e19 }` no longer panics or wraps.

## Upgrade: host changes since v0.2.8

### Protocol and wire (upgrade servers and clients together)

- **Old builds cannot join new servers**, or the reverse: `REGIA_NET_WIRE_VERSION` is 2 (`protocol_mismatch`).
  `NET_PROTOCOL_VERSION` is 2 and `MIN_NET_PROTOCOL_VERSION` is new; the replication layer negotiates protocol 1 or 2
  per connection on its first `ACK`.
- **Relay wire format**: requests are padded, `Register` needs a cookie, `HostInfo` carries a bind key, `ListGames`
  names a page. A host sends `encode_register`, answers `RelayReply::RegisterChallenge` with
  `encode_register_with_cookie`, and does the same to renew. `encode_bind(host)` is now `encode_bind(host,
  &bind_key)`. `RelayCore::handle` answers one page; a client that expected all pages must ask for each.
- A new connection gets no state until its first `ACK` on the default channel: servers driven without clients
  (benches) call `ServerReplication::set_wire` or set `replication.state_channel: Reliable`. Tools that expect a frame
  every tick set `replication.send_every_ticks: 1`.
- Many clients on one address (bench, soak, LAN party against a WAN server): set `max_peers_per_ip: 0` and
  `handshakes_per_ip_per_s: 0`.
- `CryptoMode::Off` with a password or admin token on a non-loopback link is refused. `server.key` is a new
  machine-local secret (`docs/formats/server-key.md`): keep it out of version control and across updates.
- A game that registers `HitClaim` must install a `HitClaimPolicy` on the server, or every claim is rejected. It still
  registers `HitClaim` on every process (`app.add_net_message::<HitClaim>()`), as in v0.2.8.
- Tests that forge a frame with a tick far from the stream now end the connection with `ProtocolError`.
- Code that read `PredictionStats::resets` as a count of arrivals should count `NetEvents::spawned`.

## Known issues

### Networking

- `snow` has had no formal audit, and only `chacha20poly1305` among the primitives documents one; an independent
  review is open before release (ADR-1901).
- A client without a pinned key is protected from a listener only (an active attacker can read its password). There is
  no trust-on-first-use store yet. `NetClient` used directly with `CryptoMode::Off` on a non-loopback link sends its
  password proof in the clear (`NetSession` and `session.*` refuse that).
- A NAT rebind drops the peer. Size and timing of traffic stay visible, and an on-path attacker can block a join.
- Attackers in eight or more address blocks can hold the pending handshake table, and a distributed flood can use up
  `max_handshakes_per_s`; forged `ConnectRequest`s in a victim's name can delay its first handshake packet. Connected
  peers are not affected.
- With the interest pipeline a long resync list can leave copies stale until they next change. A malicious server can
  still send large valid frames (bounded by frame size, not entity count).
- Spec 72 § 14's 3 ms send budget: the mean meets it on a shared Threadripper with free cores (2.8 ms), not with busy
  cores (3.85 ms); single ticks go above it (3.4 ms to 7 ms); the idle 8-core desktop is not measured. A state channel
  connection costs about 40 % more bytes than the reliable stream when every entity changes every tick (19 KiB/s
  against 14 KiB/s for 64 entities). `session` does not carry `NetNode` frames yet.
- The real Steam lobby and sockets path is compile- and clippy-checked only; Steam's list order and callback timing
  are not deterministic; Steam member data is read by key.
- Net characters: jumping off, landing on and losing a moving base are smoothed corrections; `CharacterMovement`
  tuning does not replicate; a base's rotation carries position, not facing; montage root motion ignores warp windows
  and live section changes. With spec 72 budgets installed, a deferred delta of a predicted entity costs a correction
  (ADR-1793 (10)). The spec 73 § 14 Pixel 6 budget is not measured.
- PIE clients have no world or viewport (corrections per second and interpolation delay are `null`); the "separate
  processes" mode of spec 77 § 10.4 is not built.

### Dedicated servers

- An Android client cannot join a desktop server on a project with terrain (cooked terrain differs; ADR-1886 (6)).
- With `--agent` or `allow_agent = true` a server links the client crates (ADR-1886 (4)).
- A dedicated server has no extensions, conversations or dialogue line player (they need `client`, ADR-1964).
- A native crash (SIGSEGV) is not mapped to exit code 70. Idle slowdown lowers the tick rate without stretching the
  fixed step. A game cannot refuse `server.tick_hz`. The arena sample has no networked build.

### Voice and media

- `unsafe-libopus` 0.2.0's own concealment pins SILK output at full scale. Voice chat never calls it, but
  `regia_media::opus` has no gate yet: a crafted WebM with 1-2 byte Opus packets can play full-scale noise (ADR-1911).
- Echo cancellation, noise suppression, automatic gain and the editor panel are not built; chat voices get no
  propagation medium or HRTF; sustained loss on a very periodic signal rings (a -12 dBFS tone at 10 % loss peaks near
  0.7). Not yet run with a real microphone on each platform or the Android prompt.

### Rendering

- Dynamic GI: the top of a room taller than the finest cascade's span still catches light (a sealed 6 m room reads 7
  to 11 % on its ceiling); after a camera at 0.5 m a frame stops, the light takes longer to return; GPU cost is not
  measured on hardware (on lavapipe about 15 % of the High probe update in one scene).
- Two-phase occlusion: no GPU measurement yet; its pipelines are made on warm-up frames only for levels that reserved
  a dense view. Shadow views and the visibility buffer as a preset default are not covered. The color pass's Hi-Z cull
  projects without the TAAU jitter (no difference found in eight jittered frames; ADR-1887 (7)).
- Staging flush: the load-RSS A/B is not measured yet; the asset server still keeps every cooked texture
  `regia_render::cooked_model` loads.
- Backdrop blur compiles on its first frame (not in warm-up); surfaces without `COPY_SRC` show only the tint; no
  golden.
- The real-time cloud model lights the ground up to 3.3 stops less than the path-traced reference under a moderate
  layer (ADR-1834); the traced slab is noisy beyond optical depth about 10.
- Entry streak: dust does not visibly fade between f1100 and f1250 of shot 3; gravity on slower pieces is neglected;
  shot 3 shows one to three pieces with the default `shed_count` of 6.

### UI, localization and input

- `spawn_ui` ignores every root-node field except `style` and `children` (the designer lint reports
  `root_field_ignored`). The designer preview is schematic; saves drop comments; no collection item templates.
- A 200-character cue on a measure-cache miss takes about 280 us against spec 36's 100 us budget; `one_at_a_time` in
  `.subs.ron` has no effect; system captions are verified by review only.
- Rebind panel labels are literal English; per-binding modifiers are dropped on rebind.
- The gesture recognizer is not fed from platform `TouchInput` automatically.

### Content, audio and tools

- `loudness.ron` is not packed; a playing voice keeps its gain when the switch flips; K-weighting uses 48 kHz
  coefficients at every rate. DDS cube maps, volumes, arrays, signed BC4/BC5 and BC6H are refused.
- Chunked packing leaves out assets that match no chunk (`regia cook` does not chunk yet).
- Sequencer: audio sections are 2D and follow the mixer clock (no time scale); sub-sequences do not loop; no dope
  sheet; a clip section on an `Animator` with `Lod` or `WhenVisible` blends over the last pose on skipped frames.
- Demos: a seek does not restore clocks or action phases; catch-up runs `First`, `PreUpdate` and `FixedUpdate` only; a
  seek rebuilds `Children` in entity-id order; no sample uses `DemoWorldPlugin` yet.
- Extensions: Windows and macOS do not check that the editor links a dynamic `std`; `params_schema` is not enforced;
  typed `AssetServer` loads do not call extension loaders; `ext://` references are found by text scan; `plugin.reload`
  of an extension that calls `add_plugin` answers `restart_required`; `toolchain_mismatch` is reserved.
- DCC feed: Windows has no named pipe (loopback TCP or WebSocket with the token).
- `fuzz.run` blocks its frame (5000 iterations at most); no `cargo fuzz` job yet (ADR-538).
- Navigation: destructible chunks reach the navmesh as bounding boxes; the streaming runtime's `nav` gate is not
  wired; the grid does not grow; costs change routes, not speed, and act between polygons only; areas are painted by
  volumes; lanes are authored, not generated; stopped lane agents block narrow lanes.
- Releases and paks are hash-checked, not signed (ADR-1957). `steamcmd` takes the password on its command line. A long
  C library call in Lua is one instruction. `TerrainHoleCommand` cannot fail an undo step. `editor.import` still reads
  any file (ADR-1816). Tiled prefabs repeat their `{index}` names per cell. A panic inside a render-out frame does not
  restore the clock or mixdown. The plugin API Highs of ADR-1897 are open.

### Engine

- Systems that spawn or despawn through `Commands` with no order against a sync point apply at whichever sync point
  follows (order them; see the determinism book page). `PhysicsWorld::remove_body` removes joints in `HashMap` order
  and `sync_2d_removed` in `Entity` order.
- Pinned determinism traces exist for Linux x86_64 only; Windows, macOS and Android report the missing file and pass.
- `geom::ellipse::Circumference::len()` truncates a fractional resolution; `PointHash` saturates past the `i32` key
  range; `DenseGrid3::new` multiplies unchecked; circ easings turn NaN into a finite value; terrain `agreement_flag`
  treats a NaN delta as in bounds.
- `lane/sprint-ui-d16` was not merged (main has its own `regia_ui::icons`, ADR-865).

## Golden changes

- No reference image was re-blessed for this release. Frames with dynamic-GI probes on change slightly near and above
  the eye under the Depth option; the merge note says goldens with probes may move (not updated). Renders and hashes
  that include entry-streak pieces change (showcase shot 3, about frames 480 to 960). Two-phase occlusion leaves the
