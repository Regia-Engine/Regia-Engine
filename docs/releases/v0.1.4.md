# Ferrite v0.1.4

Patch release for Direct Order 27's alpha (Saturday 2026-10-17). Fixes from the owner's first play of DO27 v0.0.2 on an RX 7900 XTX
(RADV), plus expanded telemetry.

- **Commit:** v0.1.4 = the tag `v0.1.4` (the gated code commit is named in the tag message).
- **Workspace version:** `0.1.4`.
- **Upgrade from v0.1.3:** to get the new per-system and host-span timings, add `.with(ferrite::frame_profiler())` to a custom tracing
  subscriber (`ferrite::run_with` does it) and forward Ferrite's `frame_summary` data into the host log. No other host changes.

## Fixed

### White lines and dots around moving things (TAAU), owner report on RADV
Detector over DO27's 7900 captures (v0.1.2, HUD masked): still frame 1 white spike pixel, panning ~4900/frame (max 7640, up to 149 lone
white dots), on scatter-rock edges and the skyline against Bore Twelve's black sky. Three causes, all fixed (ADR-160/TAAU notes):
1. **Motion sharpen** (`taau_sharpen.wgsl`): its overshoot margin was relative to the taps' log range with a 1e-8 floor, so edges against a
   black sky were brightened ×9–×84. The margin and brightening are now capped (≤ +25 %), floor 1e-4.
2. **Velocity occlusion**: the velocity pass did not depth-test against the scene, so moving geometry behind a wall wrote its motion onto
   the wall. It now discards fragments behind the scene depth (with an absolute slack for far geometry), on the instanced, graph and
   visibility-buffer paths.
3. **Firefly / NaN guards**: TAAU blends with Karis 1/(1+L) weights; NaN/Inf are zeroed by a bit-level test (not `max(x,0)`, whose NaN
   behaviour differs between drivers) on the current sample, history and output, clamped below half-float max. Same guard in the forward
   output, the bloom input, TSR, SSSR and FSR3.
Tests reproduce each bug (fail before, pass after). The RX 7900 GPU suite (98 binaries, 1171 tests) passes on these shaders.

### CPU frame cost with GI probes (Desktop High/Ultra)
`ddgi prepare` walked every vertex of every drawn mesh twice per frame; mesh bounds are now cached per mesh key (pixels unchanged).
RTX 5090, 3840×1600, do27_chase: `render_into` p50 10.2 → 2.6 ms (p99 38.8 → 17.0); with 170 moving units 10.5 → 4.3 ms
(p99 44.7 → 21.2). Frames over 2× p50 with units: 14.2 % → 2.1 %.

## Telemetry (ADR-178, additive `frame_summary` fields)
- `frame_breakdown_ms`: main-thread ms per phase (each ECS schedule, extract, render, pacing, outside-update, host-run schedules), with
  `render_split` (acquire, render_into, tail, present, other); parts sum to `sum_ms`, `frame_ms` and `unaccounted_ms` explicit.
- `top_systems`: the 10 costliest ECS systems (mean/p95/max ms). `bevy_ecs` `trace` is enabled workspace-wide for this.
- `churn`: creations and pipelines by label, uploads by source, cache growth. `counts`: instances, drawn, per-object draws, lights,
  shadow casters, culled, entities.
- `host_spans`: spans whose target starts with `do27::` (configurable once via `set_host_span_prefixes`) timed by name, main thread
  apart from other threads, explicit `unattributed_ms`. Hitch events carry the frame's breakdown, top systems and host spans.
- Overhead: ~0.04 ms/frame for 300 systems; the telemetry step 0.7 µs, no allocations.

## Known issues
- **Merge gate (2026-10-12) passed except three explained items**, recorded here instead of loosening tests:
  - `ferrite_terrain` `scatter_detail_pops::screen_size_fade_does_not_pop` fails on the RTX 5090 GPU pass (faded 5 vs control 2). The
    screen-size fade pops 5 tiles on every build including v0.1.3; v0.1.4's TAAU fix made the distance-fade control smoother (3 → 2),
    which tightened the relative bar. Passes on lavapipe (the golden reference). Fix in v0.1.5 (lane v015-scatter-fade).
  - `ferrite_editor` `hot_reload`: hung beside other binaries under farm load, was killed mid fixture edit, and the alone rerun saw the
    stale fixture; with the fixture restored it passes.
  - `ferrite_render` `pipeline_warm::tests::shutdown_joins_the_workers_and_releases_the_device`: failed once under heavy farm load
    (queue `Arc` count 2 vs 1 right after shutdown); passes 5/5 alone. Follow-up: find the helper thread that can still hold the
    queue for a moment after `shutdown()` returns.
- The owner's log showed ~33 ms/frame outside `render_into` with ~190 units: host/ECS work (DO27 investigating with the new spans).
- A host that replaces a mesh `Arc` every frame uploads a new vertex/index buffer each time (cache keyed by `Arc` address, entries kept
  600 frames). Keep mesh `Arc`s stable. Buffer recycling is a follow-up.
- The visual fix for the white dots is verified by tests and the 7900 suite, not yet by a fresh in-game capture on the 7900 (pending).
- Everything listed under v0.1.3 still applies.
