# Ferrite v0.1.2

Patch release for Direct Order 27's alpha (Saturday 2026-10-17). Fixes only; no new features (owner, 2026-10-11).

- **Commit:** v0.1.2 = the tag `v0.1.2` (the gated code commit is named in the tag message).
- **Workspace version:** `0.1.2`. `ferrite package` writes `engine: 0.1.2` into `build_info.json`.
- **Upgrade from v0.1.1:** no host code changes are required. Regenerate shipped pipeline caches with the v0.1.2 binary (the version
  is part of the cache key).

## Fixed

### Quit during a pipeline warm is fast and safe in shipping builds (ADR-170 addendum)
- In v0.1.1 a shipping build (`panic = "abort"`) could not stop a warm early: a quit during a cold first launch waited 2 s + up to 5 s,
  and on very slow devices (software rasterizers, VMs) a warm that outlasted that window could **crash (SIGSEGV) or hang at exit**.
- Every engine warm now checks `ferrite_render::warm_cancelled()` between compiles and returns normally. Encode segments that a frame
  left unjoined are finished on the frame's own thread before it returns, so no device reference outlives shutdown.
- RTX 5080, real `--profile shipping`: quit during a warm → `main` returns in 11–53 ms (up to ~1.5 s when the forward uber-shader
  compile is in flight). Intel Arc (ANV) quits during a cold warm took 7.5–9 s in v0.1.1.
- Host warm jobs that loop over their own pipeline builds should call `warm_cancelled()` (host checklist).

### GTX 1080-class cards: terrain virtual texture on by default at Low (ADR-157 / ADR-117 addenda)
- Desktop Low on a discrete GPU with ≥ 6 GB VRAM, **NVIDIA or Intel, on Linux**, now uses the terrain virtual texture.
  Not on Windows (no Windows driver measurement yet) and not on AMD (no RADV measurement yet); Medium, High and Ultra are unchanged.
- GTX 1080, 1920×1080, Low: Switchbacks 39 → 76 fps p50 (1 % low 24 → 43); Bore Twelve 75 → 100 fps (35 → 57). VRAM +671 MB atlas
  (card peak ~1.9 GB of 8 GB). Intel Arc Pro (BMG G31), Low: Switchbacks 57 → 93 fps, Bore Twelve 98 → 115.
- The VT pages now store the terrain horizon slopes ("map E"), so shadowed walls keep their darkness and relief (SSIM vs. VT-off
  0.983–0.997). Fine cracks are slightly softer (ADR-117 texel pre-filter, known limit).
- The VT cache ignores sun-direction changes under 0.1° (hysteresis), so a host that re-sends the same sun every frame (DO27) keeps
  its cache. A real time-of-day sun re-bakes every 0.1° of travel.
- Opt out permanently with `TerrainSharedDraw::set_virtual_texture`; the lever is re-applied on every switch to Low.

### Terrain map-edge seam
- A thin dark line along the far map edge (all GPUs, with VT on) is gone: the VT bake clamps texels past the edge onto it.

### Intel Arc auto-quality (first launch)
- New measured row for the Arc Pro BMG G31 (8086:e222) at **Low**; Arc B580/B570/A770/A750 move from Medium to **Low** (by class:
  the bigger G31 reaches only ~60 fps at Medium on ANV); Pro B50/B60 ("bmg g21") now match a row instead of the VRAM fallback.
- Intel Arc on v0.1.1 had no player-facing blocker (full sweep: `.claude` report arc-sweep).

### United States English
- All user-facing text (UI, perf overlay, crash/feedback notices, error and log messages, CLI output, agent-protocol messages, user
  guide) uses US spelling (owner request). Public API identifiers are unchanged in this patch.

## Known issues
- Intel Arc cold first launch is slow (~29 s to the first frame: ANV shader compiles; later launches 2.5 s). Shipped pipeline caches
  do not cover Intel.
- Terrain VT on maps with hole cuts: cut nodes shade without VT, so a slight look step at node edges is possible.
- Everything listed under v0.1.1 known issues still applies except the shipping quit-during-warm wait.

## Not in v0.1.2 (parked until after 10-17, owner: fixes only)
Zero-copy pak streaming (~40 % faster map loads measured), the install/update "prepare" step, build profiles, Windows VM GPU testing.
