# Regia Engine v0.2.6

Builds on v0.2.5. This release adds these feature sets for game teams:

- **Procedural content graphs**: the new `regia_procgen` crate (point sets with attributes, `.pgraph.ron` graphs and
  `.pgvar.ron` variants, a deterministic evaluator, 92 built-in node types, generators with a run lifecycle, `.pgout`
  bakes, detach to level content) and the editor's **Procedural Graph** panel with live preview and Paint and Box
  placement tools.
- **Gameplay data**: curve tables (`.curves.ron`, `.curves.csv`), choosers (`.chooser.ron`), and abilities,
  attributes and effects (`.ability.ron`, `.attrs.ron`, `.effect.ron`).
- **Content delivery and level storage**: content chunks with one pak per chunk, a content manager that downloads,
  verifies and mounts chunks, DLC checks, per-entity level directories, data layers and placed levels.
- **Networking**: relevance, priority and per-tick send budgets for replication, `.netprofile.ron` profiles, and proxy
  interpolation on clients.
- **XR**: the new `regia_xr` crate (session lifecycle, action manifest, tracking spaces, comfort turning, hand
  snapshots) with a scripted simulator backend; the OpenXR binding itself is not built yet.
- **Testing and diagnostics**: in-level functional tests with `regia test` and a multi-process session harness; GPU
  breadcrumbs that name the passes in a device-lost crash bundle; a trace recorder with `regia trace export`.
- **Library layers** for the DCC scene feed protocol and the extension (plugin) manifest resolver.
- **Editor**: picks over GPU panes without a full-frame readback, an optional collision-node layer for glTF models,
  and the Wayland quit crash fixed.
- **Safety and determinism**: agent and editor requests that take file paths are confined to the project and its
  allowed roots; debris lifetimes run on the physics clock; entity order is fixed wherever order reaches the
  simulation; parsers refuse non-finite and overflowing input.

All new features are opt-in, or unchanged for projects that do not use them, except where **Changed** and **Upgrade**
say otherwise (the default-on `procgen` feature, path confinement, the debris clock, entity order).

The text below consolidates the `v0.1.28-*` release fragments of the lanes merged after v0.2.5 and the integration
notes (ADR-1659, ADR-1695, ADR-1829). The lanes: `editor-quit-sigsegv`, `rr-render-out-notes`, `pane-pick-gpu` and
`collision-layer-option` (merged in `integ-fixes-v026b`), `fix-audit-findings`, `b9-curves-abilities`,
`b12-procgen-core`, `b29-procgen-editor`, `b16-net-b`, `b21-chunks-levels`, `b23-dcc-plugin`, `b25-breadcrumbs`,
`b27-functest-harness` and `b30-xr-gaps` (merged in `integ-v027`), then `audit-fix-procgen-loc` and
`gate-fix-level-build` (merged in `integ-v027-final`). The tag's gate ran 5,654 GPU tests and 12,881 lavapipe tests
with 0 failures.

Read **Upgrade: host changes since v0.2.5** first if you build a game or a shell against the engine crates.

## New

### Procedural content graphs (specs 62 and 63, ADR-1640)

- **`regia_procgen`** (layer 3; `regia::procgen` behind the default-on `procgen` feature, `ProcGenPlugin` in
  `DefaultPlugins`).
  - **Data:** `PointSet` (built-in position, rotation, scale, color, density, seed, box, hardness plus typed attribute
    columns), `Table`, shape and ground regions, `DataItem` with tags and item scope, `Bundle`, selectors (`name`,
    `item.name`, `position:y`, `$prev`).
  - **Graphs:** `ProcGraph` / `ProcGraphVariant` files read and written byte-identically, parameters with
    `Bind("name")`, variant chains (≤ 8, cycles refused), compile with every error in one pass, Kahn evaluation
    order, and a graph hash that ignores canvas positions, notes and reroutes.
  - **Evaluator:** a pure function of the compiled graph and a `WorldSnapshot`; limits (`limit_exceeded`),
    cancellation, a NaN check (`attr_nan`), bypass, inactive branches, an LRU node-output cache, run reports.
  - **Determinism:** `detmath` (`sin_cos`, `atan2`, `exp2`, `log2`, `pow` without the platform libm), scalar
    quaternions (`rot::Rot`), PCG32 draws keyed by element seed, node seed and slot; the acceptance graph's output hash
    is recorded in the test source.
  - **Nodes (92 types):** inputs (`in.self`, `in.ground`, `in.entities`, `in.table`), samplers (`sample.ground`,
    `sample.region`, `sample.poisson`, `gen.*`), density, point operations, filters and regions, items and tags,
    attributes and tables (including `attr.lookup`), control flow (`flow.if/choose/quality`), subgraphs (`graph.call`
    with recursion, `graph.loop` with carry pins, `graph.input/output/loop_index/depth`), debug, spawning
    (`spawn.mesh`, `spawn.prefab`), outputs (`out.table`, `out.points`), reads of other generators
    (`in.generator_output`, which orders the runs), masks (`in.mask`, `out.mask`), meshes (`in.mesh`,
    `sample.mesh_surface`) and physics queries (`in.rays`, `in.overlap`; overlap tests collider bounding boxes,
    ADR-1640 (12)).
  - **Override pins** (spec 62 § 4.1): an edge into `@<setting>` feeds the setting from a `Table` (row 0);
    `override_invalid` when it does not convert.
  - **Drawing:** `draw::extract_proc_instances` puts instance sets (and saved `InstancedMeshSet`s) on the frame as
    shared-mesh instances, culled by draw distance and faded over `fade_m`; meshes come from `draw::ProcMeshLibrary`.
  - **Detach:** `InstancedMeshSet` (saved component, `procgen-instanced-set` v1) and `world::detach`: generator output
    becomes ordinary level content.
  - **Generators:** `ProcGenerator` (saved, `procgen-generator` v1), `ProcGenState`, `ProcOutput`, `ProcOutputRoot`;
    states `idle` … `cleared`; messages `ProcGenStarted`, `ProcGenFinished`, `ProcGenFailed`, `ProcGenCancelled`,
    `ProcGenCleared` (`Cancelled(old)` always precedes `Started(new)`); staleness from read entities, tag queries,
    ray-hit and overlap colliders and the new `ProcTerrainEdited` message; spawned prefab entities under one output root
    carry `Generated`.
  - **Painted points:** `regia_procgen::painted::PaintedPoints` (saved, `procgen-painted-points` v1); `in.self` emits
    them as a second item tagged `painted` with the integer attribute `layer`.
  - **Bakes:** `.pgout` v1 (magic `RPGO`), written atomically with the `pipeline` feature, loaded with the level without
    running the graph, re-hashed on load (a hand edit fails), `verify` re-runs and compares hashes.
  - Also: `ProcGraph::node_pins`, `world::evaluate_detached`, `NodeKind::reads_world` and
    `WorldSnapshot::content_hash` (provided methods; see **Upgrade**).
- **`regia_core::math::hash`**: `pcg_hash` and `mix` (same output as the terrain grass hash; a test pins it).
- **`regia_scene::components::Generated { generator, run_id }`** marks generated entities; `snapshot_scene` (level
  save) skips them.
- **Agent methods** `procgen.list`, `procgen.get`, `procgen.run` (`wait`, `keep_debug`), `procgen.cancel`,
  `procgen.clear`, `procgen.report`, `procgen.inspect`, `procgen.graph_get`, `procgen.graph_edit` (16 ops, unsaved
  overlay or `save`), `procgen.node_types`, `procgen.bake`, `procgen.verify`, `procgen.detach` (editor); guide topic
  `procgen`; page `book/agents/procgen.md`.
- **CLI** `regia procgen graph check <file> [--project DIR] [--json]`.

### Gameplay: curve tables, choosers, abilities (specs 51 and 53, ADR-1649)

- **Curve tables** (`regia_framework::curve_table`): `CurveTable` holds named float curves (`.curves.ron` v1,
  `.curves.csv`): step, linear or cubic Hermite interpolation per table, curve or key (cubic tangents derived at load
  with the Fritsch-Carlson limiter, so monotone keys never overshoot; explicit tangents win), and hold, linear,
  cycle, cycle-offset or ping-pong extrapolation per side. `sample_named`, `CurveHandle`, `range`, validating edits,
  RON and CSV import/export that round-trip; the `CurveTables` resource, `app.register_curve_table(path)` with hot
  reload (a reload applies only when it loads), `CurveRef` for data-table rows.
- **Choosers** (`regia_framework::chooser`): `ChooserTable` (`.chooser.ron` v1) with declared inputs and outputs, gate
  columns (bool, int and float ranges with circular wrap, enum, name, tags, asset), distance rank, weight and emit
  columns; `First`, `Best`, `Weighted` (one `Rng::f32` per draw, `near_best`, recency penalty) and `All` modes; nested
  `Chooser(..)` and `Inline(..)` results, catch-all, `evaluate_traced` with a per-row, per-cell trace, and the spec's
  validation codes. The `Choosers` resource with hot reload, `ChooserBinding` components re-evaluated `OnChange`,
  `EveryTick` or `Manual` in `ChooserSet::Evaluate` with providers from `app.register_chooser_provider(name, fn)`, the
  `ChooserPicked` message, `ChooserTraceLog` and `ChooserStats`. `ChooserBridgePlugin` plays `montage` picks on the
  entity's `MontagePlayer` (with `rate`, `section`, `start_time`) and `cue` picks through `Audio::play_cue`.
- **Abilities, attributes and effects** (`regia_framework::abilities`): `Attributes` (base and current, clamps,
  `max_from`, derived values); effects (`.effect.ron` v1: instant, timed, until removed; pulses, stacking, status tags
  with counts, conditions and suspension, immunity, cleanses, chains, chance); abilities (`.ability.ron` v1: grants,
  the ready/running/ending state machine, requirements, cost, cooldown, cancel and block, triggers, signals, input
  codes, picks); cues; `.attrs.ron` v1; the fixed-step `AbilitySet` schedule; `HealthBridge`. Curve amounts read
  `CurveTables` by asset path.
- **Agent methods**: `curves.*` (11, `install_curve_table_methods`), `chooser.*` (14, `install_chooser_methods`),
  `abilities.*` (17, `install_ability_methods`). Pages `book/agents/curve-tables.md`, `choosers.md`, `abilities.md`.

### Content chunks, level directories, layers, placed levels (specs 40 and 37, ADR-1667)

- **Content chunks** (`regia_asset::content`, `regia_asset_pipeline::chunks`): `[cook.chunks.<name>]` rules in
  `Regia.toml` (globs, tags, priority, delivery, requires, follow, overrides, pin; `[cook.chunk_options] shared`)
  assign every cooked asset to a chunk deterministically, with a reason per asset. `regia cook` and `regia package`
  write one pak per chunk, `content-manifest.ron` (v1) and `chunk-map.bin` (v1); an unchanged chunk keeps its pak.
  Reference checks fail the cook (`chunk_base_reference`, `chunk_unlisted_reference`, `chunk_cycle`). Chunk assignment
  over 100,000 assets and 564,455 edges takes 255 ms (dev profile).
- **Content manager** (`ContentManager`, `ContentPlugin`): per-chunk states, requests with requirements first, summed
  progress, priority tiers, `max_concurrent`, metered approval, pause/resume/cancel with `.part` resume, BLAKE3
  verification, mount in manifest order, unmount (refused while a load set pins the chunk unless forced), release,
  `NeedsUpdate` after a build change, DLC base checks (`chunk_base_mismatch`), deterministic fault injection. Sources:
  the content directory, a directory laid out like a static host, and `http://` (a std-only HTTP/1.1 client with
  `Range` resume). Transfers are stepped by byte budgets, so tests are reproducible.
- **Unavailable assets**: an asset of an unmounted chunk loads as `LoadState::Failed("unavailable:<chunk>")`;
  `AssetServer::unavailable_chunk(id)` names the chunk.
- **Packaging**: a level directory ships folded into one `.level.ron`; `--platform android` cooks check the store pack
  rules (`pack_name_collision`, at most one fast-follow pack, `[content] android_pack_limit`) before any build step.
- **Level directories** (`regia_scene::level_dir`, format `level-dir` v1): `<name>.level.d/` holds `level.ron`
  (resources) and one `entities/<2 hex>/<guid>.entity.ron` per entity, so version control merges per entity. Saves
  rewrite only changed files; the cooked scene is byte-identical for both forms.
- **Data layers** (`regia_scene::layers`, `.layers.ron` v1): layer definitions, per-level bindings (`LevelLayers`),
  `LayerMembership`, `LayerTable` with `Absent` / `Parked` / `Live`, parent clamping, recursive requests, `peers`, the
  lowest-state rule for multi-layer entities, `LayerChanged` messages, switching in `PostUpdate` before transform
  propagation.
- **Placed levels** (`regia_scene::placed`): `PlacedLevel` places a saved level as one transformed object, inline
  (stable blake3-derived guids, layer filters, inherited membership) or streamed (`PlacedLevelLoaded`); cycles, depth
  and size limits refuse with `placed_cycle` / `placed_limit`; `break_placed` turns an instance into plain entities.
- **CLI**: `regia assets chunks`, `regia assets why <asset>`, `regia content dlc --name <chunk> --against <dir>`,
  `regia content serve <dir>` (a test and tooling file server with `Range` support), `regia level split|merge`.
- **Agent methods** `content.chunks`, `content.chunk`, `content.why`, `content.request`, `content.progress`,
  `content.pause`, `content.resume`, `content.cancel`, `content.approve_metered`, `content.mount`, `content.unmount`,
  `content.release`, `content.set_source`, `content.inject` (page `book/agents/content-chunks.md`); `level.storage`,
  `level.convert`, `level.layers`, `level.set_layer_state`, `level.set_membership`, `level.placed`,
  `level.place_level`, `level.break_placed` (page `book/agents/levels-layers-instances.md`).

### Networking: relevance, budgets and interpolation (specs 72 and 74, ADR-1662)

- **Relevance, priority and send budgets** in `regia_net`, opt-in with `regia_net::install_net_interest(world)` on the
  server:
  - The relevance pipeline (`regia_net::relevance`): owner rule, denies (`NetVisibility`, `NetGroupVisibility`),
    `owner_only`, grants (`sent_to_all`, the `follow_parent` link rule, temporary grants with
    `net_grant_relevance(world, entity, GrantTarget::Peer | Group, until_tick)`), the allow list, `group_required`,
    spatial interest around `NetViewpoint` entities with hysteresis, and custom filters
    (`app.add_net_relevance_filter::<F>("name")`, `NetRelevanceFilter`). Losing relevance lingers `linger_ticks`. A
    shared uniform interest grid over XZ (`replication.grid_cell_m`) gives each connection its candidates.
  - Priority accumulators per (connection, entity) with distance, view-cone and owner factors; `min_interval_ticks`
    and `max_interval_ticks`; a byte budget per tick from `client_rate_bytes` with one tick of carry-over and the
    `server_rate_bytes` total cap; `spawns_per_send`; deferred deltas are encoded again next tick, nothing is lost
    (`regia_net::send`). Entity state over 16 KiB is not sent (`net.state_too_large`).
  - Resync requests: 10 per second per client; three for one entity within 5 s log `net.resync_loop`.
  - **`.netprofile.ron`** (`NetProfile`, `format_version` 1, `docs/formats/netprofile-ron.md`,
    `docs/formats/netprofile.schema.json`): `regia_net::profile`, `NetProfiles` (built-ins `default`, `player`,
    `projectile`, `prop`, `held`, `game_state` under `engine://net/profiles/`), field-level validation, `NetProfileRef`;
    entities name a profile in `Replicated.profile`.
  - `why` / `brute_force` on `NetInterest` for diagnosis; per-connection counters and 5 s bandwidth windows by
    component and by entity. Example `net_relevance_bench`.
- **Proxy interpolation** in `regia_net::interp`, opt-in per client with `NetInterpolationPlugin` (or
  `interp::install_interpolation`):
  - `InterpClock`: server-tick estimate from arrival times, jitter, adaptive delay with asymmetric clock-rate control
    (+10 % / −2 %), resync on stalls (`net.interp_resync`), monotonic `interp_tick` (drives `NetInterpTick`, so
    `ALIGN_TO_VIEW` messages wait for the shown tick).
  - `SnapshotBuffer` / `NetSnapshotBuffer`: Linear or Hermite blend, snaps on the teleport bit or past
    `snap_distance_m`, the gap rule, extrapolation up to `max_extrapolate_ms` then `NetStarved`, a decaying recovery
    offset.
  - Step components apply when the interpolation tick reaches their tick (`NetStepQueue`); components registered with
    `app.interpolate::<C>(lerp)` / `interp::register_interpolated` are blended.
  - Spawned proxies stay hidden until their spawn tick is shown; despawned ones carry `NetPendingDespawn` until their
    despawn tick is shown; `appear_immediately` and `interpolation: None` bypass both.
  - View tick: `ViewTickWire` (1/256 tick), server-side `NetViewTick`, `set_view_tick`.
  - `config/net.ron` section `interpolation`; `.netprofile.ron` fields `interpolation`, `snap_distance_m`,
    `max_extrapolate_ms`, `appear_immediately`. Example `net_interp_bench` (500 proxies per frame).
- **Agent methods** `net.relevance`, `net.why_not_relevant`, `net.bandwidth`, `net.set_client_rate`, `net.profiles`,
  `net.grant_relevance` (guide topic `net-relevance`) and `net.interpolation`, `net.proxy_timeline`,
  `net.set_interp_delay` (guide topic `net-interpolation`). New `F0002` reasons: `profile_invalid`,
  `rate_out_of_range`, `interest_off`, `net_not_client`, `entity_not_proxy`, `delay_out_of_range`.

### XR: engine side (spec 58, ADR-1676)

- **`regia_xr`** (new crate, layer 2; `regia::xr` behind the umbrella's new `xr` feature, off by default). `XrPlugin`
  opens the backend named in `config/xr.ron` and drives the session from runtime events: begins the session when the
  runtime is ready, ends it on stopping, tears it down on loss pending and re-creates it after `retry_frames` fixed
  steps, and asks the app to exit when the user leaves. Components `XrRig`, `XrHead`, `XrController`, `XrEye`;
  messages `XrStateChanged`, `XrFocusChanged`, `XrOriginChanged`, `XrRuntimeLost`, `XrInteractionProfileChanged`,
  `XrRefreshRateChanged`; system sets `XrSet::{Poll, SyncInput, UpdateRig, Extract, Submit}`; resources `XrState`
  (app state `Off`/`NoSession`/`Idle`/`Starting`/`Running`/`Focused`/`Stopping`/`LossPending`/`Exiting`, options,
  stats, last error), `XrSession`, `XrActionStates`, `ActionPoses`, `XrHands`, `XrRenderProfile`.
- **Simulator backend**: `XrBackendKind::Simulator` is the scripted `NullXr` plus a `*.xrsim.ron` script player (poses
  interpolate between keyframes, exact at keyframes, so a recording replays bit for bit) and a record mode.
- **Action manifest** `assets/xr/actions.xr.ron` (`format_version` 1): action sets, typed actions with `left`/`right`
  sub-paths, suggested bindings per interaction profile, a default manifest (move, turn, select, grab, primary,
  secondary, menu, grip and aim poses, haptic), attach-once (`xr_actions_frozen`), one sync per fixed step, inactive
  defaults while unfocused, publishing to `regia_input` through `InputInjection` holds, haptics clamped to 0..=1 with a
  soft no-op on devices without haptics, a dominant-hand swap.
- **Tracking spaces and comfort**: stage → local floor → local fallback, recenter, emulated floor from `eye_height_m`;
  snap turn about the head (threshold 0.6, re-arm 0.3, cooldown 8), smooth turn, a motion-vignette strength driven
  only by rig motion, `rig_turn` / `rig_move`.
- **Frame mailbox** (a single-slot sequence lock): extraction never waits; a repeat counts `stats.stale_frames`.
- **Eye targets**: the `EyeTargets` trait and `SimEyeTargets` (two wgpu textures, readback, box-filter resize).
- **Hand tracking snapshots**: 26 joints per hand with validity flags; non-finite joints are rejected.
- `config/xr.ron` and `*.xrsim.ron` (`format_version` 1 each); a newer file is `xr_format_too_new`.
- **`regia_platform::xr`**: the OpenXR session states `Synchronized`, `Visible`, `Focused`, `LossPending`, `Exiting`
  and their transitions; `XrEvent::FocusChanged`; `SimEvent::{Runtime, Controller, ViewConfig}`;
  `XrRuntime::pump_new`; `SessionState::{ALL, from_name, frames_flow, shows_frames, input_live}`, `Transition::ALL`;
  sixteen spec 58 error reasons (`xr_no_loader` … `xr_runtime_lost`).
- **Agent methods** `xr.set_option`, `xr.recenter`, `xr.capture_eye`; `xr.drive` actions `pose`, `input`,
  `session_state` (simulator only, `xr_simulator_only` elsewhere); `xr.get` reports the plugin's fields and can report
  `{ kind: "focus_changed", focused }` events. Page `book/agents/xr.md`.

### Diagnostics: GPU breadcrumbs and trace files (spec 54, ADR-1671)

- **GPU breadcrumbs** (`regia_render::breadcrumbs`, on by default): a ring of per-frame pass markers recorded in GPU
  order, submission counters (`submitted`, `completed`, `acknowledged_frame`) fed by `on_submitted_work_done`, and a
  `BreadcrumbReport` that states its evidence level (`timestamped`, `fenced`, `recorded`, `none`). Pass scopes cover the
  shadow cascades, depth prepass, opaque forward, translucent layers, post, fade overlay and display stage.
- **Device-lost bundles name the passes**: a device-lost crash bundle holds `gpu_breadcrumbs.json` (`gpu-breadcrumbs`
  v1) and a `gpu breadcrumbs:` block in `crash.txt`, and lists the entry in `feedback.json`. `BUNDLE_FORMAT` stays 1.
- **Trace recorder** (`regia_telemetry::trace`): marks, nestable ranges (per lane, 32 deep, forced close), frame and
  pass events in a rolling in-memory window and/or a `.regiatrace` file (`regiatrace` v1).
- **`regia trace export <file> --format jsonl|trace-event`** converts a recording to JSON lines or the public Trace
  Event Format.
- **Agent methods** `render.breadcrumbs`, `telemetry.mark`, `telemetry.range_open`, `telemetry.range_close`,
  `telemetry.trace`, and `render.fault_inject` (only with `regia_agent`'s new `test-hooks` feature). Hosts register
  them with `install_breadcrumb_methods` and `install_trace_methods`. Page `book/agents/gpu-breadcrumbs-and-trace.md`.

### DCC scene feed and extension manifests (specs 60 and 57, ADR-1669; library layer)

- **DCC scene feed wire protocol v1** (`regia_agent` feature `dcc-feed`, off by default; `regia_agent::dcc_feed::wire`,
  `docs/formats/dcc-feed-protocol-v1.md`): the binary codec with `Limits`, a bounded `FrameReader`, a fragment
  `Reassembler`, `encode`, `encode_fragments` and a total `decode` (no panics; every count checked against the bytes
  present and the limits before allocation). `check_vertex_only` reports `topology_mismatch` for a vertex-only mesh
  update whose per-vertex counts differ from the mesh it modifies.
- **`.rfdrec` recordings v1** (`dcc_feed::recording`, `docs/formats/rfdrec.md`): atomic write, total read,
  `replay_corrupt` for bad or newer files.
- **Feed inbox** (`dcc_feed::inbox`): byte-credit window, `overloaded` then close after three, coalescing of
  transform/camera/light/pose frames, vertex-only mesh merge into a pending full update (only when the vertex counts
  match), delete discards pending data.

## Changed

- **`regia` default features include `procgen`.** A game built with default features links `regia_procgen` and gets
  `ProcGenPlugin` in `DefaultPlugins` (it registers the generator types and a lifecycle system in `Update`; a world with
  no generators pays one empty query per frame). New umbrella feature `xr` (off). `regia_dylib` forwards `procgen` and
  `xr`. `regia_agent` has a new default feature `xr` (links `regia_xr`).
- **Agent and editor request paths are confined** (ADR-1816). Methods that take file paths (list in
  `book/agents/safety.md`) refuse absolute paths outside the project, the temp dir, the working dir and
  `output_roots`, drive-relative and UNC paths, and `..` and symlinks leading out. `editor.import` sources,
  `editor.new_project`, `editor.open_project`, `editor.fbx_inspect`/`obj_inspect`, `editor.open_kit`, `editor.bake_gi`
  `scene`, `replay.load` and `demo.*` are unchanged by design. `telemetry.trace` refuses a `file` with `:`;
  content-manifest chunk files refuse `:` and NUL; the DCC extension manifest refuses `..`, `...`, UNC and
  device-name paths. Cook: material-graph parent/function/texture paths stay inside the project; `regia bake-gi
  --from-scene` keeps the level's volume under `assets/`; `regia upgrade-project` never writes through a symlink at
  its staged name.
- **Debris lifetimes run on the fixed-step clock**, not the frame clock: a chunk leaves the solver on the same physics
  step at any frame rate. `DebrisTag::spawn_time_secs` is a physics-clock time (the end of the first step that
  simulates the chunk). A world that never runs a fixed step no longer expires debris.
- **Entity order where order reaches the simulation**: `Changed<Collider>` rebuilds, behavior-tree and state-tree agent
  ticks, platformer handle minting, `overlap()` results, and the sim bridge's spawns of new sim ids (by sim id).
- **State trees**: a tree's `state_key` is cleared (empty string) when the tree finishes or restarts.
- **Damage**: `regia_framework::damage::apply_damage` skips entities with `HealthFromAttributes` (the health bridge
  applies their damage through the attributes), so a hit is never applied twice.
- **Localization**: each `.ftl` file parses on its own, a bad file or locale is logged and left out, and files join
  with a newline. `loc gather` skips keys inside `/* */` comments, accepts any spacing in `loc! (` and a new line
  before the key, and treats `exclude` entries with a trailing `/` or `\` separators as the same folder.
- **Cook and package**: `regia cook` / `regia package` always write `content-manifest.ron` and `chunk-map.bin` next to
  the paks and stage them into `content/`; without chunk rules `base.fpak` is byte-identical to before. `regia package`
  stages non-install chunks into `dist/<platform>/chunks/` (with a manifest copy); `ship_check` expects exactly the
  install chunks in `content/` and rejects `*.level.d`.
- **Asset server**: with a content manifest, listed chunks mount in manifest order before unlisted paks (which keep the
  lowercased file-name order). Without a manifest nothing changes.
- **Net gather**: with the interest pipeline installed, the server encodes each spawn record and update on its own and
  lets the budget pick them; without it the output is unchanged. Tick frames record their message bytes for the next
  tick's budget.
- **GPU submissions**: `TrackedQueue::submit` registers a completion callback per submission while breadcrumbs are on.
- **XR null backend**: `NullXr` reports `should_render: false` while synchronized, and accepts frames, `locate_views`
  and `sync_actions` in every state where frames flow (running, synchronized, visible, focused).
- **Editor**: its GPU device requests the renderer's optional features (it requested none), so the viewport no longer
  reports `fallback_*` problems on adapters that have them. `pick_in_frame` and `pick_hit_in_frame` are thin wrappers
  over the new view picks, and `render_id_buffer` shares its body with `render_id_window`; results and pixels are
  unchanged. Wiring a second source into an unresolvable `graph.call` input keeps the first wire.
- **Validation messages**: `DuplicateIds` names at most 8 other owners of a shared id and adds "and N more".
- **Profiling**: tracing spans on the 2D physics sync, platformer and character-move systems.
- **Manual**: the Regia Engine Manual (`docs/manual/manual.html`) includes every `docs/formats/*.md` page a book page
  links to, after the chapters, under "Format pages"; `cargo xtask manual` resolves such links to an in-manual anchor
  `#p-docs-formats-<name>`.
- **Docs**: the render-out audio length rule (`floor(N * rate * fps_den / fps)`, exact on every timeline; `sim` under a
  real `time_map` follows the nanosecond sim clock and can be one sample under the ideal duration).
- **Dependencies and layers**: `regia_procgen` at layer 3 with a `regia_agent → regia_procgen` same-layer edge;
  `regia_procgen` depends on `regia_physics`; `regia_agent`, `regia_cli` and `regia_editor` depend on `regia_procgen`
  (`pipeline` feature); `regia_framework` depends on `semver`, `toml` and `blake3` (`semver` is new to the workspace
  list, already in the lockfile); `regia_scene` depends on `blake3`; `regia_cli` depends on `regia_framework` and
  `regia_telemetry`; `regia_render` gains `serde_json`, `regia_telemetry` gains `lz4_flex`, `regia_test_utils` gains
  `thiserror` (all already in the workspace). The workspace has 58 members; no third-party version changed.

## Fixed

### Existing features

- **The editor exited with SIGSEGV after `quit.request` on Wayland** (ADR-1655): the `smithay-clipboard` worker (inside
  `egui_winit::State`) was torn down after winit had closed the display connection. The editor now releases surface,
  window and egui-winit state in `exiting`, while the connection is open.
- **Localization**: one `.ftl` file without a trailing newline merged into the next file's first message; one bad
  locale file removed every locale. Pseudo-locale entries keep `has_value` for attribute-only messages.
- **Cook**: the cook deleted any path an edited asset database named.
- **Parsers and non-finite input** (ADR-1660):
  - `.fracture.ron` with a non-finite chunk volume, point or bound is refused (`fracture_format`); it used to become an
    infinite rigid-body mass. `DebrisSpawner` skips a chunk with a non-finite mass.
  - `.flmap`: a huge width or height no longer overflows (a debug panic) before the size cap; a subnormal exposure is
    refused, and a non-finite scale uploads as 0.
  - `.shots.ron`: keys or look-at points past `MAX_PATH_COORDINATE` are refused (the Catmull-Rom phantom point
    overflowed to NaN), and the shot player never writes a non-finite pose to the camera.
  - `regia apk-size`: a zip64 offset near the address limit is an error, not a debug panic.
  - `DemoRecording::verify` on an in-memory recording whose first snapshot keyframe is past its steps is
    `tick_out_of_range`, not an underflow.
  - `spectator.*` and `xr.drive` refuse numbers too large for `f32`, a non-number `yaw`, and a negative `duration_ms`
    (`F0002`). `SpectatorCamera::new` with a NaN pitch limit or swapped follow distances no longer panics.
  - Subtitles refuse a `start + duration` that overflows (the line never expired).
  - `NullXr` ignores a simulated head pose with a non-finite position; a refused `begin_session` while running no
    longer resets the frame index.
- **Fracture tool**: `candidates_per_site` is capped; a `min_chunk_volume_fraction` that drops every chunk is
  `fracture_invalid_settings` instead of an empty set; a mesh with both a doubled edge and a hole names the same error
  every run; joint anchors average both measured sides.
- **2D physics and platformer**: a removal or despawn on a frame without a fixed step is no longer lost.
- **Sim bridge**: a bare spawn no longer inherits the previous view's extras flag.
- **Tests**: `level_build` and `anim_editor` no longer fail with "agent endpoint never appeared" or F0006 when their
  test binary is paged in slowly; the agent script starts when `edit_app` has returned and every call carries a 180 s
  `timeout_ms` (ADR-1824). New tests pin the exact render-out WAV length for several rates, frame rates and frame
  counts.

### Features new in this release (found by the 10-30 audit before the tag, ADR-1816)

- Path escapes in `procgen.graph_get` / `graph_edit` and procgen graph reads; `level.convert` could delete a level

## Known issues

### Procedural graphs

- Instance sets draw only for meshes the host registered in `regia_procgen::draw::ProcMeshLibrary` (`procgen.list`
  `draw.missing_meshes` names the rest); per-instance tint and custom floats are not passed to shaders and
  `cull_below_px` is not applied. No golden image covers the draw path or the editor panel capture yet. Prefab records
  resolve to prefab instances only for `guid:` references.
- `in.overlap` tests point boxes against collider bounding boxes (rotated or concave colliders count as their AABB).
- `in.mask` reads only mask pixels a host supplies; `in.table` reads `.table.ron` (untyped) but not `.table.csv`;
  `in.entities` emits points only.
- Runs evaluate on one thread; the spec 62 § 12 performance budgets are measured by `perf_micro` (hand-run), not met
  or enforced yet. `regia procgen bake` and `regia procgen verify` are not built (the agent methods cover them).
- Cross-platform hash equality has been run on Linux x86_64 only.
- Audit items not done (ADR-1816): M17 (`FromSpline` warning) needs a run-level warning channel; the Lows that change
  recorded output hashes; M1, M5, M6, M16 and the tile part of L2 apply to `tiles.rs`, which is not in this tree.
- Editor: Path and Area tools answer `procgen_tool_unavailable` until spec 64's `Spline` merges; the Box tool writes
  the generator's box bounds instead of a `Shape` component. "Generate around view", the tiles overlay, spline and
  polygon drawing and shipped tool starter graphs are not built. Panel frame cost with a 300-node graph is 6.7 ms on a
  loaded build box (budget 2 ms; `egui-snarl` lays out every node each frame).

### Gameplay data

- Not built (ADR-1649): `clip` picks and the cue position / `volume_db` / `bus` overrides in the bridges, the editor
  Tables panel, postcard cooking of the new formats, spec 53's editor surface.
- Loading a 4,096-row `.chooser.ron` from text takes about 0.5 s (ron 0.12 parses long lists super-linearly); the spec
  51 budget of 20 ms applies to the cooked form, which is not built yet.
- `ChooserBinding` state (its random stream, recent picks) is not saved in save games.

### Content chunks and levels

- No `https://` source yet (`HttpSource` refuses it with `source_not_supported`); `fetch_manifest` has no agent method.
- Android store packs (JNI source, asset-pack Gradle modules) are not built; `check_android_packs` enforces pack names
  and counts at cook time.
- No free-space query (only the injected `no_space` fault fails before writing); verification runs inline, not on the
  I/O pool; level loads do not yet log one warning per unavailable chunk. `content.why` at run time names the chunk
  only; the reason chain is `regia assets why`.
- Parked layer members are hidden but still simulated (`Without<LayerParked>` is not yet in the physics, script, AI,
  picking and render queries). The asset server does not load `.level.d` directories or `.layers.ron` into the level
  and layer libraries yet. No editor surface for layers or placed levels.

### Networking

- Spec 72 § 4 (per-entity version ring, deltas against acknowledged baselines, repeat spawns) is not built: the tick
  stream stays reliable and ordered, so head-of-line latency remains under loss (ADR-1662 (2)). A frame still goes out
  every tick (`send_every_ticks` is read by interpolation only).
- The send loop is far above the spec 72 § 14 budget: `net_relevance_bench` (20,000 entities, 64 connections, ~2,000
  relevant each, 10 % moving) measures about 79 ms per tick on a shared build machine against 3 ms (8 connections:
  22 ms; 2,000 entities and 8 connections: 6 ms). Encoding and packing are serial (ADR-1662 (10)). The
  `net_relevance` gizmo group is not done; `position_step_m` is validated but the transform fast path keeps its own
  encoding.
- Profiles load with `NetProfiles::load_ron` (no asset-server loader) and are not in a content hash or
  `check-formats` yet.
- Hidden proxies keep their colliders and proxy bodies are not kinematic; the view tick does not ride input commands
  yet (spec 73); animation graphs do not read interpolated values yet. The 500-proxy interpolation number (0.08 ms
  mean, 0.28 ms worst per frame) is from a desktop build machine, not the Pixel 6 the spec 74 budget names.

### XR

- The OpenXR binding is not built: `backend: OpenXr` or `Auto` start in app state `Off` with `xr_no_loader`.
  Swapchains, the Vulkan device hand-off and the XR frame thread need an XR runtime.
- The renderer does not draw the two eyes yet (no multiview or two-pass eye render, no vignette pass, no quad or depth
  layers); `xr.capture_eye` returns the view data, and images only with a `SimEyeTargets` resource installed.
- Eye projections use the frame's standard depth (ADR-869), not reversed-Z (ADR-1676 (4)). Nothing was verified on a
  headset.
- The XR backend's `apply_haptic` still accepts a negative length from Rust callers; the agent protocol refuses it.

### Testing and diagnostics

- Functional tests: no `functional-tests` cargo feature and no shipping-cook strip yet; the viewpoint camera service,
  the editor Tests panel, Android `--platform android` and the arena smoke session are not built (ADR-1673). `Remote`
  session roles are parsed but not launched.
- Breadcrumbs: only the main frame-renderer pass sites have scopes (about 70 other pass sites and the UI pass do not);
  no GPU timestamp backing (`timestamped` evidence only through the scripted source); trace file writes run on the
  calling thread (flushed at 256 KiB); no `telemetry.screenshot_mark` method; the default cost on Mobile Low is
  unmeasured.
- The `Session`, `rfdrec`, plugin manifest, `gpu-breadcrumbs`, `.regiatrace`, `config/xr.ron`, `actions.xr.ron` and
  `.xrsim.ron` formats have no schema fingerprint in `check-formats` yet and are not frozen in spec 12 § 4a.
- The merge gate runs test binaries at idle IO class from the bulk disk; under a saturated disk any test with a short
  wall-clock limit can still fail there (ADR-1824).

### DCC feed and extensions

- Not built: the DCC feed socket server, session state machine, entity mapping, ownership rules, bake, editor panel,
  reference client and the `dcc_feed.*` agent methods; the extension registry, `ExtensionContext`, dynamic loading
  with the ABI stamp, feature packs, content mounts, the `plugin.*` agent methods and the Extensions panel.

### Path confinement

- Not confined yet (read only, or files from the project itself): content-file readers in the asset pipeline (glTF
  buffer/image URIs, `.obj` `mtllib`, tiled `image`/`source`, atlas sprites, glass-crack masks, terrain-layer names),
  `regia upgrade-project`'s `.bak` copy following file symlinks, the runtime baked-GI volume read from a level,
  `localization.ron` gather roots, theme font files, `regia test session` packaged build paths.
- The methods unchanged by design take paths from anywhere; whether they need an agent permission is an owner
  decision. The Windows path behavior is covered by platform-independent lexical tests on Linux; the Windows run is
  pending.

### Editor and other

- The editor's exit code after `quit.request` on Wayland and the viewport fallback list on RADV are checked only on
  X11 (xvfb) and by reading the code; the reporter's machine confirms them.
- `PaneRequest` cannot ask for a windowed id read; use `render_pane_id_window` next to the pane render.
- A second render-out job in one running app does not reproduce the first one's frames when the scene animates on the
  app clock; this is by design (ADR-1656), so start a fresh app to repeat a take.
- `size_rollup` and the fracture cell builder stay quadratic on very large graphs and meshes.
- Real-GPU, Windows, macOS, headset and device runs are the lanes' open items; the integration ran on lavapipe only.
  The new gameplay-data modules were checked on Android, Windows and macOS with `cargo ndk check` only.
