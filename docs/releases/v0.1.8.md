# Ferrite v0.1.8

Patch release for Direct Order 27's alpha (Saturday 2026-10-17), driven by the first Windows tester logs (RTX 5080 and
RTX 4080) and the owner's sessions: CPU-bound frames on Switchbacks, 5–10 minute shader waits, 3 s stalls, blurry
terrain at 4K, and quits that froze or hard-locked the PC.

- **Commit:** v0.1.8 = the tag `v0.1.8` (the gated code commit is named in the tag message).
- **Workspace version:** `0.1.8`.

## Upgrade from v0.1.7.1
No host source changes for DO27 (checked from the code diff). Hosts that build these literally need one field each:
`TerrainBudget { .. }` gained `anisotropy` (use `TerrainBudget::with_anisotropy` or a preset). New APIs are additive.
Behavior changes to know:
- **Quit is a clean, ordered teardown** (ADR-188). Send `AppExit` (or `ferrite::request_clean_exit`); never `_exit`.
  Set `CleanExitSettings { watchdog: Some(3 s), .. }` as the last resort (off by default).
- **A large new scene on a window that shows only UI is warmed on a worker** (ADR-190): the window keeps presenting
  the UI until the scene's pipelines and uploads are ready. On by default (`GameFrameWarm::on_new_scene`).
- **Terrain uses anisotropic filtering** (ADR-192): Desktop Ultra 16×, High 8×, Low/Deck 4×, Mobile High 2×, Mobile
  Low off; plus the TAAU mip bias. Terrain pixels at grazing angles change (sharper), as intended.
- **Cache budgets scale with VRAM** (ADR-189): textures get at least a quarter of a discrete card's VRAM (16 GB at
  High: 4094 MiB, was 2048); meshes have their own budget, so textures can no longer evict meshes. The scaling
  raises any streaming budget, a host's own small one too: a host that wants exactly its budget calls
  `FrameRenderer::set_vram_scaled_budgets(false)`.

## Fixed
### CPU-bound frames on Switchbacks (RTX 4080 tester: render_into ~30–45 ms) (ADR-189)
The real cost was terrain hole staging: DO27 cuts tunnel mouths with a 42-ellipse chain, and every terrain node of every
pass list (4 cascades + 4 page regions + the view) was tested against every shape every frame. Hole states are now
kept per node until the mask changes, nodes fully inside the union of shapes are culled once, and the cheap bounds test
runs first. Repro (Switchbacks with the shell's holes, 800 casters): render_into p50 4.14 → 1.78 ms (p99 10.07 → 3.57);
the sun-shadow share that DO27 measured at ~11 ms is gone with it. Also: the mesh/material cache no longer thrashes at
DO27's scale (VRAM-scaled, separate budgets; a cache over twice its budget evicts without waiting for the seconds
floor), and emissive light fits are kept (≤ 16 lights traced per frame after the load frame).

### Shader waits before the menu (ADR-190, ADR-191, ADR-193)
- The first frame's forward pipelines and their GPU-driven variants compile in parallel instead of back to back:
  cold map warm on an RTX 5080 (driver cache off) 2961 → 2273 ms median (−23 %).
- The heavy forward pipeline is 35–40 % cheaper for the NVIDIA driver to compile (`lab_forward` fs_main 1095 →
  670–720 ms on a 5080): the sun-shadow filters are compiled once instead of per cascade.
- The warm queue has two budgets (ADR-193): **Boot** (cores − 2, up to 12 threads) until the first game frame, then
  **Play** (a quarter of the cores, 1–4). `PipelineWarmQueue::set_mode` lets a host return to Boot around a later load.
- Every log now ends the warm with "pipeline creation this run: N pipelines, X ms each" and the wgpu instance flags.
  The v0.0.4 Windows logs pick Vulkan (not DX12) and the same naga → SPIR-V path as Linux.

### 3 s stalls (ADR-190)
- First frame behind the menu (1650 MB uploaded, 107 pipelines in one frame): the scene is now warmed off the frame
  thread; the menu keeps ticking. 5080 headless: the map's first frame 3.4 ms, 0 pipelines and 0 MB inline, no tick
  over 250 ms.
- Lobby → match (8.8 s) is a host-side wait inside DO27's `front_frame` (no engine work in that frame); reported to DO27.
- Stall and hitch durations are now real (they were reported as "250 ms": the clamped frame delta).

### Terrain looked low-res at 4K (request 20) (ADR-192)
Terrain layers, macro, triplanar and the heightfield normal sample with real UV gradients and anisotropic filtering,
plus a mip bias on TAAU frames. Far-band detail on a grazing test: isotropic 3.94 → 8× 44.1 → 16× 51.8; TAAU 0.67
dolly 2.04 → 11.31. Cost on a 5080 at 4K: +0.8–1.2 ms of the terrain pass at 8×. Not yet measured on a GTX 1080.

### Quits that froze the desktop or hard-locked the PC (ADR-188)
One ordered, time-boxed teardown for every quit: stop background work → leave fullscreen → bounded GPU idle (1 s) →
drop surfaces → drop the renderer and the world → drop the device on a helper (bounded 1 s) → save the pipeline cache.
Each step logs its time. Panic=abort child quit mid-frame: RTX 5090 exits 255 ms after the quit, 0 live wgpu objects.
Not yet tested in real fullscreen on the owner's Hyprland/RX 7900 or on Windows (Immediate, HDR).

## Known issues
- Real fullscreen quits on Hyprland/7900 and Windows, and the terrain filtering cost on a GTX 1080, are untested.
- The new-scene warm presents only UI for up to 15 s on a first large scene in any app (editor included).
- Emissive probe sets are kept up to 36 000 frames per mesh; a lamp first traced in an occluded place can reuse them.
- Windows per-pipeline compile time is still 10–20× Linux in testers' logs; the new log line will measure it.
- Gate items (2026-10-14): `resize_memory` can fail on a real GPU beside other test binaries (passes alone 3/3);
  `device_lost_exit[surface]` once missed its crash bundle under load (passes alone 9/9, also under CPU load; two
  bundles written in the same second share a name). Follow-ups after the alpha.
- Everything listed under v0.1.7 still applies, except the items fixed above.
