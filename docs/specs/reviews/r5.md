## Spec 53: abilities, attributes and effects

**Verdict: fixed and ready to build.**

Set ids compared: `runtime-gameplay/runtime-gameplay-abilities`, `runtime-gameplay/runtime-gameplay-tags`
(both found).

Crates and modules: `regia_framework::abilities` (new module; submodules `attributes`, `modifiers`, `effects`,
`stacking`, `grants`, `cues`, `assets`, `migrate`); `regia_agent::abilities` (handlers); one-line baseline change
in `regia_framework::damage::apply_damage` (skip `HealthFromAttributes`). New formats: `.attrs.ron`
(`attributes` v1), `.effect.ron` (`effect` v1), `.ability.ron` (`ability` v1). `.cues.ron` dropped. New agent
methods: `abilities.{list, inspect, check, grant, revoke, activate, charge, end, cancel, signal, apply_effect,
remove_effect, set_base, add_attributes, cues, validate, stats}`.

Changes:

- Standalone gaps filled: baseline table with module paths and built API facts (tags, damage, timers,
  `regia_core::math::Rng`, `EntityGuid`, save game, state hash, `regia_ai::abilities`); agent registration
  pattern (`AgentExtension`, like `regia_agent::cloth`), permission classes mapped to `Permission::{Read, Play,
  EditScene}`, `F0002`/`F0003` + `data.reason` errors, COVERAGE rows per method and per format; format table
  with doc paths and the frozen-format rule; schedule placement relative to `ScriptsSet::FixedUpdate` and
  `DamageSet`.
- Replaced copied attribute, asset, running-effect, handle, phase, duration, pulse, tag and
  activation vocabulary with Regia terms. Replacements include `Attributes`, `AttributesAsset`,
  `EffectAsset`, `AbilityAsset`, `AppliedEffect`, `AppliedEffects`, `EffectId`, `GrantId`, `Grant`;
  phases `AddPre/Percent/Scale/AddPost/Replace`; `Lifetime::{Instant, Timed, UntilRemoved}`;
  `pulse`, `on_apply`, `base_edits`, `live_mods`; suspension with
  `on_resume: Continue/Restart/FireAndRestart` and `freeze_clock`; `status_tags`, `run_tags`,
  `kind_tags`, `apply_if`, `active_if`, `immunity`, `cleanses`, `chain { on_apply, on_lapse, on_removed }`.
  Magnitudes use `Const/Curve/Stat/Param/Function` and `LevelCurveRef` (spec 51 owns `CurveRef`).
  Signals/picks use `AbilitySignal`, `send_signal`, `Picks`, `submit_picks`, `abort_picks`, `IntentSeq`;
  triggers use `Signal/TagGained/WhileTagged`; run state uses `FreshEachRun/KeepAcrossRuns/ScratchOnly`
  and `when_running`; charging uses `charge`, `OnStart/Explicit`; run location uses
  `OwnerOnly/OwnerPredicts/HostStarts/HostOnly`. Cues use `CueKind::{Burst, Begin, End}` and
  `CueAt::{Applied, Pulsed, Removed, Sustained}`. Activation uses `check_activation`,
  `abilities.check`, `try_now`, `one_shot`, `cheats { free_costs, no_cooldowns }`,
  `AbilitiesLocked`, `owner_locked`, `Running`; error/cause codes follow.
- Paraphrase rewrites: stacking (§ 2.5) regrouped from six parallel policy fields that tracked the set's list into
  `key`, `cap`, `on_add { time, pulse }`, `when_full`, `on_lapse`, `cue_each_stack`, with own value names and an
  added `RejectRenew` case; effect fields (§ 2.4) regrouped by decision (lifetime, pulse, numbers, tags,
  conditions, interactions, chain, presentation); cue model rebuilt as burst vs begin/end.
- Contradictions resolved: `regia_framework` already depends on `regia_vfx`/`regia_audio` (Gameplay layer
  above Systems), so the old "no upward edge" text was wrong; the cue router depended on request types that do
  not exist (only `regia_vfx::CameraShakeRequest`), so it moved to follow-ups. `.curves.ron` collided with
  spec 51's `curve_table` format; spec 53 now uses inline curves plus an adapter over spec 51's `CurveTables`.
  `time.step` does not exist: `play.step`. `edit` class -> `edit_scene`. `regia check` does not exist: loaders +
  `abilities.validate`, registry validator as follow-up. Test 18's spawn-order shuffle contradicted ordering by
  `Entity` bits: ordering and RNG streams now key on `EntityGuid`. `DeterministicRng` does not exist:
  `regia_core::math::Rng`. Save path does not remap `Entity` fields: `source` and picks skip serialization.
  `HealthBridge` would have double-applied damage with the built `apply_damage`: marker + skip filter.
  `smallvec` was proposed as new: already a dependency. `regia_ai::abilities` (ext2) coexists (decision below).
- Provenance: rows now in the spec's own § 12 (public sources only; no set file cited).
- Second pass: test 17 now names entities (the built `world_snapshot` keys entities by `Name`, so a spawn-order
  shuffle only hashes equal with names) and adds `AbilityCounters` through `insert_resource_text`; the cue section
  notes that gameplay cues are not the `regia_audio` sound-cue asset (format `cue`). Length 697 lines (was 723): above
  the ~650 guide because the baseline table, layering facts and agent conventions the brief requires are now inline;
  the rest was tightened.

Decisions (ADR-1585):

- `regia_ai::abilities::Abilities` stays as the AI slot component; spec 53 uses `EffectAsset`/`AbilityAsset`
  names and a narrow prelude; a BT task bridge needs a `regia_ai -> regia_framework` edge and is a follow-up.
- `Cooling` is derived from cooldown tags, not stored.
- No cue router in v1.
- Game-registered gates, magnitude functions and run-state types are owner-tagged, dropped and re-registered on
  hot reload; assets refer to them by name.
- The pulse on the expiry tick runs before removal (5 pulses for 1 s / 0.25 s with `on_apply`, 4 without).
- `HealthBridge` marks bridged entities and `apply_damage` skips them.
- Save: effect source and picks are not serialized until entity remapping lands.

Owner decisions: none.

Builder notes: depends on spec 51 only optionally (adapter); spec 61 uses it behind `feature = "abilities"`.
Size L. Suggested order: attributes + modifiers -> effects + stacking -> grants/state machine -> signals/picks/
input -> cues -> agent + book -> bridge. The lead registers the three formats (`cargo xtask check-formats
--update`) and runs `cargo xtask manual`.

## Spec 54: GPU breadcrumbs and trace markers

**Verdict: fixed and ready to build.**

Set ids compared: `runtime-rhi/runtime-rhi-gpu-diagnostics`, `developer-insights/developer-insights-trace-capture`,
`developer-insights/developer-insights-timing-analysis` (vocabulary grep only). All found.

Crates and modules: `regia_render::breadcrumbs` (new; scopes at the ~50 pass sites of `FrameRenderer::render_into`,
`RenderGraph::execute`, `TrackedQueue::submit` hook), `regia_render::gpu_health` (`note_injected_destroy`, `test-hooks`
only), `regia_framework::feedback::crash` (bundle entry), `regia_telemetry::trace` (new recorder), `regia_cli`
(`regia trace export`, new), `regia_agent::{breadcrumbs, trace}` (+ `test-hooks` feature). New formats:
`gpu_breadcrumbs.json` (`gpu-breadcrumbs` v1), `.regiatrace` (`regiatrace` v1). New agent methods:
`render.breadcrumbs`, `render.fault_inject` (test-hooks), `telemetry.{mark, range_open, range_close, trace,
screenshot_mark}`. Host-visible: new zip entry in feedback bundles (additive, `BUNDLE_FORMAT` stays 1).

Changes:

- Contradictions with built code (all aligned to the code): the frame is recorded by `FrameRenderer::render_into`
  with parallel encode workers, not through `RenderGraph`, so "graph hooks around each node" became pass scopes at
  the existing `info_span!` sites with per-segment marker lists ordered at submit by `TrackedQueue` (also fixes the
  "single writer" assumption, which parallel encoding broke); crash bundles are written by
  `regia_framework::feedback::crash::write_device_lost_bundle` (a zip), not `regia_crash`, so the `BundleSection`
  trait in `regia_crash` was removed and the entry is written by the feedback writer; graph epochs dropped
  (static names interned in an append-only table); agent namespaces moved to the existing `render.*` and
  `telemetry.*`; permission classes mapped to `Permission::{Read, Play}`; errors to `F0002`/`F0003` + `data.reason`;
  `lz4_flex` and CRC are already in the tree (no new dependency); `test-hooks` already exists on `regia_render`;
  native-crash "raw ring dump from the signal handler" replaced by "the ring is in the minidump" (no handler code;
  Android native capture is a no-op today).
- Replaced copied tracing vocabulary with mark/range/lane/stream/window and `forced_close`,
  `save_window`, recorder states `Idle/Windowed/Writing`, evidence levels
  `timestamped/fenced/recorded/none`, `.regiatrace`/`RGTR`, `--record-trace`,
  `render.breadcrumbs`, `render.fault_inject`, `telemetry.*`, `stall_at_submission`,
  `ScriptedProgress`, `GpuProgressSource`, and export `--format trace-event`.
- Paraphrase rewrites: § 2.4 recorder state table rebuilt around Regia's window/file model (own states, own
  triggers); the snapshot sentence reworded; default window 4 MiB (the set's documented default) -> 2 MiB;
  default file name kept generic.
- Standalone gaps filled: baseline with module paths, the bundle's entries, `TIMESTAMP_QUERY_INSIDE_ENCODERS`
  rule of `capabilities.timestamp_query`; COVERAGE rows (§ 2, § 3 CLI, § 4 formats).
- Provenance: own § 12 rows; the seqlock row removed (design changed to mutex slots).

Decisions (ADR-1585):

- Ring slots are `Mutex`es published once per frame, readers `try_lock` with a bounded retry; no `unsafe`, no seqlock.
- The export to the Trace Event Format stays in this spec.
- `.regiatrace` and `gpu_breadcrumbs.json` are diagnostic outputs: registered in `check-formats`, never rewritten by
  `regia upgrade-project`; readers keep decoders for every older version (v1 fixture test).
- `gpu_health::note_injected_destroy()` (test-hooks only) lets `mode: "destroy"` count as a loss.
- Breadcrumbs default on everywhere; the lead measures N150 and Android before v0.2.x and turns the Mobile Low default
  off if the total exceeds 0.05 ms.
- Each mark also emits a `regia::mark` tracing event; `regia::phase` events are recorded as marks.

Owner decisions: none.

Builder notes: no spec dependency. Size M (breadcrumbs + bundle entry + `render.breadcrumbs`, v0.2.x) then M (recorder,
file, export, telemetry methods, v0.3.x). Order: interning + scopes + counters -> report + bundle entry -> agent read
-> scripted source and fault injection -> recorder -> file -> export. GPU tests (9, 16, 17, 20) need lavapipe: the lead
runs them on the build server. The lead registers the two formats and runs `cargo xtask manual`.

## Spec 55: cloth, skinned cloth and soft bodies

**Verdict: fixed and ready to build.**

Set ids compared: `runtime-physics/runtime-physics-cloth-deformables`, `runtime-characters/runtime-characters-cloth-assets`
(both found).

Crates and modules: `regia_physics::cloth` (`cloth.rs` -> `cloth/mod.rs` + `skin`, `asset`, `wind`, `selfcol`, `soft`,
`snapshot`, `lod`, `maps`); `regia_framework` glue (`sync_cloth_pose`, `sync_cloth_colliders`, `sync_cloth_visibility`,
`publish_cloth_mesh`); `regia_agent::cloth`; `regia_asset_pipeline` (cooker, tet generator). New formats: `.cloth.ron`
(`cloth` v1), `.soft.ron` (`soft` v1), `.cloth.bin` (`cooked-cloth` v1), `.soft.bin` (`cooked-soft` v1). New agent
methods: `physics.cloth_{inspect, set_params, pin, unpin, wind, step, reset, edit_map}` (`physics.cloth_stats`
unchanged). Host-visible: new `ClothError` variants (exhaustive matches need an arm); `ClothConfig`, `ClothCollider`
and `ClothShape` deliberately unchanged.

Changes:

- Contradictions with built code: the writer's plan added `prev_shape`/`cur_shape` fields to `ClothCollider` and new
  `ClothShape` variants, which would break struct literals and exhaustive matches; now `set_collider_previous` and
  snapshot-only shape kinds. The agent namespace `cloth.*` -> the built `physics.cloth_*`; `cloth_plugin_missing` as
  an error on reads -> the baseline `{ plugin: false }`; errors on `F0002`/`F0003` + `data.reason`; `edit` class ->
  `edit_scene`. "The renderer's existing dynamic-mesh upload path" does not exist: the cloth section is split into
  its own unskinned `MeshRenderer` updated by publishing a new `Arc<CpuMesh>` per frame (upload by `Arc` identity,
  which the renderer does today), in-place dynamic buffers a follow-up. `collide_with` mask in `config/physics.ron`
  -> the built `PhysicsLayers` + `overlap(.., QueryFilter::from_layer(..).exclude_sensors())`. Visibility ->
  `regia_scene::ViewVisibility`. Stable collider ids -> `EntityGuid`. Glue names were `*System` types; now plain
  system functions. The root-inertia formula was inverted against its own description (default 1 applied the full
  root displacement yet "0 simulates in the root frame"); fixed to scale by `1 - inertia_scale`.
- Replaced copied cloth field, map, collision, wind, preset and synchronization vocabulary
  with `reach`, `standoff`, `pose_pull`, `sim_mix`, vertex maps/`PoseMaps`, `Spheres`,
  `WindModel::{Aerodynamic, Push}`, presets `light_fabric/heavy_fabric/stiff_fabric/elastic/chain`,
  `max_per_step`, `physics.cloth_edit_map`, `sync_cloth_pose`, `sync_cloth_colliders`.
- Paraphrase rewrites: § 3.4 painting rebuilt as a data API (`MapEdit::{Set, Sphere, Relax, Ramp, Flood,
  FromVertexColor}`, `transfer_maps`) instead of the set's tool list and its "one active map per target" rule; the
  0-100 paint scale mapped to one meter (the set's documented convention) removed (maps store meters); LOD inheritance
  "a new LOD inherits from the preceding one" (the set's rule) replaced by "LOD 0 is the only source; other LODs resample
  from LOD 0"; "importing vertex colors" and "copy setup between meshes" now map-edit operations with own semantics.
- Standalone gaps filled: full baseline (types, fields, limits, error codes, agent behavior); compatibility note;
  format ids and the frozen rule; COVERAGE rows; budgets marked as lead measurements, never test asserts; test 13
  (LOD resample), 14 (map edits), 18 (zero allocation) added.
- Provenance: own § 12; added Kim et al. 2012 (tethers), Taubin 1995 (relax), marching-tetrahedra split.
- Open questions resolved: wind split equal thirds (decision); meters, no percent scale (decision); inertia scale is
  a Regia design, documented with its formula; tearing as edge deactivation (decision, true cuts a follow-up);
  budgets are lead-measured estimates; paint list re-derived; 5-tet voxel split kept with better meshing a follow-up.

Decisions (ADR-1585):

- Vertex maps store meters; no percentage paint scale.
- Cloth render section is its own mesh, republished per frame as a new `Arc<CpuMesh>` until a renderer dynamic buffer exists.
- LOD 0 is the only authored LOD; other LODs resample maps from it and share its parameters unless overridden.
- `ClothConfig`/`ClothCollider`/`ClothShape` keep their shape; new data lives in `ClothTuning`, `PoseMaps`,
  `set_collider_previous` and `WorldSnapshot`.
- Wind force split equally among a triangle's three vertices.

Owner decisions: none.

Builder notes: depends on spec 15 (rigid queries, built) and spec 17 / `regia_framework::skinning` (built). Size L:
M for skinned cloth + assets + agent, M for snapshots + self-collision + wind + LOD, M for soft bodies + tet tool.
Order: module split + maps + pose constraints -> asset + cooker -> glue + render section -> agent -> snapshots ->
self-collision -> wind -> LOD -> soft bodies. The lead registers the four formats and runs `cargo xtask manual`; the
GPU screenshot test and the Android run are lead TODOs.
