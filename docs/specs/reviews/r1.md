## Spec 33: Spatial queries for AI (file kept its old name at review; renamed `33-spatial-queries.md` by ADR-1661)

- Verdict: fixed and ready.
- Set file compared: `runtime-ai/runtime-ai-environment-queries.md` (its open-question list was the hint).
- Changes: the draft mirrored the set's generator list (7 generators), test list (9 tests), run modes, clamp sources and
  combine operators almost one-to-one, and used another product's feature title. The Regia feature is now
  **spatial query** (`.spatialquery.ron` v1, `regia_ai::spatial_query`, errors `sq_*`, page `spatial-queries`).
  Generator names now describe Regia's geometry: `Ring`, `Wedge`, `Annulus`, `Lattice`, `ReachLattice`,
  `Union`, `NearbyEntities`, `AtAnchor`. Tests use `Facing`, `TagMatch`, `Clearance`, `Route`, `RouteAll`,
  `Cast`, `InsideZone`, `Snap`; input roles use `Anchor`, `Asker`, `Candidate`. Clamp sources use
  `Fixed`, `FilterBound`, `Seen`; score origins use `Floor`/`Zero`; curves use
  `Flat/Linear/Quadratic/Falling/Root`; combination uses `Mean/Lowest/Highest/Product`; run modes use
  `Best`, `Sample{band}`, `All` with default band 0.1 instead of copied presets. The probe is
  `SpatialQueryProbe`, with `only_through_test`. Tests were regrouped by geometry, physics and navigation,
  and the score pipeline was rewritten.
- Contradictions resolved against built code: `regia_ai` and `regia_framework` are siblings in `xtask/src/layers.rs`
  with no allowed edge, so the tag test uses a host-registered `TagMatcher` callback (decision). `server_only` has no
  build-profile basis in Regia: stored and ignored until a client-only profile exists. Built baseline confirmed:
  `NavMesh::find_nearest/find_path`, `regia_physics` `raycast/shapecast/overlap`, `regia_core::math::Rng` (PCG32),
  `BtTaskRegistry`; `regia_agent -> regia_ai` edge exists, so `ai.query_*` methods are ordinary agent methods.
- Open questions: none for the owner.
