# `.kind.ron` — entity kind declaration (format `kind`, v1)

Status: v1, frozen on merge (ADR-2488, `docs/specs/101-entity-kinds-and-project-map.md` § 2.3). Reader:
`regia_scene::kind::file::KindFile`.

A data kind: a declared label and contract for one game type. Entities carry it through the reflected component
`regia_scene::kind::KindTag(String)`.

```ron
(
    format_version: 1,
    name: "Crate",
    icon: "crate",
    color: "#c08a3e",
    description: "A breakable supply crate",
    category: Some("Props"),
    required: ["regia_scene::transform::Transform", "my_game::Health"],
    marker: None,
)
```

| Field | Type | Default | Rule |
|---|---|---|---|
| `format_version` | `u32` | required | `1`. `0` is refused; a newer version is refused (`kind_version_newer`), peeked before the body parses. |
| `name` | string | required | `[A-Za-z0-9_]`, 1-64 bytes, unique in the project. |
| `icon` | string | `""` (the generic `kind` icon) | An icon name (spec 101 § 4.3); unknown names show the generic icon. |
| `color` | string | required | `#rrggbb` (or `rrggbb`). |
| `description` | string | `""` | One line, at most 120 characters. |
| `category` | `Option<String>` | `None` | Display group; `None` lists under `Uncategorized`. |
| `required` | list of strings | `[]` | Component type paths (as scene files write them); sorted and deduplicated on load; no empty entry. |
| `marker` | `Option<String>` | `None` | The code marker type path this declaration describes, for tools that do not link the game. |

Unknown fields are ignored. Canonical text: `KindFile::to_ron_string` (pretty, trailing newline).

## Versions and migration

v1 is the first version: no migrator (`kind_migration_sources()` is empty). A later shape change bumps
`KIND_FORMAT_VERSION`, adds a migration step and a `regia upgrade-project` migrator (the `kind` row of its registry,
which reads the version from the top-level `format_version`). `cargo xtask check-formats` hashes the serde field list
(`kind_schema_fingerprint`).

## The project map files

`project-map.json` (`map_version: 1`) and `project-map.md` are generated by `regia describe` and `project.describe`
(`regia_scene::kind::map::ProjectMap`). They are output, not input, except that offline tools read the code kinds of an
existing `project-map.json` (entries whose `source.type` is `code`) to recognize code markers. A later layout change
bumps `map_version`; readers ignore a map whose version they do not know.
