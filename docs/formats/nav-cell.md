# Nav cell (cooked)

The walkable cells of the navmesh tiles of one streaming cell (ADR-1934, spec 78 § 13.2). The bytes
sit in the opaque `nav` field of a cell blob. Written by `regia_nav::NavTileCache::cook_cell`, read by
`NavTileCache::load_cell`.

Cooked output, regenerated by a cook: there is no migrator. A build that meets a newer version refuses it with
`nav_cell_version`; re-cook. The layout is written by hand, not through serde: `regia_nav::NAV_CELL_LAYOUT` lists it
field by field and `cargo xtask check-formats` hashes that list (`nav-cell`, ADR-2316), so a layout change without a
version bump fails the gate. The bytes live inside a cell blob, not in a file of their own, so `regia upgrade-project`
has no entry for them.

Version: `NAV_CELL_FORMAT_VERSION` = 3 (ADR-2589: v2 adds each tile's off-mesh links; ADR-8899: v3
keeps the v2 byte layout and its heights come from conservative rasterisation). All numbers are
little-endian.

Migration: the loader reads v1 and v2 cells directly (`nav_cell_migration_sources()` = `[1, 2]`). A v1
tile has no link section and loads with no links. The heights of a v1 or v2 cell were centre-sampled (a
cell took a triangle only where the cell centre lay inside it, ADR-7558); they load unchanged, and the
loader logs a warning naming the re-cook. Until the content is re-cooked, a runtime region rebuild
(`rebuild_region`, which rasterises conservatively) next to such a cell can disagree with it at the seam,
and thin walls or planks the old rasteriser missed stay missing in that cell. `regia cook` re-cooks
streamed levels on every run and writes v3. A newer version is refused with `nav_cell_version`.

v3 changes no byte: only the meaning of the heights moved (a cell takes every triangle whose XZ
projection overlaps its square), so `NAV_CELL_LAYOUT` and its hash are unchanged and only the version
number moved.

| Offset | Size | Field |
|---|---|---|
| 0 | 4 | magic `RNVC` |
| 4 | 4 | `format_version` (u32) |
| 8 | 8 | layout hash (u64) |
| 16 | 4 | tile count (u32) |
| 20 | | the tiles, in tile index order |
| end - 8 | 8 | checksum (u64): FNV-1a of everything before it |

One tile:

| Size | Field |
|---|---|
| 4 | tile x (u32) |
| 4 | tile z (u32) |
| 4 × cells | the tile's cells, row by row: surface height (f32), NaN for not walkable |
| cells | the same cells' area ids (u8, below 64), as painted when cooked |
| 4 | link count (u32, v2 and later; at most 65536) |
| 53 × links | the links this tile owns (v2 and later), see below |

A link belongs to the tile under its `from` point. A link that crosses a tile border belongs to its start
tile. Links whose `from` lies off the grid are never cooked. On the tile, the cache's own links come first,
then the ones the tile streamed in. One link record (53 bytes):

| Offset | Size | Field |
|---|---|---|
| 0 | 12 | `from` (3 × f32), in the cook's frame |
| 12 | 12 | `to` (3 × f32) |
| 24 | 1 | `bidirectional` (0 or 1) |
| 25 | 1 | `area` (below 64) |
| 26 | 2 | kind (u16): 0 jump, 1 drop, 2 climb, 3 teleport, 4 custom |
| 28 | 2 | the custom kind's id (u16; 0 otherwise) |
| 30 | 2 | `flags` (u16) |
| 32 | 1 | `enabled` (0 or 1) |
| 33 | 8 | `user_id` (u64) |
| 41 | 4 | `radius` (f32) |
| 45 | 4 | `cost_scale` (f32) |
| 49 | 4 | `duration` (f32) |

The cell count is the tile's rectangle: `tile_size²`, less on the grid's far edges.

The layout hash is FNV-1a of `cell_size`, `cell_height`, `border_size`, the agent's `radius`, `height`,
`max_climb` and `max_slope` (f32 bits), then `tile_size`, the grid width and height (u64). The grid
origin is left out, because a floating-origin rebase moves it. Heights are in the cook's frame; a
shifted cache adds its shift on load.

A blob that fails any check changes nothing. `nav_cell_corrupt` covers a bad magic, version 0, a
truncated blob, a checksum mismatch, a tile outside the grid or listed twice, an infinite height, an
area id of 64 or more, and trailing bytes. Since v2 it also covers a link count past the bytes or above
65536, an unknown link kind, a flag byte other than 0 or 1, and a link that fails `OffMeshLink::validate`. `nav_cell_layout_mismatch` means another layout or other build parameters.
