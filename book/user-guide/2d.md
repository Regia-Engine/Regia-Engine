# 2D: sprites, tilemaps, 2D physics

Regia Engine's 2D toolkit (`specs/22` § T2.10) draws sprites from packed atlases, plays sprite-sheet
animations, renders Tiled maps, gives you a pixel-perfect orthographic camera and two kinds of 2D
physics: a pixel-exact platformer model and rapier2d rigid bodies.

## Set up

```rust
use regia::prelude::*;
use regia::two_d::{Sprite, Sprite2dPlugin, TileMap};
use regia_core::math::{UVec2, Vec3};
use regia_scene::Transform;
use regia_framework::camera::ortho::{Camera2d, Camera2dFollow, Camera2dPlugin};

fn build(app: &mut App) {
    app.add_plugins((Sprite2dPlugin, Camera2dPlugin));
    app.add_systems(Startup, |mut commands: Commands| {
        // A 320×180 pixel-perfect view, scaled by the largest whole number that fits the window.
        commands.spawn(Camera2d {
            pixel_perfect: Some(UVec2::new(320, 180)),
            clear: Some([0.12, 0.16, 0.22, 1.0]),
            ..Default::default()
        });
        commands.spawn(TileMap::new("assets/maps/level1.tmx"));
        commands.spawn((
            Sprite::named("assets/sprites/hero.atlas.ron", "hero"),
            Transform::from_translation(Vec3::new(40.0, 16.0, 1.0)),
        ));
    });
}
```

The 2D world is **+X right, +Y up**; one world unit is one source pixel at zoom 1. A sprite's
world pose is its `GlobalTransform` (the `Transform` composed with its parents', after `TransformPropagate`; equal to `Transform` without a parent); its z is its draw order (higher in front); a tilemap's layers stack above its z. Sprites
draw over the 3D scene (after tonemapping) and under the runtime UI.

## Sprite atlases (`.atlas.ron`)

List your images in an `.atlas.ron` next to them; `regia cook` packs them into pages
(`texture_packer`'s skyline packer, deterministic) and keeps the pixels exact (no compression).

```ron
(
    version: 1,
    padding: 1,
    extrude: 1,          // repeat edge pixels: no bleeding when zoomed
    trim: true,          // pack only the opaque part; pivots still refer to the full image
    sprites: [
        (name: "hero", image: "hero.png", pivot: (0.5, 0.0)),                 // feet at the origin
        (name: "run", image: "hero_run.png", grid: Some((16, 16))),          // run_0, run_1, …
        (name: "panel", image: "ui/panel.png", nine_slice: Some((4, 4, 4, 4))),
    ],
)
```

- **Pivot**: `(0, 0)` bottom-left, `(1, 1)` top-right; `Sprite::anchor` overrides it per entity.
- **9-slice**: give the sprite a `size`; the corners keep their size, edges and center stretch. When the
  `size` is smaller than the borders added together, the two borders on that axis shrink
  proportionally (the center collapses to nothing).
- `Sprite::flip_x` / `flip_y`, `color` (tint), `visible`.

Format reference: `docs/formats/atlas-ron.md`.

## Sprite-sheet animation

```rust,wrap
use regia::two_d::{AnimatedSprite, Animation};
use regia::two_d::Sprite;
# use regia_ecs::prelude::Commands;
fn spawn_hero(mut commands: Commands) {
commands.spawn((
    Sprite::rect("assets/sprites/hero.atlas.ron", [0, 0, 16, 16]),
    AnimatedSprite::new(16, 16, &[
        Animation::new("idle", 0, 4, 8.0),
        Animation::new("run", 1, 6, 12.0),
        Animation::new("jump", 2, 3, 10.0).once(),   // holds its last frame
    ], true),
));
}
// later: animated.play("run");
```

One row per animation; the frame clock keeps its remainder, so playback speed does not depend on
the frame rate. `sheet_offset` is the pixel offset of tile (0, 0) inside the atlas rect; animated
sprites always sample atlas page 0 for now, so keep the run sheet on the first page.
`play(name)` restarts that animation unless it is already the current one and not finished (a paused
clip resumes where it stopped); once an animation is `finished`, `playing` is ignored.

## Tilemaps (Tiled)

Save maps from [Tiled](https://www.mapeditor.org) as `.tmx` (XML) or `.tmj` (JSON), with tilesets
embedded or as `.tsx`/`.tsj` files. `regia cook` imports them into the `.tilemap.ron` structure
(`docs/formats/tilemap-ron.md`) and embeds the tileset pixels. You can also write `.tilemap.ron`
yourself. Supported: finite maps in every Tiled orientation, CSV/base64 (zlib/gzip) layers, group layers
(flattened), flips (including diagonal), animated tiles, object layers, custom properties.

Collision for the platformer comes from tile properties in Tiled: set a string property
`collision` to `solid` or `one_way` (or a bool `solid` / `one_way`, or the tile's class), or draw a
collision shape on the tile.

At run time `SpriteAssets::tilemap(path)?.map` gives you the `TileMapAsset` for queries:
`tile_at(layer, x, y)`, `cell_at_world` and `collision_grid_all()`. `SpriteAssets::tilemap_mut(path)?`
returns it mutably to edit tiles (the renderer picks the edit up next frame). Saving the `.tmx` or
`.tmj` itself while `regia run --dev` or the editor is watching recooks that map and reloads it.
An external tileset (`.tsx` / `.tsj`) or its PNG does not pull the map in: cook the map again, then
restart the game, to see that change.

### Orientations

A map is `Orthogonal` (square grid), `Isometric` (diamond), `Staggered` (diamonds in offset rows or
columns) or `Hexagonal` (pointy or flat, with Tiled's stagger axis, stagger index and side length).
The importer reads Tiled's `orientation`, `staggeraxis`, `staggerindex` and `hexsidelength`. Cell
`(x, y)` is still the column and row of the layer data; `TileMapAsset::cell_at_world`,
`tile_world_rect` (the cell's bounding box), `tile_world_outline` and `tile_world_center` convert
between cells and the world for every orientation, and the sprite pass draws tiles back to front.
Tile images draw from the bottom-left of the cell's box, so taller tiles (trees, walls) overlap the
cells behind them.

Auto-tiling rules read the cells that touch a cell on screen: on staggered and hexagonal maps the
neighbors depend on the row (or column) being shifted, and a hexagon has six (pointy: no north or
south; flat: no west or east); the table is in `docs/specs/86-2d-toolkit.md` § 13. Use `Rules`
terrains on hexagons. Tiled stores object positions in map pixels, except on isometric maps, where
they are grid units scaled by the tile height; `TileMapAsset::object_world_position` converts either to
the map's world space (+Y up). Tiled 1.0 `<terraintypes>` import as corner Wang sets
(`regia tiled-autotile`).

## Auto-tiling

An `.autotile.ron` (`docs/formats/autotile-ron.md`) turns "this cell is grass" into the right edge,
corner or inner tile of a tileset. Each terrain picks its tile from its neighbours with one of four
layouts:

- `Edge16([..16 ids..])`: walls, pipes, fences. The index is N 1 + E 2 + S 4 + W 8.
- `Blob47([..47 ids..])`: ground, water, anything with inner corners. Entry *i* is drawn for the
  *i*-th of the 47 neighbour masks listed in the format page.
- `WangCorner([..16 ids..])`: corner-based sets. The index is which corners of the cell lie inside
  the terrain: TL 1 + TR 2 + BR 4 + BL 8; a corner counts when the cell and the three neighbours
  touching it are all the terrain. Tiled's corner, edge and mixed Wang sets (and Tiled 1.0
  terrains) import as `WangCorner`, `Edge16` and `Blob47` terrains with
  `regia tiled-autotile <tileset-or-map> [--out-dir DIR]` (a mask without a tile borrows the
  nearest mask's tile and the import warns).
- `Rules([(pattern: "?#? / ### / ?.?", tile: 12), …])`: your own 3×3 patterns, first match wins
  (`#` this terrain, `.` not, `?` either).

`variants` swaps a resolved tile for a weighted pick (flowers in the grass) that depends only on
the cell, so repainting never reshuffles them. The result is an ordinary tile layer: painting is an
authoring step, nothing changes at draw time.

`regia cook` turns each `.autotile.ron` into a binary payload stored with the other 2D assets, so a
shipped game loads its rules from the pak: `AutoTiles::load_from_server(name, path, &mut server)`
(or `tilemap.autotile_register` with `path`) gives the same rule set the raw file parses to.

```rust,ignore
use regia::two_d::autotile::{AutoTileSet, TerrainBrush};

let rules = AutoTileSet::from_ron(include_str!("../assets/maps/terrain.autotile.ron"))?;
let mut assets = world.resource_mut::<SpriteAssets>();
if let Some(map) = assets.tilemap_mut("assets/maps/level1.tilemap.ron") {
    let bound = rules.bind(map)?;
    let grass = rules.terrain_index("grass").unwrap_or(0);
    let layer = map.layer_index("ground").unwrap_or(0);
    // Paint a 10×3 patch; its border and the cells around it re-resolve.
    let cells: Vec<(u32, u32)> = (0..3).flat_map(|y| (0..10).map(move |x| (x, y))).collect();
    bound.paint(map, layer, TerrainBrush::Terrain(grass), &cells)?;
}
```

The result does not depend on the order you paint cells in. `apply_layer` re-resolves a whole layer
after hand edits. Register rule sets in `regia::two_d::AutoTiles` to make them available to agents
(`tilemap.paint`, `book/agents/2d.md`).

## The 2D editor mode

Press `B` in the editor viewport (or `editor.mode2d_set`, `book/agents/editor-2d.md`). The mode
loads the `.tilemap.ron` your level shows and switches to the front view, which looks at the 2D
plane (+X right, +Y up), and frames the map. When the level shows no such map, the **2D** tab opens:
use Open map… there. Open rules… loads an `.autotile.ron`.

Pick the brush in the 2D tab: a tile from the palette (with its flips), a terrain of the rule set, or
Erase. Left-drag paints; hold Shift to erase. Ctrl-drag copies a rectangle of cells into a
**stamp**; the stamp brush then pastes it centered on every painted cell, and the tab's Rotate and
Flip buttons turn it (the tiles' flips turn with it). Picking and the grid follow the map's
orientation. A stroke is one undo step. `,` `.` change the layer and
`[` `]` the terrain. The viewport shows the map's tiles as Play does, with the map bounds, the tile
grid, the cell under the pointer and a preview of the tile. Animated tiles show their first tile. Save
map writes the `.tilemap.ron`, as does saving the level, and the asset watcher re-cooks it. Tiled
sources are edited in Tiled.

### Tools, random brush, patterns, layers and guides

The **Tool** row of the 2D tab picks how a press paints: **Paint** (freehand), **Line** and
**Rectangle** (drag from one end or corner to the other; the cells show while you drag and land when
you let go; Rectangle has a **Filled** option), **Bucket** (fills the cells around the pressed one
that hold the same tile; turn **Contiguous** off to fill every such cell of the layer) and **Pick**
(click takes a cell's tile as the brush, drag takes a rectangle as the stamp; Ctrl does the same with
any tool). A right-click erases the cell under the pointer in every tool, or the bucket's region; a
right drag still pans the view. With the stamp brush, Line, Rectangle and Bucket repeat the stamp
over their cells.

**Random brush** paints one of several tiles per cell: turn it on, click palette tiles to add them,
set each tile's weight and the **Chance of nothing** (cells left alone). With a rule set loaded,
**Connect** joins a terrain to every neighbor of the same terrain, and **Path** joins only the cells
of the same stroke, so a path can run next to another without merging with it.

**Patterns** keeps stamps by name: type a name and **Save stamp as pattern**; click a pattern to make
it the stamp again. They are stored with the tileset in a `.tilepatterns.ron` next to its image, so
every map that uses the tileset sees them.

**Layers** lists the map's tile and object layers, top first, with their depth; **Raise** and
**Lower** change the drawing order. Pick a tile layer to paint it, or an object layer to edit its
objects: add, select, rename, move and delete them in the tab, or drag them in the view.

**Rulers and guides**: the view shows rulers along its top and left edges in level units. Drag from a
ruler to pull out a guide; drop it back on a ruler to remove it. Dragged objects snap to guides and
line up with the edges and centers of nearby objects, or space evenly between their neighbors, with
lines showing what they snapped to; hold Alt to place freely. Guides are saved with the editor's view
state for the level, not in the level.

## The camera

`Camera2d` (in `regia_framework::camera::ortho`) sets the zoom (`pixels_per_unit`), the optional
pixel-perfect virtual resolution with letterbox bars (`bar_color`), `snap` (round the center to
whole pixels so scrolling never shimmers) and the 2D clear color. `Camera2dFollow` follows an
entity with a deadzone and exponential lag. Mouse/touch to world:
`camera.screen_to_world(&transform, window_size, cursor)` (returns `None` on the bars).

## Platformer physics

`regia_physics::platformer2d` is the "actors and solids" model of pixel platformers (ported from
macroquad): actors move one whole pixel at a time with a sub-pixel remainder and stop at the first
pixel that would overlap; solids push actors and carry the ones standing on them; one-way tiles
only block a fall.

```rust,wrap
use regia::physics::platformer2d::*;
use regia::two_d::TileCollision;
# use regia_app::App;
# use regia_ecs::prelude::{Commands, Res, ResMut};
# use regia::two_d::SpriteAssets;
# use regia_core::math::{IVec2, Vec2};
# use regia_scene::Transform;
fn install_platformer(app: &mut App) {
    app.add_plugins(PlatformerPlugin);
}
fn add_tile_layer(
    mut world: ResMut<PlatformerWorld>,
    assets: Res<SpriteAssets>,
    mut commands: Commands,
) {
    // Static tiles from the map (rows bottom first).
    let Some(loaded) = assets.tilemap("assets/maps/level1.tmx") else { return; };
    let map = &loaded.map;
    let grid = map.collision_grid_all().iter().map(|c| match c {
        TileCollision::Solid => Tile::Solid,
        TileCollision::OneWay => Tile::JumpThrough,
        TileCollision::Empty => Tile::Empty,
    }).collect();
    world.add_static_tiled_layer(grid, 8, 8, map.width as usize, IVec2::ZERO, 1);
    commands.spawn((PlatformerActor { size: IVec2::new(8, 12), gravity: 600.0, ..Default::default() }, Transform::default()));
    commands.spawn((PlatformerSolid { size: IVec2::new(32, 8), velocity: Vec2::new(20.0, 0.0) }, Transform::default()));
}
```

Each fixed step moves solids, then actors (gravity, horizontal, vertical) and writes
`PlatformerContacts { grounded, hit_wall, hit_ceiling, squished }`. Set `drop_through` to fall
through a one-way platform.

## Rigid bodies (rapier2d)

Enable the `physics2d` feature (`regia = { features = ["physics2d"] }`) and add
`Physics2dPlugin`: `RigidBody2d` (dynamic/kinematic/static), `Collider2d` (ball, box, capsule,
segment, convex polygon, polyline), `Velocity2d`, `Collision2d` messages, and
`PhysicsWorld2d::raycast` / `entities_at`. Set `set_length_unit` to your typical object size when
you work in pixels.
