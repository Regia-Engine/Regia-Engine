# Showcase tunnels: a tunnels-armed frame scene

`samples/showcase/tunnels_scene/` is a showcase scene directory with tunnels armed: the Switchbacks tunnel
layout (Regia's fixture of DO27's map: a lava tube, a mine gallery, four openings, two of them skylight climbs)
under a 1280 m canyon floor. It exists to measure tunnel frames against the matching outdoor frames on the same
map (ADR-8825; the D8 bars: the interior frame is no slower than the outdoor frame on the Deck preset, and the
Very Low tier holds 720p30 on the min-spec laptop with tunnels armed). Every file is generated by Regia code
from fixed numbers; there are no downloaded assets.

Tunnels are an optional showcase feature: a scene directory that holds `tunnels/tunnels.ron` arms them, and a
scene without the file loads and renders as before ([Showcase](showcase.md), "Optional engine features").

## Run it

```text
# Headless, agent protocol advertised under /tmp/tunnels_project/.regia/agent/.
cargo run --release -p showcase -- samples/showcase/tunnels_scene --project-dir /tmp/tunnels_project

# Check the scene loads (cooks the tunnels; no GPU).
cargo run --release -p showcase -- samples/showcase/tunnels_scene --check
```

The load cooks the mesh layers on the CPU: a few seconds in a release build, longer in a debug build.

## What the scene holds

```text
tunnels_scene/
  scene.ron                           4096² flat heightfield at -256 m over 1280 m (the cook's ground lattice)
  heightfield.png, terrain.layers.ron, sky.ron, scatter/rocks.scatter.ron
  perf_views.json                     the views: tube_west, outdoor_west, tube_east, outdoor_east, mouth_drive
  tunnels/tunnels.ron                 the switch (below)
  tunnels/switchbacks.meshlayers.ron  the mesh-layers document: one `tubes` layer filling every mouth
  tunnels/switchbacks.passages.ron    the Switchbacks passages (regia_world_geom's fixture)
```

At load the host:

1. Turns the heightfield into the cook's ground lattice, one count a sample:
   `count = (height - ground_offset_m) / ground_step_m`.
2. Cooks the document with `regia_world_geom::cook::cook`: the canonical world geometry, the tube render mesh,
   the mouth cut and the indoor cells. This is the same cook `regia cook` runs for a level.
3. Arms the mouths. Each cooked mouth is an open named hole of the terrain draw (its lattice rings), and the draw
   discards the cooked lattice cut there (`TerrainMeshLayers::lattice_hole_cut`, ADR-8470). That is the same cut
   the sim's ground has. Scatter is kept out of the holes.
4. Spawns the tube render mesh (one mesh per passage, flat normals), a point light every 40 m along the covered
   tube and gallery centrelines, and inserts the cooked `VisCells`. The renderer's portal cull then drops outdoor
   terrain and scatter that no portal shows from inside a tube ([Indoor cells](viscells.md)).

Switchbacks has no water, so the scene has none.

### `tunnels/tunnels.ron` (version 1)

```text
(
    version: 1,
    document: "switchbacks.meshlayers.ron",   // inside tunnels/; its Passages paths are inside tunnels/ too
    ground_offset_m: -512.0,                  // height of ground count 0
    ground_step_m: 0.03125,                   // metres per ground count
    lights: (spacing_m: 40.0, height_m: 9.0, intensity_lm: 60000.0, radius_m: 36.0, color: (1.0, 0.78, 0.55)),
    rock: (0.42, 0.27, 0.17),                 // tube rock albedo, linear
)
```

The heightfield must be square, and every sample must sit on a ground count (within a quarter count). Set
`spacing_m` to 0 for no lights. Otherwise it is at least 4 m.

## View pairs

`perf_views.json` is the showcase views file ([Showcase performance table](showcase-perf-table.md)), so
`cargo xtask showcase-table` plays it too. The pairs are named `tube_<pair>` and `outdoor_<pair>`:

- `tube_<pair>` starts in the middle of the longest sealed run of one half of the lava tube, 3 m over the
  floor. It follows the tube's centreline for 30 m in 6 s, looking along its heading.
- `outdoor_<pair>` is the same keys and heading 3 m over the plain, right above the tube.

`mouth_drive` drives from the plain down the `mid_east` skylight ramp into the tube.

## Agent methods

Registered on the `AgentExtension` (capability `showcase_tunnels`) by every showcase host built with the agent
feature.

### tunnels.state

```json
{"jsonrpc":"2.0","id":1,"method":"tunnels.state","params":{}}
```

The reply holds the following fields:

- What the load armed: `armed`, `document`, `mouths` (`id`, `rings`, `ring_points`, `cut_triangles`, `centre`)
  and `lattice_cut` (whether the terrain draws the cooked cut).
- The tubes: `meshes`, `triangles` and `lights`.
- The cooked indoor cells and portals: `cells` and `portals`.
- The sizes: `sim_bytes` (spec 121 § 11's measure) and `cooked_bytes`.
- The scene's views: `views`, `pairs` (`pair`, `tube`, `outdoor`) and `playing`, the view `tunnels.view` played
  last.
- `views_error`, when `perf_views.json` did not read.

### tunnels.view

```json
{"jsonrpc":"2.0","id":2,"method":"tunnels.view","params":{"pair":"west","side":"tube"}}
{"jsonrpc":"2.0","id":3,"method":"tunnels.view","params":{"name":"outdoor_west"}}
```

Plays one view on the camera as a one-shot camera path, as `camera.set_path` with `play` does. Name the view
with `name`, or with `pair` and `side` (`tube` or `outdoor`). With `play: false` the path loads held at its
first key. The reply is `{ view, pair?, side?, seconds, playing }`.

### Errors

The code is in `data.code`.

| Code | Meaning |
|---|---|
| `tunnels_off` | The scene has no armed tunnels (no `tunnels/tunnels.ron`). |
| `no_views` | The scene has no `perf_views.json`, or it did not read (the message says why). |
| `unknown_view` | No view of that name (the message lists the views). |
| `bad_view_params` | Neither `name` nor `pair` with `side`; both given; `side` is not `tube` or `outdoor`; a parameter of the wrong type. |

Load errors (`--check`, the scene loader) have their own codes, also listed in [Showcase](showcase.md):

| Code | Meaning |
|---|---|
| `tunnels_malformed` | `tunnels/tunnels.ron`, the document or a passages file does not parse, has the wrong version, an unknown field, a path outside `tunnels/` or an out-of-range number. |
| `tunnels_ground_mismatch` | The heightfield is not square, or a sample is not on a ground count. |
| `tunnels_cook_failed` | The mesh-layers cook refused the document. The message carries the cook's own code (for example `input_missing`, `meshlayers_parse`, or a check code; see [Mesh-layer seams](terrain-mesh-layers.md)). |

## The frame job: per-pass GPU times for a view pair

The D8 measurement is a headless render-out job per view, timed with `play.hitch_report` during the job:

```json
{"jsonrpc":"2.0","id":4,"method":"tunnels.view","params":{"pair":"west","side":"tube"}}
{"jsonrpc":"2.0","id":5,"method":"render.out_start","params":{"out":"/tmp/tunnels","name":"tube_west","frames":240,"width":1280,"height":800,"fps":60,"warmup_frames":30}}
{"jsonrpc":"2.0","id":6,"method":"play.hitch_report","params":{"seconds":3,"warmup_s":0.5,"timeout_ms":60000}}
```

Use the GPU times from `play.hitch_report`: `gpu` holds the percentiles and `gpu_passes.nodes` the pass times.
The job's `render_ms` is wall time (render plus readback). It is not a GPU number.

The test `samples/showcase/tests/tunnels_frames.rs` runs this job for both views of a pair. It reads the
renderer's GPU timings on every frame of the job and writes the per-pass medians, the frame median, the drawn
terrain nodes and the hitch report of each view, plus `interior_over_outdoor`, the ratio the D8 bar reads.
Lavapipe runs a small job by default and asserts no time. For a measurement:

```text
REGIA_TUNNELS_PROFILE=Deck REGIA_TUNNELS_SIZE=1280x800 REGIA_TUNNELS_FRAMES=240 \
  REGIA_TUNNELS_REPORT=/tmp/tunnels-deck.json \
  cargo test --release -p showcase --test tunnels_frames -- --nocapture
```

For the min-spec leg use `REGIA_TUNNELS_PROFILE=DesktopLow` with `REGIA_TUNNELS_SIZE=1280x720`. The demo's Very
Low tier is DesktopLow drawn at a 33 % render scale, and the test does not set a render scale, so this leg
measures Low at 720p: an upper bound on Very Low's cost. `REGIA_TUNNELS_PAIR=east` picks the other pair.

## Known limits

- The tube meshes carry no `VisCell` tag, so the portal cull never drops them. They are culled by the frustum
  only, and seen from the plain they still draw where the frustum holds them. The portal cull does drop the
  outdoor terrain and scatter seen from inside.
- The plain is flat (the canyon floor the fixture is cooked on). The look is plain; the frame cost is what the
  scene is for.
- The tubes draw the cooked presentation mesh as entities, not the chunk stream (`TerrainLayerStream`). The chunk
  LODs need the asset pipeline's chunk cook, and a sample cannot link that crate.
