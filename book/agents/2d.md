# 2D

Methods for the 2D toolkit (`specs/22` § T2.10, `specs/86`). They need `regia_2d::Sprite2dPlugin`
in the app; use `seeing.screenshot` for the picture itself. The first five read; the `tilemap.*`
writes below change the loaded map (see [Tile writes and auto-tiling](#tile-writes-and-auto-tiling)).

| Method | Params | Result |
|---|---|---|
| `sprite.list` | `limit?` (500) | `{ total, sprites: [...] }` in entity order |
| `sprite.get` | `entity` | one sprite |
| `tilemap.list` | — | `{ tilemaps: [{ entity, map, loaded, visible, position, detail }] }` |
| `tilemap.get_tile` | `entity?`, `x` + `y` **or** `world: [x, y]`, `layer?` | hit: `{ cell, layer, tile, map_rect, orientation, outline }`; empty in-range cell: `{ cell, tile: null }`; world outside the map: `{ tile: null, reason }` |
| `view2d.get` | — | `{ camera, pixel_perfect, snap, clear, last_frame }` |
| `tilemap.set_tile` | `entity?`, `layer`, `x`, `y`, `gid` (0 = erase), `flip? { x, y, diagonal }` | `{ cell, layer, before, after }` |
| `tilemap.autotile_register` | `name`, `ron` (`.autotile.ron` text) **or** `path` (a cooked `.autotile.ron`) | `{ name, terrains, replaced, path? }` |
| `tilemap.autotile_list` | — | `{ rule_sets: [{ name, tileset, seed, border, terrains }] }` |
| `tilemap.paint` | `entity?`, `layer`, `rules`, `terrain` **or** `erase: true`, `cells: [[x, y], …]` **or** `rect: [x0, y0, x1, y1]` | `{ count, truncated, changed: [{ cell, before, after }] }` |
| `tilemap.autotile` | `entity?`, `layer`, `rules` | `{ changed }` |
| `tilemap.stamp_copy` | `entity?`, `layer`, `rect: [x0, y0, x1, y1]` | `{ width, height, cells }` |
| `tilemap.stamp_paste` | `entity?`, `layer`, `x`, `y`, `stamp`, `op?` **or** `ops?`, `skip_empty?` | `{ stamp, count, truncated, changed: [{ cell, before, after }] }` |

A sprite entry: `entity`, `atlas` (path), `loaded`, `source` (`{name}` or `{rect}`), `region`
(`page`, `rect`, `source_size`, `pivot`, `nine_slice`; the last three are `null` for a rect source), `position` `[x, y, z]` (z = draw order),
`size`, `color`, `flip` `[x, y]`, `visible`, and `animation` (`animation`, `index`, `frame`,
`playing`, `finished`, `animations`) when it has an `AnimatedSprite`.

`tilemap.list` `detail`: `size` (tiles), `tile_size`, `orientation` (`orthogonal`, `isometric`,
`staggered` or `hexagonal`), `tilesets`, and `layers` — tile layers with
their non-empty `tiles` count, object layers with every object's `id`, `name`, `class`, `position`
and `size` (Tiled coordinates). Spawn points and triggers authored in Tiled show up here.

`tilemap.get_tile` addresses a cell with `x`, `y` (row 0 = **top**, as in Tiled) or a world point
(`world: [x, y]`, through the map entity's transform; its origin is the map's bottom-left). Without
`layer` it returns the topmost tile layer that has a tile there.

A cell that holds a tile returns `cell`, `layer` (`index`, `name`), `tile`, `map_rect`,
`orientation` and `outline`. `tile` is `gid`, `tileset`, `local_id`, `flip { x, y, diagonal }`,
`collision` (`empty` / `solid` / `one_way`), `class` (`""` when the tile has no data), `animated`
and `properties` (`{}` when none). `map_rect` is the bounding box of that cell and `outline` its
shape (4 points, 6 for a hexagon) in map pixels, +Y up; `orientation` names the map's layout.

An in-range cell with no tile returns `{ cell, tile: null }` and omits `layer`, `map_rect`,
`outline` and `orientation`. An `x`/`y` past the map takes that same result (it is not an error).
A world point outside the map returns `{ tile: null, reason: "outside the map" }` and omits `cell`.

On isometric, staggered and hexagonal maps `world` picks the cell whose diamond or hexagon holds
the point ([map orientations](../../docs/formats/tilemap-ron.md)).

`map_rect` retains double precision, including on wide maps. Use integer `x`, `y` cell addresses
for such queries: `world` input and `outline` coordinates still use single precision. Rendering
also uses single-precision GPU instances; translate/rebase far map cells near the world origin
to preserve pixel detail.

`view2d.get` `last_frame` counts the sprites and tiles drawn last frame, the sorted instances and the
texture batches (draw calls).

## Tile writes and auto-tiling

The writes change the map loaded in the running app (copy-on-write; the sprite pass draws the new
tiles the next frame). They are runtime edits: a hot reload of the map's source file replaces them.
To edit the source itself, use the editor's 2D mode ([Editor 2D mode](editor-2d.md)). The editor also
creates new maps, edits their tileset binding and layer order, and edits `.autotile.ron` rule sets
with a preview painted by the same auto-tiler ([Auto-tile rule editor](editor-2d.md#auto-tile-rule-editor)).

- `tilemap.set_tile` writes one tile. `gid` is the bare id (`first_gid + local id`, 0 = empty);
  flips go in `flip`. `gid` 0 ignores `flip` and stores 0. `before` and `after` are raw GIDs with Tiled's flag bits.
- `tilemap.autotile_register` parses `.autotile.ron` text (`docs/formats/autotile-ron.md`, at most
  1 MiB; a longer `ron` is refused with `F0002` before the method runs) and registers it under
  `name`. Games register rule sets in code with `regia_2d::AutoTiles::insert`.
- `tilemap.autotile_list` lists the rule sets: `tileset`, `seed`, `border` (`same` / `empty`) and each
  terrain's `name`, `layout` (`edge16` / `blob47` / `rules`), `rules` (count), `members` (local tile
  ids that count as the terrain) and `variants` (entries).
- `tilemap.paint` paints a terrain, or erases, over `cells` or an inclusive `rect` (at most 65 536
  cells). The painted cells and their 8 neighbours re-resolve, so edges and corners appear by
  themselves. Every cell is checked before anything is written. `changed` lists at most 1 000 cells
  sorted by row then column; `count` is the total and `truncated` says whether the list was cut.
  The result does not depend on the order of cells or calls.
- `tilemap.autotile` re-resolves every terrain cell of a layer: after `tilemap.set_tile` placed member
  tiles by hand, or on an imported map.
- `tilemap.autotile_register` also takes `path`: a `.autotile.ron` cooked with the project's other
  2D assets (`regia cook`, stored in the pak) is loaded instead of parsing text, and equals the raw
  file's rule set. `layout` is also `wang_corner` (16 tiles indexed by which cell corners lie inside
  the terrain). Rules work on the cell grid, so on staggered and hexagonal maps the 8 neighbours are
  the grid neighbours, not the geometric ones.
- `tilemap.stamp_copy` returns a rectangle of a layer as a stamp (`width`, `height`, `cells`: raw gids
  with flip bits, row 0 on top). `tilemap.stamp_paste` puts it back with its top-left cell at `x`, `y`
  (negative is fine; the part off the map is clipped), after the optional `op` / `ops`
  (`rotate_cw`, `rotate_ccw`, `rotate_180`, `flip_x`, `flip_y`, at most 16): the tiles' flip bits turn
  with the stamp, so a rotated stamp looks like the rotated picture. Empty stamp cells leave the map
  alone unless `skip_empty: false`. Every check happens before the first write.
  The transformed stamp's last cell must fit signed 64-bit coordinates; an overflowing extent
  answers `tile_bad_params` and leaves the map and its revision alone.

Error codes (`data.code`; `errors.explain` gives the long form). The JSON-RPC error code is
`-32602` (invalid params) for every one of them except `tile_unknown_rules`, which is `-32001`
(not found):

| Code | Meaning |
|---|---|
| `tile_bad_params` | A parameter is missing or has the wrong shape (`terrain` and `erase` together, `cells` and `rect` together, a cell that is not `[x, y]`). |
| `tile_bad_gid` | `gid` carries flag bits, or no tileset holds it. |
| `tile_not_tile_layer` | The layer does not exist or is an object layer. |
| `tile_outside_map` | A cell is outside the map; nothing was written. |
| `tile_too_many_cells` | More than 65 536 cells in one `tilemap.paint` or one `tilemap.stamp_paste`. |
| `tile_unknown_rules` | No rule set has that name. |
| `tile_unknown_terrain` | The rule set has no terrain of that name. |
| `tile_bind_failed` | The rule set's `tileset` is not in this map, a tile id is past its `tile_count`, or the layer's data is not `width × height` cells long (nothing was written). |
| `tile_bad_rules` | The `.autotile.ron` text does not parse or validate, or is a newer version, or the cooked `path` is not in the manifest. |
| `tile_bad_stamp` | The stamp is empty, over its size limit (`1 << 20` cells, including a `tilemap.stamp_copy` rectangle), has the wrong cell count, or the rectangle is empty. |

`F0003` means no tilemap entity exists or its map is not loaded.

## Recipes

- **Did the player land on the platform?** `sprite.get` the player, then `tilemap.get_tile` with
  `world: [x, y - 1]` under its feet: `collision` should be `solid` or `one_way`.
- **Is the animation playing?** `sprite.get` → `animation.frame` changes between two calls with
  `play.step` frames in between; `finished` turns true for play-once animations.
- **Build a wall and check its corners.** `tilemap.paint` a `rect` with the wall terrain, then
  `tilemap.get_tile` at its ends: the `local_id`s are the end-cap tiles, the middle cells the
  straight piece. `tilemap.paint` with `erase: true` on one cell splits it into two walls.
- **Is the map loaded and visible?** `tilemap.list` → `loaded: true` and `visible: true`. Then
  `view2d.get` → `last_frame.tiles > 0` tells you whether any of its quads fall inside the camera
  (a visible map that sits off camera reports `0`).

## Example calls

Example calls (`regia agent call <method> '<params json>'`; entity ids come from `scene.query_entities`):

```text
sprite.list {"limit": 20}
sprite.get {"entity": 4294967310}
tilemap.list {}
tilemap.get_tile {"x": 3, "y": 2}               # row 0 is the top row
tilemap.get_tile {"world": [48.0, 32.0]}
view2d.get {}
tilemap.set_tile {"layer": "ground", "x": 3, "y": 2, "gid": 5, "flip": {"x": true}}
tilemap.autotile_list {}
tilemap.paint {"layer": "ground", "rules": "walls", "terrain": "wall", "rect": [0, 4, 9, 4]}
tilemap.paint {"layer": "ground", "rules": "walls", "erase": true, "cells": [[4, 4]]}
tilemap.autotile {"layer": "ground", "rules": "walls"}
tilemap.autotile_register {"name": "walls", "path": "assets/maps/walls.autotile.ron"}   # cooked, from the pak
tilemap.stamp_copy {"layer": "ground", "rect": [0, 0, 3, 2]}
tilemap.stamp_paste {"layer": "ground", "x": 10, "y": 4, "op": "rotate_cw",
                     "stamp": {"width": 2, "height": 1, "cells": [5, 6]}}
```
